# 01-business / 流程

> 面向 HIS/EMR 平台的流程定义。每个流程均说明其触发条件、步骤以及约束这些步骤的规则。规则位于 `business-rules.md`（BR-xx）中，仅被引用，绝不重复陈述。
>
> ⚠️ ASSUMPTION — 流程分解属于方案包设计。未引用任何外部标准。

## P-01 — 登记与身份识别

| | |
|---|---|
| **触发条件** | 登记，或提交新的标识符 |
| **结果** | 一条 EMPI 记录，其中疑似重复档案会被标记，而非静默处理 |

1. 根据标识符和人口学信息解析患者身份。
2. 疑似存在重复档案时，**标记待主索引核对**（BR-04）。
3. 关联就诊上下文。

> BR-04：重复患者会静默割裂病史；错误合并会把两个人的生命合并在一起。两者都比留下一个尚未处理的标记更糟糕。

## P-02 — 合并与拆分

| | |
|---|---|
| **触发条件** | 经人工复核的合并决策 |
| **结果** | 已记录的合并，或已记录的**拆分** |

1. 执行合并，并**记录该合并**（BR-05）。
2. 将**拆分**作为一等操作提供，并将其传播至临床事实（BR-05）。
3. 记录匹配置信度和所使用的规则（BR-06）。

> BR-05：无法拆分的合并，是针对某个人作出的、无人能够纠正的决定。

## P-03 — 就诊与文档

| | |
|---|---|
| **触发条件** | 发生诊疗活动 |
| **结果** | 临床文档均已**签署**，此后仅可通过补录修改 |

1. 在临床病历中撰写文档。
2. **签署**——署名指谁撰写了该文档，签署则证明文档完整且正确（BR-07）。
3. 签署后，更正以引用原文档的**补录**形式进行——绝不进行原地编辑（BR-07）。
4. 作废会将文档标记为自始无效；原文档仍保持可见（BR-08）。

> BR-07：已签署的病程记录是某一时刻认知的证据。原地更正会同时破坏该证据和临床病历。

## P-04 — 医嘱与结果

| | |
|---|---|
| **触发条件** | 下达医嘱 |
| **结果** | 闭环——医嘱、结果、处置、复核 |

1. 下达医嘱（用药、检验、影像）。
2. 结果从 LIS 或 RIS/DICOM 返回，并与相应医嘱和就诊关联归档（BR-09）。
3. 医嘱形成结果、处置和复核——这是衡量医嘱是否悬而未决的指标（BR-09）。
4. 影像以 **DICOM 对象**的形式进入平台，而不是被拆解为多个表（BR-10）。

## P-05 — 编码

| | |
|---|---|
| **触发条件** | 对就诊进行编码 |
| **结果** | 带有**编码体系与版本**的已编码事实 |

1. 分配诊断和诊疗操作编码。
2. 在每项已编码事实上记录**编码体系与版本**（BR-11）。
3. 重新映射是一项版本化、可审计的操作——绝不能进行静默升级（BR-11）。

> BR-11：代码会在上游被废止、替换和重新映射。在实施时一次性建立的映射会在无任何提示的情况下静默失效。

## P-06 — 收费与结算

| | |
|---|---|
| **触发条件** | 就诊完成 |
| **结果** | 从就诊派生的收费项目——**绝不**通过编辑临床病历来生成 |

1. 根据就诊的已编码事实派生收费项目（BR-12）。
2. 收费/结算记录与临床病历不一致时，应解释这两个相互冲突的事实——绝不能通过编辑临床病历来消解差异（BR-12）。
3. 通过保险功能完成结算。

> BR-12 是本方案包的第一条法则（`AGENTS.md`）：将临床病历与收费/保险记录分离。绝不能为满足收费要求而编辑临床事实。

## P-07 — 访问与紧急访问

| | |
|---|---|
| **触发条件** | 临床医师打开病历 |
| **结果** | 基于诊疗关系授予并记录的访问；或具有正当理由的紧急访问 |

1. 依据**诊疗关系**及已声明的授权基础授予访问权限（BR-13）。
2. 紧急情况下，若正常访问过慢，则允许**紧急访问**——须记录日志、说明理由并进行**事后复核**（BR-14）。
3. 无论采用哪种方式，都记录访问。

> BR-14：紧急访问按定义属于例外情况。使用率上升意味着正常访问路径已失效，这是平台的缺陷，而不是工作人员的缺陷。

## P-08 — 治理

| | |
|---|---|
| **触发条件** | 按计划执行，或收到请求时执行 |
| **结果** | 按类别执行保留期；删除操作随之传播 |

1. 按**数据类别**执行保留期（BR-15）。
2. 将删除操作传播至副本、缓存、日志和派生数据集（BR-16）。
3. 无法验证删除完成时，应记录该限制，而不是记录为已完成。
