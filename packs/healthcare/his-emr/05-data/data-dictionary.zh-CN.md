# 05 · 数据字典

> 仅包含核心实体。字段语义具有规范性；类型仅供说明。
>
> ⚠️ ASSUMPTION — 字段级设计属于方案包设计。FHIR 资源名称用作
> 本方案包的词汇；**不主张将任何 FHIR 发布版本作为规范性依据**——该选择是
> 一项方案包决策，记录于 `SOURCES.md` §2。

## 合并 / 匹配置信度（MERGE / MATCH_CONFIDENCE）

| 字段 | 语义 |
|---|---|
| `rule_id` / `rule_version` | 生成此次匹配所采用的解析规则，使合并操作可以接受审查并明确归因，而无须依赖推断 |
| `confidence` | NOT NULL，并须存储该值——而不是事后派生。身份解析具有概率性，且该概率必须可见（BR-06） |
| 约束 1 | 不得存在其评分低于 `performed_ts` 时刻**生效阈值**的合并。应按历史阈值进行评估，因为阈值变更不得追溯性地使某项合并无效或有效 |

## 文书 / 签署（DOCUMENT / SIGNATURE）

| 字段 | 语义 |
|---|---|
| `author_ref` | 谁撰写了该文书。**署名。** |
| `SIGNATURE.signer_ref` | 谁证明其完整且正确。**签署。** |
| 为何分为两个实体 | 约束 3。本方案包将二者分开，因为混同二者会使“已签署”成为一个没有明确指代对象的词——而且这种区分在操作层面切实存在：由代班临床医师录入的内容已签署但未署名；由记录员转录的口述内容已署名但未签署 |
| `state` | 为 `draft`、`signed`、`retracted`。一旦状态为 `signed`，便不再授予 UPDATE 权限（约束 3）：更正应写入一条 `ADDENDUM` 行，绝不能进行编辑 |
| `retracted` | 该文书保持可见，并标记为自始无效（BR-08）。删除它会抹去曾发生错误的证据 |

## 申请/医嘱 / 结果 / 处置 / 复核（ORDER / RESULT / DISPOSITION / REVIEW）

| 字段 | 语义 |
|---|---|
| 四个实体 | 约束 4：没有结果、处置**和**复核，医嘱不得置为 `closed`。采用三个独立行，而不是在医嘱上设置三个标志位，因为缺失一行会以缺口形式显现，而采用默认值填充的标志位则不可见 |
| `RESULT.source_version` | 结果携带其来源的版本，因此由较旧 LIS 接口生成的结果在接口变更后仍可解释 |
| 悬空医嘱 | 缺少上述三行中任意一行的医嘱即为悬空医嘱，且 `dangling_order` 为 sev-1：在有人查找之前，它与已完成医嘱无法区分 |

## 编码体系 / 代码值 / 已编码事实（CODE_SYSTEM / CODE_VALUE / CODED_FACT）

| 字段 | 语义 |
|---|---|
| `code_system.version` / `coded_system_version` | NOT NULL（约束 6）。在**生成时**记录——事后无法重建，因为映射此后已发生变更。缺少此信息，历史就诊/诊疗活动将无法解释 |
| `MAPPING_VERSION` | 代码重新映射构成一个新版本，绝不是对已存储事实的编辑。原地更改映射会悄然按新的解释重新表述整个历史语料库 |

## 收费项目（CHARGE）

| 字段 | 语义 |
|---|---|
| `coded_fact_ref` | NOT NULL，指向临床事实。这体现了 ADR-0005 的单向依赖关系：收费项目派生自已编码事实，并且不存在任何字段或路径，使收费操作能够写入临床病历（约束 7） |
| 临床与收费差异 | 预期之内，应予报告，而不是就地解决。NFR-009 将其作为一种状态进行跟踪；NFR-010（归因于收费的临床变更）必须为零 |

## 访问决策 / 紧急访问事件（ACCESS_DECISION / BREAK_GLASS_EVENT）

| 字段 | 语义 |
|---|---|
| `basis` | 一个诊疗关系引用和一项已声明的理由。约束：没有依据的决策属于非法行为。仅凭部门成员资格不足以构成依据 |
| `BREAK_GLASS_EVENT.justification` | NOT NULL，并转交复核（约束 8）。在没有理由说明的情况下，绕过正常授权获取访问属于缺陷，而不是紧急通道 |
| `break_glass_rate` | 其上升属于**平台缺陷**（FR-023），而不是有关员工使用情况的数据。应将其作为编写易用性问题予以提示 |

## 擦除结果（ERASURE_OUTCOME）

| 字段 | 语义 |
|---|---|
| `destination` | `record`、`cache`、`log`、`derived`、`imaging`、`backup`。后四项最容易被遗忘——搜索索引、审计日志、派生队列和训练后的模型都会持续保存个人数据 |
| `state` | 为 `completed` 或 `limitation`（约束 9）。不存在 `unknown`，因为没有对应行的目标并未被擦除，将其写为 completed 会形成虚假记录 |
| 删除如何执行 | ⚠️ 本方案包未作规定。与不可变副本、备份、影像和派生机器学习制品的交互属于部署选择；在此指定一种机制无异于臆造确定性 |

## 数据类别保存期限（RETENTION_CLASS）

| 字段 | 语义 |
|---|---|
| `declared_window` | 每个类别均为 NOT NULL（约束 10）。临床病历、影像、审计日志、收费/结算记录和日志的性质与义务各不相同；BR-15 禁止设置全局行 |
| 取值 | **本方案包未指定任何值。** |
