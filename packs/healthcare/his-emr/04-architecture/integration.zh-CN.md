# 04 · 集成

> 与外部系统的集成契约。ID 保持稳定；每个流程都可追溯
> 至需求和规则。
>
> ⚠️ ASSUMPTION — 接口选择和协议属于方案包设计。HL7 FHIR 是
> 本方案包的临床数据模型，HL7 v2.x 是其旧版消息边界；DICOM
> 是影像边界。不指定任何 API 版本。

## I. 集成点

| ID | 相邻系统 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **身份/员工目录** | 入站 | 身份验证和诊疗关系属性 |
| **I-02** | **LIS (检验)** | 双向 | 申请/医嘱发出、结果返回 (HL7 v2.x 类) |
| **I-03** | **RIS / PACS** | 双向 | 影像申请/医嘱和 DICOM 对象 |
| **I-04** | **药房自动化** | 双向 | 配药和给药 |
| **I-05** | **医疗保险 (医保)** | 出站 | 结算——独立的记录边界 |
| **I-06** | **收费/财务** | 出站 | 收费项目和结算 |
| **I-07** | **公共卫生报告** | 出站 | 法定传染病报告和登记 |
| **I-08** | **数据平台/研究** | 出站 | 去标识化或经同意的导出 |
| **I-09** | **床旁监护仪/设备** | 入站 | 设备生成的观察/体征 |
| **I-10** | **保留与删除工具** | 入站 | 删除和导出请求 |

## F. 内部流程

### F-01 — 登记并解析身份
1. 提交标识符和人口学信息。
2. 身份解析对匹配结果进行评分，并记录规则、版本和匹配置信度。
3. 低于阈值时，记录会被**标记**以进行主索引核对，且对临床医师而言仍无法明确归属。
4. 记录经批准的合并，且拆分仍可用。

### F-02 — 文档
1. 文档由作者撰写，并记录署名信息。
2. 文档经签署；签署、签署人、时间戳和签署声明均被**分别记录**。
3. 后续更正以引用原文档的补录形式作出。
4. 作废将文档标记为自始无效，原文档仍保持可见。

### F-03 — 申请/医嘱与结果
1. 针对一次就诊/诊疗活动开具申请/医嘱。
2. 申请/医嘱最终形成结果、处置和复核。
3. 结果同时归档至申请/医嘱和就诊/诊疗活动。
4. 影像以 DICOM 对象形式到达并被引用，绝不拆解。

### F-04 — 编码、收费、结算
1. 分配诊断和诊疗操作编码，并记录编码体系与版本。
2. 收费项目由已编码事实派生——只能单向派生。
3. 临床与收费差异会被报告并分流处理。
4. 结算继续由保险职能处理。

### F-05 — 访问与紧急访问
1. 基于诊疗关系授予访问权限，并明确声明依据。
2. 紧急访问会记录理由并转入复核。
3. 每次访问都必须能够归责到具体主体。

### F-06 — 保留与删除
1. 保留期按已声明的各类别时间窗口执行。
2. 删除操作传播至记录、缓存、日志和派生目标。
3. 每个目标均记录处理结果。

## 故障模式契约

| 集成 | 必须处理的故障模式 |
|---|---|
| **I-01 身份** | 无法获取诊疗关系上下文时意味着**无访问权限**，而不是获得更广泛的访问权限。临床病历访问若在故障时默认放行，则是本方案包最严重的风险方向 |
| **I-02 LIS / I-03 RIS** | 结果缺失或延迟到达时，申请/医嘱应保持**未结状态**，绝不能被视为“正常”。申请/医嘱不得在没有结果的情况下静默关闭 |
| **I-05 保险** | 结算失败属于收费状态事件，绝不修改临床内容。临床与收费差异路径的存在，正是为了避免需要进行这种修改 |
| **I-06 收费/财务** | 财务侧调整属于收费侧记录，不能波及临床病历 (BR-12) |
| **I-08 研究** | 导出内容须经去标识化处理或取得同意，重新识别尝试属于受治理事件 |
| **I-10 删除** | 不可达的目标应记录为一项限制，绝不能记录为已删除 (BR-16) |
| **I-09 设备** | 设备生成的观察/体征携带其来源和版本，数据缺口应明确显示为缺口，而不是通过插值生成 |

> 规律是：集成不可用时，应使外部路径降级，并将其记录为*未知*——绝不推定，也绝不采用默认值。身份是唯一必须采用故障时关闭（fail-closed）的情况，因为缺少诊疗关系依据的访问决定不是强度较弱的决定，而是根本不构成决定。

## 编码契约（已编码事实的使用方必须接受的内容）

| 方面 | 集成所声明的内容 |
|---|---|
| **编码体系与版本** | 每项已编码事实均须包含编码体系与版本，否则该事实不可导出 (BR-11) |
| **映射版本** | 明确给出，且绝不回溯应用于已存储事实 |
| **术语时效性** | 重新映射是一项带版本的操作；下游使用方若应用自己的映射，就会产生第二项未记录的重新映射 |
| **临床事实** | 临床病历是权威依据；需要采用不同编码进行支付的使用方应在收费/结算记录中解决，而不是在临床病历中解决 |

> 在导入时重新编码的使用方——这在研究和支付方数据馈送中很常见——会产生平台并不掌握的第二套术语历史，并使历史就诊/诊疗活动在两套历史之一中变得无法解读。
