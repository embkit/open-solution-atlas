## 绝不作取舍的八项不变量

`signed_document_edited`、`clinical_record_edited_by_billing`、
`access_granted_without_basis`、`coded_fact_without_system_version`、
`dangling_order`、`erasure_destination_unresolved`、
`auto_merge_below_threshold` 和 `imaging_objects_discarded` 必须为 **零**。

八项均为 sev-1，其数量多于任何同级方案包；原因在于这一领域的特性：在临床系统中，这些情况全都**不可逆**。没有办法撤销对已签署病程记录的编辑、把悬空医嘱恢复为“正常”、让已丢弃的 DICOM 对象重新显现、撤销已经告知患者其病历从未被查看这一事实，或解读术语版本未知的已编码事实。

> 如果仪表板让这些信号看起来与其他信号无异，就会让团队学会把这些信号*全部*当作可交换项。之所以标记这八项，是为了让取舍变得明确且可复核；并且本方案包有意比其他同级方案包标记更多项目，因为这里的后果不会逆转。

## 平台必须能够回答的问题

| 问题 | 回答依据 |
|---|---|
| “谁撰写了这份文件、谁签署了它，以及更正了什么？” | 签署链和补录链接 |
| “该医嘱最终闭环了吗？” | 医嘱的结果、处置和复核事件 |
| “该诊断在当时意味着什么？” | 已编码事实的编码体系与版本 |
| “为什么该患者的历史记录被拆分或合并？” | 合并记录、匹配置信度和拆分状态 |
| “谁读取了这份病历，依据是什么？” | 访问决策，包括紧急访问理由 |
| “该患者是否确实已在所有位置删除？” | 各目标位置的删除结果 |

> 每个问题均可仅凭平台自身记录回答。其中第一个和最后一个问题最常改用重构来回答——而在临床审查中，重构并不足够。

## 追踪与关联

- 一条**就诊/诊疗活动**追踪涵盖：登记 → 身份解析 → 医嘱 → 结果 → 文档记录 → 签署 → 编码 → 收费。它携带患者引用和诊疗活动引用，因此整个诊疗阶段均可重构。
- 一条**医嘱**追踪涵盖：开立 → 结果 → 处置 → 复核，影像检查还附带检查引用。缺少任何步骤都会形成悬空医嘱，表现为缺口，而不是“正常”状态。
- 一条**访问**追踪涵盖：决策 → 诊疗关系依据 →（如适用）紧急访问理由 → 复核。每个步骤均可明确归属，这正是分级控制所要求的证据。

## 告警策略

- **呼叫**：任何不变量遭到违反时，或紧急访问复核超过其时限时。
- **工单**：针对重复档案处置延迟、医嘱闭环延迟、临床与收费差异及删除结果缺口。
- **复核**：每周复核三项趋势，因为其*方向*比其数值更重要：紧急访问率上升意味着正常访问路径已失效，且平台正是原因；补录率上升意味着文档编写过程正在产生需要更正的文件，这属于编写缺陷，而不是文档记录缺陷；临床与收费差异上升意味着编码本体与收费本体正在逐渐偏离，这是术语方面的治理问题。
