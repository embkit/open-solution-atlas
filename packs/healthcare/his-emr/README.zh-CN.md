## 本方案包涵盖的内容

医院的临床与行政核心：用于记录患者身份、已下达的医嘱和已执行的诊疗操作、
已记录的临床内容以及收费情况的权威记录系统。其核心难题是
**跨诊疗场景的临床数据完整性**——统一的患者身份（EMPI）、统一的纵向病历（EMR）、
始终保持关联的医嘱与结果（CPOE → LIS/RIS），以及能够与临床诊疗活动对账、
且不会扭曲该诊疗活动的收费/保险链路。

## 范围内

- 患者身份：EMPI（企事业主索引 / 主索引）、重复档案合并/拆分、
  跨机构身份映射
- 登记与接诊：门诊挂号/就诊、住院入院/转科/出院登记（ADT）、
  基础预约排程
- 临床文书记录：EMR（问题列表、病程记录、生命体征、医嘱）、
  模板、已签署/经补录修订的文书、CPOE
- 医嘱与结果：医嘱生命周期、闭环关联，以及检验（LIS）和影像（RIS/PACS）的
  集成边界
- 用药：药房发药、给药记录、过敏/相互作用检查、处方生命周期
- 收费与结算：诊疗活动收费项目、费用项、医疗保险（医保）接口边界、
  结算/退款
- 临床术语：ICD-10/11 编码、FHIR 资源建模、术语服务边界
- 报告：临床质量指标和医院运营报告

## 明确不在范围内

- LIS/RIS/PACS 检验和影像系统本身（通过 HL7 v2/FHIR 和 DICOM
  接入的集成目标）
- 区域健康信息交换 / 区域健康平台运营
  （候选同级方案包；本方案包是医院侧节点）
- 保险支付方理赔裁定引擎（集成目标）
- 远程医疗和消费者健康应用

## 开放问题

1. EMR 文档模型：采用 FHIR 原生存储，还是采用带有 FHIR 外观层的
   面向文档临床存储库？
2. 与区域交换方案包的边界：患者身份联邦中哪一部分位于医院侧？
3. 医疗保险（医保）接口深度：仅支持结算，还是涵盖完整的对账与审计？
4. 临床决策支持（CDS）是核心能力，还是明确规定的扩展点？

## 已确定的 ADR（不得重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | 身份合并是**可逆的**，拆分操作会**传播**至临床事实；低于匹配置信度阈值的合并不得存在 |
| **0002** | 已签署文书是**证据**——通过**补录**更正，绝不原地编辑；署名与签署是彼此独立的属性 |
| **0003** | 影像以**DICOM 对象**形式跨越边界，且这些对象予以保留；索引绝不具有权威性 |
| **0004** | 术语映射是一项**版本化服务**；每项已编码事实在生成时都记录其编码体系和版本 |
| **0005** | 临床病历与收费/结算记录彼此分离，并具有**单向**依赖关系——收费/结算记录读取已编码事实，绝不回写 |
| **0006** | 访问遵循**诊疗关系**，无法确立授权依据时即拒绝；紧急访问按定义属于例外，使用率上升即表示平台存在缺陷 |
| **0007** | 删除操作延伸至**副本、缓存、日志和派生数据**，并记录每个目标位置的处理结果 |

## 阻断 L3

1. **约束的完整组件列表**——最小三元组已经固定；真实部署额外固定的内容，
   则属于本方案包已列明但未作出的版本化决策。
2. **删除如何覆盖不可变副本、备份、镜像和派生 ML 工件**——BR-16 确定了要求；
   具体机制是部署选择，本方案包有意不作决定。
3. **八项零容忍不变量的验收标准**——NFR-001、NFR-005、NFR-007、NFR-008、
   NFR-010、NFR-014，以及访问依据检查和禁止自动合并约束，都需要能够使构建失败的
   判据，而不是仅供报告的阈值。
4. **FHIR 发布版本**——资源名称作为词汇使用，未将任何发布版本声明为规范性依据；
   选定版本是一项版本化决策。

### 明确尚未解决（已记录，未遗忘）

- **行业规则的正式文本**——国卫规划发〔2026〕6号的依据来自二手摘要，而非正式通知。
  它是本方案包最直接适用的规范文件。
- **HIPAA**——沿用清单中的标识；来源页面未响应自动探测，未读取到任何内容。
  本方案包任何地方均未提出 HIPAA 相关主张。对于美国区域配置，这是阻断项。
- **保留期限值**——要求按数据类别分别规定，本方案包任何地方均未断言具体期限。
- **如何证明病历人工智能处理的安全性**——第二十八条确立了这项义务；
  证明工作属于 L3 阶段的工作。
