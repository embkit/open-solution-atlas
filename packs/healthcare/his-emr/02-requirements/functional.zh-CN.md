# 02 · 功能需求

> EARS 句式：`当 <触发条件> 系统应当 <响应>`。
> 稳定 ID 永久有效；每项需求均追溯到一项能力（`CAP-xx`）、一条规则（`BR-xx`）和一项
> ADR。验收标准（AC-*）在 L3 定义。
>
> `verification: unverified` — 这些需求属于方案包设计，未针对部署进行验证。

## CAP-01 患者身份（EMPI）

### FR-001 — 标记疑似重复档案
- **当** 身份解析产生的匹配结果低于配置的匹配置信度
- **系统应当** 将该记录标记为需要人工主索引核对，且不得自动合并（BR-04）
- 追溯：CAP-01、BR-04、ADR-0001

### FR-002 — 记录匹配置信度与规则
- **当** 提出一项匹配建议
- **系统应当** 记录匹配规则、规则版本及由此产生的匹配置信度（BR-06）
- 追溯：CAP-01、BR-06、ADR-0001

### FR-003 — 记录合并
- **当** 两条 EMPI 记录被合并
- **系统应当** 持久保存一条合并记录，注明被合并的记录及所用规则（BR-05）
- 追溯：CAP-01、BR-05、ADR-0001

### FR-004 — 拆分操作传播
- **当** 一次合并被撤销
- **系统应当** 恢复合并前的身份，并将拆分操作传播至与其关联的临床事实——就诊/诊疗活动、观察/体征、文档（BR-05）
- 追溯：CAP-01、BR-05、ADR-0001

### FR-005 — 匹配阈值策略可修订
- **当** 操作员更改匹配阈值
- **系统应当** 要求作出明确标明责任人的变更，且不得将新阈值追溯应用于已解决的合并（BR-06）
- 追溯：CAP-01、BR-06

### FR-006 — 向临床医师呈现歧义
- **当** 临床医师打开带有尚未解决的重复档案标记的记录
- **系统应当** 呈现该歧义，而不是呈现一名已解析的患者（BR-04、BR-06）
- 追溯：CAP-01、BR-04、BR-06

## CAP-03 临床文档

### FR-007 — 签署与署名分离
- **当** 一份临床文档被签署
- **系统应当** 将署名与签署分别记录为独立属性，并记录签署人、时间戳和认证声明（BR-07）
- 追溯：CAP-03、BR-07、ADR-0002

### FR-008 — 仅可通过补录修订
- **当** 一份已签署文书需要更正
- **系统应当** 要求提供一份具有明确作者归属、带时间戳并引用原文的新补录，且不得允许原地编辑（BR-07）
- 追溯：CAP-03、BR-07、ADR-0002

### FR-009 — 作废后保留原文档
- **当** 一份文档被作废，例如归档到了错误的患者名下
- **系统应当** 将其标记为自始无效，且不得删除它（BR-08）
- 追溯：CAP-03、BR-08

## CAP-04 医嘱与结果

### FR-010 — 医嘱闭环完整性
- **当** 提交一项医嘱
- **系统应当** 跟踪该医嘱直至产生结果、处置和复核，且不得允许其在三者未全部具备时结束（BR-09）
- 追溯：CAP-04、BR-09

### FR-011 — 未闭环医嘱检测
- **当** 开展闭环复核
- **系统应当** 报告未形成结果、处置或复核中任一环节的医嘱（BR-09）
- 追溯：CAP-04、BR-09

### FR-012 — 结果归档至医嘱和就诊/诊疗活动
- **当** 结果从 LIS 或 RIS 返回
- **系统应当** 将其归档至相应医嘱和就诊/诊疗活动，并记录来源及版本（BR-09）
- 追溯：CAP-04、BR-09

### FR-013 — 影像以 DICOM 对象形式存储
- **当** 影像进入平台
- **系统应当** 存储 DICOM 对象并对其进行引用，且不得将影像拆解为关系表后丢弃这些对象（BR-10）
- 追溯：CAP-04、BR-10、ADR-0003

### FR-014 — 通过 DICOM 划定影像边界
- **当** 呈现或交换一项影像结果
- **系统应当** 以 DICOM 对象模型作为边界（BR-10）
- 追溯：CAP-04、BR-10、ADR-0003

## CAP-06 编码与临床病历

### FR-015 — 记录编码体系与版本
- **当** 对诊断或诊疗操作进行编码
- **系统应当** 在已编码事实上记录编码体系 **及其版本**（BR-11）
- 追溯：CAP-06、BR-11、ADR-0004

### FR-016 — 以带版本的操作执行重新映射
- **当** 代码在上游被废止、替换或重新映射
- **系统应当** 以带版本、可审计的操作实施该变更，且不得静默升级已存储的代码（BR-11）
- 追溯：CAP-06、BR-11、ADR-0004

## CAP-07 收费与保险

### FR-017 — 收费项目源自临床病历
- **当** 计算收费项目
- **系统应当** 从该次就诊/诊疗活动的已编码事实中推导收费项目，且不得为获得可支付代码而修改临床内容（BR-12）
- 追溯：CAP-07、BR-12、ADR-0005

### FR-018 — 解释临床与收费差异，而非通过编辑解决
- **当** 收费/结算记录与临床病历不一致
- **系统应当** 报告该临床与收费差异，并将其转交责任职能部门处理，且不得通过编辑临床病历来解决该差异（BR-12）
- 追溯：CAP-07、BR-12、ADR-0005

### FR-019 — 记录分离，修改权限分离
- **当** 任一记录需要更正
- **系统应当** 要求通过各记录自身的流程提出更正——临床更正采用补录（BR-07），收费更正采用经批准的调整（同级资金模式的 BR-10）——且不得在两类记录之间交叉修改（BR-12）
- 追溯：CAP-07、CAP-03、BR-12、ADR-0005

## CAP-05 用药与药房

### FR-020 — 用药医嘱下达时进行相互作用与过敏检查
- **当** 下达一项用药医嘱
- **系统应当** 针对患者当前用药清单和已记录的过敏信息执行相互作用与过敏检查，且不得允许静默覆盖（该系列的 BR-09；边界参见 ADR-0003）
- 追溯：CAP-05、CAP-04、BR-09

## CAP-09 保障与诊疗

### FR-021 — 以诊疗关系作为访问依据
- **当** 用户访问患者记录
- **系统应当** 基于诊疗关系和已声明的依据授予访问权限，且不得仅因部门成员身份而授予访问权限（BR-13）
- 追溯：CAP-09、BR-13、ADR-0006

### FR-022 — 紧急访问须记录并说明理由
- **当** 用户在正常授权范围之外取得紧急访问
- **系统应当** 记录此次访问，要求提供理由，并将访问转交复核（BR-14）
- 追溯：CAP-09、BR-14、ADR-0006

### FR-023 — 紧急访问率作为平台信号
- **当** 开展访问复核
- **系统应当** 按用户、科室和时段报告紧急访问率，使访问率上升被明确识别为正常路径缺陷，而非仅被视作使用情况（BR-14）
- 追溯：CAP-09、BR-14、ADR-0006

## CAP-10 主索引核对、报告与隐私生命周期

### FR-024 — 按数据类别应用保存期限
- **当** 保留、归档或处置临床数据
- **系统应当** 应用为其数据类别声明的保存期限，且不得采用单一全局设置（BR-15）
- 追溯：CAP-10、BR-15、CTL-04

### FR-025 — 删除操作传播
- **当** 删除请求得到满足
- **系统应当** 将删除操作传播至副本、缓存、日志和派生数据集，且不得仅删除主记录（BR-16）
- 追溯：CAP-10、BR-16、ADR-0007

### FR-026 — 按目标位置记录删除完成情况
- **当** 传播完成或无法完成
- **系统应当** 按各目标位置记录结果，且不得将不可达的目标位置记录为已删除（BR-16）
- 追溯：CAP-10、BR-16、ADR-0007
