## 本方案包覆盖什么

产品与增长团队真正在跑的那个数据闭环：事件跟踪治理、用户/设备身份缝合、
漏斗/留存/群组分析、归因、带统计严谨性的 A/B 与多变量实验、用户分群，以及
消息编排（推送/应用内/邮件）与实验一致的曝光日志。按 B2C 规模设计，默认以
隐私为先。

## 范围内

- 埋点计划治理：事件 schema 注册中心、命名约定、SDK/服务端事件、校验与质量
  监控、计划版本化
- 身份：匿名 → 登录 ID 关联、身份图规则、用户合并/删除（隐私操作）、同意状态
  传播
- 分析：事件流 → ODS → 集市；漏斗、留存曲线、LTV/RFM、路径分析、归因模型
  （规则 + 多触点模式）
- 实验：功能开关投递、流量切分、曝光日志、护栏指标、样本量/检验力、序贯 vs.
  固定时域检验、SRM 检测、保留组
- 分群与激活：群组构建器 → 同步到消息/CDP 目的地，带频次上限与抑制
- 隐私：同意感知的采集、数据最小化、删除流水线、聚合上报阈值
- 面向产品经理的自助分析：指标构建器、报表模板、异常告警

## 明确不在范围内

- 营销活动采买/广告网络优化（只集成，不拥有）
- 通用数仓平台（兄弟方案包）
- 推荐模型训练（MLOps 方案包候选；含激活集成）

## 待决问题

2. 在线特征服务被排除——边界陈述放在 L2。
3. 统计引擎：与平台无关地规定检验与假设（方差、多重比较）。

## 已定 ADR（不可翻案）

| ADR | 决策 |
|---|---|
| **0001** | **任何客户端都不得发出 schema 未被声明的事件**——一个事件只到达一次，因此 schema 治理是写入时控制，而没有理由的隔离是缺陷 |
| **0002** | 合并**可逆且会传播**；删除覆盖**档案、连接键与派生事实**——留下连接键会让身份从残留中重新形成 |
| **0003** | **分配住在实验引擎里**，而不是交付/开关系统里，且决策规则**预先声明** |
| **0004** | 目的地**在抽象层之后**，绝不是数据所有者；目的地自己的数字是对账输入 |

## 阻塞 L3 的事项

1. **一份统计方法论** —— 样本量、SRM、护栏、保留组与偷看纪律都是来自
   `AGENTS.md` 的设计要求，而本方案包为其中任何一项都**不**引用规范来源。
   采纳一份是写出可核验的实验需求的前提。
2. **作为契约的同意状态模型** —— 按目的限定、带版本的状态目前存在于散文里；
   L3 需要同意状态迁移契约。
3. **五条零容忍不变量的验收标准** —— NFR-001、NFR-002、NFR-004、NFR-005
   以及两项同意检查，需要让构建失败的标准，而不是只报告一个阈值。
4. **删除核验流程** —— 「三部分全部被移除」是要求；它如何跨派生事实被*核验*
   属于 L3 的工作。
