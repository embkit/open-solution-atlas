# 00-context / 干系人

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **增长 / 产品分析团队** | 拥有事件模型、漏斗、实验 | 主要运营者，也是语义层的作者 |
| **产品团队** | 提出问题、定义实验、消费结果 | 实验的消费方与需求方 |
| **研发（客户端侧）** | 按 schema 实现埋点 | 上游：**不能在 schema 声明之前上线** |
| **增长营销** | 分群、活动、激活 | 分群的消费方；向目的地的发送方 |
| **数据科学** | 因果估计、实验设计、建模 | 消费方与方法权威 |
| **法务与隐私** | 同意目的、留存、权利请求 | 对同意模型与删除拥有权威 |
| **安全** | 对原始与派生行为数据的访问 | 约束每一项能力 |
| **财务 / FinOps** | 平台成本与工具支出 | 消费成本遥测 |
| **研发管理** | 决定一个实验是否上线 | 决策消费方，不是数据消费方 |
| **广告平台方** | 运营目的地 | 外部对手方；绝不是数据所有者 |

## 2. 角色（应用参与者）

| 角色（英） | 中文 | 关键权限 / 任务 |
|---|---|---|
| Schema steward | 事件 Schema 管理者 | 声明、版本化并废弃事件 schema |
| Instrumentation engineer | 埋点工程师 | 对照 schema 实现并测试客户端发出 |
| Analyst (growth) | 增长分析师 | 构建漏斗、人群、留存报表 |
| Experiment owner | 实验负责人 | 设计实验、定义护栏、声明决策规则 |
| Experiment analyst (stats) | 实验分析师 | 计算样本量、SRM、护栏；签署读数 |
| Segment builder | 人群构建者 | 为激活定义一个分群，并记录其目的 |
| Activation operator | 触达运营 | 经由抽象层把分群发往目的地 |
| Consent / privacy operator | 同意运营者 | 管理目的、同意状态、撤回 |
| Data subject (rights requester) | 数据主体 | 行使访问、导出、删除权利 |
| Platform administrator | 平台管理员 | 管理连接、目的地、留存；**无** schema 权威 |
| Incident responder | 事件响应 | 隔离处理、数据流切断 |

### 非人类参与者

| 参与者 | 说明 |
|---|---|
| **事件 Schema 注册表** | 主干；在采集时校验并做版本化 |
| **采集 SDK / 流水线** | 发出并接入事件；对照注册表校验 |
| **隔离存储** | 持有无效事件**并附理由**——一个埋点信号来源，而不是一个垃圾桶 |
| **身份解析服务** | 关联匿名 → 已知，记录合并并能撤销合并 |
| **事件数仓导出** | 把精选事件与实验结果送到数据平台 |
| **实验引擎** | 分配、比例核查、指标计算、护栏、保留组 |
| **人群服务** | 在某个时点把分群定义解析为成员列表 |
| **激活 / 目的地抽象层** | 经由一个接口发往消息与广告目的地 |
| **同意服务** | 存储按目的限定的同意状态，在采集与激活处被检查 |
| **通知** | schema 变更告警、SRM 告警、护栏突破 |

## 3. 作为参与者的外部 / 上下游系统

- **网页 / 移动 / 服务端客户端** —— 事件来源。
- **身份 / CRM / 支付后端** —— 匿名标识符成为已知用户的地方。
- **数仓 / 数据平台** —— 导出目标。
- **活动 / 消息平台**（邮件、推送、短信）。
- **广告网络** —— 拥有各自 schema 与报表的目的地。
- **同意管理平台** —— 权威的同意状态。
- **归因 / 监测 API** —— 网络侧的转化报表。
- **功能开关系统** —— 常与实验引擎混淆；它是一种交付机制，不是分配记录。
- **数据主体请求工具** —— 删除与导出工作流。
- **数据防泄露 / 审计工具** —— 原始事件是行为个人数据。

## 4. 参与者目标（主要）

- **实验负责人**：知道这个改动是否真的奏效，且有足以上线或砍掉它的信心——而
  不是一句百分比比较。
- **分析师**：早上搭好一个漏斗，下个月还信任它，因为 schema 没有在它脚下移动。
- **机器 / 数据科学家**：一个带 SRM 检查与护栏的因果估计，让结果成为一个
  决定而不是一张图。
- **客户端工程师**：不因为等一个 schema 而被阻塞，也不为了保住流水线速度而
  上线一个破坏性改名。
- **隐私法务**：在采集与激活两处都站得住的同意，以及能挺过连接键的删除。
- **增长营销**：把东西发到目的地，而目的地不拥有事件模型。
- **研发管理**：实验计划的一份诚实的成本收益，并对着保留组核验。

> ⚠️ ASSUMPTION: 本方案包假设**功能开关 / 交付系统与实验引擎是不同的**。
> 让一个开关服务承载实验是便利，但实验记录必须留在平台里；否则分配就不可
> 审计，SRM 也无法计算。
