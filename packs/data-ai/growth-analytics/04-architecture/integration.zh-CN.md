# 04 · 集成

> 与外部系统的集成契约。ID 稳定；每条流都追溯到需求与规则。
>
> ⚠️ ASSUMPTION — 接口选型与协议属于方案包设计。

## I. 集成点

| ID | 伙伴 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **网页 / 移动 / 服务端客户端** | 入 | 事件发出，按注册中心校验 |
| **I-02** | **数仓 / 数据平台** | 出 | 带 schema 版本的精选事件与实验结果 |
| **I-03** | **身份 / CRM / 支付后端** | 入 | 匿名标识符成为已知用户的地方 |
| **I-04** | **活动 / 消息平台** | 出 | 邮件、推送、短信发送 |
| **I-05** | **广告网络** | 出 | 人群上传与转化上报 |
| **I-06** | **同意管理平台** | 入 | 权威的同意状态 |
| **I-07** | **归因 / 监测 API** | 入 | 目的地侧的转化报表 |
| **I-08** | **数据主体请求工具** | 入 | 擦除与导出工作流 |

## F. 内部流程

### F-01 — 声明与采集
1. 一个 schema 在**发出之前**就在注册表中被声明并版本化。
2. 客户端发出；采集按注册中心校验。
3. 有效事件被接入，并记录其 schema 版本。
4. 畸形事件被**带着理由**隔离。

### F-02 — 解析身份
1. 匿名标识符、设备、会话与已知用户被关联。
2. 合并连同其规则与所用的连接键一起被记录。
3. 派生事实在合并后的图上计算。
4. 一次撤销恢复合并前的状态，并传播到派生事实。
5. 一次擦除移除档案、连接键与派生事实。

### F-03 — 实验
1. 决策规则与所需样本量在实验**开始之前**被声明。
2. 单元被随机化，分配被记录在引擎中。
3. 观测比例与预期比例被核查（SRM）。
4. 主指标**与**护栏指标被度量。
5. 在计划需要时计算保留组差值。
6. 结果在预先声明的时点按决策规则读出。

### F-04 — 激活
1. 一个分群被解析为**某一时点的成员快照**。
2. 在激活处检查**使用**目的的同意状态。
3. 抽象层把平台的模型映射到目的地的 schema。
4. 这次发送连同其目的与同意依据被记录。

### F-05 — 撤回
1. 某个目的的同意被撤回。
2. 该目的的采集立即停止。
3. 该目的的激活立即停止。
4. 在收到擦除请求之处，档案、连接键与派生事实被移除。

### F-06 — 导出与对账
1. 事件与实验结果带 schema 版本被导出。
2. 目的地报表作为**对账输入**被接入。
3. 平台数字与目的地数字被比较，差值按账龄管理。

## 失败模式契约

| 集成 | 必须具备的失败模式 |
|---|---|
| **I-01 客户端** | 一个发出未声明事件的客户端必须被**拒绝**，而不是尽力而为地接入——一个未声明的事件在结构上就不可复现 |
| **I-03 身份** | 一个无法解析的已知用户关联让档案保持匿名，而不是猜测；一次错误的合并比没有合并更糟 |
| **I-06 同意** | 不可用的同意状态在激活处**失败关闭**——在未知状态下采集的数据不用于新的目的 |
| **I-05 广告网络** | 网络回报的数字绝不覆盖平台的；差异是一个对账发现 |
| **I-02 数仓** | 一次导出要么携带 schema 版本，要么不被导出；没有版本的导出事后无法被解释 |
| **I-08 DSR** | 一次擦除必须能在全部三部分（档案、连接键、派生事实）上被核验，而不只是档案记录 |

> 这个模式是：集成不可用时降级外部路径——除了同意，它在激活处失败关闭，
> 因为一个未知的同意状态被当作通用许可证，正是 BR-11 存在所要防止的失败。

## 目的地契约（每个目的地都必须接受什么）

| 方面 | 由目的地集成声明 |
|---|---|
| **字段映射** | 平台字段 → 目的地字段，带转换，住在抽象层里 |
| **目的** | 这个目的地服务的目的，用于同意检查 |
| **传输属性** | 该目的地是否在声明的管辖范围之外 |
| **报表格式** | 该目的地如何回报它自己的数字，仅用于对账 |
| **失败语义** | 一次发送失败长什么样，以及它是否可重试 |

> 一个要求其 schema 被存储为平台自身 schema、或其数字必须被当作权威的目的地，
> 不是抽象层之后的目的地——它是一个所有者，而 BR-09/BR-10 拒绝它。
