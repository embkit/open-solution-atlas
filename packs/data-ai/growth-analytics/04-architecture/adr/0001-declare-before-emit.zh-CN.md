# ADR-0001 — 任何客户端都不得发出 schema 未被声明的事件

- 状态：已接受
- 日期：2026-10-12
- 决策人：本方案包维护者

## 背景

`AGENTS.md` 陈述：事件 schema 注册中心是主干，因为未被治理的事件让每个数字都
不可复现。

这个失败的机制恰恰是：**一个事件只到达一次。** 没人能用不同的属性名重新摄入上
个季度。所以，一个客户端带着改名上线的瞬间，每一个建立在旧名字上的历史漏斗都会
静默地改变含义——没有部署、没有 diff、没有告警。

这让 schema 声明成为一个*写入时*控制。事后才查阅的注册表是文档；写入时就查阅
的注册表才是主干。

## 备选方案

1. **文档页面，在分析时查阅** —— 维护成本为零，也毫无用处。改名上线，历史改变
   含义，而页面只是记录了这些事件曾经是什么样。
2. **在接入时强制 schema，尽力而为** —— 一个发出未声明事件的客户端照样被接入。
   保护恰好在最需要它的时候消失，因为一个已经漂移的客户端还会继续漂移。
3. **先声明后发出，在接入时强制** —— schema 版本未注册的事件一律不被接入；
   一次校验失败被**带着理由**隔离；导出携带版本。

## 决策

方案 3，由 BR-01、BR-02、FR-001、FR-002、FR-003、FR-004 以及 NFR-001、
NFR-002、NFR-012 强制执行。

两个属性承载着超出显然之外的重量：

- **带理由的隔离。** 没有理由的隔离是一个垃圾桶，不是一个信号。理由是埋点健康
  遥测，它告诉团队某个客户端已经漂移。
- **导出带版本。** 带 schema 版本的导出，正是使下游数字在事后仍可解释、而不是
> 被假定为现在的含义的东西。

## 后果

- 正面：一次属性改名成为一次可见的、带版本的迁移，带有映射历史，而不是一次
  静默的含义变化。
- 正面：埋点健康变得可度量。隔离理由是「某个客户端已漂移」这一事实最早可得
  的信号，而 NFR-002 强制这个信号存在。
- 正面：导出携带其含义，因此 `lakehouse-platform` 与 `enterprise-bi` 两个兄弟
  方案包可以信赖它们收到的东西。
- 负面：客户端团队必须先声明再上线，这给他们的发布路径加了一道闸门。这道闸门
  正是要点，但它是真的摩擦，而且在它抓到某个人之前会被怨恨。
- 负面：一个漂移的客户端会停止发出。这是正确的——一个未声明的事件在结构上就
  不可复现——但它把一个数据质量问题转成了可用性问题，而本方案包的立场是这一
> 笔交易是对的。
