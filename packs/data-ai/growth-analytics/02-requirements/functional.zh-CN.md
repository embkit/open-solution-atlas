# 02 · 功能需求

> EARS 记法：`当 <触发条件> 系统应当 <响应>`。
> ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）、一条规则（`BR-xx`）与一个
> ADR。验收标准（AC-*）在 L3 定义。
>
> `verification: unverified` —— 这些需求是方案包设计，未针对任何部署验证。

## CAP-01 事件 schema 注册表

### FR-001 — 先声明后发出
- **当** 任何客户端将要发出一个新事件或新属性
- **系统应当** 要求注册表中存在一个已声明且带版本的 schema，**之后**才允许发出
  （BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-002 — 固定已声明的 schema 版本
- **当** 一个事件被接入
- **系统应当** 解析其 schema 版本，且**不得**接受 schema 未被声明的事件
  （BR-01、BR-02）
- 追溯：CAP-01、BR-01、BR-02

### FR-003 — 带理由的校验与隔离
- **当** 一个事件未通过 schema 校验
- **系统应当** 把它**带着理由**隔离（缺字段、类型错误、未知属性、版本不匹配），
  且**不得**静默丢弃它（BR-02）
- 追溯：CAP-01、CAP-02、BR-02

### FR-004 — 导出携带 schema 版本
- **当** 事件被导出到数仓
- **系统应当** 携带每个事件的 schema 版本，使下游含义可被追溯而不是被假定
  （BR-02）
- 追溯：CAP-01、CAP-09、BR-02

## CAP-03 身份解析

### FR-005 — 被记录的合并
- **当** 两个标识符被解析为同一个人
- **系统应当** 创建合并，并持久化记录合并了什么、按哪条规则合并（BR-03）
- 追溯：CAP-03、BR-03、ADR-0002

### FR-006 — 会传播的撤销
- **当** 一次合并被撤销
- **系统应当** 恢复合并前的身份，并传播到派生事实——人群成员资格、漏斗步骤、
  实验分配（BR-03）
- 追溯：CAP-03、BR-03、ADR-0002

### FR-007 — 覆盖连接键与派生事实的删除
- **当** 一次擦除请求被受理
- **系统应当** 移除档案、该合并的**连接键**与派生事实，使身份无法从残留中重新
  组成（BR-04）
- 追溯：CAP-03、BR-04、ADR-0002

## CAP-06 实验引擎

### FR-008 — 由引擎记录的分配
- **当** 一个单元被分配到某个处理
- **系统应当** 在实验引擎中记录这次分配，且**不得**把交付/开关系统当作记录
  （BR-05）
- 追溯：CAP-06、BR-05、ADR-0003

### FR-009 — 比例核查
- **当** 分配推进
- **系统应当** 核查观测比例与预期比例，并在失衡时发出 SRM 信号（BR-07）
- 追溯：CAP-06、BR-07、ADR-0003

### FR-010 — 因果边界
- **当** 产出一个漏斗、人群或归因结果
- **系统应当** 把它标记为描述性的，且**不得**把它呈现为因果估计（BR-06）
- 追溯：CAP-05、CAP-06、BR-06

### FR-011 — 声明样本量
- **当** 一个实验被配置
- **系统应当** 要求预先声明的效应量与由此得出的样本量，然后它才可以开始
  （BR-07）
- 追溯：CAP-06、BR-07、ADR-0003

### FR-012 — 度量护栏
- **当** 一个实验运行
- **系统应当** 连同主指标一起度量其声明的护栏指标，并报告护栏突破（BR-07）
- 追溯：CAP-06、BR-07、ADR-0003

### FR-013 — 保留组支持
- **当** 一个实验计划需要保留组
- **系统应当** 支持一个刻意不暴露的总体，并度量全计划的差值（BR-07）
- 追溯：CAP-06、BR-07、ADR-0003

### FR-014 — 预先声明的决策规则
- **当** 一个实验被配置
- **系统应当** 记录上线/搁置/砍掉的决策规则，且**不得**允许判据在结果可见之后
  才被选定（BR-08）
- 追溯：CAP-06、BR-08、ADR-0003

## CAP-07 / CAP-08 分群、激活与目的地

### FR-015 — 平台侧发出的模型与分配
- **当** 一个目的地被集成
- **系统应当** 把事件模型、身份模型与实验分配保留在平台侧，由抽象层负责映射
  （BR-09、BR-10）
- 追溯：CAP-07、CAP-08、BR-09、BR-10、ADR-0004

### FR-016 — 目的地不是权威
- **当** 一个目的地回报它自己的数字
- **系统应当** 把它们当作对账输入，绝不当作真相来源（BR-09、BR-10）
- 追溯：CAP-08、BR-09、BR-10

### FR-017 — 采集时强制
- **当** 一个事件被采集
- **系统应当** 求值该采集目的的同意状态，在不允许时不予采集（BR-11）
- 追溯：CAP-04、BR-11

### FR-018 — 激活时强制
- **当** 已采集的数据被用于某个目的（活动发送、广告上传、档案丰富）
- **系统应当** 求值该目的的同意状态，且**不得**使用在更宽泛状态下采集的数据
  （BR-11）
- 追溯：CAP-04、CAP-07、CAP-08、BR-11

### FR-019 — 两个点上都撤回
- **当** 同意被撤回
- **系统应当** 立即为该目的停止采集与激活（BR-11）
- 追溯：CAP-04、BR-11

### FR-020 — 某时刻的分群快照
- **当** 一个分群被用于一次活动
- **系统应当** 把它解析为某一时刻的成员快照，且**不得**使用实时视图（BR-12）
- 追溯：CAP-07、BR-12
