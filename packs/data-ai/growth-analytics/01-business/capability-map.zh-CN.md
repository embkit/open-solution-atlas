## 1. 一级能力

| # | 能力 | 它必须回答什么 | 说明 / L1 立场 |
|---|---|---|---|
| **CAP-01** | **事件 schema 注册表** | 一个事件与属性*意味着什么*——在任何客户端发出它**之前** | 主干；`AGENTS.md`：未被治理的事件让每个数字都不可复现 |
| **CAP-02** | **采集与隔离** | 哪些事件是畸形的，以及**为什么** | 在采集时校验；带理由的隔离是埋点信号 |
| **CAP-03** | **身份解析** | 匿名如何变成已知，以及它能否被撤销 | 合并**被记录且可逆**，并传播到派生事实（`AGENTS.md`） |
| **CAP-04** | **同意强制** | 这份数据是否可以被采集，以及**另外**是否可以用于这个目的 | 在**两个**点强制（`AGENTS.md`） |
| **CAP-05** | **分析** | 某人做了什么、以什么顺序、在多长跨度上 | 漏斗、人群、留存、归因 |
| **CAP-06** | **实验** | 这个改动是否造成了它 | 样本量、SRM、护栏、保留组、偷看纪律——*不是*百分比比较 |
| **CAP-07** | **分群与激活** | 谁被触达，基于什么目的 | 分群是某时刻的快照，不是实时视图 |
| **CAP-08** | **目的地** | 数据如何离开，而出口不拥有这个模型 | 消息与广告网络在抽象层之后，绝不是所有者 |
| **CAP-09** | **导出与数仓交接** | 什么流向分析存储 | 带 schema 版本的导出，使下游含义可追溯 |
| **CAP-10** | **权利、隐私与运维** | 一个人能否被移除，平台能否运行 | 删除覆盖档案**以及连接键与派生事实**；留存；成本 |

## 2. 边界（每项能力*不*拥有什么）

| 能力 | 明确**不**是它的职责 |
|---|---|
| 01 Schema 注册表 | 决定*跟踪什么*——由产品/分析师决定；01 让它变得可治理 |
| 02 采集 | 更正一个畸形事件——它**带着理由**隔离 |
| 03 身份解析 | 认证——它关联标识符，不核验凭据 |
| 04 同意 | 判定合法目的——由法务决定；04 强制状态 |
| 05 分析 | 因果论断——漏斗与人群是**描述性**的；因果属于 06 |
| 06 实验 | 在生产交付中分配处理——开关系统负责交付；06 记录分配 |
| 07 分群 | 授予使用数据的权限——04 的同意闸门先于任何激活 |
| 08 目的地 | 定义事件 schema——目的地只是**消费**它 |
| 09 导出 | 把事件改造成目的地的 schema——由 08 的抽象层映射；09 导出平台自己的模型 |
| 10 权利与运维 | 批准某个目的——它执行并留证 |

> 两条边界承载着本方案包的重量。**06 vs. 交付系统**：如果分配发生在功能开关
> 服务里，实验引擎就无法核查比例，于是 SRM 无法计算、比较无法核查。而
> **03 vs. 删除**：一个连接键在删除后仍然存活的合并，会让整个隐私故事变成
> 虚构，因为身份可以从残留中重新组成。

## 3. 一级优先级

为讨论而完整，为估算而不完整；刻意不谈相对难度。

> ⚠️ ASSUMPTION: 能力 **01（schema 注册表）** 与 **06（实验统计）** 被排在
> 前面，是因为 `AGENTS.md` 把「事件不可复现」与「统计上的空洞」定为一个增长
> 平台在看起来正常运作时失败的两条路径。这是编辑排序，不是以证据为依据的
> 关键性论断。

## 4. 整个平台范围之外

- **数仓本身** —— 接入、存储、表格式与建模留在 `lakehouse-platform`；本方案
  包拥有导出契约。
- **BI 与报表界面** —— `enterprise-bi`；本方案包向它导出。
- **活动内容制作** —— 文案、创意、旅程设计。
- **广告竞价 / 投放** —— 是抽象层之后目的地自己的事。
- **产品自身的功能语义** —— 平台对行为做埋点，它不拥有功能。
- **归因模型选择的经济学** —— 一个数据科学决策，不是平台能力；平台必须
  *支持*多于一种。
