## 本方案包涵盖内容

机器学习模型生命周期的工程主干：共享特征定义、实验跟踪、模型注册与版本管理、训练流水线编排、部署与推理服务、包含漂移检测的运行时监控，以及使预测可复现、可审计的血缘。核心问题是**双重版本管理与可复现性**——已提供服务的模型必须精确固定到其训练时使用的代码、数据和特征版本，发布后其行为必须持续受到监控。

## 范围内

- 特征平台：特征注册表/定义、离线/在线存储、时间点正确性、训练/服务一致性
- 实验跟踪：运行、参数、指标、制品、比较
- 模型注册中心：模型版本、阶段（候选/生产/已归档）、元数据、审批闸门
- 训练流水线：编排、定时/触发式运行、环境与依赖项捕获、可复现性清单
- 部署与服务：批量评分和在线推理、灰度/影子发布、回滚、端点治理
- 监控：预测漂移和特征漂移、数据质量、性能衰减、告警、反馈采集
- 治理：血缘、审批工作流、模型卡/文档、访问控制、审计轨迹
- 可复现性：从已提供服务的预测回溯至源数据和代码的数据集/特征/模型血缘

## 明确不在范围内

- 数据仓库/数据湖仓流水线本身（兄弟数据平台方案包；MLOps 使用受治理的数据）
- BI 仪表板和分析（兄弟企业 BI 方案包）
- 推荐/搜索应用逻辑（候选的下游方案包）
- GPU 集群开通/基础设施即代码（集成基础层）

## 待决问题

1. 特征存储：在核心中构建离线/在线双存储，还是通过接口集成现有存储？
2. 服务架构：采用核心推理运行时，还是设置面向运维方服务栈的边界（KServe/Triton 类）？
3. 生产晋级中的人工参与式审批闸门位于何处。
4. 自动化漂移响应的深度：仅发出告警，还是采用自动重新训练策略。

## 已确定的 ADR（不再重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | 版本绑定**作为一个整体**记录，且**可查询**；代码/数据/特征三元组是最小集合，而非充分集合 |
| **0002** | 模型注册中心是**唯一准入门禁**；回滚选择此前已提供服务的版本绑定，而非重新构建流水线 |
| **0003** | 血缘以**“为何会有这一预测”作为查询**作答，而不是以图表作答 |
| **0004** | **分片评估是审批证据**；仅依据汇总指标进行审批属于违反规则 |
| **0005** | 特征存储的存在是为了**时间点正确性**，而非缓存；“回放等于训练时的值”是检验训练服务偏斜的标准 |

## L3 阻断项

1. **版本绑定的完整组件清单**——最小三元组已经确定；真实部署还会额外固定哪些内容，需要作出本方案包已指出但尚未作出的版本化决策。
2. **生命周期状态机**——各项规则中已对状态命名；L3 要求将其逐一列举。
3. **五项零容忍不变量的验收标准**——NFR-001、
   NFR-002、NFR-005、NFR-011 和未注册晋级信号需要使用能使构建失败的标准，而不是仅报告阈值。
4. **将训练服务偏斜测试实施为可执行流程**——“回放等于训练”是要求；如何*验证*它是 L3 阶段的工作。
5. **版本绑定的保留期**——BR-11 要求设置该保留期，但它与训练数据的删除要求存在张力；此处刻意保持未解决。

### L2 阻断项

1. **版本绑定的完整组件清单**——`AGENTS.md` 将代码提交、数据快照和特征定义列为最小集合，但真实部署还会固定更多内容（超参数、框架版本、随机种子、环境）。版本绑定必须包含哪些内容，应由版本化决策确定，而不是采用默认值。
2. **保留与删除**——回滚和重新训练要求保留快照；数据保护义务要求训练数据支持删除特定个人的数据。本方案包刻意保持未解决；需要明确给出重新生成窗口。
3. **风险等级分类体系**——按照未验证任何框架条款的范围决策，本方案包要求声明风险等级字段，却未定义等级集合。
