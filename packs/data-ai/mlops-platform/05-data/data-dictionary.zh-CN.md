# 05 · 数据字典

> 仅包含核心实体。字段语义具有规范性；类型仅作示意。
>
> ⚠️ ASSUMPTION — 字段级设计属于方案包设计。若某字段因某项规范文件而存在，则该规范文件会在
> `02-requirements/compliance.md` 中被指定为依据，且未引用具体条款。

## 版本绑定

| 字段 | 语义 |
|---|---|
| `code_commit_ref` | 生成权重的训练代码，以不可变方式锁定。NOT NULL |
| `data_snapshot_ref` | 生成权重时的确切训练数据——**不是**明天重新求值时会产生不同结果的查询。NOT NULL |
| `feature_definitions_ref` | 将数据转换为特征的转换代码和时间点语义，与代码一同锁定。NOT NULL |
| `hyperparameters_ref`、`framework_version_ref`、`environment_ref`、`random_seed` | 附加锁定项。**已声明的方案包设计**：实际部署会锁定这些项；方案包将其列明，而不是假装三元组已经充分 |
| 不可变性 | 记录后不再授予 UPDATE 权限（约束 1）。更正应创建一个**新的**版本绑定 |

## 审批记录

| 字段 | 语义 |
|---|---|
| `approver` | **人员**引用。不是构建引用、不是 CI 运行 ID、不是团队别名（BR-04）。该字段决定“谁授权了它？”这一说法是有据可依还是纯属虚构 |
| `evidence_refs[]` | 审批人所依据的材料，并且**包括分片评估**（BR-02、BR-04） |
| `decision` / `basis` | `approve` 或 `reject`，并在审批时说明理由。没有依据的拒绝与未进行审查无法区分 |
| 不可变性 | 仅可追加（约束 3） |

## 特征定义/特征值

| 字段 | 语义 |
|---|---|
| `point_in_time_semantics` | NOT NULL。值以**观察时点**为基准计算，仅使用当时可用的数据 |
| `version` | 定义变更会创建一个新版本；历史值**不得**原位重新计算（约束 10） |
| `available_at_ts` | NOT NULL，且必须 ≤ `observation_ts`（约束 9）。该字段用于防止后见之明——包括使用后续信息的补算 |
| `value` | 计算得到的特征值。定义版本未知的值不可用于版本绑定 |

## 模型服务部署

| 字段 | 语义 |
|---|---|
| `model_version_ref` | 必须解析为**模型注册中心**条目（约束 7）。以其他任何方式解析都会得到未注册的服务版本，也是“当前线上运行的是哪个模型？”这一问题的最常见成因 |
| `previous_version_ref` | 支持将回滚作为一种**选择**（BR-06）：指针可移至先前提供服务的版本绑定，但不得超出 NFR-004 规定的范围 |
| `traffic_split` | 灰度发布和影子发布的流量百分比。影子发布只计算，不对外提供服务 |

## 漂移发现

| 字段 | 语义 |
|---|---|
| `kind` | NOT NULL，取值之一为 `data`（输入分布发生变化）、`concept`（输入与输出之间的关系发生变化）、`prediction`（输出分布发生变化——**无需标签**即可察觉）、`label`（标签漂移/泄漏，或标签本应被更改）。约束 5。未分类的发现就是“无解释告警（反模式）” |
| `evidence_ref` | 线上流量测量结果。只能基于线上流量检测（BR-07）——离线留出集不构成证据 |
| `response_ref` | 引用此发现的已记录响应。没有响应的发现只是一条仪表板记录（NFR-007） |

## 预测追溯

| 字段 | 语义 |
|---|---|
| `model_version_ref` | 产生该预测的模型 |
| `feature_values_used[]` | 包含其**定义版本**，使“为什么”不仅包括值，还包括转换过程 |
| `upstream_rows[]` / `source_systems[]` | 数据来自何处——这种解析使追溯成为答案，而不只是描述 |
| 保留期 | 包含特征值，因此既是**隐私暴露面**，也是审计面（`security.md` §3） |

> ⚠️ ASSUMPTION — 此处的每个字段语义均属于方案包设计。规范文件与字段之间的关联记录的是某项规范文件要求软件*执行*什么，而不是它写了什么，遵循本仓库的范围决定。NIST AI RMF 和 ISO/IEC
> 42001 被采用为治理**框架**（采用为形状）；欧盟《人工智能法案》的风险等级分类体系**未**经验证，且未在此复现。
