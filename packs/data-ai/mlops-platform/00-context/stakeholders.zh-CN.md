# 00-context / 利益相关方

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **数据科学/机器学习工程**（算法/机器学习工程） | 训练并评估模型 | 已注册制品的主要作者 |
| **MLOps/平台团队**（平台工程） | 构建实验、特征、注册中心和服务技术栈 | 负责平台 |
| **模型风险/评审职能**（模型风险评审） | 基于已记录的依据批准模型投入生产 | 准入门禁的审批人 |
| **应用/产品工程**（业务研发） | 在产品中使用模型 | 服务使用方；劣质模型的影响范围 |
| **数据治理职能**（数据治理） | 特征负责人、数据契约、分类 | 为特征存储的语义提供输入 |
| **安全** | 模型制品、密钥、服务访问权限 | 约束每一项能力 |
| **法务/合规**（法务合规） | 用途声明、文档义务 | 使用治理制品 |
| **模型的业务负责人**（模型业务负责人） | 负责模型所支撑的决策 | 对预期用途和下线退役负责 |
| **内部审计**（内审） | 为审批、血缘和监控确实存在提供证据 | 只读使用方 |

## 2. 角色（应用参与者）

| 角色（英文） | 中文 | 关键权限/任务 |
|---|---|---|
| ML researcher / data scientist | 算法研究员 | 开展实验、记录版本绑定、进行评估 |
| ML engineer | 机器学习工程师 | 构建训练流水线、特征定义、服务路径 |
| Feature owner | 特征负责人 | 负责特征的定义和时间点语义 |
| Registry approver | 注册审批人 | 以已记录的依据批准晋级 |
| Serving / SRE operator | 服务运维 | 执行灰度发布、回滚到锁定版本 |
| Monitoring / drift analyst | 漂移分析 | 调查漂移信号，启动响应 |
| Model card author | 模型卡作者 | 记录预期用途、局限和评估结果 |
| Governance reviewer | 治理审查 | 根据已采用的治理框架（采用为形状）审查制品 |
| Data subject (indirect) | 数据主体 | 受预测影响；相关权利传递至训练数据 |
| Auditor (internal) | 审计员 | 查询血缘和审批记录，以作为证据 |
| Business owner | 业务负责人 | 提出模型需求，接受模型或使其下线退役 |
| Platform administrator | 平台管理员 | 运行平台；**无权**晋级 |

### 非人类参与者

| 参与者 | 说明 |
|---|---|
| **实验跟踪** | 将版本绑定作为一个单元记录 |
| **特征存储** | 以完全相同的方式向训练和服务提供满足时间点正确性要求的特征 |
| **训练流水线** | 使用数据快照和特征定义 |
| **模型注册中心** | 唯一的准入门禁；存储版本绑定和审批记录 |
| **服务运行时** | 提供锁定版本；支持灰度发布/影子发布/回滚 |
| **监控/漂移服务** | 在线上流量上运行；生成可审计的漂移结果 |
| **血缘服务** | 以查询方式回答“为什么会有这一预测” |
| **治理制品存储** | 模型卡、用途声明、局限、评估结果 |
| **回放/补算作业** | 为版本绑定重新计算时间点特征——偏斜测试 |
| **通知** | 漂移告警、审批请求、回滚事件 |

## 3. 外部/上游—下游系统作为参与者

- **数据平台/数据仓库** — 特征和标签的上游。
- **特征源（流式和批处理）** — 观察时点值的来源。
- **消费预测的应用** — 影响范围。
- **人在环路工具** — 高风险决策的审查界面。
- **模型服务基础设施** — 可以是平台自有或供应商提供的；它是模型注册中心的使用方。
- **CI/CD 和制品仓库** — 代码和容器的来源性质。
- **身份/访问管理** — 谁可以晋级，谁可以提供服务。
- **模型文档和披露渠道** — 在适用情况下，面向监管机构和公众。
- **偏差/公平性评估工具** — 分片评估的一种专门形式。

## 4. 参与者目标（首要）

- **数据科学家**：交付成果，同时不丧失说明模型学习依据的能力。
- **MLOps/平台**：让受控路径成为*快速*路径，使临时晋级没有存在的理由。
- **注册审批人**：依据可复现的证据作出审批，而不是依据聊天消息中的某个指标数值。
- **服务运维**：在几分钟内回滚到已知版本绑定，而不是重新构建先前的流水线。
- **漂移分析**：在任何人为此花费成本之前，知道*什么*发生了漂移以及它会产生什么影响。
- **业务负责人**：知道模型获准决定哪些事项，以及何时将其下线退役。
- **业务研发**：模型在预发布环境和生产环境中的表现一致，且在两种环境下表现一致的原因相同。
- **审计员**：血缘应当能够回答问题，而不是靠图表来描述。

> ⚠️ ASSUMPTION: 本方案包假定，只要模型仍可能提供服务，平台就能够**保留数据快照和特征定义**。实践中，保留期通常是有界的，因此回滚和再训练也受到边界限制。这一点被记录为一项明确的张力，但尚未解决。
