# 02 · 功能需求

> EARS 需求句式：`WHEN <trigger> THE SYSTEM SHALL <response>`。
> 稳定 ID 永久有效；每项需求都追溯至一项能力（`CAP-xx`）、一项规则（`BR-xx`）和
> 一项 ADR。验收标准（AC-*）在 L3 中定义。
>
> `verification: unverified` — 这些需求属于方案包设计，未经部署验证。

## CAP-01 实验跟踪

### FR-001 — 将版本绑定作为一个整体记录
- **当** 一次训练运行被记录时
- **系统应当** 将代码提交、数据快照和特征定义共同锁定为单个可查询绑定，**并且应当** 不接受缺少该三元组的运行（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-002 — 版本绑定可查询性
- **当** 用户或审计人员查询某个模型版本时
- **系统应当** 返回生成它所采用的代码提交、数据快照和特征定义，无需重建（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

## CAP-09 评估

### FR-003 — 记录分片评估
- **当** 对一次运行进行评估时
- **系统应当** 除总体指标外，还针对已声明的**分片**计算指标，并同时记录两者（BR-02）
- 追溯：CAP-09、BR-02、ADR-0004

### FR-004 — 审批读取分片
- **当** 某个版本接受审批评审时
- **系统应当** 将分片结果与总体指标并列呈现，**并且应当** 不允许仅依据总体指标进行审批（BR-02）
- 追溯：CAP-09、CAP-04、BR-02

## CAP-04 模型注册中心

### FR-005 — 已声明的风险等级
- **当** 一个模型被注册时
- **系统应当** 要求提供已声明的风险等级字段，**并且应当** 不在审批时推断风险等级（BR-03）
- 追溯：CAP-04、BR-03、CTL-01

### FR-006 — 审批记录
- **当** 某个版本被晋级时
- **系统应当** 记录具名审批人、所引用的证据和日期，**并且应当** 不将成功的 CI 运行视为审批（BR-04）
- 追溯：CAP-04、BR-04、CTL-02

### FR-007 — 仅从注册中心读取以供生产
- **当** 服务运行时加载一个模型时
- **系统应当** 从模型注册中心读取该模型，**并且应当** 不加载注册中心中不存在的版本（BR-05）
- 追溯：CAP-04、CAP-05、BR-05、ADR-0002

### FR-008 — 未注册制品检测
- **当** 发现某个模型版本在没有注册中心条目的情况下提供服务时
- **系统应当** 对其进行标记并将其转入晋级路径，而非静默注册该版本（BR-05）
- 追溯：CAP-04、BR-05

## CAP-05 服务与发布

### FR-009 — 回滚至已固定的版本绑定
- **当** 提出回滚请求时
- **系统应当** 在已声明的回滚目标时限内恢复所选的较旧版本绑定并使其提供服务，无需重建任何流水线（BR-06）
- 追溯：CAP-05、BR-06、ADR-0001

## CAP-06 监控与漂移

### FR-010 — 线上流量漂移分类
- **当** 对漂移进行测量时
- **系统应当** 基于线上流量进行测量，并将其分类为数据漂移、概念漂移、预测漂移或标签漂移/泄漏，**并且应当** 不报告未加区分的“漂移”信号（BR-07、BR-08）
- 追溯：CAP-06、BR-07、BR-08

### FR-011 — 可审计漂移结果
- **当** 记录一项漂移发现时
- **系统应当** 保留该发现，以便后续响应决策将其作为依据引用（BR-07）
- 追溯：CAP-06、BR-07、CTL-02

## CAP-07 血缘

### FR-012 — 血缘即查询
- **当** 某项预测受到质疑时
- **系统应当** 依据自身记录回答：使用了哪个模型版本、哪些特征值、来自哪些上游数据、处于什么时间、采用了哪种转换（BR-09）
- 追溯：CAP-07、BR-09、ADR-0003

## CAP-08 治理制品

### FR-013 — 下线退役记录
- **当** 某个版本下线退役时
- **系统应当** 记录依据和具名主体，**并且应当** 不让审批在无记录的情况下失效（BR-10）
- 追溯：CAP-08、BR-10

### FR-014 — 可服务期间的版本绑定保留
- **当** 某个版本处于已注册、已审批或服务中状态时
- **系统应当** 在已声明的保留期内保留其数据快照和特征定义（BR-11）
- 追溯：CAP-08、CAP-01、BR-11、CTL-03

### FR-015 — 治理制品位置
- **当** 一个模型被注册或审批时
- **系统应当** 在平台中保存其用途声明、局限、评估结果、审批记录、漂移发现和下线退役记录（BR-12）
- 追溯：CAP-08、BR-12、CTL-02

## CAP-10 运维

### FR-016 — 权限分离
- **当** 用户尝试将某个版本晋级到生产环境时
- **系统应当** 仅允许拥有晋级权限的角色执行，并且无论服务运维人员是否拥有运维访问权限，都应拒绝其执行
- 追溯：CAP-10、BR-04

### FR-017 — 确定性特征服务
- **当** 某个特征在训练或推理期间提供给模型时
- **系统应当** 在两种情况下均依据相同的定义和相同的时间点语义进行计算，使回放能够复现训练时的取值（BR-13）
- 追溯：CAP-02、CAP-03、BR-13

### FR-018 — 通过回放检测偏斜
- **当** 回放某个版本绑定的特征时
- **系统应当** 将任何与模型训练时所用取值不同的值报告为训练服务偏斜缺陷（BR-13）
- 追溯：CAP-02、CAP-03、BR-13
