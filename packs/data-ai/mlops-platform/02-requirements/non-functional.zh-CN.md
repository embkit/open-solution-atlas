# 02 · 非功能需求

> 可衡量的目标。**标记为 `(A)` 的数值目标属于政策假设，而非事实**——将这些目标记录下来，以便固定、论证和变更；其依据见 [`../SOURCES.md` §4](../SOURCES.md)。
>
> 公式已固定，任何一方都能复算出相同数值。没有公式的目标只是一种愿望。
>
> `verification: unverified`——这些目标属于方案包设计。

## NFR-001 — 版本绑定完整性
- **目标**：100% 正在提供服务的模型版本具有可查询绑定。
- **公式**：`count(served versions with a queryable binding) / count(served versions)`。
- **依据**：这是一项不变量（BR-01），而不是服务级别。没有版本绑定的版本无法复现、重新训练、审计或为其辩护。

## NFR-002 — 审批记录完整性
- **目标**：100% 在生产环境中提供服务的版本均具有审批记录。
- **公式**：`count(serving versions with a named approver and cited evidence) / count(serving versions)`。
- **依据**：BR-04；该记录是回答“谁授权了它？”这一问题的唯一有据可依的答案。

## NFR-003 — 分片评估覆盖率
- **目标 (A)**：至少 95% 的已审批版本已对其声明的分片进行评估，且不存在占比高于所声明份额的未检查分片。
- **公式**：`count(versions with segment evaluation) / count(approved versions)`。

## NFR-004 — 回滚时间
- **目标 (A)**：从作出决定到由较旧的版本绑定提供服务，用时不超过 5 分钟。
- **公式**：`older_binding_serving_ts - rollback_requested_ts`。
- **依据**：BR-06 使回滚成为一次*选择*，因此该时间上限涵盖选择和传播过程。如果某项部署无法满足这一要求，它就是在重建而非选择，这意味着实际上违反了 BR-06。

## NFR-005 — 特征服务一致性
- **目标**：100% 的回放特征值等于训练特征值。
- **公式**：`count(replayed == training values) / count(replayed values)`。
- **依据**：这是一项不变量（BR-13）。偏斜从构造上就是静默的——模型会正常运行，返回看似合理的数值，却给出错误结果。

## NFR-006 — 漂移监控覆盖率
- **目标 (A)**：至少 90% 正在提供服务的模型针对其已声明特征设有实时流量监控。
- **公式**：`count(served models with live monitors) / count(served models)`。

## NFR-007 — 漂移响应延迟
- **目标 (A)**：从发现漂移到记录响应，p95 ≤ 24 小时。
- **公式**：`response_recorded_ts - drift_finding_ts` 的 p95 值。
- **依据**：BR-07 要求结果可审计，以便响应决策可以引用。没有响应的漂移发现只是一条仪表盘记录。

## NFR-008 — 漂移分类完整性
- **目标**：100% 的漂移发现均被归入四种类型之一。
- **公式**：`count(classified findings) / count(findings)`。
- **依据**：BR-08；未分类的发现就是“无解释告警”。

## NFR-009 — 血缘查询延迟
- **目标 (A)**：针对正在提供服务的模型，回答“为什么会有这一预测？”的 p95 ≤ 5 秒。
- **公式**：`lineage_answer_ts - query_ts` 的 p95 值。

## NFR-010 — 版本绑定保留完整性
- **目标**：100% 的可服务版本均保留数据快照和特征定义。
- **公式**：`count(servable versions with retained bindings) / count(servable versions)`。
- **依据**：BR-11。丢弃版本绑定会限制回滚和重新训练的范围，这是一项通常未被明确说明的能力缩减。

## NFR-011 — 模型注册中心门禁
- **目标**：正在提供服务的未注册版本数为 0。
- **公式**：`count(unregistered serving versions) = 0`。
- **依据**：这是一项不变量（BR-05）。

## NFR-012 — 受控路径吞吐量
- **目标 (A)**：对于证据完整的版本，从已注册到服务中的晋级过程应在不超过 1 个工作日内完成。
- **公式**：适用于已批准候选项的 `serving_ts - registered_ts`。
- **依据**：恰恰当受控路径比非受控路径更慢时，临时晋级就会出现。

## 已固定公式

| 量化项 | 定义 |
|---|---|
| **可查询绑定** | 三元组可以解析，且每个组件仍可检索 |
| **分片** | 由特征谓词定义的已声明分片，而非事后分组 |
| **偏斜** | 针对同一版本绑定和特征定义，`replayed feature value != training feature value` |
| **漂移类型** | 数据/概念/预测/标签之一，在发现时指定 |
| **可服务** | 状态属于（已审批、服务中、已被取代但保留） |
| **再生成窗口** | 版本绑定被保留且该版本仍可提供服务的已声明时间段 |

> ⚠️ ASSUMPTION — 每个 `(A)` 目标都是政策性目标。本仓库不主张这些目标来自基准测试、法规或实际部署。
