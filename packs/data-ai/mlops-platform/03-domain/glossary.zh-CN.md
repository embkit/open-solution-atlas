# 03-domain / 术语表

> 此处定义的术语在本方案包中含义唯一；后文不引入同义词。`Source` 记录其依据：**[AGENTS]** 本方案包的
> `AGENTS.md` 设计立场，**[PACK]** 本方案包的定义，**[CONV]** 行业惯例，**[GOV]** NIST AI RMF / ISO/IEC 42001
> **作为采用的词汇和框架形态——未引用具体条款，也不声称符合相关标准**。

## 1. 复合制品

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Model version** | 模型版本 | 完整的已训练制品。绝不只是编号——始终是编号**加上**其版本绑定。 | [AGENTS] |
| **Binding** | 版本绑定 | 指向生成模型版本的三项内容（代码提交、数据快照、特征定义）的指针，即该制品的复合身份。 | [AGENTS] |
| **Code commit** | 代码提交 | 生成权重的训练代码，以不可变方式锁定。 | [AGENTS] |
| **Data snapshot** | 数据快照 | 训练数据在当时的精确状态——而不是一个明天重新求值时会产生不同结果的查询。 | [AGENTS] |
| **Feature definitions** | 特征定义 | 将数据转换为特征的转换代码及时间点语义，与代码一同锁定。 | [AGENTS] |
| **Queryable binding** | 可查询绑定 | 核心属性：“模型 1.7 使用什么数据、采用什么代码和哪些特征定义进行学习？”必须能够直接查询作答，而不能依靠推断。 | [AGENTS] |
| **Reproducible binding** | 可复现绑定 | 可查询、已保留且能够重新执行的版本绑定。 | [PACK] |

> 上述三项构成本方案包依据 `AGENTS.md` 定义的**最小**三元组。实际部署会锁定更多内容（超参数、框架版本、
> 随机种子、环境）。本方案包不主张该三元组已经充分——只主张它是最小版本绑定。

## 2. 特征与偏斜

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Feature** | 特征 | 供模型使用的、从源数据派生的输入值。 | [CONV] |
| **Point-in-time correctness** | 时间点正确性 | 特征值以**观察时点**为基准定义，仅使用当时可用的数据——在训练、回放和服务时均以相同方式计算。 | [AGENTS] |
| **Training/serving skew** | 训练服务偏斜 | 训练特征与服务特征的计算方式不同（窗口、连接、缺失值默认值）所导致的静默故障。不会导致崩溃；只会使预测性能下降。 | [AGENTS] |
| **Feature store** | 特征存储 | 该服务以完全相同的方式向训练和服务提供满足时间点正确性要求的特征。**其存在正是为此目的，而非为了缓存。** | [PACK] |
| **Cache-with-governance-document (anti-pattern)** | 缓存加治理文档（反模式） | 不强制执行时间点语义的特征存储。披着治理文档外衣的缓存。 | [PACK] |
| **Replay / backfill** | 回放/补算 | 重新计算模型在训练时看到的特征值。当时间点正确性成立时，结果**等于训练时的值**——这正是检验偏斜的标准。 | [PACK] |
| **Label leakage through time** | 时间泄漏 | 相对于标签使用了未来信息的特征。时间点正确性是唯一的结构性防护。 | [PACK] |
| **Feature owner** | 特征负责人 | 对单个特征的定义和语义承担责任的具名责任方。 | [PACK] |

## 3. 注册中心、审批与服务

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Model registry** | 模型注册中心 | 存放已注册制品及其版本绑定的模型注册中心——也是**进入生产环境的唯一闸门**。 | [AGENTS] |
| **The gate** | 准入门禁 | 生产环境中的服务只从模型注册中心读取。以任何其他方式进入生产环境的模型，其版本绑定都不可查询。 | [AGENTS] |
| **Unregistered artefact** | 未注册制品 | 已晋级但没有模型注册中心条目的模型。“线上运行的是哪个模型？没人知道”的最常见原因。 | [PACK] |
| **Approval record** | 审批记录 | 由**具名主体**基于明确依据作出并记录在案的模型晋级行为。晋级并非某个恰好通过的 CI 作业。 | [AGENTS] |
| **Risk tier** | 风险等级 | 已注册模型的一项已声明且有记录的属性，因为文档、监控和监督义务均取决于该风险等级。 | [GOV]（仅涉及设计后果；不主张存在分类体系） |
| **Canary release** | 灰度发布 | 由新版本承载一部分流量，其余流量仍由当前版本承载。 | [CONV] |
| **Shadow release** | 影子发布 | 使用新版本计算预测，**不对外提供这些预测**，以便针对线上流量进行离线评估。 | [CONV] |
| **Rollback** | 回滚 | 选择**较旧的版本绑定**。仅当版本绑定可查询且已保留时，这才合理。 | [AGENTS]/[PACK] |
| **Lifecycle state** | 生命周期状态 | 已注册 → 已审批 → 服务中 → 已被取代 → 已退役。退役不同于撤销审批。 | [PACK] |
| **Retirement** | 下线退役 | 审批的永久终止，并记录相应依据。 | [PACK] |

## 4. 监控与漂移

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Drift detection** | 漂移检测 | 监控线上行为与模型验证时行为之间的差异。必须针对**线上流量**运行，且结果必须**可审计**。 | [AGENTS] |
| **Data / covariate drift** | 数据漂移 | 输入分布发生了变化。 | [CONV] |
| **Concept drift** | 概念漂移 | 输入与输出之间的关系发生了变化。 | [CONV] |
| **Prediction drift** | 预测漂移 | 输出分布发生了变化——即使**没有标签**也可以察觉。 | [PACK] |
| **Label drift / leakage** | 标签漂移/泄漏 | 标签相对于其应有取值发生了变化，或标签泄漏进了特征。 | [CONV] |
| **Alert-that-explains-nothing (anti-pattern)** | 无解释告警（反模式） | 将四种漂移混为一谈，造成持续告警，却无法给出诊断。 | [PACK] |
| **Auditable drift result** | 可审计漂移结果 | 可作为后续响应决策依据被引用的漂移发现。 | [AGENTS] |

## 5. 血缘、评估与治理制品

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Lineage** | 血缘 | 由预测 → 模型版本 → 特征值 → 上游数据行 → 源系统及时间构成的链条。必须能够通过查询回答**“为什么会有这一预测”**。 | [AGENTS] |
| **Lineage diagram (anti-pattern)** | 血缘图（反模式） | 向工程师解释架构，却**对审计人员毫无价值**的图表。这不是 `AGENTS.md` 所要求的能力。 | [PACK] |
| **Sliced evaluation** | 分片评估 | 在已声明的**分片**上进行评估，而不只是进行总体评估。总体指标会掩盖分片故障。 | [PACK] |
| **The slices nobody looked at** | 无人查看的分片 | 真正重要的审计就存在于这些分片中。这也是分片评估之所以是一项能力的原因。 | [PACK] |
| **Model card** | 模型卡 | 承载预期用途、局限、评估结果和负责人的治理制品。 | [GOV]（采用的形态） |
| **Intended-use statement** | 用途声明 | 模型获准决定的事项。它是闸门依据，而不只是文档。 | [GOV]/[PACK] |
| **Named approver** | 具名审批人 | 其记录在案的行为授权了某一版本的主体。能够有充分依据回答“谁授权了它？” | [PACK] |
| **Governance shape (RMF/42001)** | 治理框架（采用为形状） | 风险界定与具有明确责任归属的文档制品，作为词汇和框架形态被采用。**未引用具体条款，也不声称符合相关标准。** | [GOV] |
| **Training-data governance** | 训练数据治理 | 合法依据、目的限制，以及删除操作向快照和派生特征的传播。 | [GOV]/[PACK] |

## 6. 约定

- **“不得”**标记违反后即构成缺陷的规则——生产环境不得为未登记在模型注册中心中的模型提供服务；同一特征在训练和服务时的计算方式不得不同；没有审批记录不得进行晋级；血缘不得仅仅是一张图。
- **不使用同义词**：本方案包用**版本绑定**表示代码/数据/特征的组合，用**模型版本**表示制品；用**漂移**表示四种不同现象，绝不将其笼统称为“模型变差了”；**审批记录**与 **CI 作业**是不同的概念，不得将后者称为前者。
- 兄弟方案包共享同一种可复现性规范：`telecom-bss` 的不可变计费事件、`omnichannel-commerce` 的定价快照、`growth-analytics` 的版本化模式，以及本方案包的双重版本管理，都表明了同一条规则——编号必须能够在事后复现。
