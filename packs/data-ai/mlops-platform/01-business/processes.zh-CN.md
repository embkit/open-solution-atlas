# 01-business / 流程

> MLOps 平台的流程定义。每个流程都说明其触发条件、步骤，以及约束这些步骤的规则。规则位于 `business-rules.md`（BR-xx），仅作引用，不在此重述。
>
> ⚠️ ASSUMPTION — 流程拆解属于方案包设计。未引用任何外部标准。

## P-01 — 实验

| | |
|---|---|
| **触发条件** | 研究人员训练模型 |
| **结果** | 一次运行，其**版本绑定**作为一个整体被记录 |

1. 将**代码提交**、**数据快照**和**特征定义**一并固定（BR-01）。
2. 按分片记录指标，而不只是记录总体指标（BR-02）。
3. 附加实际使用的超参数、框架版本和环境——并标记为*方案包设计：最小三元组并不充分*（BR-01）。

> 以松散元数据记录的一次运行并不具备版本绑定。BR-01 要求将三元组**作为一个整体**记录，因为它所防范的故障是：版本号无法反向追溯到产出它的具体内容。

## P-02 — 注册

| | |
|---|---|
| **触发条件** | 某次运行被提议成为候选项 |
| **结果** | 模型注册中心中的一项制品及其版本绑定 |

1. 注册该制品及其版本绑定。
2. 附加**风险等级**并将其设为已声明字段（BR-03）。
3. 声明生命周期状态：已注册。

## P-03 — 审批

| | |
|---|---|
| **触发条件** | 审查已注册候选 |
| **结果** | 一份**审批记录**，或附有理由的拒绝 |

1. 审查评估证据，**包括各分片**（BR-02）。
2. 由**具名主体**基于明确依据予以批准或拒绝。
3. 记录此次审批——而不是一次碰巧通过的 CI 作业。

> 审批记录使“谁依据什么证据、在什么日期授权了它”能够被回答。以 CI 作业充当闸门，只会得出无人能够为之辩护的答案（BR-04）。

## P-04 — 服务

| | |
|---|---|
| **触发条件** | 已审批版本被提升 |
| **结果** | 固定版本提供服务，并支持灰度发布和影子发布 |

1. 生产环境**仅从模型注册中心**读取该版本（BR-05）。
2. 按配置将流量路由至灰度发布和影子发布。
3. **回滚选择较旧的版本绑定**——而不是重新构建（BR-06）。

## P-05 — 监控

| | |
|---|---|
| **触发条件** | 正在提供服务的版本接收线上流量 |
| **结果** | 具有可审计轨迹的漂移结果 |

1. 在**线上流量**上运行漂移检测，绝不在离线留出集上运行（BR-07）。
2. 对漂移进行分类：数据漂移、概念漂移、预测漂移或标签漂移（BR-08）。
3. 记录结果，以便后续响应决策能够引用（BR-07）。

## P-06 — 响应

| | |
|---|---|
| **触发条件** | 漂移、护栏违规或事件 |
| **结果** | 一次响应——回滚或重新训练——并记录相应依据 |

1. 回滚到固定版本（BR-06），或者
2. 依据**新的**版本绑定重新训练（BR-01），或者
3. 将该版本下线退役，并记录依据（BR-09）。

## P-07 — 解释

| | |
|---|---|
| **触发条件** | 某个预测受到质疑 |
| **结果** | 一次查询，答案来自平台自身的记录 |

1. 沿血缘链条追溯：预测 → 模型版本 → 特征值 → 上游行 → 源系统及时间（BR-10）。
2. 依据记录作答，而不是依据图示。

## P-08 — 下线退役

| | |
|---|---|
| **触发条件** | 版本被取代或被发现存在缺陷 |
| **结果** | 一份下线退役记录 |

1. 在记录依据并指定具名主体后，将该版本下线退役。
2. 只要该版本仍可能被提供服务，就**不得**丢弃已保留的版本绑定（BR-11）。

## 规则覆盖范围

| 规则 | 流程 |
|---|---|
| BR-01 版本绑定 | P-01, P-02, P-06 |
| BR-02 分片评估 | P-01, P-03 |
| BR-03 已声明的风险等级 | P-02 |
| BR-04 审批记录 | P-03 |
| BR-05 模型注册中心是准入门禁 | P-04 |
| BR-06 回滚选择版本绑定 | P-04, P-06 |
| BR-07 漂移检测在线上运行且可审计 | P-05 |
| BR-08 漂移分为四类 | P-05 |
| BR-09 记录下线退役 | P-08 |
| BR-10 血缘是一种查询 | P-07 |
| BR-11 版本绑定保留 | P-08 |
