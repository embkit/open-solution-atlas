# ADR-0003 — 血缘用于回答问题；它是查询，而不是图示

- 状态：已接受
- 日期：2026-10-12
- 决策人：方案包维护者

## 背景

`AGENTS.md` 要求血缘能够端到端回答**“为什么会有这一预测”**。

这一要求看似容易满足，实际上却很难做到。平台的组件与流程图可以向工程师解释架构，却无法回答与某一次具体预测有关的任何问题。

对于单次预测，答案是：使用了哪个模型版本、哪些特征值、来自哪些上游数据、处于什么时间，以及采用了哪种转换。

## 备选方案

1. **架构图**——描述系统。无法解释预测；如果不加审视，人们就会把这类图称为“血缘”。
2. **数据级血缘（表 → 表）**——优于图示，但仍无法回答为什么会有*这次*预测，因为它止于表级，而没有到具体数据行和具体值。
3. **带特征级来源性质的执行级追溯**——一种查询，其结果包含所用版本、连同其定义版本的特征值、上游数据行，以及所涉及的源系统和时间戳。

## 决策

采用选项 3，并由 BR-09、FR-012 和 NFR-009 强制执行。

该追溯是建立在预测追溯记录和版本绑定之上的读模型，因此它是派生得到的，而非人工编写。特征的定义版本是该追溯的一部分，因为如果无法确定生成该值的转换，就无法回答“为什么会有这一预测”。

## 后果

- 正面：答案是设有延迟目标（NFR-009）的查询结果，而不是一次调查。没有延迟目标的能力就是一张图。
- 正面：同一条记录服务于审计、支持与调试，因此三者不会构建彼此不一致的独立制品。
- 负面：必须保留追溯记录，且它**包含特征值**，因此它构成隐私暴露面，而不只是审计面。已记录于 `security.md` §3——从追溯记录中重新识别数据主体这一行为受到治理约束，而非仅被视为查询便利。
- 负面：每次预测的计算和存储都会产生成本。采样是在成本与覆盖范围之间取舍，而采样所得的追溯记录只是一个采样答案——本方案包不在此处决定采样策略。
