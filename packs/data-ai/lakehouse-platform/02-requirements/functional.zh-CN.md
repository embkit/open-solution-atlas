# 02 · 功能需求

> EARS 记法：`当 <触发条件> 系统应当 <响应>`。
> ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）、一条规则（`BR-xx`）与一个
> ADR。验收标准（AC-*）在 L3 定义。
>
> `verification: unverified` —— 这些需求是方案包设计，未针对任何部署验证。

## CAP-01 接入

### FR-001 — 原始以仅追加方式落地
- **当** 一次加载写入原始层
- **系统应当** 以 load id 作键追加，且**不得**覆盖或编辑先前的原始记录（BR-02）
- 追溯：CAP-01、BR-02、ADR-0001

### FR-002 — 加载记录
- **当** 一次加载完成或失败
- **系统应当** 记录其来源、抽取时间、分区键、行数与结果，使任何下游结果都能
  被归因到一次加载（BR-02）
- 追溯：CAP-01、BR-02

### FR-003 — 幂等落地
- **当** 一次加载在同一来源窗口上被重试
- **系统应当** 产出同一原始分区，且**不得**产生重复行（BR-05）
- 追溯：CAP-01、BR-05、ADR-0002

## CAP-02 存储与表格式

### FR-004 — 快照读取
- **当** 一个读取方读一张表
- **系统应当** 提供一致的快照，使一次读取不受并发写入影响（BR-02）
- 追溯：CAP-02、BR-02

### FR-005 — 规范层的规范键
- **当** 规范化数据被构建
- **系统应当** 只把来源标识符解析一次到规范键上，且**不得**允许一个集市以不同
  方式解析它们（BR-03）
- 追溯：CAP-03、BR-03

### FR-006 — 集市不得直读原始
- **当** 一个集市被定义
- **系统应当** 从规范化层构建它，且**不得**允许一个读原始层的集市（BR-04）
- 追溯：CAP-03、CAP-04、BR-04、ADR-0001

## CAP-04 数据质量

### FR-007 — 每个数据集的规则编目
- **当** 一个数据集被接入
- **系统应当** 要求一份质量规则编目，声明哪些规则是**阻断性**、哪些是**告警性**
  （BR-06）
- 追溯：CAP-04、BR-06、ADR-0003

### FR-008 — 阻断行为
- **当** 一条阻断性规则失败
- **系统应当** 停止流水线，且**不得**把该分区暴露给任何消费方（BR-06）
- 追溯：CAP-04、BR-06、ADR-0003

### FR-009 — 告警行为与路由
- **当** 一条告警性规则失败
- **系统应当** 记录该失败、把它路由给一名具名负责人，并允许流水线继续
  （BR-06、BR-07）
- 追溯：CAP-04、BR-06、BR-07、ADR-0003

### FR-010 — 闸门不得静默降级
- **当** 一名操作员试图改变某条规则的阻断/告警分类
- **系统应当** 要求一次显式、有记录、带具名操作者的变更，且**不得**允许就地
  降级（BR-06）
- 追溯：CAP-04、BR-06、ADR-0003

## CAP-03 转换与建模

### FR-011 — 契约固定的派生
- **当** 一个集市被构建
- **系统应当** 记录它派生自哪些规范化分区与哪个契约版本（BR-01）
- 追溯：CAP-03、BR-01

### FR-012 — 集市可重建性
- **当** 一个集市被重建
- **系统应当** 从其记录的输入复现它，且**不得**依赖任何只存在于该集市之中的
  转换（BR-08）
- 追溯：CAP-03、BR-08

## CAP-05 目录与元数据

### FR-013 — 分类被记录并被强制
- **当** 一个数据集被接入或变更
- **系统应当** 记录其分类，并在平台中强制由分类派生的访问（BR-09）
- 追溯：CAP-05、BR-09、ADR-0004

### FR-014 — 对每个消费方都被强制的访问
- **当** 任何消费方——BI、notebook、导出、市场数据馈送或数据科学工作区——读取
- **系统应当** 强制同一套由分类派生的访问，且**不得**提供任何绕过它的消费方
  （BR-09）
- 追溯：CAP-05、BR-09、ADR-0004

## CAP-06 血缘与影响分析

### FR-015 — 字段级血缘
- **当** 一个集市列被追溯
- **系统应当** 返回规范化字段、**规则及其版本**，以及产生它的源字段（BR-10）
- 追溯：CAP-06、BR-10、ADR-0005

### FR-016 — 基于字段级血缘的影响分析
- **当** 一次对源字段或转换规则的变更被提出
- **系统应当** 报告受影响的集市、消费方与已报出的数字（BR-10）
- 追溯：CAP-06、BR-10、ADR-0005

## CAP-08 编排与可运维性

### FR-017 — 分区隔离的重处理
- **当** 一个分区范围被重处理
- **系统应当** 幂等地只重建该范围，且**不得**改写或阻塞其他分区（BR-05、BR-11）
- 追溯：CAP-08、BR-05、BR-11、ADR-0002

### FR-018 — 从血缘得出重处理范围
- **当** 发现一个逻辑缺陷
- **系统应当** 从字段级血缘算出受影响的分区范围，而不是要求一次完整重建
  （BR-10、BR-11）
- 追溯：CAP-08、CAP-06、BR-10、BR-11

### FR-019 — 按分区的成本可见性
- **当** 一个作业或重处理运行
- **系统应当** 把其算力与存储成本归集到它触及的分区，而不只是归集到提出请求
  的消费方（BR-14）
- 追溯：CAP-08、BR-14

## CAP-07 访问控制与隐私

### FR-020 — 运行式删除流水线
- **当** 收到一条删除或擦除请求
- **系统应当** 执行穿过原始、规范化、集市、导出、缓存、快照与派生 ML 数据的
  传播路径，并记录结果（BR-12）
- 追溯：CAP-07、BR-12、ADR-0006

### FR-021 — 降级的删除状态
- **当** 删除无法传播到某个仅追加或派生的层
- **系统应当不**继续假装删除成功；它**应当**执行被记录的降级路径并记录完成
  （BR-12）
- 追溯：CAP-07、BR-12、ADR-0006

### FR-022 — 按类别声明的留存窗口
- **当** 数据被留存
- **系统应当** 应用为其类别声明的留存窗口，且**不得**套用单一的全局设置
  （BR-13）
- 追溯：CAP-07、BR-13、ADR-0006
