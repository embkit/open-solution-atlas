# 02 · 非功能需求

> 可度量的目标。**标注 `(A)` 的数值目标是策略假设，不是事实**——记录下来是为了
> 能被锁定、争论和修改；它们的依据见
> [`../SOURCES.md` §4](../SOURCES.md)。
>
> 公式被固定下来，以便任何一方都能复算出同一个数字。没有公式的目标只是一个
> 愿望。
>
> `verification: unverified` —— 目标属于方案包设计。

## NFR-001 — 加载幂等性
- **目标**：100%。一次被重试的加载产出完全相同的原始分区。
- **公式**：`count(产出相同分区的重试加载) / count(重试加载)`。
- **依据**：BR-05；正是让重试成为常规路径的那条性质。

## NFR-002 — 原始不可变
- **目标**：对原始记录的就地编辑为 0。
- **公式**：`count(写入后被修改的原始记录) = 0`。
- **依据**：一条不变量（BR-02），不是一个服务级别。

## NFR-003 — 分区隔离的重处理
- **目标 (A)**：单个分区范围的重处理 p95 完成时间在该范围正常时间的 2 倍
  之内。
- **公式**：该范围的 `reprocess_ts / normal_run_ts` 的 p95。
- **依据**：BR-11 —— 如果一个分区的重建代价等于一次完整重建，恢复就被最坏
  情况界住，于是团队会跳过它。

## NFR-004 — 闸门覆盖率
- **目标**：100% 已接入的数据集都有一份声明了阻断/告警的质量规则编目。
- **公式**：`count(有编目的数据集) / count(已接入的数据集)`。

## NFR-005 — 闸门决策正确性
- **目标**：在一条阻断性规则失败期间暴露给消费方的数据集为 0。
- **公式**：`count(存在失败阻断规则时仍被暴露的分区) = 0`。
- **依据**：一条不变量（BR-06）。这正是「什么都阻断所以我们关掉闸门」与
  「什么都不阻断所以坏数据流出」两种失败都会显形的地方。

## NFR-006 — 告警解决
- **目标 (A)**：从告警提出到负责人采取行动的 p95 ≤ 5 个工作日。
- **公式**：`action_ts - raised_ts` 的 p95。
- **依据**：BR-07；一条既没有负责人也没有时延的告警，是一份没人读的报表。

## NFR-007 — 集市可复现性
- **目标**：100%。被重建的集市与从同一输入重建的结果逐字节相同。
- **公式**：`count(与先前重建完全一致的重建) / count(重建)`。
- **依据**：BR-08；一个无法被复现的集市就不是派生的。

## NFR-008 — 血缘完整度
- **目标**：100% 的集市列都解析到一个源字段**以及**一个规则版本。
- **公式**：`count(已解析源字段 + 规则版本的集市列) / count(集市列)`。

## NFR-009 — 访问控制覆盖率
- **目标**：100% 的消费方路径都强制由分类派生的访问。
- **公式**：`count(执行强制的消费方路径) / count(消费方路径)`。
- **依据**：BR-09；放在 BI 工具里的控制不是控制——一个 notebook 也是消费方。

## NFR-010 — 删除完成度
- **目标**：100% 已受理的请求在每一层与每个目的地都达成一个被记录的结果。
- **公式**：`count(每一层/目的地都有记录结果的请求) / count(请求)`。
- **依据**：BR-12；这条运行流水线要么完整，要么就是工单队列里的一条请求。

## NFR-011 — 删除 SLA
- **目标 (A)**：从请求到记录完成的 p95 ≤ 30 天。
- **公式**：`completion_ts - request_ts` 的 p95。
- **依据**：以天计，是因为这条流水线横跨工程与运行系统；更短的目标只能靠
  丢弃某些层达成，而那正是这条规则禁止的失败。

## NFR-012 — 跨界面一致性
- **目标 (A)**：从分区状态变更到读取方与派生集市之间一致的 p95 ≤ 60 秒。
- **公式**：`consistency_ts - state_change_ts` 的 p95。

## NFR-013 — 打开时的数据新鲜度
- **目标 (A)**：按契约，以与 BI 兄弟方案包相同的方式度量——相对于契约，而不
  是数据库最后一次写入。

## NFR-014 — 新鲜度契约覆盖率
- **目标 (A)**：≥ 90% 的集市有一条已声明的新鲜度契约。
- **公式**：`count(有契约的集市) / count(集市)`。

## 固定公式

| 量 | 定义 |
|---|---|
| **幂等加载** | 在同一来源窗口上重跑产出一个逐字节相同的分区 |
| **分区隔离的重处理** | 重建只触及被请求的分区范围；其他分区的字节与读取方不受影响 |
| **阻断闸门** | 一条其失败要求流水线停止、并扣留该分区的规则 |
| **告警闸门** | 一条其失败被记录、路由给具名负责人、且不停止流水线的规则 |
| **字段级血缘** | 集市列 → 规范化字段 → 源字段，每条边上都带规则及其版本 |
| **删除结果** | 每一层与每个目的地上的被记录结果，即 `completed` 或一个具名的降级状态——绝不是静默 |
| **已声明的世代窗口** | 按类别的留存期限，已声明且写明；本方案包不指名取值 |

> ⚠️ ASSUMPTION — 每一个 `(A)` 目标都是策略。本仓库不主张这些数字来自基准、
> 法规或某个部署。
