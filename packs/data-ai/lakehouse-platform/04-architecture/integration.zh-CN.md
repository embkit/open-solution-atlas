# 04 · 集成

> 与平台邻居的集成契约。ID 稳定；每条流都追溯到需求与规则。
>
> ⚠️ ASSUMPTION — 接口选型与协议属于方案包设计。

## I. 集成点

| ID | 邻居 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **源系统**（OLTP、日志、SaaS、IoT/OT、文件） | 入 | 抽取到原始，按 load id 作键 |
| **I-02** | **表格式 / 目录** | 两者皆可 | 快照与 schema 演进——一项部署选择，不是平台决策 |
| **I-03** | **BI / 分析消费方** | 出 | 经平台的访问控制提供集市 |
| **I-04** | **数据科学 / notebook 工作区** | 出 | 最常被给予绕过路径的消费方 |
| **I-05** | **ML 特征流水线** | 出 | 派生特征与训练数据——一个删除目的地 |
| **I-06** | **市场 / 伙伴馈送** | 出 | 受治理的导出 |
| **I-07** | **删除请求工具** | 入 | 擦除与删除请求 |
| **I-08** | **成本 / FinOps** | 出 | 按分区归集 |

## F. 内部流程

### F-01 — 接入
1. 一次加载在一个窗口上从来源读取。
2. 原始被追加，按 load id 作键。
3. 写入加载记录：来源、抽取时间、分区键、行数。

### F-02 — 规范化
1. 原始被读取，规范键被解析——**只在这里**。
2. 源头特有的混乱被解决——**只在这里**。
3. 规范化分区被幂等地写入。
4. 它所满足的契约版本被记录。

### F-03 — 闸门
1. 该数据集的质量规则针对该分区被求值。
2. 一次阻断性失败停止流水线，并把该分区扣留给每个消费方。
3. 一次告警性失败被记录并路由给一名具名负责人，流水线继续。
4. 一次严重级别变更需要一次显式且有归属的动作。

### F-04 — 策展与提供
1. 集市只由规范化构建，对照被记录的契约版本。
2. 一个消费方读取，由分类派生的访问**由平台**强制。
3. 访问决策被记录。

### F-05 — 追溯与重处理
1. 一个集市列被追溯到源字段，以及每条边上的规则版本。
2. 一个逻辑缺陷的受影响分区范围由该血缘算出。
3. 重处理幂等地只在该范围内运行。
4. 成本被归集到被触及的分区。

### F-06 — 治理
1. 一条带范围的删除请求到达。
2. 流水线传播穿过原始、规范化、集市、导出、缓存、快照与派生的 ML 数据。
3. 每个目的地记录一个结果：**completed** 或一个具名的 **degraded** 状态。
4. 留存应用已声明的按类别窗口。

## 失败模式契约

| 集成 | 必须具备的失败模式 |
|---|---|
| **I-01 源系统** | 一次部分抽取是一次失败的加载，而不是一个部分的原始分区。一次加载要么完整，要么没有落地 |
| **I-02 表格式** | 一次压实或快照过期作业绝不能使一条原始记录失效。仅追加是对底座的硬性要求，不是约定 |
| **I-03/I-04 消费方** | 一个无法接受平台访问控制的消费方**不被接入**——没有绕过路径，数据科学工作区也不例外 |
| **I-05 ML 流水线** | 一个派生特征或训练快照是一个**删除目的地**；一条无法被删除触及的流水线是一个治理缺口，不是一个便利问题 |
| **I-06 市场馈送** | 一次受治理的导出与其他任何消费方一样受由分类派生的访问约束 |
| **I-07 删除工具** | 一个未解决的目的地被记录为 **degraded** 状态，绝不记为 completed |
| **I-08 成本** | 成本归集失败只会降级归集报表，绝不降级流水线 |

> 这个模式是：集成不可用时降级外部路径，并记录为*未知*——绝不被假定，绝不被
> 默认化。唯一的例外是消费方路径：一个无法接受平台强制访问的消费方不被
> 接入，而不是被授予一个例外，因为例外界面正是一个受治理的平台悄悄不再受
> 治理的地方。

## 消费方契约（必须接受什么）

| 方面 | 由消费方集成声明 |
|---|---|
| **身份** | 消费方的身份，以及访问所依赖的组/角色属性 |
| **访问** | 由分类派生的策略，由平台强制——而不是由消费方 |
| **数据处置** | 消费方是否可以保留、缓存或再导出，以及可以多久 |
| **删除可达性** | 消费方的副本、缓存与派生制品必须能被删除流水线触及 |
| **血缘** | 读取被记录，使血缘与影响分析保持完整 |

> 一个无法接受全部五项的消费方——尤其是第四项——是一个治理缺口。一个在
> 平台触及范围之外快照数据的数据科学工作区是最常见的例子，而本方案包的答案
> 是：它不被接入。
