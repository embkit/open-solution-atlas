# 04 · 安全

> ⚠️ ASSUMPTION — 安全态势属于方案包设计。`02-requirements/compliance.md` 中
> 指名的文件只是名称标注；不引用任何条款。

## 1. 访问控制属于平台，否则它并不存在

核心规则是结构性的：由分类派生的访问**由平台**强制，对每一种消费方都如此
（BR-09）。

让它变得真实的检查不是「BI 是否强制了它」——而是*一个 notebook 算不算消费
方？* 绕过 BI 层控制的消费方有：一个数据科学工作区、一次导出到文件、一个
市场数据馈送、某个持有数仓凭据的人做的一次临时查询，以及一个定时作业。它们
全都是消费方。

> 放在 BI 工具里的控制不是控制。NFR-009 统计消费方**路径**而不是工具配置，
> 正是为此——失败是一条路径，不是一个设置。

## 2. 原始不可变是一项完整性控制

原始不可变且仅追加（BR-02）。它之所以属于安全章节而不是运维章节，是因为
替代方案是一次**静默的完整性失败**：一份被编辑过的原始层意味着每个下游数字
都已是一段不复存在的历史的函数，而它在多年之后才被发现——某个人重算并得到
了一个不同的数字。

> 这也是为什么仅追加这条性质是对存储底座的硬性要求而不是约定：一个使一条
> 原始记录失效的压实或快照过期作业是一次安全事件，不是例行杂务。

## 3. 闸门是控制边界，不是过滤器

阻断闸门把该分区扣留给**每一个**消费方——而不是靠在读取时过滤。这个区别
很关键：

| | | |
|---|---|---|
| **在流水线中扣留** | 在闸门放行之前，该分区在下游并不存在；没有消费方能触及它 |
| **在读取时过滤** | 坏数据是存在的，于是每个消费方都要单独决定是否应用这个过滤器 |

第二种是常见的实现，也正是「这个仪表盘为什么显示这个？」在事后仍是个问题的
原因。

## 4. 删除是一条带被记录结果的流水线

删除会传播，并**逐目的地**记录一个结果（BR-12）。一个没有被记录结果的目的地
不是被删除了——它是未知的，而未知被记录为**降级**状态而非成功（FR-021）。

被忘记的目的地正是那些不那么明显像「数据」的：缓存、快照、导出、市场数据
馈送，以及**派生的 ML 数据**，例如特征与训练快照。最后一项被单列为一项控制
（CTL-05），因为它最常无法触及。

> ⚠️ ASSUMPTION — 本方案包不解决删除如何与仅追加存储及派生 ML 制品相互
> 作用。候选做法（对带键列做密码学销毁、被每个读取方遵守的逻辑墓碑、快照
> 过期窗口、有界的特征重算）是部署方必须选择的机制；本方案包陈述这项要求
> 而不指明方法。在此选定一种就是臆造确定性。

## 5. 严重级别变更是受控动作

改变一条质量规则的阻断/告警分类需要一次显式且有归属的动作（BR-06、
FR-010）。替代方案——就地降级——正是闸门沦为装饰的方式：流水线被阻断，
有人把规则降级，下一次构建就通过了。

## 6. 审计证据

| 制品 | 存放在哪 | 它回答什么 |
|---|---|---|
| **原始分区 + 加载记录** | 原始存储 + 加载表 | 「数据是什么、什么时候、从哪个来源来的？」 |
| **规范化分区上的契约版本** | 规范化存储 | 「这个数据集当时意味着什么、依据哪份契约？」 |
| **闸门求值 + 严重级别变更历史** | 质量存储 | 「这个分区在阻断规则失败期间是否被暴露过，谁改了规则？」 |
| **带规则版本的血缘边** | 血缘存储 | 「哪个源字段、哪个规则版本产生了这一列？」 |
| **每个消费方的访问决策** | 审计轨迹 | 「谁在什么由分类派生的策略下读了什么？」 |
| **每个目的地的删除结果** | 生命周期存储 | 「这真的到处都删掉了吗——还是仍有一部分在？」 |

> 每一个都能从平台自己的记录中回答。加载记录与删除结果是实践中最常缺失的
> 两样，而它们正是让平台的论断可被核验而不是仅被断言的东西。

## 7. 留存，以及刻意留下的张力

留存按类别声明（BR-13）：原始抽取、规范化历史、集市、导出与血缘边性质
不同、义务也不同。

> ⚠️ ASSUMPTION — 在「为重算而保留原始」与「原始所含数据附带的个人数据
> 义务」之间的张力，此处**未**予解决。设计必须提供的机制是一份带声明的
> 世代窗口的按类别留存策略；窗口是一个业务决策，本方案包不指名取值。
