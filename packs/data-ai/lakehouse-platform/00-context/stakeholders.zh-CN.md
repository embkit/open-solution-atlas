# 00-context / 干系人

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **数据平台团队** | 构建并运行接入、存储、算力、目录 | 拥有并运营该平台 |
| **数据工程** | 编写并维护流水线与转换 | 平台内容的主要作者 |
| **分析工程** | 按契约构建规范化模型与集市 | 规范化的消费方；集市的作者 |
| **报表与 BI** | 仪表盘与法定报表 | 集市的消费方；对信任的声音最大 |
| **数据科学与算法** | 特征、训练、评估 | 规范化与集市的消费方；常常最少被治理 |
| **数据治理委员会** | 分类、归属、留存、策略 | 权威；平台执行他们的决定 |
| **数据负责人/领域管家** | 对某个数据集的含义与质量负责 | 声明契约，并接受或拒绝质量失败 |
| **安全与隐私** | 访问策略、驻留、擦除请求 | 消费分类结果；驱动删除流水线 |
| **法务合规** | 法定报送义务、记录义务 | 定义什么必须可证明、证明多久 |
| **源系统负责人** | 数据所来自的那些系统 | 上游对手方；常常是质量问题的真正原因 |
| **财务与成本** | 平台成本归集与预算 | 消费成本遥测；是真实相关方，不是旁观者 |
| **内审** | 控制执行情况的证据 | 审计与血缘的只读消费方 |
| **监管与外部审计** | 法定检查 | 只读证据；无平台访问权 |

## 2. 角色（应用参与者）

| 角色（英） | 中文 | 关键权限 / 任务 |
|---|---|---|
| Data engineer | 数据工程师 | 编写/运营流水线、安排回填、响应作业失败 |
| Analytics engineer | 分析工程师 | 定义规范化模型与集市、声明契约、版本化变更 |
| Data steward | 数据管家 | 认证某个数据集的含义与质量；接受/拒绝闸门失败 |
| Dataset owner | 数据集负责人 | 对一个数据集负责：定义、质量、访问申请 |
| Platform operator | 平台运维 | 管理算力、存储、调度、容量；无业务规则权威 |
| BI developer | 报表开发 | 在集市上构建仪表盘；不能写原始或规范化层 |
| Data scientist | 数据科学家 | 抽取特征、读取被提供的数据集；不能绕过平台访问控制 |
| Governance officer | 治理专员 | 分类数据集、设定留存、驱动擦除与访问复核 |
| Security/privacy engineer | 安全隐私工程师 | 实现策略即代码，端到端处理删除请求 |
| Access requester / approver | 访问申请人/审批人 | 申请并审批数据集访问 |
| Auditor | 审计员 | 血缘、策略与审计证据的只读读取者 |
| FinOps analyst | 成本分析师 | 归集并预测平台成本 |

### 非人类参与者

| 参与者 | 说明 |
|---|---|
| **接入连接器** | 拉取或接收源数据；重放时必须幂等 |
| **流式消费方** | 若采用流式接入；偏移量管理与重放是它的正确性面 |
| **转换引擎** | 解析分层模型；确定性是一项要求，而不是待发现的属性 |
| **质量闸门** | 执行检查并路由到阻断 vs. 告警——`AGENTS.md` 强制的区分 |
| **目录与元数据服务** | schema、归属、分类、血缘图 |
| **访问控制引擎** | 求值谁可以读哪个数据集，在平台层面强制 |
| **调度器 / 编排器** | 作业、依赖、重试、回填 |
| **压实 / 维护作业** | 小文件压实、快照过期、孤儿清理 |
| **通知与告警** | 新鲜度、质量、作业失败、成本异常 |
| **擦除流水线** | 把删除请求传播到各层、缓存、导出与派生数据 |

## 3. 作为参与者的外部 / 上下游系统

- **OLTP 数据库** —— 记录派生数据的主要来源。
- **SaaS 与伙伴数据源** —— 外部数据；通常契约最弱。
- **应用日志 / 事件流** —— 行为数据。
- **对象存储** —— 表格式的底座。
- **身份提供方** —— 认证与访问策略所需的组成员关系。
- **BI 工具** —— 主要消费方；访问控制常被错误地假定住在那里。
- **ML 特征与模型注册表** —— 位于规范化数据之下游。
- **数据市场 / 产品门户** —— 若对外暴露数据产品。
- **SIEM / 审计存储** —— 消费访问与策略遥测。
- **工单 / ITSM** —— 访问请求，以及太多本该自动化的擦除请求。
- **成本/计费来源** —— 供 FinOps 归集。

## 4. 参与者目标（主要）

- **报表开发**：一个稳定、有新鲜日期、可追溯到来源字段的数字——并且在仪表盘坏掉
  *之前*就被告知。
- **数据管家**：知道某个数据集何时漂移到了契约之下，并拥有一道拦住它的闸门，
  而不是一份事后解释它的报表。
- **数据科学家**：可从快照复现的特征，而不必申请直接读取原始数据的权限。
- **治理专员**：到处都被强制的分类，以及一个可证明地在每一层都完成的删除请求。
- **平台运维**：安全地回填一个分区，而不破坏下游集市或成本预算。
- **源系统负责人**：当源数据质量导致流水线失败时，收到一个精确而不归咎的
  信号。
- **审计员**：为任何集市数字演示，是哪些源字段与规则产生了它，以及谁有权
  访问。

> ⚠️ ASSUMPTION: 本方案包假设**访问控制由平台强制**，绝不委托给消费方，
> 并且**每一层只能通过平台读取**。这遵循本方案包的 `AGENTS.md`；它是一项
> 设计立场，不是引用。
