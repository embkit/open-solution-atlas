# 01-business / 流程

> 数据仓库与湖仓平台的流程定义。每条流程指明其触发条件、步骤，以及约束其
> 步骤的规则。规则位于 `business-rules.md`（BR-xx），此处只引用、不复述。
>
> ⚠️ ASSUMPTION — 流程分解属于方案包设计。没有为它引用任何外部标准。

## P-01 — 接入

| | |
|---|---|
| **触发** | 一次来自来源的定时或触发式加载 |
| **结果** | 原始层中的一个新分区，被追加且绝不编辑 |

1. 从来源读取（批量、微批或流式）。
2. 以**仅追加**方式落地到原始层，按 load id 作键（BR-02）。
3. 记录这次加载：来源、抽取时间、行数、分区键。

> BR-02：原始不可变，因此下游结果总能从头重算。一份被编辑过的原始层会摧毁
> 使重处理成为可能的性质。

## P-02 — 规范化

| | |
|---|---|
| **触发** | 原始数据到达，或一个规范化分区被重建 |
| **结果** | 一个可按分区重处理的规范化分区 |

1. 去重、类型化、校验、按规范键连接（BR-03）。
2. 源头特有的混乱**只在这里**解决（BR-04）。
3. 幂等地写入规范化分区——重跑产出同一分区（BR-05）。
4. 记录这个分区所满足的契约（BR-01）。

> BR-04：源头特有的混乱在规范化层**只被解决一次、且为所有人解决**。一个读
> 原始的集市绕过了那一层的存在意义——那一层正是为了防止混乱被解决两次、且
> 两次不同。

## P-03 — 闸门

| | |
|---|---|
| **触发** | 一个分区或数据集被评估 |
| **结果** | **被阻断**或**被告警**——两种不同的机制 |

1. 求值为该数据集编目的质量规则。
2. **阻断性**失败停止流水线；下游消费方绝不能看到这些数据（BR-06）。
3. **告警性**失败被记录并路由给负责人；流水线继续（BR-06）。
4. 把每个失败路由给其负责人——一条没有负责人的告警，是一份没人读的报表
   （BR-07）。

> BR-06：阻断/告警的区分不是装饰性的。把二者混为一谈会产生两种失败之一——
> 一个什么都阻断的平台（于是团队关掉闸门），或一个什么都不阻断的平台（于是坏
> 数据静默流出）。

## P-04 — 策展

| | |
|---|---|
| **触发** | 规范化数据满足其契约 |
| **结果** | 一个集市，派生的且可重建 |

1. 按已声明的契约构建集市。
2. 集市是可丢弃且可重建的——不允许手工编辑（BR-08）。
3. 记录该集市派生自哪个规范化分区与契约版本。

## P-05 — 提供

| | |
|---|---|
| **触发** | 一个消费方读取 |
| **结果** | 数据在平台自身的访问控制下被提供，而不是消费方的 |

1. **在平台中**强制由分类驱动的访问（BR-09）。
2. 记录这次访问。

> BR-09：访问强制属于平台。实现在 BI 层的控制意味着每一个其他消费方——
> 一个 notebook、一个数据科学家、一次导出——都绕过了它。

## P-06 — 解释

| | |
|---|---|
| **触发** | 一个下游数字被质疑 |
| **结果** | 端到端追溯的 源字段 → 集市列 血缘 |

1. 从集市列经规范化层回溯到**源字段**（BR-10）。
2. 从记录中回答「是哪个源字段与哪条规则产生了这个？」

> BR-10：字段级血缘正是能回答「哪个仪表盘数字错了」的东西。表级血缘做不到，
> 因为它停在答案的上一层。

## P-07 — 重处理

| | |
|---|---|
| **触发** | 一个逻辑缺陷、一个迟到的来源，或一次契约变更 |
| **结果** | 一个有界的分区被重建，别的一概未动 |

1. 选出受影响的分区范围。
2. 从原始幂等地重建（BR-05）。
3. 保持其他所有分区不受影响（BR-11）。

> BR-11：「重载上周二」必须是一等的安全操作。如果一个分区的重处理无法被
> 隔离，那么从逻辑缺陷中恢复就是无界的——这正是团队最终开始信任陈旧数据的
> 方式。

## P-08 — 治理

| | |
|---|---|
| **触发** | 定期，或按请求 |
| **结果** | 删除被传播，或运行式删除路径被执行 |

1. 接收一条删除或擦除请求。
2. 传播穿过原始、规范化、集市、导出、缓存、快照与派生的 ML 数据（BR-12）。
3. 在仅追加的层无法传播的地方，执行运行式删除路径并记录完成。

> BR-12：删除是一条**运行流水线**，不是一张工单。一个唯一的答案是「去问每个
> 消费方」的平台，无论其访问控制多好，都没有满足这项义务。
