# 00-context / 干系人

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **数据与分析负责人** | 拥有分析策略与认证边界 | 治理平台 |
| **分析工程** | 编写语义层：模型、指标、RLS/CLS | 已认证内容的主要作者 |
| **数据平台团队** | 运行数仓、流水线、契约 | 上游兄弟方案包（`lakehouse-platform`） |
| **数据治理 / 管理员委员会** | 批准指标定义与分类 | 对口径与策略的权威 |
| **业务部门负责人** | 消费报表；定义他们需要度量什么 | 主要消费方；指标含义的来源 |
| **内审** | 访问控制与变更被记录的证据 | 只读消费方 |
| **信息安全与隐私** | 访问策略、分类、留存 | 约束每一件制品 |
| **财务 / FinOps** | 平台成本归集 | 消费成本遥测 |
| **企业架构** | 与平台标准和身份的一致性 | 治理集成模式 |
| **产品与研发（嵌入式消费方）** | 把指标嵌入自己的产品 | 经 API/嵌入方式消费 |

## 2. 角色（应用参与者）

| 角色（英） | 中文 | 关键权限 / 任务 |
|---|---|---|
| Semantic modeler | 语义建模者 | 定义数据集、实体、指标、RLS/CLS；为其做版本 |
| Metric owner | 指标负责人 | 对某个指标的含义负责；批准定义变更 |
| Dashboard author (certified) | 认证看板作者 | 针对模型版本构建并发布已认证制品 |
| Analyst | 分析师 | 探查、构建查询、另存为用户内容 |
| Self-service builder | 自助分析用户 | 基于共享数据集构建；提交晋升 |
| Promotion reviewer | 晋升审核人 | 评审并发布或拒绝提交的制品 |
| Viewer | 查看者 | 在自己的权限下消费已认证制品 |
| Platform administrator | 平台管理员 | 管理工作区、连接、版本；**无权**干预定义 |
| Security/RLS administrator | 权限管理员 | 维护 RLS/CLS 规则；与模型编写分离 |
| External/share recipient | 外部接收人 | 消费已发布的导出或嵌入视图 |
| Cost/usage administrator | 成本管理员 | 归集算力与许可成本 |

### 非人类参与者

| 参与者 | 说明 |
|---|---|
| **语义模型服务** | 在一处求值指标、连接与 RLS/CLS |
| **查询引擎 / 执行器** | 在语义层之下运行查询，而不是绕开它 |
| **认证服务** | 从模型契约与流水线状态计算认证状态 |
| **新鲜度监控** | 依据底层契约计算制品新鲜度 |
| **调度器 / 刷新** | 把已认证仪表盘物化到 SL |
| **身份与属性提供方** | 提供 RLS/CLS 所依赖的身份上下文 |
| **通知与告警** | 新鲜度突破、晋升决策、定义变更 |
| **导出 / 嵌入服务** | 产出分享与嵌入视图 |
| **使用分析** | 谁消费了什么、延迟多少——它本身就是一个受治理的数据集 |

## 3. 作为参与者的外部 / 上下游系统

- **数据平台 / 数仓** —— 兄弟方案包；规范化数据与契约的来源。**作为接口在范围内，
  作为主题不在范围内。**
- **身份提供方** —— 认证，以及 RLS 所依赖的组/角色属性。
- **下游 BI/ETL 工具** —— 任何读取语义层的消费方。
- **嵌入式宿主应用** —— 展示指标的产品界面。
- **协作 / 消息** —— 导出与告警的分发。
- **成本 / 计费系统** —— FinOps 归集用。
- **SIEM / 审计存储** —— 消费访问与变更遥测。
- **ML 特征流水线** —— 集市的下游消费方（常常绕过语义层——这是本方案包标记
  的一处边界）。

## 4. 参与者目标（主要）

- **分析师**：不依赖平台团队，从问题走到答案；跑通之后把结果发布出去——而不是
  永远留在一个私人文件夹里。
- **指标负责人**：在一处修改定义，并让使用它的每一件制品都知道，同时旧制品
  仍然可解释。
- **业务部门负责人**：一个我能在董事会上引用的数字，带可见的认证状态和日期。
- **查看者**：相信我看到的对*我*是正确的——而不只是总体上对我这个部门正确。
- **安全管理员**：一处即可修改访问规则，并能证明它对每个消费方都生效，包括
  嵌入。
- **平台管理员**：滚动一个模型版本，而不会一次性弄坏 40 个仪表盘。
- **治理委员会**：知道哪些指标存在分歧，并推动一次决策。

> ⚠️ ASSUMPTION: 本方案包假设**用户身份上下文可以被提供进查询**，并认为这是
> 硬性的平台要求。无法满足它的地方，语义层 RLS 不可执行，本方案包的设计也
> 不适用——这一限制必须被说明，而不是被绕开。
