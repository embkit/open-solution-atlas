# 02 · 功能需求

> EARS 记法：`当 <触发条件> 系统应当 <响应>`。
> ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）、一条规则（`BR-xx`）与一个
> ADR。验收标准（AC-*）在 L3 定义。
>
> `verification: unverified` —— 这些需求是方案包设计，未针对任何部署验证。

## CAP-01 产品主数据（共享）、CAP-02 定价与促销（此处不在范围内）

> 能力地图中的 CAP-01/CAP-02 描述的是共享的产品主数据与兄弟方案包的定价面。
> 本方案包的需求从语义模型开始。

## CAP-01 语义模型

### FR-001 — 有归属、带版本的指标定义
- **当** 一个指标定义被创建或变更
- **系统应当** 要求一名具名负责人与一个版本，且**不得**接受缺少其中任何一项
  的定义（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-002 — 单一连接键
- **当** 两个指标在同一件制品中被使用
- **系统应当** 要求它们按一个已声明的连接键相连，且**不得**允许靠名字相同
  来判定可比（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-003 — 保留版本历史
- **当** 一个定义被修订
- **系统应当** 保留先前版本，使固定在较旧版本上的制品仍然可解释（BR-01、BR-06）
- 追溯：CAP-01、BR-01、BR-06

### FR-004 — 声明式关系
- **当** 某个连接需要一条实体关系
- **系统应当** 要求它在语义模型中被声明，且**不得**允许按约定相连（BR-02）
- 追溯：CAP-01、BR-02、ADR-0001

## CAP-03 访问控制

### FR-005 — 语义模型中的 RLS/CLS
- **当** 一条行级或列级访问规则被定义
- **系统应当** 把它挂到语义模型上，在查询上下文中求值，且**不得**接受只在
  仪表盘上定义的规则（BR-03）
- 追溯：CAP-03、BR-03、ADR-0002

### FR-006 — 对每个消费方求值规则
- **当** 任何消费方——交互式、嵌入式、导出的或管理性的——通过语义层消费数据
- **系统应当** 求值同一套 RLS/CLS 规则（BR-03、BR-10）
- 追溯：CAP-03、BR-03、BR-10

### FR-007 — 规则可测试性
- **当** 一条 RLS/CLS 规则被变更
- **系统应当** 允许它被单独测试并作为定义被审计（BR-03）
- 追溯：CAP-03、BR-03

### FR-008 — 身份上下文传播
- **当** 一条查询被执行
- **系统应当** 把用户身份与属性传进查询上下文，且**不得**以呈现时过滤替代
  （BR-04）
- 追溯：CAP-03、BR-04、ADR-0002

### FR-009 — 各界面统一限定范围
- **当** 用户打开任何查询界面，包括沙箱、预览、嵌入与管理工具
- **系统应当** 以同样的 RLS/CLS 求值限定数据范围，且**不得**提供绕过界面
  （BR-10）
- 追溯：CAP-03、BR-10、ADR-0002

## CAP-05 已认证制品

### FR-010 — 制品版本固定
- **当** 一件已认证制品被发布
- **系统应当** 把它固定到一个模型版本，且**不得**让新版本静默改变它（BR-06）
- 追溯：CAP-05、BR-06、ADR-0003

### FR-011 — 变更影响报告
- **当** 一个模型版本被发布
- **系统应当** 报告哪些制品固定在哪些版本上、该变更会影响什么，且发生在任何
  制品迁移之前（BR-06）
- 追溯：CAP-05、BR-06、ADR-0003

### FR-012 — 计算得出的新鲜度
- **当** 一件制品被渲染
- **系统应当** 依据其模型的新鲜度契约计算新鲜度，且**不得**从数据库最后一次
  写入推导它（BR-07）
- 追溯：CAP-05、BR-07、ADR-0004

### FR-013 — 计算得出且无需交互即可见的认证
- **当** 一件制品被渲染
- **系统应当** 从模型契约与流水线状态推导认证，并展示它而不需要用户点击
  （BR-07）
- 追溯：CAP-05、BR-07、ADR-0004

## CAP-07 服务、嵌入与分发

### FR-017 — 嵌入是消费方
- **当** 一个指标被嵌入到另一个产品
- **系统应当** 在同一语义层、同一 RLS/CLS 下求值它，且**不得**允许嵌入界面在
  该层之外读取（BR-08）
- 追溯：CAP-07、BR-08、ADR-0002

## CAP-06 自助分析与晋升

### FR-014 — 已认证/用户边界
- **当** 内容被创建
- **系统应当** 把它记录为用户内容或已认证，不存在第三种状态（BR-05）
- 追溯：CAP-06、BR-05、ADR-0005

### FR-015 — 晋升路径
- **当** 用户内容被提交晋升
- **系统应当** 让它走评审流程，或发布为已认证，或**带理由**拒绝它（BR-05）
- 追溯：CAP-06、BR-05、ADR-0005

### FR-016 — 发布时附加认证要素
- **当** 用户内容被发布为已认证
- **系统应当** 附上一名负责人、一个固定的模型版本与一条新鲜度契约，缺少任何
  一项它都不能成为已认证（BR-05、BR-06、BR-07）
- 追溯：CAP-06、CAP-05、BR-05、BR-06、BR-07

## CAP-09 治理、审计与生命周期

### FR-018 — 陈旧度被标记并带归属
- **当** 治理复核运行
- **系统应当** 把固定在被取代内容上的制品标记为陈旧，且**不得**静默删除它们
  （BR-09）
- 追溯：CAP-09、BR-09、ADR-0003

### FR-019 — 审计的权威记录
- **当** 一次审计追问某件制品为何那样说
- **系统应当** 依据该制品固定的模型版本、它所用的定义版本以及当时在生效的
  访问记录来回答（BR-06、BR-07）
- 追溯：CAP-09、BR-06、BR-07

## CAP-10 平台运维

### FR-020 — 数仓内部留在兄弟方案包
- **当** 本平台需要接入、存储、表格式或转换机制
- **系统应当** 委托给兄弟方案包 `lakehouse-platform`，且**不得**重新实现它们
  （AGENTS.md）
- 追溯：CAP-10
