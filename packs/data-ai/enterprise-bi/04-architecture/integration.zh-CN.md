# 04 · 集成

> 与平台邻居的集成契约。ID 稳定；每条流都追溯到需求与规则。
>
> ⚠️ ASSUMPTION — 接口选型与协议属于方案包设计。

## I. 集成点

| ID | 邻居 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **数据平台 / 数仓**（`lakehouse-platform`） | 入 | 规范化数据与契约——**委托**，不重新实现 |
| **I-02** | **身份提供方** | 入 | 认证，以及 RLS 所依赖的组/角色属性 |
| **I-03** | **嵌入式宿主应用** | 入 | 在其他产品内部渲染指标 |
| **I-04** | **协作 / 消息** | 出 | 导出与告警的分发 |
| **I-05** | **成本 / 计费** | 入 | 算力与许可归集 |
| **I-06** | **通知** | 出 | 新鲜度突破、晋升决策、定义变更通知 |
| **I-07** | **ML 特征流水线** | 出 | 集市的下游消费方——经常绕过该层，而这正是本方案包标记的 |

## F. 内部流程

### F-01 — 建模
1. 声明数据集、实体与**关系**。
2. 定义带有具名负责人、版本与连接键的指标。
3. 把 RLS/CLS 挂到语义模型上。
4. 做版本并发布模型。

### F-02 — 已认证编写
1. 选择要固定的模型版本。
2. 构建制品。
3. 发布——认证状态从模型契约与流水线状态计算得出，新鲜度取自契约窗口。

### F-03 — 探查与晋升
1. 在用户自己的 RLS/CLS 下探查。
2. 另存为用户内容。
3. 提交晋升。
4. 评审，然后或发布为已认证，或**带理由**拒绝。

### F-04 — 消费
1. 把身份上下文提供进查询。
2. 在语义层中求值 RLS/CLS。
3. 无需交互地展示计算得出的新鲜度与认证。
4. 渲染，包括嵌入——嵌入是消费方，绝非绕过路径。

### F-05 — 变更一个定义
1. 负责人记录变更及其理由。
2. 系统报告影响：哪些制品固定在哪些版本上。
3. 发布新版本；既有制品不受影响。
4. 制品各自迁移，每次迁移都是一个带版本的动作。

### F-06 — 治理与审计
1. 盘点制品、负责人、版本与认证状态。
2. 把固定在被取代内容上的制品标记为陈旧。
3. 用一个归属决定解决每一个标记——指派，或退役。
4. 依据固定版本、定义历史与访问记录回答审计问题。

## 失败模式契约

| 集成 | 必须具备的失败模式 |
|---|---|
| **I-01 数据平台** | 契约不可用时，把制品的新鲜度展示降级为*未知*，绝不是降级为一个默认窗口。一件在陈旧数据上却看起来新鲜的制品，就是那个失败 |
| **I-02 身份提供方** | 身份上下文不可用意味着**不提供任何数据**，而不是提供全部。失败开放的 RLS 是本方案包点名的反模式 |
| **I-03 嵌入式宿主** | 嵌入的请求按与交互式查询完全相同的方式求值；无法接受这一点的宿主不是嵌入 |
| **I-07 ML 流水线** | 直接读集市的流水线是一次**被标记的绕过**，不是受支持的路径——记录下来是为了让它可见，而不是被默认 |
| **I-05 成本** | 缺失的归集不阻塞渲染；成本是被度量的，不是被闸控的 |

> 这个模式是：集成不可用时降级外部路径——除了身份，它失败关闭。失败开放的
> RLS 求值是本方案包唯一视为不可接受的方向，因为它恰恰在最需要的时候把整套
> 访问控制设计变成装饰。

## 嵌入契约（宿主必须接受什么）

| 方面 | 由嵌入集成声明 |
|---|---|
| **身份** | 宿主提供查看者的身份，该层带着它求值 |
| **范围** | 制品的模型版本及其 RLS/CLS，与交互式使用完全一致 |
| **新鲜度与认证** | 按计算结果渲染，宿主不得抑制或改述它们 |
| **不读数据** | 宿主收到的是渲染输出，绝不是层外的数据读取 |
| **失败** | 身份不可用 ⇒ 无数据，而不是全部数据 |

> 无法接受全部五项的嵌入式宿主不是嵌入消费方，而是绕过路径，BR-08 拒绝它。
