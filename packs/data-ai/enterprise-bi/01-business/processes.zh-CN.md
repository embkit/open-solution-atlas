# 01-business / 流程

> 企业 BI 与自助分析平台的流程定义。每条流程指明其触发条件、步骤，以及约束
> 其步骤的规则。规则位于 `business-rules.md`（BR-xx），此处只引用、不复述。
>
> ⚠️ ASSUMPTION — 流程分解属于方案包设计。没有为它引用任何外部标准。

## P-01 — 建模

| | |
|---|---|
| **触发** | 一个语义模型被编写或修订 |
| **结果** | 一个带版本的模型，其中数据集、实体、关系、指标定义与访问规则在一起 |

1. 声明数据集、实体及其**关系**（BR-02）。
2. 定义带有负责人、版本与**连接键**的指标（BR-01）。
3. 把 **RLS/CLS 规则挂到语义模型上**，而不是任何仪表盘（BR-03）。
4. 做版本并发布。

> BR-02：未声明的关系正是两个指标最终无法连接的原因。关系是被声明的，不是
> 在查询时推断的。

## P-02 — 编写已认证制品

| | |
|---|---|
| **触发** | 一名分析师构建已认证制品 |
| **结果** | 一件固定到某个模型版本、带有计算得出的新鲜度与认证的制品 |

1. 选择**模型版本**（BR-06）。
2. 构建制品。
3. 附上负责人与新鲜度契约。
4. 发布——认证状态是从模型的契约与流水线状态**计算得出**的（BR-07）。

> BR-06/BR-07：固定到某个版本的制品在模型前进之后仍可解释；手工标注的认证
> 就是会与现实漂移的认证。

## P-03 — 探查

| | |
|---|---|
| **触发** | 一名分析师探查一个数据集 |
| **结果** | 用户内容，受与已认证内容相同的访问规则约束 |

1. 在用户自己的 RLS/CLS 下查询（BR-03）。
2. 另存为用户内容——探查受同样的权限约束，绝不是例外。
3. 在其受众范围内分享。

> BR-03：探查不是绕过路径。多一个强制执行点，正是语义层要防止的那种失败。

## P-04 — 晋升

| | |
|---|---|
| **触发** | 用户内容被提交晋升 |
| **结果** | 发布为已认证，或**带理由**被拒绝 |

1. 连同预期受众一起提交。
2. 按已认证标准评审。
3. 发布为已认证——附上负责人、模型版本与新鲜度契约——或带理由拒绝。
4. 状态变更显式跨越已认证/用户的边界。

> BR-05：一条无法被有意跨越的边界，就是一条会被绕过的边界。

## P-05 — 消费

| | |
|---|---|
| **触发** | 一名查看者打开一件制品 |
| **结果** | 制品在查看者自己的身份上下文下渲染，新鲜度与认证可见 |

1. 把身份上下文提供进查询（BR-04）。
2. 在语义层中求值 RLS/CLS。
3. **无需交互**地展示新鲜度与认证（BR-07）。
4. 渲染，包括**嵌入**——嵌入是消费方而非绕过路径（BR-08）。

## P-06 — 变更一个定义

| | |
|---|---|
| **触发** | 一个指标定义必须变更 |
| **结果** | 一个新的**版本**，影响被说明，旧制品不受影响 |

1. 负责人记录变更及其理由。
2. 系统报告**影响**：哪些制品固定在哪些版本上（BR-06）。
3. 新版本被发布；既有制品不受影响。
4. 制品可以各自迁移到新版本，而迁移本身也是一个带版本的动作。

> BR-06：静默到达制品的定义变更，正是「并未真正共享的共同词汇」的失败模式。

## P-07 — 治理

| | |
|---|---|
| **触发** | 定期的治理复核 |
| **结果** | 一份制品清单，陈旧度被标记并带负责人 |

1. 盘点制品、其负责人、其模型版本与其认证状态。
2. 把固定在被取代内容上的制品标记为**陈旧**（BR-09）。
3. 指派归属，并在无人接受时记录该决定。

> BR-09：陈旧制品不是错误——它是一个无人拥有的制品，而且它会被信任。治理流程
> 要产出的是负责人或一次明确的退役，绝不是沉默。

## P-08 — 审计

| | |
|---|---|
| **触发** | 一次审计或调查 |
| **结果** | 一份记录：谁在什么规则下访问了哪件制品，以及那些规则是什么 |

1. 读取访问日志，并连接当时在生效的规则版本。
2. 读取定义版本历史。
3. 从记录而非重建来回答「这个制品为什么这么说？」。

## 规则覆盖

| 规则 | 流程 |
|---|---|
| BR-01 口径带版本 + 有归属 | P-01、P-06 |
| BR-02 关系被声明 | P-01 |
| BR-03 RLS/CLS 在语义模型中 | P-01、P-03、P-05 |
| BR-04 身份上下文为必需 | P-05 |
| BR-05 已认证/用户划分带晋升 | P-03、P-04 |
| BR-06 制品固定模型版本 | P-02、P-06 |
| BR-07 新鲜度与认证被计算且可见 | P-02、P-05 |
| BR-08 嵌入是消费方，绝非绕过路径 | P-05 |
| BR-09 陈旧是无人拥有，而非错误 | P-07 |
| BR-10 探查不是例外 | P-03 |
