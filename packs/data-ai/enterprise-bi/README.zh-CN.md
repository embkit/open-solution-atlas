## 本方案包覆盖什么

企业数据之上的消费与治理层：受治理的指标、语义层、仪表盘与像素级报表、自助
探查、订阅/告警，以及面向业务应用的嵌入式分析。核心问题不是图表——而是
**一个数字，一个定义**，横跨财务、运营与管理报表，并带有行/列级访问控制与
可信的新鲜度。

## 范围内

- 指标治理：指标字典（口径管理）、维度、每个指标的唯一真相来源、归属、认证
  等级
- 语义层：数仓之上的业务模型、时间智能、跨工具一致的 KPI
- 消费：仪表盘、格式化报表、临时探查、透视、移动端交付
- 自助分析：数据集市场、带描述/质量徽章的受治理数据集、无 SQL 探查、沙箱
  晋升
- 交付与新鲜度：定时刷新、增量加载、数据新鲜度指标、缓存/加速
- 安全：SSO、行/列级安全、脱敏、查询审计、导出管控
- 运维：使用遥测、慢查询/性能管理、报表生命周期（已认证 vs. 自发布）、指标
  定义的变更管理

## 明确不在范围内

- 数仓/湖仓流水线本身（兄弟方案包 lakehouse；本方案包消费建模后的集市）
- 应用嵌入式分析的产品授权问题
- ML 实验（MLOps 方案包候选）

## 待决问题

1. 无头 BI / 指标存储 API 在内核中的深度（指标即代码）。
2. 像素级报表（分带/打印）是一等能力还是变体。
3. 与被消费集市内部的数据质量工具之间的边界。

## 已定 ADR（不可翻案）

| ADR | 决策 |
|---|---|
| **0001** | **指标定义**是核心对象；负责人是具名的人，版本不可变，而可比性需要一个已声明的**连接键** |
| **0002** | 权限在**语义层**中被求值，该层是**唯一读取路径**，且身份上下文失败时**失败关闭** |
| **0003** | 制品**固定一个模型版本**，模型变更**先报告影响**；迁移是逐制品的带版本动作 |
| **0004** | 新鲜度相对于一条**契约**，认证被**计算得出**——刻意没有可写的 `certified_by` 字段 |
| **0005** | 自助分析把已认证与用户内容分开并带**晋升路径**，使这个划分保持富有成效而不沦为层级 |

## 阻塞 L3 的事项

1. **连接键如何被强制执行** —— 术语表要求一个已声明的键；强制执行的位置
   （建模时、查询时，还是两者）尚未决定。
2. **制品→模型→定义的追溯契约** —— 该记录在数据模型中存在；L3 需要能回答
   「这个制品为什么那样说？」的查询契约。
3. **五条零容忍不变量的验收标准** —— NFR-002、NFR-004、NFR-010，加上失败
   关闭的身份规则与无 `certified_by` 约束，需要让构建失败而不是只报告一个
   阈值的标准。
4. **指标定义复用率下限** —— NFR-001 的 `(A)` 目标 70% 是策略；低于多少就
   判定这一层是复制粘贴，尚未决定。

### 明确未解决（已记录，不被遗忘）

- **指标负责人离职时会发生什么** —— 本方案包要求一名具名的人，但没有解决这个
  空缺。
- **缺失新鲜度契约时会发生什么** —— 新鲜度相对于契约；没有契约的模型就没有
  新鲜度，而本方案包没有说这时展示什么。
- **确实无法提供身份的界面** —— 例如定时导出到文件，变成不支持而不是被特例

### 阻塞 L2 的事项

1. **连接键的强制机制** —— 术语表要求指标定义按一个键相连，但*如何*强制执行
   （建模期约束、查询期校验，还是两者）尚未决定。
2. **什么让一个定义成为「重复」** —— 该状态已被命名且按定义可检测；但检测规则

3. **晋升的触发条件与评审标准** —— 工作流存在于能力地图中；什么启动它、它要求
   什么，属于尚待书写的 L2 规则。
