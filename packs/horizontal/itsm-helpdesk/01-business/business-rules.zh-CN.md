# 01 · 业务规则

> 规则的 ID 是稳定的。理由中提及标准的规则会追溯到该标准。数值参数除非另有
> 说明，否则属于**方案包策略**——见 [`../SOURCES.md` §4](../SOURCES.md)。

| ID | 规则 | 理由 |
|---|---|---|
| BR-01 | 一个工作项 = 一条工单记录；重复接入（相同告警特征/相同邮件线程）会关联或合并并保留来源——任何内容都不得存在于主干之外 | 单一真相来源（ADR-0002） |
| BR-02 | 事件与服务请求共用工单内核，但属于不同类型，有各自的 SLA 目标与解决分类法；问题与变更是各自独立、以引用关联的生命周期 | ISO/IEC 20000-1 第 8.6.1/8.6.2/8.6.3 条的区分 |
| BR-03 | 优先级 = f(影响, 紧急度)，经优先级矩阵得出（BR-03a）；智能体只能在记录理由的前提下向下调整——SLA 违约后优先级绝不可被静默修改 | 诚实报表（ADR-0002） |
| BR-03a | 优先级矩阵取值（`影响 × 紧急度 → P1..P4`，P1 目标响应 `≤ 15 分钟 (A)`）属于方案包策略，并非取自 ISO/IEC 20000-1 | 已声明的假设（第 4 节） |
| BR-04 | SLA 时钟在工单创建时开始计时（响应）/ 在首次责任人动作时开始计时（解决）；它们**仅**在等待请求人或等待供应商的状态下**暂停**并须给出理由，且在对方回复时**自动恢复**——暂停历史可审计；违约是计算出来的，绝不手工修改 | ISO/IEC 20000-1 第 8.3 条（协议）提供义务来源；暂停语义是方案包设计（第 4 节） |
| BR-05 | 业务日历（服务时间、节假日）按服务配置并带生效日期；修改日历绝不会重写已关闭工单的时钟历史 | 报表的可复现性 |
| BR-06 | 工单在路由窗口结束后仍无责任人，或按 SLA 处于风险状态时自动升级；升级追加事件（BR-07）并按角色通知升级矩阵 | 运营连续性；ISO/IEC 20000-1 第 8.7 条 |
| BR-07 | 工单历史仅可追加：备注、分级、指派、状态变更与时钟事件都是事件；更正以引用原事件的新事件表达 | 可审计性（ADR-0002，对齐 27001 A.8.15 的日志要求） |
| BR-08 | 反复发生的事件（关联数 `≥ 30 天内 3 次 (A)`）强制建立问题记录；对生产环境的修复需要 RFC——不允许直接上生产的临时绕过 | ISO/IEC 20000-1 第 8.6.3 条 + A.8.32 变更管理 |
| BR-09 | 变更带有风险分级：**标准**（预批准，仅需排期）、**常规**（需评估 + CAB）、**紧急**（快速通道 + 强制在 `≤ 5 个工作日 (A)` 内做实施后复核）；紧急是唯一绕过 CAB 批准的路径 | ISO/IEC 20000-1 第 8.5 条（移交）/ 27001 A.8.32；数值属于方案包策略（第 4 节） |
| BR-10 | 每张工单/每个 RFC 都按注册表 ID 引用 CI；被引用的 CI 在引用存在期间不可硬删除——只能退役 | CMDB 完整性（ADR-0004） |
| BR-11 | 权限约束：工单对其请求人、被指派的责任人/团队，以及按目录项/组织范围授予的角色可见；涉密事件把可见性限制给明确成员 | 最小权限；27001 A.5.15/A.5.18 |
| BR-12 | 服务请求从目录中履行：没有已发布目录项的请求会被退回请求受理积压——定制工作要么按事件/问题的形态处理，要么新增目录项 | 目录纪律（ISO/IEC 20000-1 第 8.2 条） |
| BR-13 | 邮件/聊天/告警接入解析发件人与线程，得到请求人身份；未知发件人转为「未注册请求人」工单，这类工单不得暴露 CMDB 或受限知识内容 | 防冒用 / 权限约束（第 4 节） |
| BR-14 | 自动化规则是确定性、带版本且有日志的：每次规则应用都在工单上记录规则 id + 版本——事后总能解释某次自动化做了什么 | 可审计性（ADR-0003） |
| BR-15 | 关闭需要解决代码 + 请求人确认（可配置为静默 `≤ 7 天 (A)` 后自动关闭）；重开的工单保留原有的 SLA 实例并追加重开事件 | 诚实的 MTTR（第 4 节） |
