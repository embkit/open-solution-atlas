# 02 · 功能需求

EARS 记法：`当 <触发条件> 系统应当 <响应>`。
ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）和一条规则
（`BR-xx`）。验收标准（AC-*）在 L3 定义。

## CAP-01 服务门户与目录

### FR-001 — 目录与权限约束
- **当** 请求人打开服务门户
- **系统应当** 只列出其组织/角色有权限的目录项（BR-11），每一项都带
  描述、价格/费用归属引用（如有）、履行步骤与预期 SLA 目标。
- 追溯：CAP-01.1, BR-11, BR-12

### FR-002 — 知识库
- **当** 请求人或智能体检索知识库
- **系统应当** 在遵守权限约束的前提下返回已发布文章（受限文章绝不泄露给
  未注册请求人），并在工单上提供关联文章的解决建议。
- 追溯：CAP-01.2, BR-11

### FR-003 — 自助服务进度与公告
- **当** 请求人查看自己的工单，或管理员发布公告
- **系统应当** 展示其本人工单的实时状态/SLA 位置，并把公告推送给限定范围的
  受众。
- 追溯：CAP-01.3

## CAP-02 工单内核

### FR-004 — 全渠道接入
- **当** 工作通过门户、邮件、聊天桥接、监控告警或 API 到达
- **系统应当** 创建或关联一张工单（按告警特征/邮件线程去重），按 BR-13
  解析请求人身份，并记录接入渠道与原始来源。
- 追溯：CAP-02.1, CAP-06.2/06.3, BR-01, BR-13

### FR-005 — 分级与优先级
- **当** 工单被创建或编辑
- **系统应当** 存储类型（事件|请求）、类别、影响与紧急度，经矩阵推导优先级
  （BR-03/BR-03a），并把每一次覆盖都以事件形式记录操作人与理由。
- 追溯：CAP-02.2, BR-03

### FR-006 — SLA 时钟
- **当** 工单进入计时状态
- **系统应当** 在服务的业务日历下运行响应与解决时钟（BR-05），仅通过带
  理由的等待状态执行暂停/恢复（BR-04），计算违约/预警阈值，并暴露完整的
  时钟时间线——时钟绝不直接修改。
- 追溯：CAP-02.3, BR-04

### FR-007 — 指派与升级
- **当** 工单被创建或处于违约风险中
- **系统应当** 按带版本的自动化规则路由（BR-14），在路由窗口内指派责任人，
  并在越过阈值时按职能/层级升级，同时追加事件（BR-06、BR-07）。
- 追溯：CAP-02.4, BR-06

### FR-008 — 解决与关闭
- **当** 责任人解决一张工单
- **系统应当** 要求填写解决代码与说明，请求请求人确认，在静默窗口后自动
  关闭（BR-15），并支持重开——重开保留原有 SLA 实例并追加重开事件。
- 追溯：CAP-02.1, BR-15

### FR-009 — 工作日志与协作
- **当** 智能体在一张工单上协作
- **系统应当** 以不可变事件追加备注/工作日志（内部可见与请求人可见明确
  分开）（BR-07）。
- 追溯：CAP-02.1, BR-07

## CAP-03 问题管理

### FR-010 — 问题记录与复发
- **当** 关联工单越过复发阈值，或重大事件关闭
- **系统应当** 创建或提示建立问题记录，关联所有促成该问题的工单，并跟踪
  根因分析状态。
- 追溯：CAP-03.1, BR-08

### FR-011 — 已知错误库
- **当** 某个根因被定位且存在临时规避手段
- **系统应当** 发布一条已知错误条目（原因 + 规避手段 + 受影响的 CI），对
  有权限的智能体可见，并作为工单解决的指导建议提供。
- 追溯：CAP-03.2

### FR-012 — 问题 → 变更关联
- **当** 问题的修复需要生产变更
- **系统应当** 要求先提供 RFC 引用，才能把修复标记为已实施（BR-08）。
- 追溯：CAP-03.3, BR-08

## CAP-04 变更准入

### FR-013 — RFC 与风险分级
- **当** 一个 RFC 被提出
- **系统应当** 采集受影响的 CI（BR-10）、由影响/紧急度得出风险分级
  （BR-09）、回退方案，并按分级路由：标准（排期）、常规（评估+CAB）、
  紧急（快速通道）。
- 追溯：CAP-04.1, BR-09, BR-10

### FR-014 — CAB 流程与实施
- **当** 一个常规 RFC 完成评估
- **系统应当** 路由到 CAB（排期日历、按范围确定审批人），把决议记录为事件，
  并在实施时记录实施人、验证方式与结果；紧急 RFC 需要在配置的时间窗内
  完成实施后复核（BR-09）。
- 追溯：CAP-04.2, CAP-04.3, BR-09

## CAP-05 资产与配置

### FR-015 — CI 注册表与关系
- **当** CI 与关系被维护（人工或通过数据馈送）
- **系统应当** 存储带生命周期状态（计划中/建设中/活跃/已退役）的类型化 CI、
  类型化关系与生效历史；被引用的 CI 退役而非删除（BR-10）。
- 追溯：CAP-05.1, BR-10

### FR-016 — 依赖视图与漂移
- **当** 智能体查询影响半径，或数据馈送报告状态
- **系统应当** 依据已存关系渲染依赖子图，为缺失/变更/退役等偏差开启漂移
  任务，并报告 CMDB 健康度。
- 追溯：CAP-05.2, CAP-05.3

## CAP-06 自动化与全渠道

### FR-017 — 规则引擎
- **当** 自动化规则运行（路由、优先级建议、通知、Webhook）
- **系统应当** 确定性地评估带版本的规则，在受影响的工单上打上规则 id+版本
  （BR-14），并提供试运行模式以展示将会执行的动作。
- 追溯：CAP-06.1, CAP-06.4, BR-14

### FR-018 — 邮件与聊天接入
- **当** 一封邮件或一条聊天消息到达
- **系统应当** 按 RFC 5322（邮件）解析邮件头/线程并建立工单关联，认证该
  渠道，并把无法解析或未通过认证的输入隔离留存原始消息（BR-13）。
- 追溯：CAP-06.2, CAP-06.3, BR-13

## CAP-07 报表

### FR-019 — SLA 与运营报表
- **当** 报表被请求或按计划生成
- **系统应当** 在既定公式下**从事件日志**计算 SLA 达成率、响应/解决分位数、
  MTTR、积压账龄与违约率，并在报表上显示公式版本。
- 追溯：CAP-07.1, CAP-07.2, ADR-0002

### FR-020 — CSAT 与复盘包
- **当** 工单关闭或服务复盘到期
- **系统应当** 在确认流程中采集 CSAT，并汇总该周期内按服务划分的复盘包
  （SLA、MTTR、复发率、CSAT）。
- 追溯：CAP-07.3, P-06
