# 02 · 非功能需求

> ⚠️ ASSUMPTION (A) — **本文件中的每一个数值目标都是工程预算，而不是测量
> 结果。** 这里的任何数值都未追溯到公开基准；规模档位假设一个中等规模 IT
> 组织（`≤ 5,000 名请求人`、`≤ 200 名智能体`、`≤ 300 张工单/天 (A)`）。所有
> 取值列于 [`../SOURCES.md` §4](../SOURCES.md)。

| ID | 类别 | 目标 |
|---|---|---|
| NFR-001 | 接入延迟 | 门户提交 → 工单可见 `≤ 2 秒 p95 (A)`；邮件/聊天接入 → 工单 `≤ 60 秒 p95 (A)` |
| NFR-002 | SLA 正确性 | 时钟事件（开始/暂停/恢复/停止）精确到事件时间戳；从事件日志重算能逐位复现每一个历史时钟（不存储任何可变时钟状态） |
| NFR-003 | 可用性 | 门户 + 工单 API `≥ 99.9 % 月度 (A)`；知识库读路径 `≥ 99.5 % (A)` |
| NFR-004 | 规模 | `≤ 300 张工单/天`，`≤ 5 万张工单/年在线留存 (A)`；在 10 万张工单的语料上，列表查询 `≤ 1 秒 p95 (A)` |
| NFR-005 | 报表延迟 | SLA/积压仪表盘刷新 `≤ 60 秒 (A)`；月度复盘包从冷事件生成 `≤ 5 分钟 (A)` |
| NFR-006 | 审计留存 | 工单/审计事件在线留存 `≥ 3 年 (A)`；仅追加、防篡改（BR-07）；GDPR/PIPL 的删除请求移除个人载荷，同时**保留审计事实** |
| NFR-007 | 接入韧性 | 邮件渠道中断 → 入站消息被隔离（不丢失）并重放；告警来源中断 → 接入健康度上可见缺口，绝不静默（ADR-0002） |
| NFR-008 | 安全 | SSO（跨方案包：`iam-platform`）+ 按智能体角色/范围划分的 RBAC；涉密工单按 BR-11 受限；密钥置于 KMS；Webhook/告警接入需认证（BR-13） |
| NFR-009 | 可访问性 | 公共门户满足 WCAG 2.1 AA（沿用 personal-blog 方案包所引用的立场）；智能体控制台可纯键盘操作 |
| NFR-010 | 易用性 | L1 分诊的顺路径 ≤ `3 次交互 (A)`（打开 → 分级 → 通过宏指派）；双语界面（en + zh-CN） |
| NFR-011 | 互操作性 | 接入/输出遵循所引用的规范：RFC 5322（邮件）、RFC 9110 语义、JWS/JWT 保证 Webhook 真实性；监控集成通过标准告警载荷映射 |
| NFR-012 | 性能 — 时钟与路由 | SLA 评估节拍在挂钟时间下 `≤ 5 秒 p95 (A)`；规则引擎对每张工单事件的评估 `≤ 100 毫秒 p95 (A)` |
| NFR-013 | 可观测性 | 接入健康度（按渠道）、时钟风险计数、规则引擎错误、CMDB 漂移积压以指标形式暴露并配置告警 `(A)` — 见 observability.md |

## 公式（方案包内具有规范效力）

- **SLA 达成率 %** = 期内关闭的计时项中在目标内关闭的数量 ÷ 期内应到期的计时项
  数量，剔除已取消项；只依据从事件推导出的时钟计算（NFR-002）。
- **MTTR** = 期内关闭事件的 (resolve_ts − first_owner_action_ts) 均值；起点
  的选择在每份报表上都会写明（FR-019），因为 MTTR 历来含义模糊——本方案包
  采取每份报表固定一个定义，而非全局统一一个定义。
- **积压** = 期末按账龄分桶的未关闭工单数。
