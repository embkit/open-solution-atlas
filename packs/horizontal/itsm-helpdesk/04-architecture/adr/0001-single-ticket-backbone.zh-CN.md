# ADR-0001 — 所有接入渠道共用一条工单主干

- 状态：已接受
- 日期：2026-10-09
- 决策人：本方案包维护者

## 背景

门户、邮件、聊天、监控告警与 API 各自都在诱使团队在工单系统之外保留一个
「特殊」队列。每一个这样的队列都会变成影子服务台：看不见的积压、无人负责的
工作、没有 SLA、没有报表。ITSM 平台的价值会在关键工作绕过它的瞬间崩塌。

## 备选方案

1. **渠道原生队列**（告警留在监控、邮件留在收件箱）——短期方便；工作在结构上
   变得不可追踪。
2. **人工桥接**（由人手工录入工单）——只有当人足够勤勉时才保住可见性；在高
   负载下有损。
3. **带渠道适配器的单一主干**——每个渠道都创建或关联工单并记录来源；去重键
   防止工单泛滥。

## 决策

方案 3，由 FR-004（去重 + 来源）、BR-01（主干之外无内容）、BR-13（渠道身份
规则）强制执行。合并保留来源；原始渠道消息作为证据留存。

## 后果

- 正面：一条队列、一个时钟、一份报表；自动化与升级被一致地应用。
- 负面：渠道适配器必须持续维护；嘈杂的来源（例如抖动的监控）需要调优，否则
  它们会向主干倾倒垃圾——这靠去重特征解决，而不是靠豁免。
