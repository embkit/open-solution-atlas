# ADR-0003 — 确定性规则引擎优先；AI 分诊作为扩展点

- 状态：已接受
- 日期：2026-10-09
- 决策人：本方案包维护者

## 背景

待决问题第 3 项：AI/分诊自动化放在哪里？AI 被放错位置会在工单内核里制造
无法解释的路由、有偏的优先级膨胀，以及审计失败（你无法向 CAB 说明一个 RFC
为何被自动分级）。同样地，拒绝一切自动化又会让 L1 团队淹在工单里。

## 备选方案

1. **AI 进入核心循环**（由模型直接决定路由/优先级）——演示惊艳；决策无法
   解释；模型漂移会静默改变运营。
2. **不做任何自动化智能**——只用规则；把明显的收益留在桌上。
3. **确定性引擎 + 声明式扩展点**——核心循环是带版本戳的规则（BR-14、
   FR-017）；AI/ML 组件可以通过同一套扩展契约*提出建议*（分级、建议责任人、
   查重），建议只经由带追溯的规则生效。

## 决策

方案 3。扩展点在 L3 时是 `06-contracts` 中一份有名有姓的契约；建议是规则
引擎的输入，绝不直接改变状态。每一条被应用的建议都能通过 RuleTrace 解释
（BR-14）。

## 后果

- 正面：可解释性与审计得以保留（CTL-07）；AI 可以升级、做 A/B 或下线，而不
  触碰内核。
- 负面：AI 特性总是带一个人工/规则接受步骤，这会拖慢「全自动」的企图——
  这是一次有意的取舍。
