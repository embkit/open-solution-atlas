# 04 · 安全

> 框架：在引用处对齐 ISO/IEC 27001:2022 附录 A；条款级解释标注于
> [`../SOURCES.md`](../SOURCES.md) 第 4 节。

## ITSM 特有的威胁面说明

- **接入伪造**：伪造的邮件或未签名的 Webhook 创建/解决工单（或泄露受限知识
  库）。控制项：渠道认证、邮件头规则 + 白名单、未注册请求人沙箱（BR-13、
  FR-018）、受限知识库绝不在权限范围之外提供（FR-002）。
- **以工单内容为外泄路径**：工单携带个人信息、IP，有时还有用户粘贴的密钥。
  控制项：内容扫描钩子 `(A)`、留存期限、GDPR/PIPL 擦除同时保留审计
  （NFR-006、CTL-08）。
- **经变更走特权路径**：恶意/错误的 RFC 改动生产环境。控制项：风险分级流程、
  CAB 证据、紧急变更实施后复核（BR-09、CTL-04）；智能体不能审批自己的 RFC
  `(A)` 职责分离说明。
- **权限范围泄露**：涉密事件出现在检索/导出中。控制项：在列表/检索/导出路径上
  于服务端强制范围，分级由关联记录继承（BR-11、CTL-03）。

## 控制项摘要

| 领域 | 控制 | 引用 |
|---|---|---|
| 身份认证 | 经跨方案包 `iam-platform` 的 SSO；无本地口令 | NFR-008 |
| 授权 | 按智能体角色 + 目录/组织范围的 RBAC；受限分级 | BR-11、CTL-03 |
| 审计 | 仅追加的工单/自动化历史；规则版本留痕 | BR-07、BR-14、CTL-07 |
| 接入信任 | 经认证的渠道；隔离并保留原始证据 | BR-13、FR-018 |
| 变更职责分离 | 在可行范围内审批人 ≠ 实施人 ≠ 请求人；紧急变更事后复核 | BR-09 `(A)` |
| 数据保护 | 留存窗口、最小化、保留审计事实的擦除 | NFR-006、CTL-08 |
| 中国基线 | 等保2.0 区域控制，标准级别 | CTL-09 |

> `iam-platform` 方案包是身份/RBAC 的参考；本方案包不重复规定它。
