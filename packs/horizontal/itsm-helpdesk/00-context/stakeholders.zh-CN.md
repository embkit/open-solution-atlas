# 00 · 干系人

| 干系人 | 对系统的关注点 | 主要接触面 |
|---|---|---|
| 请求人（员工 / 部门） | 快速、可追踪的解决；清晰的预期 | 门户、邮件接入、通知、CSAT |
| 服务台智能体（L1） | 队列分诊、宏模板、万物归一 | 工单控制台、知识库、指派规则 |
| 解决团队 / L2–L3 工程师 | 不被打断的深度工作；对事件上下文的掌握 | 工单详情、CI 关联、问题流程 |
| 问题经理 | 降低复发率、已知错误记录 | 问题/CIs/已知错误库、关联变更 |
| 变更负责人 / CAB | 受控交付、风险可见 | RFC 流程、风险矩阵、日历 |
| IT 资产 / CMDB 负责人 | 关于 CI 与依赖关系的真相 | CI 注册表、漂移报告、发现数据馈送 |
| 服务负责人 / SLA 经理 | 诚实的 SLA 报表、达到合同级精度的数字 | SLA 时钟、报表、服务目录定义 |
| 安全团队（SOC） | 涉密事件以同样受控的方式进入同一主干 | 告警接入、分级、对齐 27001 的处置 |
| 管理层 / 财务 | 积压、MTTR、服务成本 | 报表、仪表盘 |

## 说明

- **权限约束**（谁可以看到/处理一张工单）按目录项 / 部门 / 角色限定范围——本方案包
  把它当作一等控制项，而不是一个过滤器（CTL-03）。
- 安全事件共用同一条工单主干，但携带分级标记、受限可见性，以及对齐 27001
  A.5.24 的处置流程。
