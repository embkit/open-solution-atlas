# 08-quality · 验收标准

每项 AC 都是映射到需求 ID 的可证伪测试陈述，是本方案包的
**完成定义**。NFR AC（`AC-N*`）以
[非功能需求](../02-requirements/non-functional.md) 中的 `(A)` 指标预算为闸门；
这些数值属于方案包策略，等待以实测值替换。

## 身份主数据与生命周期

- **AC-001** (FR-001): 通过 HRIS 事件创建的身份进入所配置的初始状态，并带有
  来源引用和域；无效的 SM-1 转换（例如，未经对账即执行
  `disabled → active`）→ `422`。(CTL-01)
- **AC-002** (FR-002): 使用相同权威关联键执行两次创建 → 仅生成一个身份，
  第二次创建被拒绝并返回 `409`；在新供给目标上创建第二个账号时，
  应将其附加到现有身份，而不得复制该身份。
- **AC-003** (FR-003): 入职-调岗-离职事件重发 3× 时仅应用一次（幂等键）；
  离职事件与入职事件发生竞态时，结果解析为禁用状态，并保持至管理员完成
  对账。(BR-13)
- **AC-004** (FR-004): 一次同步发现 2 个孤儿账号和 1 个属性冲突时，
  作业报告须报告这两类问题；任何记录都不会被静默覆盖。

## 认证与凭证

- **AC-005** (FR-005): 设置包含用户名或存在于泄露列表中的密码 → 拒绝；
  符合要求的 12 个字符密码仅存储加盐的内存困难型哈希（pepper 在带外保存）
  ——任何存储转储中均不可见明文。(BR-10, CTL-02)
- **AC-006** (FR-006): 注册通行密钥会将认证器绑定到主体，并赋予
  AAL3（认证保障级别 3）能力；TOTP 绑定 AAL2（认证保障级别 2）；
  恢复码为一次性使用且经过哈希。(BR-11)
- **AC-007** (FR-007): AAL1 会话调用要求 AAL2 的资源时 → 返回需要升台阶认证
  （义务中指明因子）；完成更强验证后，同一调用可在新鲜度窗口内继续执行。(SM-2)
- **AC-008** (FR-008): 来自单一来源的突发失败达到限流阈值 → `429`；
  反复失败会锁定该**因子**（该身份仍可通过其他因子使用）；
  对于存在和不存在的主体，失败消息完全相同。(BR-06)

## 单点登录（SSO）与联邦

- **AC-009** (FR-009): 不含 PKCE 的 OIDC 授权请求（公共客户端）→ 拒绝；
  使用 PKCE 时，授权码交换生成身份令牌和访问令牌，且
  `iss/aud/exp/nonce` 验证通过，而重放的 nonce 验证失败。
- **AC-010** (FR-010): 请求超出客户端注册范围的范围 → 拒绝（不得提升权限）；
  机密客户端在令牌端点完成身份验证。(BR-14, BR-07)
- **AC-011** (FR-011): 元数据有效的 SAML 服务提供方（SP）收到一项签名断言，
  其签名和目标均验证通过；断言正文被篡改后，签名验证失败。
- **AC-012** (FR-012): 为应用 A 签发的令牌被提交给应用 B（受众错误）→ 拒绝；
  注册应用时未设置允许的范围 → `422`。(BR-07)
- **AC-013** (FR-013): 联邦登录按 `issuer+subject` 关联；任何字段均不存储
  上游密码；解除关联会终止该主体的所有会话，但审计历史仍会保留。(BR-15, BR-09)
- **AC-014** (FR-014): 密钥轮换期间，旧 `kid` 和新 `kid` 均可通过 JWKS 验证，
  直至退役（重叠期 ≥ 2× 轮换间隔）；退役后，过期密钥被拒绝。(BR-01)
- **AC-015** (FR-021): 注销传播至所有依赖方（RP，前通道/后通道）；
  未收到通知的 RP 在访问令牌 TTL 范围内的下一次验证时失败；
  离职人员的刷新令牌族被吊销——刷新尝试 → 拒绝。(BR-02)

## 授权与策略

- **AC-016** (FR-015): 有效权限 = 直接权限 + 角色 + 组；权限项目录查询显示
  每项权限的来源；移除角色后，在下一次决策中移除相应的派生权限。
- **AC-017** (FR-016): 发布无效策略（属性未定义）→ 验证错误，不创建版本；
  更新版本化策略时，进行中的决策仍记录旧版本。(SM-3, BR-14)
- **AC-018** (FR-017): 策略决策点（PDP）的一项允许结果加上一项拒绝结果 →
  返回**拒绝**（拒绝优先），并附有理由；策略执行点（PEP）尝试执行被拒绝的
  操作 → 拒绝并审计该尝试；PDP 不可达 → 需要允许的操作**失败关闭**。(BR-14, NFR-008)
- **AC-019** (FR-018): 同时授予相互排斥的角色 → 阻断；获得独立缓解措施审批
  （审批者既非请求者，也非角色持有者）后继续执行，并记录到期时间；
  通过组继承产生的间接冲突以相同方式检测。(BR-03)

## 特权访问与治理

- **AC-020** (FR-019): 已批准的访问请求创建限时指派，该指派立即在 PDP 决策中
  可见；由请求者本人审批（特权权限项）→ 拒绝。(BR-04, BR-08)
- **AC-021** (FR-020): 即时授权（JIT）提权在窗口结束时自动吊销，无需操作员
  干预；应急访问立即激活，并要求在 ≤ 24 h 内生成评审记录；逾期评审项在 n2
  之后默认为**吊销**。(SM-4, BR-05, BR-04)
- **AC-022** (FR-021): 强制吊销在访问令牌 TTL 限定的时间内使所有 RP 的会话
  和令牌族失效；基于内省的 PEP 会立即感知到该状态。(BR-02)

## 审计、租户与同意

- **AC-023** (FR-022): 每次认证、决策或管理变更都在同一事务中追加一条审计
  记录；通过任何 API 尝试执行 UPDATE/DELETE → 拒绝；改动任一已存储字节
  都会导致链验证失败。(NFR-009, CTL-05)
- **AC-024** (FR-023): 使用域 A 的令牌/查询访问域 B 的数据 → 在服务端被拒绝
  （而非交由调用方筛选器过滤）；轮换客户端密钥后，旧密钥在下一次使用时失效。(NFR-013, BR-07)
- **AC-025** (FR-024): 撤回同意会追加一条新记录（原记录保持不变），并终止
  该处理目的在传播路径上的处理；擦除钩子删除个人数据，同时保留审计事实。(BR-12, CTL-07)

## NFR / 性能闸门（`(A)` 指标预算）

- **AC-N01** (NFR-001/002): 在参考峰值负载配置下，交互式登录 p95 ≤ 500 ms、
  令牌签发 p95 ≤ 200 ms、本地 JWKS 验证 p95 ≤ 5 ms；断言实测 p95。
- **AC-N02** (NFR-003): 在 200k 个并发会话形态的负载下，可持续处理
  ≥ 500 次认证事务/秒，并可承受持续 5 min 的 ≥ 1,000 次/秒突发负载。
- **AC-N03** (NFR-004): PDP 决策在单资源场景下 p95 ≤ 20 ms；批量处理
  ≤ 100 个资源时 p95 ≤ 100 ms。
- **AC-N04** (NFR-006/007): 对身份存储进行故障注入：演练中 RPO ≤ 1 min /
  RTO ≤ 15 min；不得要求重新注册抗钓鱼认证器；JWKS 读取路径保持可用。
- **AC-N05** (NFR-009/010): 审计存储以 ≥ 2× 峰值吞吐量接收数据且无丢失；
  最近窗口查询 p95 ≤ 2 s；对 10⁶ 条记录进行链验证时，可检测出人为植入的篡改。
- **AC-N06** (NFR-011): 乱序投递和重发的供给事件均收敛到最新权威状态
  （性质：最终状态与投递顺序无关）。
- **AC-N07** (NFR-012/013): 签名密钥轮换不得造成停机（旧 `kid` 与新 `kid`
  有重叠）；代码仓库/配置扫描未发现任何机密材料；跨域探测矩阵全部被拒绝。
