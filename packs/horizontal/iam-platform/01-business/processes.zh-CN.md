# 01-business / 核心业务流程

端到端流程，包括参与者、触发条件、前置条件、主流程、异常路径和结果。ID `P-01..P-08`。

---

## P-01 入职/调岗/离职（JML）供给

- **触发条件**：HRIS 发出入职、调岗或离职事件（或由管理员手动创建身份）。
- **参与者**：HR 系统、IAM 供给引擎、供给连接器（SCIM/目录）、应用负责人。
- **前置条件**：已配置权威源映射；目标应用已连接；已定义组/角色映射规则（BR-13）。

1. 使用幂等键接收 HRIS 事件；通过权威关联键创建或匹配身份（01.3）。
2. 执行授权/治理检查：根据职责分离规则评估拟授予的默认角色/组（BR-03）；标记冲突，并予以阻断或路由处理。
3. 供给引擎根据映射规则计算目标操作（创建账号、加入组、分配角色）（BR-13）。
4. 通过 SCIM 2.0 / 目录协议将操作派发至目标；采用幂等的创建/更新语义；失败时退避重试。
5. 账号达到 `active` 状态；权限项以授予记录形式保存（05.7）。
6. 对供给结果及任何异常进行审计（08.3）。

- **异常**：缺少必需属性 → 隔离队列；目标不可用 → 重试后告警；职责分离冲突 → 阻断并由审批人采取缓解措施。
- **结果**：身份在各目标中处于有效状态；每项授予都可追溯至驱动该流程的 HR 事件和映射规则。

## P-02 离职即时吊销

- **触发条件**：离职/离职管理事件；或 SOC 因安全原因强制停用。
- **参与者**：HRIS、IAM 引擎、连接器、SOC、服务台。
- **前置条件**：身份已知；已为每个目标配置启用/禁用策略。

1. 收到离职事件；将身份标记为 `leaver` 并安排执行**即时吊销**（BR-13 解供给优先级）。
2. 全局吊销该主体的所有活动会话和刷新令牌（07.5、BR-02）——即使令牌尚未过期，访问也会终止。
3. 以幂等方式向所有目标派发解供给操作（禁用账号、移除组/角色）。
4. 吊销限时特权授予和长期有效的特权授予（P-07/BR-05）。
5. SOC/审计人员可确认不存在残留访问权限；发现残留时触发告警。
6. 对完成情况及残留发现进行审计（08.3）。

- **异常**：目标无法访问 → 账号在中心保持禁用，但在确认前标记为*残留风险*；通过应急访问保留账号（例如邮箱）必须由策略明确驱动，而非偶然发生。
- **结果**：在解供给时效内完成访问权限吊销（industry-brief §5）；不留下处于活动状态的孤儿权限项。

## P-03 单点登录（SSO）登录（OIDC）

- **触发条件**：未经身份验证的主体访问受保护应用（RP）。
- **参与者**：主体、身份提供方（IdP）、依赖方（RP）。
- **前置条件**：RP 已注册重定向 URI 和允许的 scope；主体拥有有效身份。

1. RP 使用 response_type=code、PKCE、state/nonce 发起 OIDC 授权请求。
2. 如果不存在有效会话，IdP 将对主体进行身份验证（P-04）。
3. IdP 签发**授权码**；RP 在令牌端点使用该授权码（客户端认证 + code verifier）换取身份令牌和访问令牌（在适用时还换取刷新令牌）。
4. 访问令牌为**短期有效**；刷新令牌在使用时轮换（BR-01）。
5. RP 建立本地会话；策略执行点（PEP）缓存经验证的令牌（而非凭证）。
6. 记录身份验证事件（成功）（08.1）。

- **异常**：授权码无效/过期或 PKCE 不匹配 → 拒绝并记录；重定向 URI 不可信 → 拒绝；scope 权限提升 → 拒绝（BR-14）。
- **结果**：主体只需登录一次；RP 持有可验证的短期令牌；不会向 RP 披露密码。

## P-04 多因素认证（MFA）/风险自适应升台阶认证

- **触发条件**：主认证成功；或高风险操作/高保障级别资源要求更高的认证保障级别（AAL）（BR-11）。
- **参与者**：主体、身份提供方、风险引擎、通知渠道。
- **前置条件**：主体已注册符合所需认证保障级别（AAL）的认证器；已按应用/操作定义升台阶策略。

1. 根据上下文评估风险（设备、位置、网络、行为、资源敏感度）。
2. 确定所需认证保障级别；若当前保障程度不足，IdP 提示用户提供额外或更强的认证因子（TOTP、推送或 WebAuthn）。
3. 验证成功后，在有限的有效期窗口内将提升后的保障级别声明附加到会话/令牌。
4. 失败尝试消耗限流额度，并可能锁定该认证因子（BR-06）。
5. 记录结果（使用的因子、保障级别、风险）（08.1）。

- **异常**：认证器不可用 → 按身份核验策略（03.5/BR-10）采用恢复路径；反复失败 → 锁定。
- **结果**：仅在风险所要求的保障级别上授予访问权限；升台阶认证与风险相称，而非一律适用。

## P-05 访问申请 → 审批 → 授予

- **触发条件**：主体（或代理人）申请访问某项资源/角色。
- **参与者**：申请人、审批人/资源负责人、IAM 引擎、策略执行点（PEP）。
- **前置条件**：已定义申请目录；已配置审批路由；已加载职责分离规则。

1. 申请人选择目录项并提供理由；计算所申请的有效期和风险。
2. 执行职责分离检查（BR-03）；冲突会阻断申请，或要求由第二方批准缓解措施。
3. 审批路由依据以下因素评估（资源负责人、成本中心/组织、风险层级）：预先批准的目录项无需审批。
4. 批准后创建授予记录（按要求限时）；更新供给目标（BR-13）。
5. 有效权限在策略决策点（PDP）下一次决策时得到反映（05.4/05.5）；缓存按可预测方式失效（BR-14）。
6. 记录申请、审批和授予（08.3）。

- **异常**：审批人不可用 → 启动升级计时器；申请过期 → 自动拒绝；并发申请冲突 → 授予时重新检查职责分离。
- **结果**：以最小权限、限时、可审计的方式完成授予，并明确所有者和理由。

## P-06 定期访问评审/认证

- **触发条件**：评审活动计划（定期执行）或触发事件（角色变更、职责分离发现、安全事件）。
- **参与者**：评审人员/认证人员、IAM 管理员、审计人员。
- **前置条件**：已定义评审活动范围（应用/角色/组织）；已设置评审人员指派规则；权限项快照可用。

1. 为指定范围创建评审活动；对条目（主体 ↔ 权限项）创建快照并指派给评审人员（BR-04）。
2. 评审人员逐项认证（保留）或吊销；显示风险/使用情况上下文以支持决策。
3. 逾期条目按照策略升级/自动处理规则执行（BR-04）。
4. 经批准的吊销作为解供给/移除授予执行（采用 P-02 机制）；记录决策和结果（08.5）。
5. 向合规部门报告评审活动完成率和整改情况。

- **异常**：评审人员不可用/回避 → 重新指派；所有权不明确 → 路由至应用负责人；存在争议 → 升级评审。
- **结果**：权限项经重新认证；移除不必要/已过期的访问权限；生成审计证据。

## P-07 特权即时授权（JIT）提权

- **触发条件**：特权操作员为某项任务申请提权（通常是生产/管理员任务）。
- **参与者**：操作员、审批人、特权访问管理（PAM）/提权服务、目标系统、SOC。
- **前置条件**：操作员持有非特权的基线身份；目标角色符合即时授权资格；已加载职责分离规则。

1. 操作员申请特定特权角色，并提供业务原因和所需时间窗口；执行职责分离检查（BR-03）。
2. 根据政策获得审批（最敏感的角色可能需要双重审批）。
3. 在**有限时间窗口**内授予提权；在适用托管访问的情况下，即时签发凭证/机密（不长期存储）。
4. 提权期间的所有操作均与会话上下文一并捕获；该授予对 SOC 可见（08.1/08.2）。
5. 窗口到期或显式吊销时，访问权限会被**自动吊销**（BR-05）；同时移除任何残留的长期权限项。
6. 应急/应急访问路径绕过审批，但会触发强制事后评审（06.7）。

- **异常**：事件中审批人不可用 → 记录在案的应急访问，并进行事后审批；失控会话 → SOC 强制终止（07.6）。
- **结果**：不存在长期有效的管理员权限；特权访问稀缺、限时、经过审批且完全可审计。

## P-08 建立联邦信任与 SCIM 供给

- **触发条件**：接入新的外部身份源（联邦身份提供方），或接入必须接受供给的下游应用。
- **参与者**：IAM 管理员、合作伙伴/身份提供方管理员、应用负责人。
- **前置条件**：已通过带外方式商定信任关系或凭证材料；已交换实体标识符和端点。

1. **联邦路径**：交换并验证元数据/JWKS 或 SAML 元数据；配置属性映射（主体关联键、组、声明）；将信任状态设为 `test`，验证后设为 `active`。
2. **联邦登录**：主体在上游身份提供方完成认证；IAM 关联会存储联邦主体标识符，且**绝不存储上游密码**（BR-15）。
3. **供给路径**：配置 SCIM 连接（基础 URL、凭证、属性映射）；执行带过滤条件的测试同步，以验证映射和幂等性（BR-13）。
4. 启用完整同步，然后启用增量同步；配置孤儿账号处理和错误报告；监控连接的偏差。
5. 对信任/连接生命周期及其变更进行审计（08.3）。

- **异常**：证书/元数据过期 → 连接降级为 `failed` 并触发告警；映射错误 → 条目级隔离，而非静默丢弃。
- **结果**：身份通过基于标准的信任在域之间流动；已供给的目标与权威源保持一致。
