# 00-context / 监管与标准环境

> 身份与访问管理（IAM）所受的约束并非主要来自某一部成文法，而是来自密集的**开放标准**，以及横跨各领域的安全/隐私框架。标准以引用方式采用；司法辖区特定强制要求（密码学、数据驻留）通过变体引入。本方案包绝不嵌入成文法原文。

## 1. 协议与交换标准（全球）

| 标准 | 范围 | 对本方案包的影响 |
|---|---|---|
| **OpenID Connect Core 1.0** | 基于 OAuth 2.0 的认证层；身份令牌、UserInfo、发现、会话管理、前端/后端通道注销 | 主要单点登录/认证协议；令牌与会话模型；FR-010..FR-013 |
| **OAuth 2.0** (RFC 6749) + Bearer (RFC 6750), PKCE (RFC 7636), Token Revocation (RFC 7009), Introspection (RFC 7662) | 面向 API 的委托授权 | 访问令牌/刷新令牌模型、客户端类型、令牌吊销；BR-01, FR-014 |
| **SAML 2.0** | 身份提供方（IdP）与服务提供方（SP）之间基于 XML 的联邦/单点登录 | 面向现有服务提供方（SP）的企业互操作；元数据与断言签名；FR-013 |
| **SCIM 2.0** (RFC 7642/7643/7644) | 用于用户/群组供给的 REST 模式与协议 | 向下游应用进行生命周期供给；FR-006, FR-007, BR-13 |
| **WebAuthn Level 2 / FIDO2 / CTAP2** | 公钥认证器、通行密钥、认证器证明 | 抗钓鱼的无密码认证；FR-009, BR-11 |
| **XACML 3.0** | 策略语言与策略决策点（PDP）/策略执行点（PEP）/策略信息点（PIP）/策略管理点（PAP）架构 | 基于属性的访问控制（ABAC）策略评估与决策审计的参考模型；ADR-0003 |
| **OIDC Session / Front-Channel Logout 1.0** | 跨依赖方（RP）的注销传播 | 会话终止与单点登出；BR-02 |
| **RFC 7517 (JWKS) / RFC 7515 (JWS) / RFC 8725** | 密钥分发与签名令牌；JWT BCP | 令牌签名、JWKS 轮换、令牌验证规则；BR-01 |

## 2. 身份保障与密码学指南

| 框架 | 范围 | 对本方案包的影响 |
|---|---|---|
| **NIST SP 800-63-4**（2025；分卷 800-63A-4 / 800-63B-4 / 800-63C-4） | 身份核验（IAL）、认证保障级别（AAL）、联邦保障级别（FAL） | 由 AAL 驱动的认证器选择、升台阶认证、凭证存储/速率限制规则；BR-10, BR-11, FR-008/FR-009。**Rev 4 取代 SP 800-63-3，后者于 2025-08-01 撤销。** |
| **NIST SP 800-63B-4**（认证器与验证器） | 密码/认证器策略、节流、查询保密性 | 不设口令组合/有效期复杂化要求；泄露名单核查；锁定/节流阈值；BR-06/BR-10 |
| **NIST SP 800-207**（零信任） | 默认拒绝、逐请求决策 | 策略执行点（PEP）/策略决策点（PDP）逐请求模型；不隐含网络信任；ADR-0001/0003 |
| **FIPS 140-2/3**（在有强制要求时） | 加密模块验证 | 密钥/HSM 配置基线（变体）；核心方案规定要求，而非具体模块 |

## 4. 隐私与同意（全球/欧盟）

| 法规 | 范围 | 对本方案包的影响 |
|---|---|---|
| **GDPR (EU 2016/679)** | 个人数据、合法依据、数据主体权利、同意 | 同意记录、数据主体访问请求（DSAR）支持、数据最小化、保留/删除；CTL-05, BR-12 |
| **CCPA/CPRA 及类似法规（参考）** | 消费者隐私权利 | 客户身份管理（CIAM）的同意/偏好处理（变体） |

> 核心方案规定控制义务（例如，“同意被记录且可撤回”，“身份数据经过最小化处理并按策略保留”）。具体保留期、合法依据和司法辖区叠加层属于变体层。

## 5. 审计预期（必须存在哪些证据）

1. **认证事件**：每次登录尝试的结果（成功/失败、使用的因子、风险信号、来源、设备）均须记录。
2. **授权决策**：每次访问决策均须记录
   *主体、操作、资源、上下文、策略/依据、结果*（ADR-0003）。
3. **管理操作**：身份/策略/角色/应用变更均须记录
   操作者、变更前/后状态和时间戳（谁更改了什么）。
4. **特权与治理**：提权授予/使用、职责分离决策、访问评审/认证结果、同意记录——均须保留。
5. **防篡改与保留期**：审计记录仅可追加、具有防篡改性，并按策略保留（ISO 27001 / 等保2.0 预期）。
6. **可追溯性**：任何访问权限授予均可重建其来源
   （请求 → 审批 → 指派 → 决策）。
