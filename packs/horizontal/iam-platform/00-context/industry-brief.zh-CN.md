# 00-context / 行业简报 — 企业身份与访问管理（IAM）

## 1. IAM 在价值链中的定位

每项数字能力都始于一个问题：**此人是谁，他们可以做什么？** **身份与访问管理（IAM）**平台是一个横向系统，以集中、统一且可审计的方式，为组织中的所有其他应用回答这一问题。

IAM 位于**身份权威来源**（人力资源系统、客户注册、合作伙伴入驻、目录）与**身份信息使用方**（应用程序、API、基础设施）之间。它不拥有业务数据；它拥有主体与其可访问资源之间的*关系*。

```
人力资源系统（HRIS）/ 注册 / 合作伙伴入驻        应用程序与资源
-------------------------------                            ------------------------
员工与客户记录                     IAM 平台                 内部应用 / SaaS
是人员存在与否的权威依据  ->        身份 + 凭证             API / 微服务
                                  + 会话/令牌   ->          基础设施 / 数据库
                                  + 授权决策                本地部署 / 云端
```

组织中通常有三条业务线共用一个平台，但不得共享同一个信任域：

| 体系 | 主体 | 凭证所有者 | 典型目标 |
|---|---|---|---|
| **员工身份管理** | 员工、承包商 | 雇主 | 最小权限、入职—调岗—离职生命周期、合规性 |
| **客户身份管理（CIAM）** | 客户、公民 | 客户 | 无摩擦注册、同意、规模化 |
| **特权访问管理（PAM）** | 管理员、服务账号 | 组织（保管库） | 即时授权提权、职责分离、会话控制 |

> ⚠️ ASSUMPTION: 本方案包将三条业务线建模在同一逻辑平台上，并使用相互隔离的信任域（利益相关方 §2、ADR-0004）。部署时可以将它们作为独立实例运行；保持不变的是模型本身。

## 2. 部署原型

同一核心模型可服务于多种运营形态；它们的差异在于凭证权威和策略的所在位置，而不在于基本模型。

| 原型 | 特征 |
|---|---|
| **本地部署 / 自托管** | 身份提供方、目录和策略在企业数据中心运行；具备较强的数据驻留控制能力；采用经典 AD/LDAP + SAML 联邦 |
| **云身份提供方 / IDaaS** | 托管式身份提供方；OIDC 优先；按租户划分的域；通过 SCIM 接入 SaaS 应用目录 |
| **混合部署 / 联邦** | 本地目录是权威来源，云身份提供方承接联邦连接；逐个应用分阶段迁移 |
| **多域企业** | 包含多个组织/业务单元，或具有并购历史的控股集团；域到域的联邦，以及面向外部身份的共享权威来源 |

## 3. 核心身份流程（L1 视图）

1. **供给（JML）**：来自 HRIS 的入职—调岗—离职事件 → 账号、组/权限项授予、解供给——主要由机器驱动（目标系统使用 SCIM 2.0）。
2. **认证**：主体向身份提供方证明其凭证/认证器（密码 + 多因素认证（MFA），或 WebAuthn/通行密钥）；身份提供方签发会话和令牌。
3. **单点登录与联邦**：应用程序（依赖方（RP）/服务提供方（SP））通过 OIDC 或 SAML 将登录委托给身份提供方；每个应用的信任均通过元数据建立一次。
4. **授权**：资源服务（策略执行点，PEP）向策略决策点（PDP）询问主体是否可以执行某项操作；该决策会被执行并接受审计。
5. **治理**：访问请求、审批、定期评审、职责分离检查、同意的采集与撤回——围绕权限项的人工控制闭环。

## 4. 为何 IAM 是价值最高的攻击面

- **中心性**：攻破身份提供方就会让人掌握所有联邦应用的密钥（形成“掌握王国钥匙”般的波及范围）。其他所有系统都依赖身份提供方的可用性。
- **凭证窃取**：密码复用、网络钓鱼和令牌窃取（会话/刷新令牌重放）是主要入侵向量；多因素认证和抗钓鱼 WebAuthn 可降低但不能消除这些风险。
- **授权蔓延**：当授权逻辑嵌入各个应用时，权限项会逐渐漂移，离职后仍保留无人归属的访问权限，并且无人能回答“谁可以做什么？”——这是大多数审计发现的根本原因。
- **生命周期缺口**：未及时解供给的离职人员，或临时继承了范围过宽的组，都是持续存在的风险。
- **内部人员与特权风险**：常驻管理员权限；缺少即时授权（JIT）提权和职责分离控制。

塑造设计的关键张力（每项均由一项 ADR 解决）：

- 集中管控与联邦系统自主性之间的取舍（ADR-0001）。
- 开放标准与专有方案/企业互操作性之间的取舍（ADR-0002）。
- 表达力强的授权与决策延迟及可审计性之间的取舍（ADR-0003）。
- 面向所有人的单一平台与对差异极大的信任域进行隔离之间的取舍（ADR-0004）。

## 5. 性能与质量指标的定义

| 指标 | 典型目标区间 | 含义 |
|---|---|---|
| 认证成功率（合法请求） | ≥ 99.5% | 有效主体成功登录次数 / 尝试次数 |
| 认证 p95 延迟 | ≤ 500 ms | 交互式登录/令牌交换，度量无歧义 |
| 令牌内省/JWKS 查询 | p95 ≤ 50 ms | 每请求的验证开销 |
| 多因素认证（MFA）注册覆盖率（员工） | ≥ 95% | 已注册的第二因子数 / 活跃用户数 |
| 解供给延迟（离职） | ≤ 15 min | HR 事件 → 所有位置的访问权限均被吊销 |
| 访问评审完成率 | 评审活动/周期的 100% | 治理控制合规性 |
| 孤儿账号/孤儿风险账号 | → 0 | 没有权威所有者的账号 |

> 确切的阈值及其计算公式在 `01-business/business-rules.md` 中固定（BR 层级）；本章仅界定意图。

## 6. 锚定模型的公共标准

- **OIDC（OpenID Connect Core 1.0）**——主要的认证/联邦协议；身份令牌、UserInfo、发现、会话管理。
- **OAuth 2.0**（RFC 6749/6750/7636/7009/7662）——面向 API 访问的委托授权；持有者令牌、PKCE、吊销、内省。
- **SAML 2.0**——与现有服务提供方（SP）实现企业联邦/单点登录互操作。
- **SCIM 2.0**（RFC 7642/7643/7644）——用于身份生命周期供给。
- **WebAuthn / FIDO2**——抗钓鱼的无密码认证器。
- **XACML 3.0**——用于基于属性的决策的策略语言/架构。
- **NIST SP 800-63-4**（2025；取代已撤回的 SP 800-63-3）——认证保障级别（AAL）、身份/联邦保障级别（IAL/FAL）以及凭证管理规则。
