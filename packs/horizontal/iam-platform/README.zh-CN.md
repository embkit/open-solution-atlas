## 本方案包涵盖的内容

组织的核心身份平面：员工/合作伙伴/客户身份生命周期、内部应用和 SaaS 应用间的单点登录、强认证（多因素认证/无密码）、授权（基于角色的访问控制 + 基于属性的访问控制策略引擎）、特权访问治理、目录/HRIS 同步、审计和身份联邦。所有其他需要认证的方案包都接入本方案包。本方案包建立在严格分离认证、授权决策和生命周期供给的基础之上（ADR-0001）。

## 范围之内

- 身份生命周期：入职-调岗-离职自动化、账号供给/解供给（SCIM 2.0）、目录（LDAP/AD 风格）集成
- SSO：OIDC（主要）+ SAML 2.0 联邦、SAML 服务提供方（SP）/OIDC 依赖方（RP）目录、会话治理和单点登出
- 认证：密码策略（SP 800-63B-4）、多因素认证（MFA，TOTP/推送）、无密码/WebAuthn/FIDO2、风险自适应认证与升台阶认证（按 BR-11 执行认证保障级别（AAL））
- 授权：组织/域/角色/权限模型（以基于角色的访问控制为基线），并增加基于属性的访问控制策略引擎（依据 XACML 设置策略决策点（PDP）/策略执行点（PEP））；每项决策均可审计
- 特权访问：即时授权（JIT）提权，并设置时限/自动吊销、职责分离（SoD）规则、应急访问及事后复核
- 治理：访问请求/审批、访问评审/认证、同意记录、完整的认证与决策审计轨迹
- 多租户/域隔离；将身份作为一项平台能力

## 范围之外（明确排除）

- 员工 HRIS 主数据（作为权威来源使用，但不在本方案包范围内）
- 应用特定业务角色设计（本方案包提供模型；各领域方案包定义自己的角色目录）
- 终端/设备 MDM 和网络零信任执行代理（仅作引用；安全态势作为信号使用）
- PAM 产品功能（会话录制、目标凭据保管、特权威胁分析）——JIT/SoD/限时 *模式*属于范围内
- 去中心化/区块链身份实验

## 重要性

IAM 是整个规范库中复用率最高的横向能力，也是价值最高的攻击面；攻破身份提供方（IdP）就等同于“掌握了王国钥匙”，而身份/访问证据会出现在每一次合规审计中。正确构建本方案包，可以提升规范库中每个需要认证的方案包的质量。

## 待解决的问题（延续至 L4 / 采用阶段）

1. **客户身份管理（CIAM）深度**：客户身份（自助注册、同意、规模、隐私监管制度）应在核心章节中全面细化，还是推迟到 `ciam-customer` 变体？当前取舍：核心定义域隔离 + 同意 + 自助注册挂钩点；CIAM 规模的具体内容作为变体（参见 ADR-0004）。
2. **策略引擎深度**：是制定 XACML/Rego 风格的求值引擎规范，还是仅达到模式层？当前取舍：核心固定模式层策略决策点决策和决策审计契约；具体策略语言属于 L3/变体（ADR-0003）。
3. **PAM 边界**：本方案包在多大程度上进入 PAM 产品领域（会话录制、目标凭据保管）？当前取舍：核心包含模式（JIT、SoD、限时、审计）；产品功能作为 `pam-privileged` 变体。
4. 与现有 IdP 的迁移/共存（双运行）目前是一项假设，但尚未明确——可作为 L3 集成规范候选项。
5. **采用时需要解决的假设**：本方案包中的策略数量和性能目标是方案包提案，而非有来源依据的事实。所有这些内容均列于 [`SOURCES.md` §4](./SOURCES.md)，并在使用位置标记为 `⚠️ ASSUMPTION`（`non-functional.md` 中的 `(A)` 标记；`business-rules.md` 引言）。应根据每次部署重新推导。
6. **验证状态**：`source-checked`（截至 2026-10-08）——引用内容已对照标准核实（本轮校验纠正了一处已撤回的 NIST SP 800-63-3 引用和一个 ISO/IEC 27002 条款编号）。要达到 `practitioner-reviewed`，必须由指定的领域从业人员审阅范围；要达到 `field-proven`，则必须具备参考实现/部署。
