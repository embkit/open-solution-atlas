# 02-requirements / 功能需求

EARS 句式：`当 <触发条件> 系统应当 <响应>`。ID 为 `FR-001..FR-024`。各项需求在行内追溯至相应能力和规则。

## 身份主数据与生命周期（能力 01–02）

- **FR-001** **当** 创建主体（员工、客户、合作伙伴或服务身份）时，**系统应当** 存储该主体，并记录其生命周期状态 (`invited/provisioned/active/suspended/disabled/leaver`)、权威来源引用和域范围，**并且应当** 强制执行有效的状态转换 (SM-1). (01.1/01.2)
- **FR-002** **当** 创建或匹配身份时，**系统应当** 对权威关联键强制执行唯一性约束，并维护一个或多个映射到该身份的账号（每个供给目标可对应多个账号），**并且应当** 避免重复创建该身份记录. (01.3/01.4)
- **FR-003** **当** HRIS 发出入职/调岗/离职事件时，**系统应当** 以幂等方式摄取该事件，应用已配置的映射规则，**并且应当** 按 BR-13 应用解供给优先顺序. (01.6/02.1, P-01/P-02)
- **FR-004** **当** 目录（LDAP/AD 风格）或 HRIS 同步运行时，**系统应当** 执行增量差异同步以及计划的全量对账，按映射转换属性，**并且应当** 报告孤儿账号和冲突，且不得静默覆盖. (02.2–02.6)

## 认证与凭证（能力 03）

- **FR-005** **当** 主体登记密码凭证时，**系统应当** 强制执行 BR-10（最小长度、泄露列表检查、不强制字符组合/轮换），**并且应当** 仅存储内存困难型加盐哈希（使用 pepper 密钥）. (03.1/03.2)
- **FR-006** **当** 主体登记第二因子时，**系统应当** 支持基于时间的一次性口令（TOTP）、带恢复码的推送/口令，以及 WebAuthn/FIDO2 认证器，**并且应当** 将每个认证器与主体及其认证保障级别绑定（AAL 依据 BR-11）. (03.3/03.4)
- **FR-007** **当** 主体进行认证时，**系统应当** 评估风险和所需认证保障级别（AAL），**并且应当** 在当前会话的认证保障级别不足以满足所请求资源或操作的要求时，要求采用更强的认证因子进行升台阶认证. (03.6, BR-11, P-04)
- **FR-008** **当** 尝试进行认证时，**系统应当** 按主体/来源/设备实施节流，在多次失败后锁定该认证因子，以恒定时间进行验证，并且绝不泄露主体是否存在 (BR-06). (03.7)

## 单点登录与联邦（能力 04）

- **FR-009** **当** 依赖方发起 OpenID Connect（OIDC）授权请求时，**系统应当** 认证主体并返回授权码（包含 PKCE、state 和 nonce），**并且应当** 在令牌端点签发身份令牌和短期访问令牌 (07.2, BR-01). (04.1/04.2, P-03)
- **FR-010** **当** OAuth 客户端请求令牌时，**系统应当** 强制执行客户端认证、允许的授权类型/范围约束，并对公共客户端强制执行 PKCE，**并且应当** 拒绝范围或受众提升 (BR-14). (04.2)
- **FR-011** **当** SAML 服务提供方接入联邦时，**系统应当** 充当 SAML 2.0 身份提供方：验证元数据、对断言进行签名，并遵循已配置的绑定和属性语句. (04.3)
- **FR-012** **当** 应用注册为 RP/SP 时，**系统应当** 记录其客户端/实体标识符、重定向/认证端点、允许的范围和令牌受众，**并且应当** 将所有已签发令牌的受众限定为该应用 (BR-07). (04.4)
- **FR-013** **当** 联邦主体进行认证时，**系统应当** 依据上游标识符关联身份、映射属性/声明，**并且应当** 不存储上游密码 (BR-15). (04.5/04.6, P-08)
- **FR-014** **当** 签发或验证令牌时，**系统应当** 使用轮换密钥进行签名，发布在 `kid` 上有重叠的 JWKS/元数据，**并且应当** 向资源服务提供验证/内省契约（签发方、受众、到期时间、吊销）. (04.7/07.3, BR-01)

## 授权与策略（能力 05）

- **FR-015** **当** 管理员定义角色和权限时，**系统应当** 维护按应用以及组织/域限定范围的角色/权限目录，**并且应当** 根据直接授予、角色派生授予和组派生授予计算有效权限. (05.1/05.2/05.7)
- **FR-016** **当** 策略作者发布基于属性的访问控制（ABAC）策略时，**系统应当** 对其进行验证和版本管理，**并且应当** 由策略决策点（PDP）评估将主体/资源/操作/上下文属性组合起来的请求，采用拒绝优先规则 (BR-14, SM-3). (05.3/05.4)
- **FR-017** **当** 资源服务（策略执行点，PEP）请求作出决策时，**系统应当** 返回允许/拒绝结果、义务和机器可读的理由，**并且应当** 禁止 PEP 覆盖拒绝结果 (05.5, ADR-0001/0003). (05.4/05.5)
- **FR-018** **当** 权限项授予或角色授予将违反职责分离规则时，**系统应当** 阻断该授予，除非已记录一项独立的缓解措施审批 (BR-03). (05.8)

## 特权访问与治理（能力 06）

- **FR-019** **当** 主体请求访问权限时，**系统应当** 执行职责分离检查，根据策略路由审批，并在批准后创建一项（可选择设置时限的）授予关系，**并且应当** 使其立即反映在策略决策点的决策中. (06.1–06.3, P-05)
- **FR-020** **当** 特权操作员请求提权，或访问评审活动到期时，**系统应当** 在限定时间窗口内授予即时授权提权，并在到期时自动吊销 (BR-05)，**并且应当** 依据 BR-04 运行访问评审活动，包括指派、升级和逾期处理. (06.4/06.5, P-06/P-07)
- **FR-021** **当** 主体登出、被终止或遭到强制吊销时，**系统应当** 向依赖方传播登出/终止事件（前端通道/后端通道或 SAML 单点登出），**并且应当** 全局吊销会话和刷新令牌族 (BR-02). (07.4/07.5)

## 审计、多租户与同意（能力 07–10）

- **FR-022** **当** 发生任何认证、授权决策或管理变更时，**系统应当** 追加一条不可变、防篡改的审计记录，捕获主体/操作/资源/上下文/依据/结果（或执行者/变更前后状态），使其可按范围查询和导出 (BR-09). (08.1–08.5)
- **FR-023** **当** 域/租户或应用接入时，**系统应当** 隔离其数据、凭证策略和令牌受众，**并且应当** 对客户端凭证/机密实施轮换管理 (BR-07). (09.1–09.4)
- **FR-024** **当** 同意被授予或撤回时，**系统应当** 记录不可变的同意元组（或撤回记录）并传播其效力，**并且应当** 将身份数据最小化，仅用于已获同意或合法的目的，并支持访问/删除钩子 (BR-12). (10.1–10.5)
