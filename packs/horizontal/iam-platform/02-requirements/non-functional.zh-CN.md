# 02-requirements / 非功能需求

可度量的目标。ID `NFR-001..NFR-014`。除非另有说明，规模区间假设为中型至大型企业（员工身份数 ≤ ~100k、每个平台客户身份数 ≤ ~5M、并发会话数 ≤ ~200k、令牌/PDP 边缘层的持续峰值 ≤ ~500 RPS）；面向互联网规模的 CIAM 在变体中另行扩展。

> ⚠️ ASSUMPTION (A) — **本文件中的每个数值目标都是工程预算，而非实测结果。** 上述规模区间和所有以 `(A)` 标记的数值均为方案包建议，没有外部基准或参考硬件支撑；必须针对每项部署重新推导。这些数值列于 [`../SOURCES.md` 第 4 节](../SOURCES.md)，且**不是**有来源支撑的事实。

## 性能与规模

- **NFR-001（认证）** 一次交互式登录（提交凭证 → 会话建立）在排除用户手动输入多因素认证信息所耗时间后，系统应当能够在峰值负载下以 p95 ≤ 500 ms `(A)` 和 p99 ≤ 1 s `(A)` 完成。
- **NFR-002（令牌与验证）** 访问令牌签发应当满足 p95 ≤ 200 ms `(A)`；资源服务使用本地 JWKS 进行验证应当满足 p95 ≤ 5 ms `(A)`，远程内省应当满足 p95 ≤ 50 ms `(A)`（决策适用 NFR-004）。
- **NFR-003（会话规模）** 系统应当支持 ≥ 200k `(A)` 个并发活跃会话，并在峰值时支持 ≥ 500 `(A)` 个认证事务/秒，且能够以 ≥ 1,000/秒 `(A)` 的速率突发处理 5 min。
- **NFR-004（授权）** 对于单资源决策，PDP `POST /decision` 应当达到 p95 ≤ 20 ms `(A)` 和 p99 ≤ 50 ms `(A)`；批量决策（≤ 100 个资源）应当达到 p95 ≤ 100 ms `(A)`。
- **NFR-005（供给）** 针对响应及时的目标系统，单次目标供给操作应当达到 p95 ≤ 5 s `(A)`；涉及 ≤ 100k 个身份的完整对账同步应当在 ≤ 30 min `(A)` 内完成。

## 可用性与韧性

- **NFR-006（可用性）** 认证、令牌签发和 PDP 决策应当达到 ≥ 99.95% `(A)` 的月度可用性；只读 JWKS/验证路径应当达到 ≥ 99.99% `(A)`（每个请求都会经过该路径）。已声明维护窗口之外的计划内维护不计入可用性。
- **NFR-007（RPO/RTO）** 身份/策略存储应当满足 RPO ≤ 1 min `(A)`、RTO ≤ 15 min `(A)`；刷新/会话状态可重建；站点发生故障时，系统不应当要求重新注册抗钓鱼认证器。
- **NFR-008（降级）** **当** PDP 不可达时，**系统应当** 对需要许可的操作**失败关闭**；已签发的短期令牌应当仍可使用缓存的 JWKS 进行验证，且最长不超过 BR-01 规定的访问令牌 TTL，随后过期（不允许无限期离线许可）。

## 完整性与正确性

- **NFR-009（审计不可变性）** 认证、决策和管理审计记录应当仅追加且具备防篡改性（哈希链或等效机制）；应用角色不得更新或删除这些记录；验证应当检测出任何修改（BR-09）。
- **NFR-010（审计吞吐量与保留期）** 审计存储应当以 ≥ 2× `(A)` 的峰值认证/决策量无损失地摄取数据，对近期时间窗口的查询应当满足 p95 ≤ 2 s `(A)`，并按 BR-09 的要求通过在线层和归档层保留。
- **NFR-011（幂等性与收敛性）** 所有入站供给事件和令牌刷新操作在重复投递时应当具备幂等性，并且即使在乱序投递情况下也应当收敛至最新权威状态（BR-13）。

## 安全性

- **NFR-012（凭证与密钥保护）** 凭证应当以内存困难型加盐哈希的形式存储，并使用保存在密钥库/HSM 中的 pepper；签名密钥和客户端机密应当存储在 HSM/KMS 中，绝不得存放在源代码或存储库的配置中；应当支持无停机的密钥轮换（BR-01/FR-014）。具体算法套件由部署策略决定 `(A)`。
- **NFR-013（隔离强制执行）** 域/租户隔离应当由服务器端在每次数据访问和令牌接受时强制执行（BR-07）；跨域令牌或查询应当被拒绝，管理范围应当限定在已授予的域内。

## 可运维性与兼容性

- **NFR-014（可观测性与兼容性）** 系统应当为认证成功/失败、决策延迟、异常登录和供给漂移输出指标/日志/追踪信息，并配置 SLO 告警（见 `observability.md`）；为实现互操作性，系统应当符合所引用的开放标准（OIDC、OAuth 2.0、SAML 2.0、SCIM 2.0、WebAuthn），并支持双语（en + zh-CN）界面和带时区的时间戳。
