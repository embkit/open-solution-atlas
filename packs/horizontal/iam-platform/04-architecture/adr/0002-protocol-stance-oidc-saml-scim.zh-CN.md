# ADR-0002 — 协议立场：OIDC 优先的 SSO、面向企业互操作的 SAML、用于生命周期的 SCIM

- 状态：已接受
- 日期：2026-10-08
- 标签：协议、oidc、oauth2、saml、scim、互操作性、令牌

## 背景

该平台必须与异构环境进行联邦互操作：既包括现代 Web/移动应用和 API，也包括使用 SAML 的长期运行企业应用。
生命周期必须与 SaaS 和目录同步。为所有场景选择单一协议，要么无法实现企业互操作性（只能采用 SAML），要么会放弃仅支持 SAML 的应用（只能采用 OIDC）。
令牌和密钥管理同样需要清晰且基于标准的立场，而不是临时拼凑的方案。

## 备选方案

1. **仅使用 SAML** — 成熟的企业互操作能力；不适合移动端、SaaS、API 和委托式 API 访问；XML 处理负担较重。
2. **仅使用 OIDC** — 现代、基于 JSON，适合应用/API；会破坏与现有 SAML 服务提供方的互操作性。
3. **明确采用多协议立场** — 将 OIDC 作为主要认证/联邦协议，将 OAuth 2.0 用于委托式 API 授权，将 SAML 2.0 作为受支持的互操作协议，将 SCIM 2.0 用于生命周期管理；采用标准化的令牌/密钥管理（短期令牌、刷新令牌轮换、JWKS）。

## 决策

选项 3。

- **SSO 与认证**：**OIDC** 是主要协议（授权码 + PKCE、身份令牌、UserInfo、发现、前通道/后通道注销）；支持 **SAML 2.0**，以实现企业 SP 互操作性（签名断言、元数据）。
- **API 授权**：采用 **OAuth 2.0**（RFC 6749/6750/7636/7009/7662），配合限定受众的访问令牌和作用域。
- **生命周期供给**：面向下游目标系统采用 **SCIM 2.0**（RFC 7642/7643/7644）；目录（LDAP/AD 风格）可用作源或目标。
- **令牌与密钥**：采用短期访问令牌 + 轮换刷新令牌，并实施重用检测；签名密钥轮换后通过 **JWKS**/元数据发布，并保留重叠期（BR-01/FR-014）。核心中不使用专有令牌格式。

## 后果

- 实现最广泛的互操作性，同时避免将核心绑定到特定厂商或单一协议。
- 必须维护两套联邦栈（OIDC + SAML），并确保二者的会话/注销语义保持一致；前通道/后通道注销和 SAML SLO 均为必需（BR-02）。
- 使用方必须实现标准验证契约（签发方、受众、过期时间、`alg`、JWKS `kid`）——不得把按资源服务设置的共享密钥当作捷径（FR-014）。
- 协议版本漂移（OIDC 扩展、SAML 配置文件）作为变体/L3 细节进行跟踪；上述立场保持固定。
