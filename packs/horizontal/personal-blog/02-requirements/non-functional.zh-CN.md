# 02 · 非功能需求

目标假设标准场景：单一作者、≤ 500 篇文章、≤ 10 GB 媒体、≤ 5 万次访问/月，
并可能有由链接驱动的最高 100 倍的小时级尖峰。

| ID | 类别 | 需求（可度量） |
|---|---|---|
| NFR-001 | 性能 — 公开 | 4G 移动网络下文章页 LCP ≤ 2.5 秒；TTFB ≤ 200 毫秒（CDN 缓存命中）；完全静态，缓存命中时零源站依赖 |
| NFR-002 | 性能 — 创作 | 编辑器自动保存完成 ≤ 1 秒 p95；2 万字文章的预览渲染 ≤ 300 毫秒 |
| NFR-003 | 可扩展性 | 因为公开层是由 CDN 提供的静态制品集，所以能承受 100 倍流量尖峰而不降级；到 100 万次请求/天都不需要容量规划 |
| NFR-004 | 可用性 | 公开站点月度可用性 ≥ 99.9 %，不含已声明的托管窗口；创作/管理平面为尽力而为的单节点（宕机绝不影响已发布内容） |
| NFR-005 | 持久性 | 内容丢失窗口 ≤ 5 分钟：每次保存都写入持久存储；完整内容镜像到 ≥ 2 个位置（工作存储 + 带版本的备份） |
| NFR-006 | 定时精度 | 正常运行时发布延迟相对 `published_at` ≤ 60 秒（见 FR-009） |
| NFR-007 | 安全 | 除 Webmention/评论端点外没有公开写入面；管理 API 要求强认证（支持 MFA）；所有传入的不可信 HTML 经清洗；A+ 级 TLS 配置；构建中做依赖 CVE 扫描 |
| NFR-008 | 隐私 | 默认部署：无第三方请求、无非必要 Cookie、读者 IP 不存储超过 24 小时；分析为聚合/匿名（支持 CTL-001） |
| NFR-009 | 可访问性 | 全部公开页面满足 WCAG 2.1 AA；自动化 a11y 检查在构建中运行，发现违规即失败 |
| NFR-010 | 兼容性 | 公开页面：Chrome/Firefox/Safari/Edge 的当前版与上一大版本；响应式 320 像素–2560 像素；订阅源通过 RSS 2.0 与 Atom 1.0 校验器校验 |
| NFR-011 | 可移植性 | 100 % 的内容可用开放格式导出（Markdown、JSON、媒体原件）；内容路径上任何位置都没有专有二进制格式 |
| NFR-012 | 可维护性 | 通过单条命令部署；技术型作者从零到可用个人站点 ≤ 30 分钟；安全更新通过机器人 PR 合入，无需手工在服务器上操作 |
| NFR-013 | 可观测性 | 构建/部署的成功/失败可见；每周备份校验结果可见；来自外部探针的公开可用性检查（见 04-architecture/observability.md） |
| NFR-014 | 成本 | 基线流量下的生产托管成本 ≤ 5 美元/月（对象存储 + CDN 免费额度通常是够用的） |
| NFR-015 | 构建正确性 | 每次部署都可复现且原子：读者看到的要么是上一个完整站点，要么是新的完整站点；订阅源/文章/索引的版本绝不混用 |
