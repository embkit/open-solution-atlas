# 02 · 功能需求

EARS 记法：`当 <触发条件> 系统应当 <响应>`。
ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）和验收标准（08-quality 中的
`AC-xxx`）。

## CAP-01 创作

### FR-001 — 带预览的 Markdown 编辑器
- **当** 作者以 Markdown 编辑文章正文
- **系统应当** 使用与已发布页面相同的渲染器与样式渲染实时预览
- **并且应当** 把原始 Markdown 作为存储形态保留
- 优先级：必须 · 追溯：CAP-01.1 · 验收：AC-001

### FR-002 — 自动保存与修订
- **当** 作者停止输入 5 秒或关闭会话
- **系统应当** 无需保存动作即自动持久化草稿
- **并且应当** 保留带时间戳的修订历史，允许恢复到任意先前修订
- **并且应当** 明确向作者展示最后一次保存的状态
- 优先级：必须 · CAP-01.2 · AC-002

### FR-003 — 媒体库
- **当** 作者上传一张图片
- **系统应当** 校验类型（image/* 白名单）与大小（≤ 5 MB）
- **并且应当** 拒绝未通过校验的上传，并给出具体错误
- **并且应当** 要求填写替代文本（或显式标记为「装饰性」），之后该图片才可
  被嵌入面向发布的文章
- 优先级：必须 · CAP-01.3 · AC-003

### FR-004 — 文章元数据
- **系统应当** 在文章可转为 PUBLISHED 之前强制元数据完整性（标题、slug、
  标签、摘要、许可）
- 并在阻断该转换时列出每一个缺失或非法的字段。
- 优先级：必须 · CAP-01.4 · AC-004

## CAP-02 组织

### FR-005 — 分类体系
- **当** 标签被赋予
- **系统应当** 按 BR-05 规范化它们，拒绝每篇超过 8 个标签，并为每个标签/
  分类/系列生成分页索引页。
- 必须 · CAP-02.1/02.2 · AC-005

### FR-006 — 归档导航
- **系统应当** 生成按年/月的归档页，以及一份按时间倒序排列的全局归档清单。
- 必须 · CAP-02.2 · AC-006

### FR-007 — 站内检索
- **当** 读者在站点内输入查询
- **系统应当** 通过客户端索引返回匹配的已发布文章，无服务端往返，也不依赖
  第三方服务。
- 应该有 · CAP-02.3 · AC-007

## CAP-03 发布

### FR-008 — 发布/取消发布
- **当** 作者发布一篇完整的文章
- **系统应当** 原子地构建并部署文章页面、受影响的索引页、订阅源与站点地图
  （一次部署要么全旧要么全新，绝不出现混合状态）。
- 必须 · CAP-03.1/03.4 · AC-008

### FR-009 — 定时发布
- **当** 一篇文章被设为 PUBLISHED 且 `published_at` 在未来
- **系统应当** 在计划时间后 60 秒内完成发布
- **并且应当** 失败时重试，并在 3 次失败后提醒作者。
- 应该有 · CAP-03.2 · AC-009

### FR-010 — URL 治理
- **当** 已发布文章的 slug 被更改或合并
- **系统应当** 从旧 URL 创建到新 URL 的 `301` 重定向；取消发布时它**应当**
  返回 `410 Gone`；任何已发布 URL 都不应因创作动作而返回裸 404。
- 必须 · CAP-03.3 · AC-010

## CAP-04 分发

### FR-011 — 订阅源
- **系统应当** 发布最新 20 篇文章的有效 RSS 2.0 **与** Atom 1.0 订阅源，
  按 BR-08 保持稳定 GUID，具备正确的 `updated` 语义，并提供全文可选标志。
- 必须 · CAP-04.1 · AC-011

### FR-012 — SEO 制品
- **系统应当** 为每篇文章输出 XML 站点地图、robots.txt、正本链接、
  OpenGraph/Twitter Card 元数据与 JSON-LD `Article`。
- 必须 · CAP-04.2 · AC-012

## CAP-05 互动

### FR-013 — 接收 Webmention
- **当** 一个带 `source` 与 `target` 的 HTTP POST 到达 Webmention 端点
- **系统应当** 只接受语法有效且 target 为真实文章 URL 的配对，抓取来源
  源站，验证其确实回链到 target，对提及分类，存为 PENDING，并返回 202。
- 必须 · CAP-05.1 · AC-013

### FR-014 — 审核
- **系统应当** 提供单一作者的队列，列出待处理的提及/评论及其来源片段、类型、
  目标与接收时间；提供通过/拒绝/拉黑动作；已通过的提及只渲染经清洗的 HTML。
- 必须 · CAP-05.2 · AC-014

### FR-015 — 原生评论（可选）
- **当** 按文章启用
- **系统应当** 接受姓名 + URL（不要求邮箱）+ Markdown 评论，实施速率限制与
  垃圾内容评分，并挂起等待审核。
- 可以有 · CAP-05.3 · AC-015

## CAP-06 洞察

### FR-016 — 保护隐私的分析
- **系统应当** 在无 Cookie、无跨站标识符、且不把读者 IP 发给第三方的
  前提下聚合页面浏览；作者看到浏览量/去重数（粗粒度）、引荐来源与热门文章。
- 应该有 · CAP-06.1 · AC-016

## CAP-07 主权保障

### FR-017 — 完整导出
- **当** 作者触发导出
- **系统应当** 产出单一归档：文章（Markdown + frontmatter）、媒体、分类
  体系、重定向、已通过的提及，以及一份带格式版本的清单——排除访问日志与
  读者 IP。
- 必须 · CAP-07.1 · AC-017

### FR-018 — 恢复 / 迁移
- **系统应当** 把导出恢复到一套全新安装中，重建出完全相同的 URL 与内容。
- 必须 · CAP-07.2/07.3 · AC-018
