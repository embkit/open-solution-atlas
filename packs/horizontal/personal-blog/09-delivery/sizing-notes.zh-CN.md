# 09 · 规模、工作量与风险

## 参考构建画像

- 1 名熟悉静态工具的全栈开发者 + 1 个薄服务；从 L3 规范到可运行的生产级
  站点约需 4–6 个专注周（M0–M6），其中占大头的是加固（M4/M5）与导出/灾备
  （M6），而不是页面渲染。
- 若有多个编码智能体针对本方案包工作，被跟踪任务的实现预计可压缩到数天；
  不可压缩的工作是评审闸门、安全验证与真实供应商的搭建。

## 团队形态选项

| 形态 | 说明 |
|---|---|
| 单人技术作者 | 参考情形；选择托管的存储/CDN/OIDC 以避免运维 |
| 开发者 + 评审者 | 公开部署的推荐最低配置；评审者负责安全与 AC 验证 |
| 多智能体构建 | 先做 T-02/T-03（其余一切的契约）；并行 M3/M4；发布流水线的所有任务串行 |

## 主要风险与缓解

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| Webmention/评论滥用（垃圾信息、SSRF） | 高 | 高 | 先验证后存储、清洗器语料、默认审核、有界队列（T-17/18） |
| 供应商锁定渗入构建/托管选择 | 中 | 高 | 制品必须是任何静态托管都能提供的普通文件；供应商只出现在 `variants/` |
| 变更引发订阅源/SEO 回归 | 中 | 中 | 以官方校验器作为构建闸门（T-13） |
| 范围静默膨胀（多作者、多租户） | 中 | 高 | README 中的不在范围清单；拒绝需要租户隔离的 PR |
| 导出承诺腐坏 | 中 | 高（信任） | 季度演练是受跟踪的 CI/预发事件，而不是文档（T-21/22） |
| 中国部署需要 ICP 备案 + 不同的边缘选择 | 视情况 | 中 | 显式的变体覆盖层；绝不与内核纠缠（CTL-009） |

## 变体候选（不属于内核）

1. `static-pages-only`（无创作服务；仅 Git + CI——最省）。
2. `managed-cdn` 供应商覆盖层。
3. `cn-hosting`（ICP 变体；合规的分析/评论选择）。
4. `self-hosted-origin`（单台 VPS + 反向代理；备份方案相应调整）。
