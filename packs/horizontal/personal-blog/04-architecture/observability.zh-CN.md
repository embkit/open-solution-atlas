# 04 · 可观测性

运营者是一个可能几个月不看一眼的单个人：可观测性必须是**推送式且无聊的**。
没有需要盯着的仪表盘。

## 信号

| 层 | 信号 | 位置 | 动作阈值 |
|---|---|---|---|
| 构建器 | 构建结果、耗时、告警（断链、a11y 违规） | 构建日志 + 每个 Release 持久化 | 任何失败 = 管理首页红色状态；a11y/链接失败会阻断部署 |
| 部署 | 晋升成功、CDN 刷新结果 | release 记录 + I-03 日志 | 刷新失败会排队重试 + 告警；绝不回滚 release |
| 定时器 | 到期未发的定时文章 | 每分钟作业日志 | 3 次尝试失败 → 告警渠道（FR-009） |
| Webmention 接入 | 接收、验证、拒绝的计数；验证延迟 | 服务日志、每日摘要邮件（可选） | 无阻断；积压 > 1 小时在管理界面中显现 |
| 公开站点 | 外部可用性探针（GET 首页 + 最新文章），每 5 分钟一次，来自 ≥ 2 个区域 | 第三方探针 | 连续 2 次失败 → 告警 |
| 边缘安全 | 认证失败、速率限制触发、清洗器拒绝 | 服务日志 | 突发情况做汇总；不向读者暴露细节 |
| 备份 | 上次快照时间戳 + 恢复演练结果 | 每周摘要 | 超过 36 小时未更新或恢复演练失败 → 告警 |

## SLO（面向作者，不是合同）

- 公开可用性 99.9 %/月（NFR-004）。
- 发布到可见 ≤ 120 秒（构建 + 部署 + 缓存），在 ≤ 500 篇文章的规模下。
- Webmention 被接受 → 审核通过后 5 分钟处理时间内可见（审核延迟是人为的，
  不由 SLO 度量）。

## 遥测本身的隐私

- 运行日志在 24 小时后不含读者 IP；日志清洗在边缘完成，而不是事后批量处理。
- 默认部署中没有 APM/RUM 第三方。
