# ADR-0002 — 以 Git 仓库作为内容的真相来源

- 状态：已接受
- 日期：2026-10-08
- 决策人：本方案包维护者

## 背景

所有权与可移植性是核心承诺（FR-017/018、NFR-011、旅程 J-05）。内容必须
在没有发布软件的情况下依然可读，支持自然的修订历史，并在创作服务消失时
仍提供一条人工通道。可选方案：

1. Git 树：Markdown + YAML frontmatter + 媒体，仓库即 SSOT
2. 运行库数据库作为 SSOT，导出只是派生转储
3. 对象存储 blob + 独立的元数据库

## 备选方案

1. **Git 作为 SSOT** —— 可分叉、可比对、持久、与工具无关，同时兼任备份与
   应急通道；二进制媒体通过 LFS/存储引用处理。
2. **数据库作为 SSOT** —— 查询灵活、自动保存简单；但内容会受制于模式/软件，
   导出因疏忽而有损，锁定又会悄悄回来。
3. **Blob + 数据库** —— 把真相一分为二；两个存储之间的一致性会成为永久的
   缺陷来源。

## 决策

Git 仓库是一切可发布内容的真相来源。运行库数据库只保存派生/瞬时数据：会话、
提及、定时状态、审计记录。一次 Git push 就是一次有效的创作事件。

## 后果

- 正面：退出保障是结构性的（J-05）；修订版本免费获得；备份方案 = git 远程与
  存储镜像。
- 负面：自动保存需要一个暂存区（未保存的草稿工作区位于已提交树之外，直到
  去抖提交）；不支持并发编辑（可接受：单一作者）。
- 冲突规则：API 路径代作者提交；直接的 Git 提交按「最后写入者」合并，冲突
  在管理界面中显式呈现，而不是被静默覆盖。
