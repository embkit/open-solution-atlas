# 08 · 测试策略

## 层级与覆盖目标

| 层级 | 内容 | 工具特征 | 闸门 |
|---|---|---|---|
| 单元 | 领域规则（slug、BR-03/04/05；文章不变量；提及幂等性；重定向环/链检测；清洗器） | 快，无 I/O | 领域 + 清洗器的行覆盖率 ≥ 90 % |
| 契约 | 管理与接入端点的 OpenAPI 一致性 | 按模式校验的请求/响应；RFC 9457 错误形态 | 每个端点 |
| 集成 | 仓库→构建器→release→存储晋升；定时器；提及验证流水线 | 临时存储 + git 夹具仓库 | 顺路径 + 每种故障注入 |
| 构建期 | 断链、缺失替代文本、a11y axe 规则、订阅源/站点地图有效性、JSON-LD 校验 | 构建器插件 | **任何违规都会让发布失败** |
| 端到端 | 发布旅程（E-03）、读者旅程（E-01/02）、审核（E-05）、导出/恢复（J-05） | 针对预发环境的浏览器自动化 | 上文完整 AC 清单 |
| 性能 | CI 中在参考页面上跑 AC-N01 Lighthouse；AC-N03 尖峰测试按季度 | — | 跟踪回归，不在每次提交上制造噪声 |
| 安全 | 依赖 CVE 扫描、CSP/响应头测试、经提及路径的 XSS 载荷语料、SSRF 语料（169.254.169.254、localhost、DNS 重绑定） | SAST + 载荷语料 | 高危/严重 CVE = 构建红灯 |
| 性质 | 随机操作序列下的不变量：slug 操作后不出现裸 404；订阅源 GUID 稳定；release 从不被观察到混合状态 | 基于性质 | 每晚 1,000 个序列 |

## 测试数据

- 合成夹具语料：520 篇文章、9 个标签、2 个系列、1,300 个媒体资产、40 条
  提及（含恶意载荷）、6 条重定向。不含任何真实读者数据。
- 依赖时间的测试使用可控时钟来覆盖定时/订阅源窗口。

## 环境与晋级

```
PR → lint + 单元 + 契约 + 构建期检查
预发（每次合并 main）→ 集成 + 端到端 + 安全 + Lighthouse
发布标签 → 同一套件 + 恢复演练（至少每月一次）
```

## 人工检查（明确标注）

- AC-N05 成本模型复核。
- 每个发布候选版本在低端 Android 设备上的读者侧手感。
