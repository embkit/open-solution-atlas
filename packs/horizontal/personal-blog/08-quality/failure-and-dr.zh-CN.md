# 08 · 失败模式与灾难恢复

## 故障目录

| # | 故障 | 检测 | 响应 | 恢复目标 |
|---|---|---|---|---|
| F-01 | 创作服务崩溃 | 健康检查 | 重启（无状态）；公开站点不受影响（ADR-0001） | RTO 10 分钟；已发布内容 RPO 0；未保存自动保存缓冲 ≤ 5 分钟 |
| F-02 | 运行库数据库丢失 | 快照监控 + 查询失败 | 恢复最新快照；快照之后的提及可从发送方重新获取（Webmention 重试语义） | RTO 1 小时；RPO 24 小时（仅提及） |
| F-03 | 内容仓库损坏/丢失 | git 远程不匹配、校验和 | 从远程镜像重新克隆；通过重新同步对账投影 | RTO 1 小时；RPO ≤ 5 分钟（持续 push） |
| F-04 | 坏 release（内容错误、模板损坏） | 构建检查（多数在部署前被捕获）；部署后探针 | 指针即时回滚到上一个已 DEPLOYED 的 release + CDN 刷新 | RTO ≤ 5 分钟 |
| F-05 | CDN 中断 | 多区域探针 | 基于 TTL 故障切换到源站静态桶（只读） | 取决于供应商；内容仍可由源站提供 |
| F-06 | 定时器故障 | 漏跑监控 | 重试队列；3 次尝试后告警；不可能出现提前可见 | 文章只是晚发布，绝不半发布 |
| F-07 | Webmention 洪泛 / 攻击 | 速率指标 | 节流/拉黑；队列有界，溢出返回 429 | 接入降级，站点不受影响 |
| F-08 | 作者凭据被攻破 | 登录异常审计 | 吊销令牌 + 强制重新认证；受保护分支阻止未签名内容；复核审计日志 | 完整性对照 Git 签名核验 |
| F-09 | TLS 证书失效 | 到期监控（30/7/1 天） | 自动续期；附带人工操作手册 | 到期之前 |
| F-10 | 区域灾难 | 外部探针 + 运营者告警 | 从跨区域备份 + git 远程恢复到新区域；重新指向 DNS | RTO 24 小时（业余 SLO），内容 RPO ≤ 24 小时 |

## 备份架构

1. Git 远程镜像（持续，跨区域或不同供应商）。
2. 每日加密运行快照，留存 30 天，每周 → 每月一份冷副本。
3. 发布制品留存：当前 + 此前 12 个（可即时回滚）。

## 演练（当作功能对待）

- **每月**：把快照恢复到临时环境 + 校验和比对（AC-N04）。
- **每季度**：导出 → 恢复到一套空安装（AC-018）——不经过测试的所有权承诺
  就不算数。
- **每年**：区域重建操作手册的桌面推演。

## 什么是可以接受的「丢失」

- 超出快照窗口的待处理提及是可容忍的（发送方会重试；F-02）。已发布内容的
  丢失、URL 的丢失，或静默的混合 release 绝不可接受——架构让这些需要多个
  故障同时发生才会出现。
