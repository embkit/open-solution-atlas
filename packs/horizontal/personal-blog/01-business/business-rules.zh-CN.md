# 01 · 业务规则

| ID | 规则 | 理由 |
|---|---|---|
| BR-01 | 每篇已发布文章有且仅有一个正本 URL；`https`、尾部斜杠策略全站统一 | SEO + 链接稳定性 |
| BR-02 | 每篇文章都有：标题、slug、作者、创建日期、发布日期、许可；正文用 Markdown | 必需的元数据完整性 |
| BR-03 | Slug = 小写 ASCII kebab-case，最长 80 字符；在包括未发布在内的全部文章中唯一 | URL 安全性、避免冲突 |
| BR-04 | 首次发布前 slug 可编辑；首次发布后不可变，除非通过显式的重定向动作 | 既有链接绝不能静默 404 |
| BR-05 | 标签在存储前被规范化（去空白、按语言折叠小写）；每篇文章最多 8 个标签 | 分类体系卫生 |
| BR-06 | 取消发布返回 `410 Gone`；改名/合并创建 `301`；任何 URL 都不会被静默留在悬空状态 | 读者/爬虫契约 |
| BR-07 | 一篇文章公开可见当且仅当 status = PUBLISHED 且 `published_at <= now` | 定时发布语义 |
| BR-08 | 订阅源条目保持稳定的 GUID = 正本 URL；编辑更新条目，绝不复制条目 | RSS 阅读器行为 |
| BR-09 | Webmention 按 `(source, target)` 幂等；重复时更新状态 | 网络重试是常态 |
| BR-10 | 已发布内容中的图片必须带非空替代文本；装饰性图片显式标记 | WCAG 2.1 AA |
| BR-11 | 没有匿名写入路径能到达公开内容：发布需要作者身份；评论/提及需要验证 + 审核 | 垃圾内容/涂改防御 |
| BR-12 | 所有第三方请求（字体、分析、联合发布嵌入）都在隐私页中声明；默认部署在未获同意时不发出任何请求 | 默认保护隐私 |
| BR-13 | 导出必须包含收到的 Webmention；导出绝不包含 IP 地址或原始访问日志 | 保有所有权而不泄露读者 |
| BR-14 | 草稿绝不进入站点地图、订阅源、检索索引或公开构建 | 防泄露 |
