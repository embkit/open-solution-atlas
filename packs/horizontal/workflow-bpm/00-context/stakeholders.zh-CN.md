# 00-context / 利益相关方

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **企业 IT / 平台团队** | 运维引擎、表单、集成和升级 | 拥有并运维平台 |
| **业务流程负责人** | 端到端负责流程定义及其规则 | 提出变更请求；批准流程版本 |
| **办公管理 / 办公室** | 管理公文、发文字号/文号、模板、归档与保管期限 | 对内容拥有管理权，而非平台管理权 |
| **人力资源 / 组织主数据** | 组织架构、岗位和任职状态的权威数据源 | 将组织架构和汇报关系变更馈送至参与者解析流程 |
| **财务** | 费用、报销和付款规则；控制措施 | 下游使用方；定义规则密集型流程 |
| **法务 / 合规** | 合同模板、印章使用和记录方面的义务 | 界定必须保留且可证明的内容 |
| **内审** | 提供控制执行情况的证据 | 审计轨迹的只读使用方 |
| **档案主管机构** | 保管期限、归档与处置 | 接收已完成的记录 |
| **信息安全** | 访问控制、等级保护合规（等保）、日志完整性 | 接收遥测数据；制定控制要求 |
| **业务系统负责人** | 流程所调用的系统 | 上游/下游集成对接方 |
| **监管机构 / 外部审计人员** | 法定检查 | 仅可读取证据；无权操作平台 |

## 2. 角色（应用执行者）

| 角色（英文） | 中文 | 关键权限 / 任务 |
|---|---|---|
| Applicant | 申请人 | 编写并提交表单、附加证据材料、在审批前撤回 |
| Assignee / approver | 办理人/审批人 | 认领或接收任务、批准、驳回、退回、添加批注 |
| Countersigner | 会签人 | 在同一会签组中与其他会签人共同操作 |
| Process owner | 流程负责人 | 定义流程并管理版本，设置网关、办理时限和催办/升级，发布 |
| Form designer | 表单设计者 | 编制表单结构、校验规则和条件可见性 |
| Org / role administrator | 组织角色管理员 | 维护组织单元、岗位以及角色与权限的映射关系 |
| Delegate / agent | 代办人/代理人 | 在有界范围和时间窗口内代表其他参与者执行操作 |
| Transferrer / re-router | 转办人 | 将任务转办给其他参与者，并记录此次转办 |
| Office administrator | 公文管理员 | 管理发文字号/文号分配、模板、核稿/签发路由和归档规则 |
| Seal custodian | 印章管理员 | 授权并记录印章/签名的使用；不得自行批准印章的使用 |
| Auditor | 审计员 | 对实例、事件轨迹和文档拥有只读访问权限 |
| Operations administrator | 运维管理员 | 管理引擎、作业和集成；无权制定业务规则 |
| Process analyst / miner | 流程分析师 | 导出并分析事件日志（只读） |

### 非人类执行者

| 执行者 | 说明 |
|---|---|
| **工作流引擎** | 创建实例、评估流程定义、生成任务、驱动定时器 |
| **表单引擎** | 解析表单结构、应用校验和条件可见性 |
| **规则/决策服务** | 评估审批条件（候选标准：DMN） |
| **集成连接器** | 调用下游系统；必须具备幂等性 |
| **作业调度器** | 定时器、提醒、催办/升级巡检、保留期作业 |
| **身份提供方（IAM）** | 对参与者进行身份验证；提供群组/角色声明 |
| **文档/内容存储库** | 存储文档及其元数据（候选接口：CMIS） |
| **通知网关** | 投递待办、提醒和催办/升级通知 |
| **电子签名 / 电子签章服务** | 应用并验证电子签名与电子签章 |

## 3. 作为执行者的外部 / 上游-下游系统

- **人力资源 / 组织主数据**——员工、组织树、汇报关系、岗位。
- **身份提供方**——身份验证、群组成员身份、角色声明。
- **财务系统**——费用/付款入账；往往是实际承担记录职责的系统。
- **ERP / 采购 / 资产系统**——调用目标与数据提供方。
- **文档/内容存储库**——文档和记录背后的存储系统。
- **电子签名与电子签章服务**——受监管的依赖项；参见 `regulatory-landscape.md`。
- **通知渠道**——应用内待办、电子邮件、IM、短信。
- **SIEM / 日志平台**——接收审计与运维遥测数据。
- **归档 / 记录系统**——长期保留期、归档与处置。

## 4. 执行者目标（主要）

- **申请人**：一次提交，准确了解申请当前处于何处、由谁持有，
  附件永不丢失。
- **审批人**：在同一处查看申请及其证据，快速作出决定，
  且不会被要求审批超出其权限范围的事项。
- **流程负责人**：无需发布新版本即可变更路由规则，并在变更生效前
  查看其对在途实例的影响。
- **公文管理员**：签发使用受控发文字号/文号的公文，并证明
  编号序列从未重复或跳号。
- **审计员**：重建任一实例的完整历史——谁在何时基于何种依据做了什么，
  以及文档在每个步骤中呈现为何种状态。
- **运维管理员**：保持引擎可用且状态可观测，同时无权更改审批结果。
- **安全负责人**：证明实例访问权限依据角色和业务范围授予，并证明
  任何人均无法编辑审计轨迹，管理员亦然。

> ⚠️ ASSUMPTION: 本方案包假设参与者按**角色和业务范围
> 进行解析，绝不按硬编码的用户名解析**，且人力资源是角色和业务
> 范围两方面共同的权威来源。将审批人硬编码到流程定义中的部署
> 应视为缺陷，而非捷径——这是设计立场，而非引用依据。
