## 本方案包涵盖内容

几乎每家公司和政府机构都会使用的组织流程主干：可配置审批流、动态表单、流程实例与任务、委托、消息/通知、公文管理，以及与业务系统集成的钩子。中国 OA/审批场景（钉钉/企业微信式模式、电子签章）作为明确的变体处理，而不是核心默认前提。

## 范围内

- 流程建模：与 BPMN 对齐的设计器（流、网关、定时器、信号）、版本管理、草稿与已发布定义
- 表单引擎：基于模式的动态表单、校验、数据绑定、子表单、条件可见性
- 运行时：实例生命周期、任务收件箱、签收/认领、转办、代办/委托、会签/或签模式、加签/转办、超时与催办/升级、回退/撤回语义
- 参与者：用户、组织、角色、职位/职级规则、动态组；类似职责分离的约束
- 文档与记录：公文拟稿/核稿/签发/文号管理、模板、保留期/归档、电子签章与电子签名集成
- 集成：消息/通知、业务回调、流程数据 API、webhook/事件流
- 运维：SLA 监控、效率分析（瓶颈）、完整的流程审计与重放

## 明确不在范围内

- ERP/MES 领域逻辑（本方案包负责流程编排，不负责该领域逻辑）
- 文档实时协同编辑（通过集成引用）
- HR 组织主数据（从 HR/IAM 读取）
- 超出表单和流程范围的低代码应用生成

## 已确定的 ADR（不得重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | BPMN 2.0 是建模的**词汇**；**不声明符合性**。本方案包所需的语义均已写入本方案包 |
| **0002** | 定义版本**一经发布即不可变**，且**在途实例的处理方式**随发布一并记录 |
| **0003** | 参与者按角色和范围**从组织来源解析**，绝不按用户名解析；解析失败时一律拒绝 |
| **0004** | 审批词汇**由本方案包定义**，因为 BPMN 2.0 未定义该词汇；两种完成策略记录为**待定决策**，而不是查表所得结果 |
| **0005** | 实例状态是**对事件折叠计算的结果**；历史绝不重写，更正采用补偿事件 |
| **0006** | 公文、文号和电子签章是**带明确标签的 CN 变体**，核心经证明无需它们即可运行 |

## L3 阻断项

1. **两种完成策略**——会签是否在任何一项拒绝时结束，以及或签是取消其他任务还是仅不呈现其他任务，均记录为 L2 阶段的待定决策。确定这些策略，是使 FR-013 / FR-014 不止于一项声明式要求的前提。
2. **表示法扩展**——BR-01 要求对扩展进行声明；本方案包在 BPMN 2.0 之外所需的扩展清单尚未编写。
3. **九项零容忍不变量的验收标准**——NFR-001、NFR-002、NFR-003、NFR-004、NFR-005、NFR-007，以及权限和委托检查，需要能够使构建失败的标准，而不是仅报告一个阈值。
4. **印章原语**——CTL-04 要求进行时点有效性验证；加密原语和提供方尚未指定。

### 明确未解决的事项（已记录，未遗忘）

- **符合性配置文件**——有意不主张符合性。两个引擎可能恰恰在本方案包所关心的语义上存在差异，而本方案包无法判定哪一方正确。这是必须如实面对的代价，现已记录，而非隐去。
- **文号分配规则**——要求无缺口且可审计；具体规则属于监管输入项。
- **保留期数值**——BR-09 要求按类别设定；未主张任何具体期限。
- **BPMN 发布版本**——文中引用 2.0.2 作为已发布规范；未主张任何版本作为实施的规范性依据。
