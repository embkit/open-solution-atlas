# 04 · 集成

> 与平台各相邻系统之间的集成契约。ID 保持稳定；每条流程均可追溯到需求和规则。
>
> ⚠️ ASSUMPTION — 接口选择和协议属于方案包设计。

## I. 集成点

| ID | 相邻系统 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **组织源（HR / IAM）** | 入站 | 角色、岗位、汇报关系——参与者的事实来源 |
| **I-02** | **调用方（应用程序、门户、API）** | 入站 | 实例创建和查询 |
| **I-03** | **下游系统** | 出站 | 服务任务、回调、回写 |
| **I-04** | **通知网关** | 出站 | 待办、提醒、催办/升级 |
| **I-05** | **文档/内容存储** | 出站 | 附件、生成的文档 |
| **I-06** | **电子签名/签章服务** | 出站 | CN 变体中的电子签章加盖与验证 |
| **I-07** | **记录/归档系统** | 出站 | 归档和处置 |
| **I-08** | **SIEM / 日志平台** | 出站 | 审计和运维遥测 |

## F. 内部流程

### F-01 — 定义并发布
1. 该流程采用 BPMN 2.0 词汇建模，并包含表单、网关和计时器。
2. 每项活动采用的词汇模式均连同其完成策略一并声明。
3. 该版本随生效日期和已记录的在途实例处理方式一并发布。

### F-02 — 实例化与路由
1. 调用方创建实例；引擎将其固定到当前生效的版本。
2. 参与者依据 I-01 中的角色和业务范围进行解析。
3. 对网关进行评估，并创建后续工作项。

### F-03 — 人工工作
1. 参与者认领或接收该工作项。
2. 参与者按照相应模式的语义执行操作——包括转办（永久）和委托（有边界、可撤销）。
3. **每次**操作都会追加一个事件，其中包含操作者、时间戳、原因和定义版本。

### F-04 — 催办/升级
1. 计时器触发。
2. 执行该计时器获得授权的操作——提醒、重新指派或转交上级。
3. 该催办/升级操作形成一项事件，并记录归属信息。

### F-05 — 完成与产物
1. 实例达到终态。
2. 产物生成时附带相应授权。
3. 在 CN 变体中，会进行文号分配和电子签章加盖，并记录签章的有效性。
4. 按类别适用相应保管期限，并依据记录管理职责执行归档。

### F-06 — 补偿
1. 流程定义存在缺陷，或操作员采取了需要更正的 action。
2. 按已声明的补偿路径执行，并以新事件记录。
3. 记录更正，并注明授权人姓名。

## 失败模式契约

| 集成 | 必须处理的失败模式 |
|---|---|
| **I-01 组织源** | 组织源不可用时，任务不得路由，而不是路由至后备项。路由到“上一任持有者”实质上就是换了形式的硬编码姓名（BR-04） |
| **I-03 下游系统** | 服务任务失败应作为异常处理，并配有已声明的重试和补偿路径——绝不能以静默跳过步骤的方式处理。跳过网关会产生无法解释的实例 |
| **I-04 通知** | 提醒失败只会导致通知功能降级，绝不会影响实例。工作项仍然存在，也仍会继续计时 |
| **I-06 签章服务** | 加盖电子签章失败应阻断产物，不得生成未加盖签章却标为“已签署”的文档。CTL-04 |
| **I-07 归档** | 归档失败时，实例仍按类别保留，并且该失败会被记录，而不是被静默丢弃 |
| **I-08 SIEM** | 遥测不可用只会降低可观测性，绝不会影响审计轨迹——审计轨迹存于事件日志（FR-020），而非遥测管道 |

> 其规律是：集成不可用时，外部路径会降级，并将不可用情况记录为未知——绝不假定其状态，也绝不为其设置默认值。参与者解析是唯一应采用故障关闭（fail-closed）的情形，因为将任务路由给靠猜测确定的审批人，等同于一项无人授权的审批。

## 调用方契约（调用方必须接受的内容）

| 方面 | 调用方集成所声明的内容 |
|---|---|
| **定义版本** | 调用方会收到当前生效的版本；除非获得授权，否则不得选择任意版本 |
| **参与者模型** | 调用方不提供审批人的用户名——它们提供业务范围，由引擎进行解析（BR-04） |
| **实例语义** | 实例固定到一个版本；实例化后，调用方不得假定仍使用实时定义（live definition） |
| **事件** | 状态变更以事件形式到达；缓存状态的调用方必须重新读取，而不得假定存在其未观察到的状态转换 |

> 从集成角度看，调用方提供自己的审批人列表就是硬编码参与者，其失败方式完全相同——当有人换岗时，悄无声息地失败。
