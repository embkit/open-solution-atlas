# ADR-0005 — 实例状态是事件的折叠结果，历史记录永不重写

- 状态：已接受
- 日期：2026-10-12
- 决策人：方案包维护者

## 背景

`AGENTS.md` 要求每次流程状态转换都可审计且**可重放**。

这两个要求通常由同一种实现来满足：一个当前状态字段，以及一份记录生成该状态的变更日志。这种实现满足了“可审计”，却无法满足“可重放”；这种失败值得明确指出。

可重放意味着事件本身就是状态。重新执行这些事件时，必须逐位复现实例，且不得读取可变字段。原因正是审计要求真正关注的核心：工作流平台决定**谁可以针对什么采取行动**，并记录该决定。记录的全部价值在于其内容从不被重写；而在日志旁另设一个可变的当前状态字段，就等于让事实有了第二个存放位置。

## 备选方案

1. **当前状态字段加变更日志** — 当前状态读取速度快，而“重放”意味着根据日志进行重建，这并不等同于日志本身即为状态。该字段会发生漂移，而且只有通过重放才能发现这种漂移。
2. **当前状态字段，无日志** — 速度最快，审批记录完全取决于字段的内容。“谁批准了它？”由此变得无法回答。
3. **事件即状态；当前状态是一个折叠结果，为读取而物化，并且始终可与重新折叠的结果进行校验** — 日志具有权威性，而物化视图是一个可通过检查的缓存。

## 决策

采用方案 3，并由 BR-07、FR-020、FR-021、BR-10（补偿是事件，而不是编辑）、FR-025、FR-026 以及 NFR-001、NFR-002 作为不变量加以约束。

一次更正必须是带有明确授权人的**补偿事件**——绝不能是重写。正是这条规则使审计轨迹成为证据，而不只是日志；而且在压力之下，它也是最常被违反的规则，因为操作员更正错误条目时，往往是在错误的层面做正确的事。

## 后果

- 正面：实例历史记录将成为数月后仍可作为抗辩依据的证据，状态也可以通过重新折叠来校验，而无须仅凭信任接受。
- 正面：定义中的缺陷可通过同样具备可归责性的补偿路径加以更正，而不是悄然重写其所产生的审批。
- 负面：重新折叠以进行验证会产生成本，而且大规模读取需要物化视图。本方案包将物化视图视为缓存，其偏离属于缺陷（NFR-002 用于衡量重新折叠能否复现结果）。
- 负面：操作员更正条目的正当需求必须表达为
> 一次补偿，这需要付出更多工作量，而且会让执行者感觉不对劲。
> 这条规则之所以存在，恰恰因为这种感觉十分常见。
