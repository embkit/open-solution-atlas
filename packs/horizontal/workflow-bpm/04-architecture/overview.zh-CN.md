# 04 · 架构概述

> 建模词汇表；**不声明符合任何符合性配置文件**（BR-12、ADR-0001）。
> 已确定的决策位于 `adr/`，本文不再重新讨论。

## 组件视图——不得混淆的三层

```
   ┌───────────────────────────────────────────────────────────────┐
   │  定义  (受治理、版本化)                                       │
   │  ProcessDefinition → DefinitionVersion                     │
   │  网关 · 定时器 · 表单 · 词汇语义                             │
   │  发布操作记录运行中实例的处理方式                             │
   └───────────────────────────┬───────────────────────────────────┘
                               │ 实例化（固定版本）
                               ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  运行时  (实例固定到版本)                                     │
   │  ProcessInstance · Token · InstanceEvent                     │
   │  state = fold(events)  — 可重放，绝不重写                     │
   └───────────────────────────┬───────────────────────────────────┘
                               │ 生成
                               ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  工作项  (词汇已定义)                                         │
   │  指派/分发 · 签收/认领 · 转办 · 代办/委托 ·                   │
   │  会签 · 或签 · 加签 · 退回 · 撤回 · 加签意见/批注             │
   │  每种模式都要求声明 CompletionPolicy                          │
   └───────────────────────────┬───────────────────────────────────┘
                               │ 解析
                               ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  参与者  (角色 + 业务范围，绝非姓名)                           │
   │  Participant · Role · Scope · Delegation (有范围限制、会过期)  │
   │  组织变更影响未来解析，不影响运行中的实例                     │
   └───────────────────────────────────────────────────────────────┘

   ┌───────────────────────────────────────────────────────────────┐
   │  CN 变体  (带标签——核心无需它即可运行)                        │
   │  公文 · 文号 (无缺口、可审计) · 电子签章 (签署时有效)          │
   └───────────────────────────────────────────────────────────────┘
```

## 必须始终明确区分的两条边界

### 1. 定义 → 运行时

发布操作不会影响运行中的实例。运行中实例的处理方式——按旧版本完成、
迁移还是终止——会随发布一并记录（BR-03，约束 2），否则，默认行为将取决于
引擎碰巧采用的处理方式。

### 2. 核心 → CN 变体

公文、文号和电子签章存在于一个带标签的变体中（BR-11）。核心必须能够在
缺少这些能力的情况下运行（FR-028）；这样即可通过实际运行证明隔离，而不是
仅凭声明。在 CN 规则适用范围之外进行部署时，采用不含这些能力的核心。

## 部署视图

```
                    ┌──────────────────────────────┐
                    │  建模（建模师 · 表单）         │
                    └───────────────┬──────────────┘
                                    │ 发布
   ┌──────────────────┐   ┌─────────▼──────────┐   ┌──────────────────┐
   │  组织数据源       │──▶│  定义存储           │──▶│  参与者与委托     │
   │  (HR / IAM)      │   │  (版本化)           │   │  委托             │
   └──────────────────┘   └─────────┬──────────┘   └──────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
   ┌────────────────────┐ ┌───────────────────┐ ┌───────────────────┐
   │ 运行时存储         │ │ 事件日志           │ │ 工作项收件箱      │
   │ (实例固定到        │ │ (仅追加；           │ │ (角色/范围        │
   │  版本)             │ │  可重放)            │ │  已解析)          │
   └─────────┬──────────┘ └───────────────────┘ └───────────────────┘
             │
             ▼
   ┌───────────────────────────────────────────────────────────┐
   │  定时器服务——提醒、办理时限、催办/升级                   │
   │  (触发条件 + 操作 + 权限，三者均须声明)                   │
   └───────────────────────────────────────────────────────────┘
             │
             ▼
   ┌───────────────────────────────────────────────────────────┐
   │  文档与工件——附带权限，签章变体                          │
   │  按类别设定保留期                                        │
   └───────────────────────────────────────────────────────────┘
```

**部署决策及原因：**

| 组件 | 部署位置 | 原因 |
|---|---|---|
| **定义存储** | 版本化，发布后不可变 | 运行中实例的含义不得改变（BR-02、BR-03） |
| **事件日志** | 仅追加，与实例记录行分离 | state = fold(events)；一旦修改当前状态字段，重放能力就会悄然丧失 |
| **参与者解析** | 基于角色和范围，由组织数据源驱动 | 有人换岗时，审批会在无任何提示的情况下失效（BR-04） |
| **定时器服务** | 独立服务，权限须明确声明 | 催办/升级若未记录权限，就会使控制措施变成未经审查的自动操作 |
| **CN 变体** | 带标签的模块 | 核心必须能够在无该模块的情况下运行（FR-028） |

## 本架构有意不做以下事项

- 不原地编辑已发布的定义版本（BR-02）。
- 不将新版本追溯应用到运行中的实例（BR-03）。
- 定义中不以用户名作为参与者（BR-04）。
- 不使用未声明完成策略的多参与者模式（BR-05）。
- 不重写实例历史（BR-07）。
- 核心中不包含公文 / 文号 / 电子签章行为（BR-11）。
- 不宣称 BPMN 成熟度、引擎符合性配置文件或 DMN 目标（BR-12）。
