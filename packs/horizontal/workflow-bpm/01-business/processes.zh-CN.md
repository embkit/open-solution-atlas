# 01-business / 流程

> 面向工作流/BPM/OA 平台的流程定义。每个流程均说明其触发条件、步骤，以及约束这些步骤的规则。规则位于 `business-rules.md`（BR-xx）中并通过引用使用，绝不重述。
>
> ⚠️ ASSUMPTION — 流程分解属于方案包设计。BPMN 2.0 提供建模词汇，但不提供这些流程。

## P-01 — 定义

| | |
|---|---|
| **触发条件** | 某项流程需要自动化 |
| **结果** | 一个经过版本控制且可发布的**流程定义** |

1. 使用 BPMN 2.0 词汇对流程进行建模（BR-01）。
2. 附加对其进行约束的业务规则、网关和办理时限。
3. 对其进行版本管理；发布使其成为受治理的制品（BR-02）。

## P-02 — 发布

| | |
|---|---|
| **触发条件** | 某个定义版本获得批准 |
| **结果** | 该版本成为新实例使用的版本，旧实例保留其原有版本 |

1. 发布该版本并指定生效日期。
2. 确定对**进行中实例**的处理方式（BR-03）。
3. 记录此次发布及其授权信息。

> BR-03：新版本不得在不作说明的情况下改变已在运行的实例。三种处理方式——让其完成、迁移或终止——是明确的选择，且各自产生不同后果。

## P-03 — 实例化

| | |
|---|---|
| **触发条件** | 调用方创建实例 |
| **结果** | 一个固定关联至定义版本的运行中实例 |

1. **依据角色和业务范围**解析参与者，绝不按硬编码的用户名确定（BR-04）。
2. 创建固定关联至定义版本的实例（BR-03）。
3. 打开首个工作项。

## P-04 — 路由

| | |
|---|---|
| **触发条件** | 实例向前推进 |
| **结果** | 下一个工作项（可能为多个），其语义由词汇表定义 |

1. 评估网关——排他、包容、并行（BR-01）。
2. 应用人工任务词汇，采用其**已定义**的语义：指派/分发、签收/认领、转办、代办/委托、会签、或签、加签、退回、撤回、加签意见/批注（BR-05）。
3. 应用定时器：提醒、办理时限、催办/升级（BR-06）。

> BR-05 是本方案包的核心规则，也是本方案包存在的原因。这些术语没有标准定义，因此，任何使用这些术语却不说明其语义的实现，都是在自行杜撰这些术语。

## P-05 — 人工工作

| | |
|---|---|
| **触发条件** | 工作项到达参与者 |
| **结果** | 一次可归属到操作者且带时间戳的操作 |

1. 签收或认领该工作项。
2. 执行操作：批准、驳回、退回、转办、代办/委托、会签。
3. **每一次**状态变更都追加一个事件，其中包含操作者、时间戳和原因（BR-07）。
4. 事件轨迹可**重放**（BR-07）。

> BR-07：无法重放的审批轨迹不能作为证据。正是重放使决定在数月后仍经得起质疑。

## P-06 — 完成

| | |
|---|---|
| **触发条件** | 实例到达终态 |
| **结果** | 一条已完成记录，包含其文档、时间戳和完整轨迹 |

1. 确定终态。
2. 生成制品——决定、文档、文号（BR-08）。
3. 按数据类别的保留期要求保留该轨迹（BR-09）。
4. 按照记录保存要求进行归档。

## P-07 — 补偿

| | |
|---|---|
| **触发条件** | 定义缺陷或操作员操作需要更正 |
| **结果** | 一条补偿路径，绝不编辑历史 |

1. 识别受影响的实例。
2. 采用已定义的补偿路径——即一个新事件，而不是编辑（BR-10）。
3. 记录授权人。

## 规则覆盖情况

| 规则 | 流程 |
|---|---|
| BR-01 BPMN 2.0 词汇 | P-01, P-04 |
| BR-02 定义是经过版本管理的制品 | P-01, P-02 |
| BR-03 发布不影响进行中的实例 | P-02, P-03 |
| BR-04 参与者按角色和范围确定 | P-03 |
| BR-05 审批词汇具有已定义的语义 | P-04, P-05 |
| BR-06 定时器均明确设定 | P-04 |
| BR-07 每次转换均可审计且可重放 | P-05, P-06 |
| BR-08 制品载明其授权信息 | P-06 |
| BR-09 按数据类别适用保留期 | P-06 |
| BR-10 补偿是事件，而非编辑 | P-07 |
| BR-11 公文/文号/签章是 CN 变体 | P-06 |
| BR-12 不声明一致性 | P-01 |
