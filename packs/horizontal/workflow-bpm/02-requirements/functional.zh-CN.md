# 02 · 功能需求

> EARS 表示法：`当 <触发条件> 系统应当 <响应>`。
> 稳定 ID 永久有效；每项需求均追溯至一项能力（`CAP-xx`）、一项规则（`BR-xx`）和一项
> ADR。验收标准（AC-*）在 L3 阶段定义。
>
> `verification: unverified`——这些需求属于方案包设计，尚未针对任何部署进行验证。

## CAP-01 流程定义与生命周期

### FR-001 — 以 BPMN 为基础的表示法
- **当** 对流程进行建模时
- **系统应当** 使用 BPMN 2.0 词汇表达流对象、网关、事件、泳道和制品，**并且应当**不得在未声明的情况下扩展该表示法（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-002 — 声明词汇扩展
- **当** 表示法扩展至 BPMN 2.0 之外时
- **系统应当** 将该扩展记录为带标签的新增项，**并且应当**不得将其作为 BPMN 的一部分呈现（BR-01、BR-12）
- 追溯：CAP-01、BR-01、BR-12、ADR-0001

### FR-003 — 版本化定义
- **当** 创建或修订定义时
- **系统应当** 将其存储为带有发布者和生效日期的版本化制品（BR-02）
- 追溯：CAP-01、BR-02、ADR-0002

### FR-004 — 记录运行中实例的处理方式
- **当** 发布定义版本时
- **系统应当** 记录对运行中实例的处理方式——在旧版本上完成、迁移或终止——**并且应当**不得追溯适用新版本（BR-03）
- 追溯：CAP-01、BR-03、ADR-0002

### FR-005 — 实例固定版本
- **当** 创建实例时
- **系统应当** 将其固定到当时生效的定义版本，使其历史仍能在该版本下得到解释（BR-03）
- 追溯：CAP-01、BR-03、ADR-0002

## CAP-07 身份、参与者与权限

### FR-006 — 角色与范围解析
- **当** 需要为任务确定参与者时
- **系统应当** 根据组织数据源按角色和业务范围解析参与者，**并且应当**不得在定义中接受用户名（BR-04）
- 追溯：CAP-07、BR-04、ADR-0003

### FR-007 — 应对人力资源变更
- **当** 组织数据源中的汇报关系、岗位或角色发生变化时
- **系统应当** 根据当前结构解析未来任务，**并且应当**不得使运行中的实例中断（BR-04）
- 追溯：CAP-07、BR-04、ADR-0003

### FR-008 — 可撤销的委托授权
- **当** 创建委托时
- **系统应当** 要求提供范围和有效期，**并且应当**允许通过撤销停止后续操作（BR-05）
- 追溯：CAP-07、BR-05、ADR-0004

## CAP-03 任务与工作项管理——词汇

### FR-009 — 指派/分发：任务创建时即已有归属
- **当** 采用指派/分发模式的活动开始时
- **系统应当** 创建已归属于特定参与者的工作项，**并且应当**不得允许其他参与者在未经转办或重新指派的情况下认领该工作项（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-010 — 签收/认领：任务创建时无归属
- **当** 采用签收/认领模式的活动开始时
- **系统应当** 创建无归属并提供给某个任务池的工作项，一旦认领，归属即具有排他性（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-011 — 转办：永久放弃归属
- **当** 参与者转办工作项时
- **系统应当** 永久向指定接收人放弃归属，**并且应当**不得允许原所有者此后执行操作（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-012 — 代办/委托：所有者保留归属，被委托人执行操作
- **当** 参与者在限定范围和有效期内进行委托时
- **系统应当** 允许被委托人在此期间执行操作，同时由原所有者保留归属，并将被委托人的操作既记录在其名下，也归因于委托所有者（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-013 — 会签完成策略
- **当** 会签组运行时
- **系统应当** 应用**已声明的**完成策略——一致批准或全部响应——**并且应当**不得使该策略保持隐含（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-014 — 或签完成策略
- **当** 或签组运行时
- **系统应当** 对剩余任务应用**已声明的**策略——取消这些任务或始终不呈现这些任务——**并且应当**不得使该策略保持隐含（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-015 — 加签插入
- **当** 参与者插入额外审批人时
- **系统应当** 将新增审批人置于插入点之后，并置于原有顺序继续之前（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-016 — 退回，与驳回相区分
- **当** 工作项被退回时
- **系统应当** 应用已声明的语义——**返工**表示退回申请人且可重新提交，**驳回**表示终止实例——**并且应当**不得将二者混同（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

### FR-017 — 由申请人撤回
- **当** 撤回已提交的实例时
- **系统应当** 仅允许申请人或流程所有者撤回，并且仅在尚未记录任何有约束力的决定时允许撤回（BR-05）
- 追溯：CAP-03、BR-05、ADR-0004

## CAP-06 监控、分析与运维

### FR-018 — 计时器触发
- **当** 在定义上配置计时器时
- **系统应当** 记录其触发条件、持续时间或日程，以及用于计量的日历（BR-06）
- 追溯：CAP-06、BR-06

### FR-019 — 催办/升级授权
- **当** 催办/升级触发时
- **系统应当** 执行该计时器已授权的操作——提醒、重新指派或转交上级——**并且应当**不得在没有已记录授权依据的情况下触发升级（BR-06）
- 追溯：CAP-06、BR-06

## CAP-08 事件、审计与重放

### FR-020 — 仅追加事件轨迹
- **当** 发生任何状态转换时
- **系统应当** 追加一个事件，其中包含操作者、时间戳、原因和当时生效的定义版本（BR-07）
- 追溯：CAP-08、BR-07、ADR-0005

### FR-021 — 可重放性
- **当** 重放实例历史时
- **系统应当** 根据其事件逐位一致地重现实例状态，不依赖可变的当前状态字段（BR-07）
- 追溯：CAP-08、BR-07、ADR-0005

### FR-022 — 制品归属
- **当** 实例完成时
- **系统应当** 将决定、决定作出者、决定依据和时间戳附加到所生成的制品上（BR-08）
- 追溯：CAP-08、BR-06、BR-08

### FR-023 — 决策所依据的版本
- **当** 作出网关决定或审批决定时
- **系统应当** 记录定义版本以及产生该决定的任何规则标识符，使该决定可被重构（BR-07、BR-08）
- 追溯：CAP-08、BR-07、BR-08

### FR-024 — 按类别设置保留期
- **当** 保留实例、文档、印章和日志时
- **系统应当** 应用按类别声明的保留期，**并且应当**不得采用单一全局设置（BR-09）
- 追溯：CAP-08、BR-09

### FR-025 — 以事件形式补偿
- **当** 流程定义存在缺陷而需要更正时
- **系统应当** 将已声明的补偿路径作为新事件执行，**并且应当**不得改写现有历史（BR-10）
- 追溯：CAP-08、BR-10、ADR-0005

### FR-026 — 补偿授权
- **当** 应用补偿时
- **系统应当** 要求提供已记录的授权人和原因（BR-10）
- 追溯：CAP-08、BR-10

## CAP-04 表单与数据采集、CAP-06 文档与记录

### FR-027 — 公文变体隔离
- **当** 对公文、文号或电子签章行为进行建模时
- **系统应当** 将其置于带标签的变体中，**并且应当**不得将其置于核心中（BR-11）
- 追溯：CAP-04、CAP-06、BR-11、ADR-0006

### FR-028 — 无变体的核心
- **当** 部署采用不含变体的核心时
- **系统应当** 在不存在任何公文 / 文号 / 电子签章行为的情况下运行，以证明隔离（BR-11）
- 追溯：CAP-01、BR-11、ADR-0006

### FR-029 — 禁止作出符合性声明
- **当** 平台报告其标准立场时
- **系统应当** 说明其所实现的表示法和生命周期语义，**并且应当**不得声称任何尚未确立的 BPMN 成熟度级别、引擎符合性配置文件或 DMN 目标（BR-12）
- 追溯：CAP-01、BR-12、ADR-0001
