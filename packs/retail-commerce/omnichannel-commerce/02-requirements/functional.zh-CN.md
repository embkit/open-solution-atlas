# 02 · 功能需求

> EARS 句式：`WHEN <trigger> THE SYSTEM SHALL <response>`。
> 稳定 ID 永久有效；每项需求均追溯至一项能力（`CAP-xx`）和一条规则
> （`BR-xx`）。验收标准（AC-*）在 L3 定义。
>
> `verification: unverified` — 这些需求属于方案包设计，尚未针对任何部署
> 加以验证。

## CAP-01 商品主数据

### FR-001 — 单一商品主数据
- **当** 商品被创建或变更时
- **系统应当** 存储一份唯一规范记录（身份标识、属性、分类体系、媒体、SKU），供所有渠道读取，并将渠道专属值表示为**渠道变体**（BR-14）
- 追溯：CAP-01、BR-14

### FR-002 — 渠道变体解析
- **当** 渠道呈现商品时
- **系统应当** 解析该渠道的变体属性（标题、媒体、资格条件、价格表），且不修改商品主数据记录
- 追溯：CAP-01、BR-14

## CAP-02 定价与促销

### FR-003 — 规则集驱动的定价
- **当** 请求价格时
- **系统应当** 解析适用的价格表（渠道、货币、受众），并根据当前生效的**规则集版本**评估促销规则，生成逐行价格以及每条规则的折扣贡献（BR-05）
- 追溯：CAP-02、BR-05

### FR-004 — 应用库存占用策略
- **当** 为行项目定价时
- **系统应当** 应用该商品声明的库存占用策略；若策略为定价时预留，则创建带有强制过期时间的**预留**（BR-01、BR-02）
- 追溯：CAP-02、CAP-05、BR-01、BR-02

### FR-005 — 请款时生成价格快照
- **当** 购物车被确认购买时
- **系统应当** 仅评估一次促销，并存储不可变的**价格快照**，其中记录商品价格、规则集版本、已应用规则、各规则贡献及逐行总计（BR-06）
- 追溯：CAP-02、BR-05、BR-06

### FR-006 — 请款后不重算
- **当** 任何请款后路径（履约、退款、调整、报告）需要价格时
- **系统应当** 读取已存储的价格快照，绝不重新评估促销（BR-06）
- 追溯：CAP-02、BR-06

## CAP-03 结算与支付

### FR-007 — 托管支付字段
- **当** 客户输入支付信息时
- **系统应当** 呈现托管支付字段，使任何平台组件都不会接收、传输或存储主账号，并且仅保留令牌引用（BR-10）
- 追溯：CAP-03、BR-10、CTL-01

### FR-008 — 幂等的资金授权
- **当** 支付获得授权时
- **系统应当** 要求使用由平台签发的幂等键，将同一幂等键的重复提交合并为一次授权，并将该键与由此产生的资金操作一并记录（BR-07）
- 追溯：CAP-03、BR-07

### FR-009 — 基于授权进行请款
- **当** 订单被确认进入履约时
- **系统应当** 在同一幂等键下对已授权金额进行请款，或者拒绝请款并将订单转入其取消路径（BR-03、BR-07）
- 追溯：CAP-03、CAP-06、BR-07

### FR-010 — 多路径幂等键覆盖
- **当** 资金操作由任一渠道发起时（网页、小程序、POS、第三方平台）
- **系统应当** 由平台为其签发幂等键，包括 PSP 自身的幂等机制未覆盖的路径（BR-07）
- 追溯：CAP-03、CAP-09、BR-07

## CAP-04 库存

### FR-011 — 可用库存作为计算视图
- **当** 请求可用库存时
- **系统应当** 按来源将其计算为实物库存减去库存占用和在途承诺，不得仅将其作为存储字段（BR-01）
- 追溯：CAP-05、BR-01

### FR-012 — 扣减时点强制执行
- **当** 订单推进时
- **系统应当** 恰好在该商品声明的策略节点（确认时或请款时）消耗库存，绝不可在两个节点均消耗（BR-01）
- 追溯：CAP-05、CAP-06、BR-01

### FR-013 — 到期驱动的释放
- **当** 预留过期且未发生消耗时
- **系统应当** 自动释放该预留，并将此次释放记录为事件（BR-02）
- 追溯：CAP-05、BR-02

### FR-014 — 跨渠道单次扣减
- **当** 订单的履约跨越渠道时（线上购买、到店自提）
- **系统应当** 仅在经解析确定的单一来源处扣减一次库存，并记录该来源（BR-01、BR-15）
- 追溯：CAP-05、CAP-07、BR-01、BR-15

### FR-015 — 超卖防护
- **当** 可用库存不足时尝试执行消耗
- **系统应当** 拒绝该次消耗，保留该预留，并将订单转入取消路径，同时记录原因（BR-03）
- 追溯：CAP-05、BR-01、BR-03

## CAP-05 订单生命周期

### FR-016 — 跨渠道统一状态机
- **当** 订单发生状态转换时
- **系统应当** 在每个渠道采用相同的状态名称、状态转换和时间戳，不得使用渠道专属的状态词汇（BR-14）
- 追溯：CAP-06、BR-14

### FR-017 — 按既定节点取消
- **当** 请求取消时
- **系统应当** 确定取消节点，仅释放尚未消耗的预留；若资金已请款，则启动退款；并记录原因（BR-03、BR-04）
- 追溯：CAP-06、BR-03、BR-04

## CAP-06 履约

### FR-018 — 履约时的来源选择
- **当** 订单被路由至履约时
- **系统应当** 根据适用策略为每个行项目选择来源，反映选择时点而非请款时的可用库存（BR-15）
- 追溯：CAP-07、BR-15

### FR-019 — 逐行履约状态
- **当** 发生部分发货、部分退货或部分取消时
- **系统应当** 逐行记录履约状态，并据此推导订单级状态（BR-11）
- 追溯：CAP-07、BR-11

## CAP-07 售后

### FR-020 — 带处置方式的退货授权
- **当** 请求退货时
- **系统应当** 以明确的处置方式授权退货——**重新入库**或**报废**——该处置方式在授权时确定，而非在收货时确定（BR-12）
- 追溯：CAP-08、BR-12

### FR-021 — 退款作为独立操作
- **当** 因任何原因需要退款时（退货、取消、善意补偿、拒付/争议）
- **系统应当** 在新的幂等键下发起一项新的资金操作，并将其关联到原始订单行项目和原请款操作（BR-08、BR-09）
- 追溯：CAP-08、CAP-03、BR-08、BR-09

### FR-022 — 冲正路径不是镜像
- **当** 冲正执行时
- **系统应当** 通过其自身的状态和资金操作执行冲正，重新读取当前库存状态和资金状态，而非反转正向路径（BR-09）
- 追溯：CAP-08、BR-09

## CAP-08 对账

### FR-023 — 变动账本
- **当** 发生资金或库存变动时
- **系统应当** 将其追加到不可变账本，其中包含操作、键、操作者、渠道、时间戳，以及其派生所依据的快照或读数
- 追溯：CAP-10、BR-07、BR-13

### FR-024 — 差异关闭程序
- **当** 执行对账时
- **系统应当** 从账本计算预期值，从 PSP/承运商/库存计算实际值，并针对每种对账差异类型执行关闭程序；仅对无法关闭的差异进行升级，并记录其存续时长（BR-13）
- 追溯：CAP-10、BR-13

## CAP-09 渠道

### FR-025 — 将渠道声明为变体
- **当** 渠道正式投运时
- **系统应当** 要求提供其声明信息（输入路径、支付路径、身份处理方式、履约来源），并在启用该渠道前验证 PCI 处理情况（BR-10、BR-14）
- 追溯：CAP-09、BR-10、BR-14

### FR-026 — 渠道接入闸门
- **当** 渠道无法满足托管支付字段要求时
- **系统应当** 阻断该渠道的启用，或记录一项明确例外，并注明负责人和到期时间（BR-10）
- 追溯：CAP-09、BR-10、CTL-01

## CAP-10 平台

### FR-027 — 资金权限分离
- **当** 用户尝试执行超过既定阈值的资金操作时（授权、退款、调整）
- **系统应当** 要求具备相应权限，并拒绝仅拥有履约权限或服务查看权限的操作人员
- 追溯：CAP-10、BR-07、BR-13

### FR-028 — 快照与账本保留
- **当** 存在价格快照或账本变动时
- **系统应当** 在既定保留期内保留该对象，并在拒付/争议及审计路径中将其视为证据
- 追溯：CAP-10、BR-06、BR-13
