# 03-domain / 术语表

> 此处定义的术语在整个方案包中含义唯一；后文不会引入同义词。`Source` 记录依据：**[AGENTS]** 本方案包的 `AGENTS.md` 设计立场，**[PACK]** 本方案包的定义，**[CONV]** 无单一标准的行业惯例，**[PCI]** PCI Security Standards（一种指定，不引用具体条款）。

## 1. 商品与渠道

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Product master / PIM** | 商品主数据 | 所有渠道均读取同一份所售商品描述。 | [PACK] |
| **Channel variant** | 渠道变体 | 在共享主数据之上以**配置**表达的渠道专属属性或行为。 | [AGENTS] |
| **Channel fork (anti-pattern)** | 渠道分叉 | 拥有自身订单、库存或定价模型的渠道。由此产生的订单对其他渠道不可见。 | [PACK] |
| **Marketplace** | 第三方平台 | 商家开展销售的外部第三方平台——属于另一个渠道，并遵循自身规则。 | [CONV] |
| **Listing feed** | 刊登数据流 | 从主数据向第三方平台输出的投影。 | [CONV] |
| **SKU** | 最小存货单位 | 商品的可售单位。 | [CONV] |
| **Taxonomy** | 分类体系 | 渠道对外提供的分类结构。统一共享，不重新设置键值。 | [PACK] |

## 2. 定价与促销

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Price list** | 价格表 | 按商品、渠道、货币和受众划分的价格。 | [CONV] |
| **Promotion rule** | 促销规则 | 一项明示条件，在符合资格时产生折扣贡献。 | [CONV] |
| **Stacking / exclusivity** | 叠加与互斥 | 促销是否可组合使用。对此的表达就是产品本身。 | [PACK] |
| **Pricing snapshot** | 价格快照 | 在请款时评估促销所得的冻结结果：商品价格、已应用的规则、每条规则的贡献、逐行总计，以及生成该结果的**规则集版本**。 | [AGENTS] |
| **Recompute after capture (anti-pattern)** | 捕获后重算 | 订单完成请款后重新评估促销。客户可能在付款过程中失去某项促销。 | [AGENTS] |
| **Ruleset version** | 规则集版本 | 所用促销规则集的标识符，记录在快照中，使过往订单可复现。 | [PACK] |
| **Displayed price** | 展示价 | 向客户展示的内容。是一项**记录**，而非渲染结果。 | [PACK] |

## 3. 购物车、结算与支付

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Cart** | 购物车 | 客户经定价的购买意向，并针对每个行项目设有库存占用策略。 | [CONV] |
| **Hold policy** | 库存占用策略 | 按商品设定：在加入购物车时、确认时、请款时或履约时进行预留——可逆占用应设置过期时间。 | [AGENTS] |
| **Reserve** | 预留 | 一种可逆扣减。若客户未付款，必须过期或被妥善释放。 | [PACK] |
| **Consume** | 消耗 | 一种不可逆扣减。该商品已承诺用于发货。 | [PACK] |
| **Checkout** | 结算 | 采集配送信息、身份和支付意图。 | [CONV] |
| **PSP-hosted fields** | 托管支付字段 | 由支付服务提供商呈现的支付输入项，使卡数据不会进入平台处理流程。这是承载支付合规范围排除的架构。 | [AGENTS] |
| **Tokenisation** | 令牌化 | 用可用于后续操作的引用替换卡数据。 | [PCI] |
| **PCI scope exclusion** | 支付合规范围排除 | 主张核心系统不在卡数据适用范围内——必须**予以证明**并有证据支撑，而非仅仅作出声明。 | [AGENTS]/[PCI] |
| **Idempotency key** | 幂等键 | 平台为每项资金操作签发的键，使重试合并为一次操作，而非重复扣款。PSP 自身的键并不足够——它无法覆盖 POS 或第三方平台路径。 | [AGENTS] |
| **Capture** | 请款 | 将已授权金额转为已结算金额。 | [CONV] |
| **Refund** | 退款 | 这是其**自身**的资金操作，并有自己的幂等键——不是一笔负向扣款。 | [AGENTS]/[PACK] |
| **Reconciliation spec** | 对账规格 | 对资金和库存变动所应达到状态的明确预期，以及**消除**差异的程序。它是规格，而不是报告。 | [AGENTS] |

## 4. 库存

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Availability** | 可用库存 | 可售数量——由实物库存、库存占用、预留和在途订单共同决定。 | [PACK] |
| **Oversell** | 超卖 | 销售并不存在的商品。`AGENTS.md` 中的头号大忌；本方案包的存在正是为了跨渠道防止这种情况。 | [AGENTS] |
| **Negative inventory** | 负库存 | 超卖未得到纠正后形成的持久状态。 | [PACK] |
| **Inventory count / adjustment** | 盘点与调整 | 实物库存与系统库存之间的对账及其更正。 | [CONV] |
| **Cross-channel deduction** | 跨渠道扣减 | 履约跨越渠道的订单（在线购买、到店自提）必须**只在一处扣减一次**。 | [PACK] |
| **Reservation expiry** | 预留过期 | 自动释放可逆的库存占用，使被放弃的购物车不再锁定库存。 | [PACK] |
| **Atomically scarce resource** | 原子性稀缺资源 | 库存之所以棘手的原因：两个客户、两个渠道、最后一件商品，而且该故障只有在负载下才会复现。 | [PACK] |

## 5. 订单生命周期

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Order** | 订单 | 每项下游能力都会读取的有状态承诺对象。 | [CONV] |
| **Order state machine** | 订单状态机 | 状态及转换的定义，在**每个渠道均以完全相同的方式公开**。这是支撑体系的关键决策，而不是工作流。 | [AGENTS] |
| **Paid but not accepted** | 已付未受理 | 资金已收取但履约尚未开始的状态。必须能够进入并得到解决。 | [PACK] |
| **Accepted but stock gone** | 已受理未到货 | 订单已受理但库存已无货，因而需要取消，并可能需要退款。 | [PACK] |
| **Cancellation** | 取消 | 在履约前终止订单，并确定退款路径。 | [PACK] |
| **Return / RMA** | 退货/退货授权 | 履约后的逆转：授权、接收、重新入库或报废。 | [CONV] |
| **Restock vs. scrap** | 重新入库 vs. 报废 | 退回件有两种处置方式——一种使其重新计入可用库存，另一种则不会。 | [PACK] |
| **Partial fulfilment** | 部分履约 | 部分行项目已发货，部分已取消，部分已退款。歧义会在这种状态下对客户造成损害。 | [PACK] |
| **Ambiguous state (anti-pattern)** | 模糊状态 | 在不同渠道含义不同的状态。会造成面向客户的后果，而不只是出现在日志中。 | [PACK] |

## 6. 售后冲正与账本

| 术语（英） | 中文 | 定义 | 来源 |
|---|---|---|---|
| **Ledger** | 账本 | 资金和库存变动的仅追加记录，数字由此推导，争议由此解决。 | [PACK] |
| **Reversal** | 冲正 | 通过其自身的状态转换和资金操作撤销一项承诺——绝不通过镜像正向路径实现。 | [AGENTS]/[PACK] |
| **Inverse operation (anti-pattern)** | 逆操作（反模式） | 将退款视为负向扣款，或将退货视为负向发货。当目标已进入后续状态时，这种做法就会失败。 | [PACK] |
| **Dispute / chargeback** | 拒付/争议 | 由持卡人发起、与退款进入同一账本的冲正。 | [CONV] |
| **Reconciliation gap** | 对账差异 | 预期值与实际值之间的差异。其**存续时长**才是指标：持续未关闭的差异属于缺陷，而不是报表。 | [PACK] |
| **Idempotent retry** | 幂等重试 | 使用同一个键重复执行操作，并合并为一次效果。这是常规路径，而不是错误路径。 | [AGENTS] |

## 7. 约定

- **"must not"** 标记违反即构成缺陷的规则——促销不得在请款后重算；资金操作不得在没有平台签发键的情况下进行；渠道不得分叉核心；退货不得建模为负向发货。
- **无同义词**：本方案包将 **预留** 与 **消耗** 用作不同的库存语义，将 **快照** 与 **重算** 用作不同的定价行为，并将 **退款** 与 **拒付** 用作不同的资金操作。
- 本方案包与同级方案包共享同一套可复现性规范：`growth-analytics` 要求使用带版本的模式，以便解读历史数据；`telecom-bss` 要求扣费事件不可变。同样的规则在此分别体现为价格快照和仅追加账本。
