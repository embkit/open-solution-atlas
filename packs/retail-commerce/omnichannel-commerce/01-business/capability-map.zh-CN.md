## 1. L1 能力

| # | 能力 | 必须回答的问题 | 备注 / L1 定位 |
|---|---|---|---|
| **01** | **商品主数据 (PIM)** | 我们销售什么，只描述一次 | 渠道属性是**变体**，而非重新设键的副本 |
| **02** | **定价与促销** | 客户支付什么 | 在请款时评估并形成**价格快照**；此后绝不重算 |
| **03** | **购物车与结算** | 购买意向如何成为承诺 | 按策略定价；按策略预留 |
| **04** | **支付抽象** | 资金如何流动且仅流动一次 | 托管支付字段；由**平台**签发的幂等键 |
| **05** | **库存** | 商品是否确实存在 | 稀缺资源；**超卖是头号大忌** (`AGENTS.md`) |
| **06** | **订单生命周期与状态机** | 该订单在各处的状态是什么 | 核心支撑构件 (`AGENTS.md`) |
| **07** | **履约与路由** | 商品从哪里来，如何送达 | 跨渠道路由、到店自提 |
| **08** | **售后** | 承诺如何撤销 | 退货、退款、取消——**不是**逆操作 |
| **09** | **渠道变体** | 新渠道界面如何在不分叉的情况下接入 | 小程序/POS 均为**变体** (`AGENTS.md`) |
| **10** | **账本、对账与风险** | 记录是否与现实一致 | 资金和库存变动记入仅追加账本；差异应予**消除**，而非调查 |

## 2. 边界（各项能力*不*负责什么）

| 能力 | 明确**不属于**其职责范围 |
|---|---|
| 01 商品主数据 | 渠道专属渲染——由渠道呈现；01 负责描述 |
| 02 定价与促销 | 创造折扣——营销团队拥有规则；02 负责评估 |
| 03 购物车与结算 | 划转资金——这是 04 的职责；结算提出请求，04 执行 |
| 04 支付 | 判定某笔扣款有误——由 08 处理冲正；04 执行 |
| 05 库存 | 决定履约来源——02 定价，07 路由，05 掌握实际存在的内容 |
| 06 订单生命周期 | 执行支付或发货——它负责记录和驱动，由 04/07 执行 |
| 07 履约 | 将退回商品重新入库——这是 08 的库存操作 |
| 08 售后 | 发起负向扣款——退款是一项独立的资金操作 |
| 09 渠道 | 拥有订单模型的变体——变体负责配置；不会造成分叉 |
| 10 账本与风险 | 裁定争议——它负责检测并提供证据；由人员解决 |

> 有两条边界支撑整个方案包。**02**：请款后重算的促销，就是客户可能在付款过程中失去的促销。**08**：退款不是负向扣款，退货也不是负向发货，因此冲正应拥有独立状态和受幂等保护的独立资金操作——而不是正向路径的镜像。

内容完整到足以讨论，但尚不足以用于估算；有意不说明相对难度。

## 4. 整个平台的范围外事项

- **PSP 本身**——平台负责与其集成；不会成为 PSP。
- **实体仓库运营**——WMS 执行；本方案包负责向其路由。
- **商品经营策略**——决定销售什么；本方案包描述所售商品。
- **ERP 总账**——平台负责过账，总账位于其他系统。
- **营销内容和活动设计**——促销引擎所评估的规则除外。
- **欺诈模型**——作为信号使用；模型属于 `data-ai` 范畴。
