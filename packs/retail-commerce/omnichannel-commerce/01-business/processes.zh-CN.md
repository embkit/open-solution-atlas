# 01-business / 流程

> 全渠道商务平台的流程定义。每个流程均说明其触发条件、执行步骤以及**约束这些步骤的规则**。业务规则位于 `business-rules.md`（BR-xx）中；此处仅作引用，绝不重述。
>
> ⚠️ ASSUMPTION — 流程分解属于方案包设计。此处未引用任何外部标准。

## P-01 — 浏览与定价

| | |
|---|---|
| **触发条件** | 客户（或渠道）请求商品或某个商品 |
| **结果** | 面向该渠道的、已定价且符合资格的供应商品视图 |

**步骤**

1. 从共享的商品主数据中解析商品（渠道属性以变体形式应用，绝不形成渠道分叉——BR-14）。
2. 从适用的价格表解析价格（渠道、货币、受众）。
3. **依据当前生效的规则集**评估促销规则，生成已定价结果，并逐行给出折扣贡献（BR-05）。
4. 此时不记录任何内容——浏览时的展示价不构成承诺。

> BR-05 规定：展示价仅是一种*展示*，只有在录入价格快照时才会成为**记录**（P-03）。

## P-02 — 购物车

| | |
|---|---|
| **触发条件** | 客户将商品加入购物车 |
| **结果** | 已应用商品库存占用策略的已定价购物车行项目 |

**步骤**

1. 依据当前生效的规则集重新为该行定价（BR-05）。
2. 应用商品的**库存占用策略**（BR-01）：
   - **预留**——可逆；必须设置过期时间；
   - **不占用**——仅提供可用库存提示。
3. 绝不在没有过期时间的情况下创建预留（BR-02）。

> 永不过期的购物车预留，就是被已放弃会话锁定的库存。BR-02 将过期机制设为结构性要求，而不是定时清理任务。

## P-03 — 结算与请款

| | |
|---|---|
| **触发条件** | 客户确认购物车并进行购买 |
| **结果** | 订单、**价格快照**和已授权的支付 |

**步骤**

1. **重新定价并冻结**——最后一次评估促销，并存储**价格快照**：商品价格、已应用的规则、每条规则的贡献、逐行总计以及**规则集版本**（BR-05、BR-06）。
2. 应用商品的**消耗策略**——从此时起，该商品即被承诺用于履约，因此消耗不可逆（BR-01）。
3. 收集配送信息、身份信息和支付意图；卡数据字段由 PSP 呈现，属于托管支付字段，绝不进入平台（BR-10）。
4. 使用**平台签发的幂等键**对资金操作进行授权（BR-07、BR-08）。
5. 创建状态为 `captured` 的订单。
6. **此后不允许进行任何重算**（BR-06）。

> 第 1 步保证客户在付款过程中不会失去折扣。第 6 步则将这一保证落到实处，而非仅停留于期望层面。

## P-04 — 履约

| | |
|---|---|
| **触发条件** | 状态为 `captured` 或 `accepted` 的订单 |
| **结果** | 商品已发运、交付或自提；订单已推进 |

**步骤**

1. 选择履约来源：仓库、门店或供应商代发（BR-15）。
2. 如果在请款时尚未消耗库存，则在所选来源处预留库存。
3. 创建发货单；发货单可以仅涵盖部分行项目（BR-11）。
4. 发货完成时，将订单转为 `fulfilled`；失败时，转为 `cancelled`，并确定其退款路径（P-07）。

> 部分发货是一种独立状态，而不是部分成功标志。BR-11 要求按行项目记录履约状态。

## P-05 — 售后：退货与退款

| | |
|---|---|
| **触发条件** | 退货请求，或已支付订单的取消 |
| **结果** | 承诺已冲正，资金已划转，库存已重新入库或报废 |

**步骤**

1. 授权退货并确定处置方式（BR-12）：**重新入库**（重新计入可用库存）或**报废**（不重新计入可用库存）。
2. 接收实物商品。
3. 将退款作为一项**新的资金操作**签发，并使用**新的幂等键**——绝不作为负向扣款（BR-08、BR-09）。
4. 根据第 1 步重新入库或报废。
5. 通过冲正路径推进订单。

> BR-09 是支撑性规则：冲正路径不是正向路径的镜像，因为目标可能已进入后续状态。将退款建模为负向扣款，恰恰会在原扣款此后已结算或已退款时失败。

## P-06 — 资金结算与对账

| | |
|---|---|
| **触发条件** | 定时执行，或按需执行 |
| **结果** | 资金和库存变动已完成对账；差异已关闭或已升级处理 |

**步骤**

1. 根据账本计算预期变动（订单、请款、退款、发货、退货）。
2. 根据 PSP、承运商和库存系统计算实际变动。
3. 比对差异，并按照对账规格**关闭**差异——不能仅作报告（BR-13）。
4. 对无法自动关闭的差异进行升级处理，并跟踪其存续时长。

## P-07 — 取消与补偿

| | |
|---|---|
| **触发条件** | 取消请求、请款时库存不足，或支付失败 |
| **结果** | 订单已取消，库存已释放，资金已退回 |

**步骤**

1. 确定取消节点——这决定必须撤销的内容（BR-03）。
2. 释放所有尚未消耗的预留（BR-01、BR-04）。
3. 如果资金已完成请款，则通过 P-05 第 3 步签发退款。
4. 记录取消及其原因。

> “已受理未到货”（BR-03）正是这样一种情形：如果未将其作为独立的标准路径处理，就会对客户造成伤害——客户已被告知该商品归其所有。

## P-08 — 渠道接入

| | |
|---|---|
| **触发条件** | 新的销售界面投入使用 |
| **结果** | 在共享核心之上运行的渠道 |

**步骤**

1. 将该渠道声明为**变体**：其属性、支付路径、身份处理方式和履约来源（BR-14）。
2. 按照渠道契约实现渠道适配器。
3. 验证该渠道的支付合规范围排除（BR-10）。
4. 启用。

> 无法满足第 3 步的渠道没有可证明的支付合规范围排除，只有在存在明确且已记录的例外时才可启用。
