# 00-context / 利益相关方

## 1. 组织

| 组织 | 职责 | 系统关系 |
|---|---|---|
| **商品管理/产品管理** (商品) | 负责商品目录、价格、商品关联和生命周期 | 拥有商品主数据 |
| **定价与促销管理** (价格与促销) | 负责促销规则和资格条件 | 制定快照所评估的规则集 |
| **交易平台工程** (交易平台研发) | 构建购物车、结算、订单和履约功能 | 拥有平台核心 |
| **库存/供应链** (库存与供应链) | 负责实物库存、盘点和补货 | 稀缺资源的上游权威数据源 |
| **支付/资金管理** (支付) | 管理 PSP 关系、请款、退款和结算 | 使用支付抽象 |
| **欺诈与风控** (风控) | 风险评分、拒付、阻断 | 使用订单/结算信号 |
| **客户服务** (客服) | 订单查询、取消、退款、争议 | 订单状态机使用量最大的消费方 |
| **物流/履约** (履约) | 路由、发货、门店自提、退货物流 | 订单的下游使用方 |
| **渠道所有者** (渠道运营) | 负责各个触点：网页、小程序、POS、第三方平台 | 提供渠道变体 |
| **财务/会计** (财务) | 收入确认、结算、对账 | 使用资金账本和库存账本 |
| **安全/合规** (安全合规) | PCI 合规范围、个人数据和审计 | 约束所有能力 |
| **第三方平台运营方** (平台方) | 商家开展销售所依托的外部第三方平台 | 另一个渠道，遵循自身规则 |
| **卡组织/PSP** (支付机构) | 资金流转和托管支付字段 | 集成对手方 |

### 非人类参与者

| 参与者 | 说明 |
|---|---|
| **商品主数据 / PIM** | 共享目录；渠道属性是其变体 |
| **定价与促销引擎** | 将规则求值为**快照**；请款后绝不重算 |
| **购物车与结算服务** | 定价、按策略预留、对支付意图执行请款 |
| **支付抽象** | 托管支付字段、令牌化、幂等键 |
| **库存服务** | 稀缺资源：预留、消耗、释放、盘点 |
| **订单编排** | 驱动履约、冲正和售后流程 |
| **履约与路由** | 发货、门店自提、配送、跨渠道路由 |
| **风控服务** | 风险评分和阻断，在结算时使用 |
| **对账引擎** | 按规格关闭资金和库存差异 |
| **幂等键服务** | 为资金操作签发键并去重 |
| **渠道适配器** | 小程序、POS、第三方平台——单一核心的变体 |
| **事件总线 / 账本** | 供资金和库存推导的仅追加记录 |

## 3. 作为参与者的外部/上游—下游系统

- **PSP 与支付工具**——托管支付字段、授权、请款、退款。以此证明 PCI 合规范围边界。
- **承运商与物流服务商**——生成面单、发货、追踪、退货。
- **ERP/会计**——库存记账和收入。
- **第三方平台**——订单数据流、商品目录数据流、库存数据流、结算。
- **税务引擎**——按辖区区分含税价与不含税价。
- **身份/客户主数据**——跨渠道识别购买者。
- **忠诚度/CRM**——订单的下游使用方。
- **卡组织/争议网络**——拒付和拒付抗辩。
- **商品数据池/GS1**——渠道数据交换。
- **仓储管理**——实物作业。

## 4. 参与者首要目标

- **客户**：向我展示的价格就是我支付的价格；我购买的商品确实存在；我可以从任何渠道查看我的订单；退货流程能够正常完成。
- **商品运营**：一次发布商品即可覆盖所有渠道，无需按渠道重新录入属性。
- **定价**：更改促销规则，但不改变已请款订单的含义。
- **库存**：绝不销售不存在的商品，也绝不继续占用客户已放弃的库存。
- **支付**：只扣款一次，只退款一次，并知道两个账本何时出现差异。
- **客服**：了解订单所处状态，并能安全撤销订单，而不会造成二次退款。
- **风控**：在请款前实施阻断，而不是发货后才实施。
- **安全/PCI**：证明而非仅仅声称卡数据从未进入核心系统。
- **渠道所有者**：以配置方式添加渠道，而不是进行分叉。

> ⚠️ ASSUMPTION: 本方案包假定**一个由所有渠道共享的商品主数据**和**一个库存池**——在真实部署中，二者均可按渠道划分，但一旦如此，“一个数字、一个价格、一项承诺”就不再是平台自身的属性，而成为部署方必须声明的策略。
