# 02 · 功能需求

> EARS 句式：`当 <触发条件> 系统应当 <响应>`。
> 稳定 ID 永久有效；每项需求均追溯至一项能力（`CAP-xx`）、一项规则（`BR-xx`）和
> 一项 ADR。验收标准（AC-*）定义在 L3。
>
> `verification: unverified` — 这些需求属于方案包设计，尚未
> 针对实际部署进行验证。

## CAP-01 客户与当事方

### FR-001 — 客户、账户和服务点是不同对象
- **当** 客户入驻时
- **系统应当** 创建一条客户记录、一个或多个各自具有独立生命周期的账户，以及一个或多个服务点，并且不应当将其身份合并到一条记录中
- 追溯：CAP-01、BR-05

## CAP-02 商业产品目录

### FR-002 — 具有规格说明的产品提供物
- **当** 商业产品提供物发布时
- **系统应当** 要求附有规格说明，说明该产品提供物在资源层面意味着什么以及如何验证资源实现，并且不应当在缺少规格说明的情况下发布（BR-03）
- 追溯：CAP-02、CAP-03、BR-01、BR-03、ADR-0002

### FR-003 — 商业变更独立性
- **当** 资费计划、资格规则或促销发生变更时
- **系统应当** 在不更改技术与资源目录、且无需网络工程人员参与的情况下应用该变更（BR-01、BR-05）
- 追溯：CAP-02、CAP-04、BR-01、BR-05、ADR-0001

## CAP-04 技术与资源目录

### FR-004 — 资源实现
- **当** 产品提供物的规格说明被解析时
- **系统应当** 生成用于实现该产品提供物的逻辑资源、物理资源及激活路径集合，且不同产品提供物的这些集合可能有所不同
- 追溯：CAP-03、CAP-04、BR-03

## CAP-06 订单管理与编排

### FR-005 — 分解链
- **当** 客户订单得到确认时
- **系统应当** 将其分解为业务订单和资源订单，记录 CO → SO → RO 关联，并支持入向和出向遍历（BR-04）
- 追溯：CAP-06、BR-04、ADR-0004

### FR-006 — 双向追溯
- **当** 某个流程、费用或库存变更被追溯时
- **系统应当** 回答全部三个问题：为何失败（CO→RO）、为何被收费（费用→CO），以及我启用了什么（RO→库存变更）
- 追溯：CAP-06、CAP-10、BR-04、BR-12

### FR-007 — 部分失败处理
- **当** 分解仅部分完成时
- **系统应当** 记录哪些域已成功，继续执行其余部分，并明确取消尚未完成的步骤——绝不通过撤销已完成步骤来取消（BR-07）
- 追溯：CAP-06、BR-07、ADR-0003

## CAP-07 计费与计费事件

### FR-008 — 规则版本标记
- **当** 计算一项费用时
- **系统应当** 确定适用的带生效日期规则版本，并将其记录在事件上（BR-08）
- 追溯：CAP-07、BR-08、ADR-0005

### FR-009 — 跨账期拆分
- **当** 一个账期跨越某个生效日期时
- **系统应当** 依据评估结果将每个规则版本应用于其各自适用的期间，而非由操作员决定（BR-08）
- 追溯：CAP-07、BR-08

### FR-010 — 计费事件不可变性
- **当** 一个计费事件已经生成时
- **系统应当** 阻止对该事件的任何更新或删除，并将任何更正转至新的事件处理（BR-09）
- 追溯：CAP-07、BR-09、ADR-0003

### FR-011 — 经批准的更正
- **当** 读数异常或已知计费错误得到更正时
- **系统应当** 要求在更正生效前完成审批工作流，并且不应当更改原始账单（BR-10）
- 追溯：CAP-07、CAP-08、BR-10、ADR-0005

## CAP-08 计费与开票

### FR-012 — 仅限接口的配电系统集成
- **当** 本套件与配电系统交换数据时
- **系统应当** 仅使用已声明的接口，并且不应当公开 SCADA 控制界面或直接读取网络状态（BR-02）
- 追溯：CAP-06、CAP-04、BR-02、ADR-0001

### FR-013 — 接口契约执行
- **当** OMS 或故障管理系统提供资源状态时
- **系统应当** 通过接口接收该状态，并且不应当据此计算费用（BR-02）
- 追溯：CAP-06、CAP-07、BR-02

### FR-014 — 发票可重算性
- **当** 因争议、审计或更正而重算发票时
- **系统应当** 依据计费事件以及各事件计算时所依据的规则版本重现该发票（BR-11）
- 追溯：CAP-08、BR-11、ADR-0003

## CAP-10 对账、报告与隐私生命周期

### FR-015 — 订单侧对账
- **当** 对账运行时
- **系统应当** 将每项计费事件归属于一个订单，并报告无法归属于任何订单的费用（BR-12）
- 追溯：CAP-10、BR-12

### FR-016 — 库存侧对账
- **当** 对账运行时
- **系统应当** 将计费事件与库存使用情况进行对账，并报告无主使用和无费激活（BR-12）
- 追溯：CAP-10、CAP-05、BR-12

### FR-017 — 按类别设定保留期
- **当** 保留、归档或处置数据时
- **系统应当** 应用其所属类别所声明的保留期，并且不应当采用单一的全局设置（BR-13）
- 追溯：CAP-10、BR-13、CTL-04

## CAP-09 保障与客服

### FR-018 — 信息完整的客服受理
- **当** 客户联系 95598 或创建客服工单时
- **系统应当** 在无需转接的情况下呈现账户、计量表、读数历史、未付款项以及任何影响相关情况的故障中断（BR-06）
- 追溯：CAP-09、BR-06、BR-02

### FR-019 — 故障单
- **当** 识别出保障问题时
- **系统应当** 创建与服务实例及商业关系关联的故障单，并通过接口调度现场作业（BR-02、BR-06）
- 追溯：CAP-09、BR-02、BR-06

## CAP-10（续）

### FR-020 — 接口词汇
- **当** 定义 BSS 与 OSS 之间的新接口时
- **系统应当** 使用 ODA 组件词汇和 TMF Open API 词汇对其进行表述，并且不应当声称尚未确立的成熟度级别或 API 版本（BR-14）
- 追溯：CAP-10、BR-14、ADR-0005

### FR-021 — 断开连接护栏评估
- **当** 提议断开连接时
- **系统应当** 将资格类别、通知期限和限制期限作为强制执行的流程状态进行评估，并在任一护栏未通过时阻断断开操作（BR-15）
- 追溯：CAP-10、BR-15、CTL-05

### FR-022 — 护栏审计
- **当** 执行断开连接或重新连接时
- **系统应当** 将护栏评估及其输入和结果记录为该决策及其依据的完整记录（BR-15）
- 追溯：CAP-10、BR-15、CTL-05
