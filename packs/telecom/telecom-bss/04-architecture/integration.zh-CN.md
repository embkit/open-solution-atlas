# 04 · 集成

> 面向外部系统和 BSS/OSS 边界的集成契约。ID 保持稳定；每个流程都可追溯至需求和规则。
>
> ⚠️ ASSUMPTION — 接口选择和协议属于方案包设计。TM Forum ODA 和 TMF Open API 作为**词汇**被采用（BR-14）；不主张任何 API 版本。

## I. 外部集成点

| ID | 合作方 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **分销 / OMS** | 双向 | 资源订单履约和状态反馈——**该边界** |
| **I-02** | **AMI / 计量网络** | 入站 | 自动读数接入 |
| **I-03** | **现场作业管理** | 双向 | 为表计服务派工并记录完工 |
| **I-04** | **支付渠道** | 入站 | 实际催收结果 |
| **I-05** | **资金管理 / 会计** | 出站 | 收入与结算 |
| **I-06** | **服务中断通知** | 双向 | 服务中断事件与客户通知 |
| **I-07** | **监管报告** | 出站 | 法定报告 |
| **I-08** | **欺诈 / 风险** | 入站 | 通话详单与订单级信号 |
| **I-09** | **通知网关** | 出站 | 包括断开连接前通知在内的通知事项 |

## F. 内部流程

### F-01 — 销售
1. 由参与方解析出客户、账户和服务点。
2. 商业产品目录解析出产品提供物及其资费计划。
3. **规格说明**解析出该产品提供物在资源层面的含义。
4. 创建客户订单。**不查询网络状态**（BR-01）。

### F-02 — 分解
1. 规格说明产生服务实例。
2. 为每项服务创建业务订单。
3. 为每项资源创建资源订单，并以**双向**方式记录关联（BR-04）。

### F-03 — 履约
1. 每个 RO 均通过接口路由至 OSS 侧（BR-02）。
2. 执行预留、激活并报告状态；一个域可能失败，而其他域仍会成功。
3. 状态向上传播至 SO 和 CO（BR-04）。
4. 对部分完成情况进行显式处理，绝不回退已完成的步骤（BR-07）。

### F-04 — 计费与出账
1. 使用事件、周期性事件或激活操作触发计费。
2. 解析**带生效日期的规则版本**，并将其标记在计费事件上（BR-08）。
3. 发出计费事件，该事件随即不可变（BR-09）。
4. 账期结束时，各项费用汇总为一张发票；发票包含所使用的规则版本，并可依据其事件进行发票重算（BR-11）。

### F-05 — 服务
1. 创建 95598 案例，并从账户、表计、读数历史、付款和服务中断上下文中解析出客户的实际情况（BR-06）。
2. 将故障单与服务实例关联。
3. 通过接口派发现场作业（BR-02）。
4. 记录结案及其解决结果。

### F-06 — 对账
1. 从仅追加存储中读取计费事件。
2. 对账以**双向**方式进行：与订单（BR-12）进行对账，并与库存使用（BR-12）进行对账。
3. 上报发现的泄漏问题——无主使用、无费激活——并进行账龄跟踪（NFR-004）。

### F-07 — 断开 / 重连
1. 拟执行该操作。
2. 流程**评估**资格类别、通知期限和限制期，并将其作为强制执行状态（BR-15）。
3. 任何未通过的护栏都会阻断该操作。
4. 将评估、其输入和结果记录为完整的决策记录（FR-022）。

## 故障模式契约

| 集成 | 必须应对的故障模式 |
|---|---|
| **I-01 Distribution/OMS** | OSS 侧不可用不得导致商业订单路径失败；履约状态为*未知*，且链路应记录该状态。绝不可假定已激活 |
| **I-02 metering** | 错过采集窗口会产生**异常**（P-04），绝不生成静默估算的读数——估算只能依据规则作出并加以标记（术语表中 BR-15 的相邻条目，见 `00-context` §3） |
| **I-04 payment** | 渠道超时属于*未知*状态，通过资金查询解决——绝不能通过重试而产生第二笔贷记 |
| **I-06 outage** | 服务中断事件为客服上下文补充信息（BR-06）；信息流不可用只会使上下文降级，绝不会影响案例 |
| **I-08 fraud** | 风险信号不可用时，对受影响操作执行 fail-closed（失败即阻断），而不是绕过 |
| **I-07 reporting** | 报告失败会阻断报告，绝不静默缩小其范围 |

> 这一模式：外部系统不可用时，外部路径会降级，并记录为*未知*——绝不假定结果。欺诈是唯一采用 fail-closed 的情形，因为绕过控制会使控制沦为装饰。

## 接口契约（必须声明的内容）

| 方面 | 接口必须声明的内容 |
|---|---|
| **载荷结构** | 资源订单请求和状态反馈，采用所采纳的 TMF 词汇 |
| **状态词汇** | 激活状态及其允许的状态转换 |
| **时序** | 按操作区分同步确认与异步状态 |
| **责任归属** | 哪一侧负责资源供给、预留和释放 |
| **失败语义** | *未知*状态的具体表现形式及其解决方式 |

> 无法声明全部五项的集成不是接口，而是一种耦合；它最终会将 SCADA 职责移入 BSS 套件。
