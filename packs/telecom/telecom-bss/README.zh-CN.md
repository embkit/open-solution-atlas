## 本方案包涵盖范围

本方案包涵盖电信运营商商业生命周期背后的业务与运营支撑套件：商业层将客户、产品目录条目和订单转化为已激活、已计费且受支持的服务（BSS）；此外还涵盖商业意图被移交给网络与资源履约（OSS）的边界。核心问题是**订单到回款与订单到激活的一致性**——商业产品目录所销售的内容、订单编排器所履约的内容、计费所收取的费用，以及网络实际激活的内容，必须在长期、跨域的流程中保持一致。

## 包含范围

- 客户与相关方：客户主数据、账户、协议、联系人、分群
- 产品目录：商业产品提供物与技术规格说明/资源的划分、产品提供物、资费计划、资格规则
- 订单管理：订单捕获、分解为业务订单、订单编排与异常落项处理、订单到激活跟踪
- 计费与账单：使用量/事件计费、周期性和一次性费用、账期、开票、调整/冲抵、与币种无关的货币模型
- 应收款项：未支付/逾期处理（欠费催缴）、支付分摊、催收工作流
- 客服：故障单、投诉、客服工单生命周期、知识库
- 资源与号码库存：逻辑/物理资源、电话号码与码号资源库存、分配/释放
- 开通边界（OSS 侧）：业务订单向激活的移交、网络资源预留、激活状态反馈——已纳入集成，但未在 BSS 核心中实现

## 明确排除的范围

- 网元管理 / NMS / 深层 OSS 履约引擎本身（属于集成目标，不在此处构建）
- 收入保障 / 欺诈管理（候选同级方案包）
- 5G 核心网 / RAN 工程以及 IP/传输规划
- 物理网络建设与外勤队伍管理

## 已确定的 ADR（不得重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | BSS/OSS 边界是**集成契约**，绝不只是为了图方便；商业决策绝不查询网络状态 |
| **0002** | 两个目录由**一个规格说明**衔接，绝不重复建模；规格说明是唯一允许的衔接方式 |
| **0003** | 订单分解在**两个方向**上均可追溯——“端到端”这一表述允许采用仅向前实现 |
| **0004** | 计费事件**不可变**，并且可同时与**订单**和**库存**进行对账 |
| **0005** | ODA 和 TMF Open API 被**采用为词汇**，而非用于声明符合性 |

### 阻断 L2 的事项

1. **词汇锁定到哪些 ODA/TMF 版本。** 本方案包采用了该词汇，但未指定版本；其符合的接口系列和组件集是一项尚未决定、需绑定版本的决策。
2. **最低保留期与擦除**——术语表记录了相关机制（按类别制定策略并明确生成/再生窗口），但未规定具体窗口。这是设计必须显式呈现的业务/法律决策，而不是设计可以自行选择的默认值。
3. **一对 N 的全部规格说明形态**——术语表指出“一个产品提供物可以映射到 N 种资源实现”，但所支持的基数以及下单时如何选择替代方案尚未规定。
