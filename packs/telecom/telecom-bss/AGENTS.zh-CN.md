## 扩展到 L3 或实施时的硬性规则

- **BSS/OSS 边界是一项契约，而非便利机制**（ADR-0001、BR-01、BR-02、CTL-06）：所有集成仅限通过接口进行，且不包含 SCADA 范围。商业决策绝不查询网络状态，运营侧也绝不计算费用。以其他任何方式跨越该边界均属缺陷。
- **规格说明是商业产品目录与技术与资源目录之间唯一允许的连接机制**（ADR-0002、BR-03、FR-002）。产品提供物在没有规格说明的情况下不得发布，任何其他组件也不得推断二者之间的关系。
- **订单链必须双向链接**（ADR-0003、BR-04、FR-005、FR-006）。“端到端”这一表述允许仅正向实施；但本方案包还要求反向遍历。部分完成是订单链的一种状态，尚待执行的步骤必须明确取消——绝不能通过反向执行已完成步骤来取消（BR-07）。
- **计费事件不可变，并携带各自的规则版本**（ADR-0004、BR-08、BR-09、NFR-001）：这一点由仅追加存储强制执行，而非依赖应用程序自律。更正应创建一个带有审批记录的新事件（BR-10）。
- **对账是双向的**（BR-12、FR-015、FR-016），且 NFR-003 应分别报告两个方向——合并为一个数字会掩盖究竟哪一侧发生故障。
- **资费规则必须版本化、可审计并带生效日期**（BR-08、FR-008、FR-009）：引擎与计费代码分离，因为某次发布中的规则变更与缺陷修复无法区分。跨越生效日期的账期应**按评估**拆分，绝不能依据操作员的决定拆分（NFR-007）。
- **发票携带其据以计算的规则版本**（BR-11、FR-014、NFR-005）——即重算路径所用的版本，而非当前版本。
- **管控护栏通过流程状态强制执行，而非通过配置实现**（BR-15、FR-021、NFR-009）：执行断开连接的操作员与评估是否允许断开连接的操作员并非同一人。
- **客服无需转接即可解决实际问题**（BR-06、FR-018）：账户、仪表、读数历史、付款以及相关故障中断均应呈现在同一视图中。
- **采用 ODA 和 TMF Open API 的词汇，而非作出符合性声明**（ADR-0005、BR-14、FR-020）：不主张任何成熟度级别或 API 版本。
