## CAP-01 政务信息资源目录与资源登记

### FR-001 — 以目录项为根
- **当** 资源被登记时
- **系统应当** 创建一个目录项，关联提供部门、资源、分类分级、共享类型和使用部门，**并且应当** 不允许在没有目录项的情况下共享资源（BR-01）
- 追溯：CAP-01、BR-01、ADR-0001

### FR-002 — 共享授权引用目录项，而非源系统
- **当** 创建共享授权或审批时
- **系统应当** 引用目录项，**并且应当** 不直接针对源系统解析共享授权（BR-01）
- 追溯：CAP-01、CAP-02、BR-01、ADR-0001

### FR-003 — 记录更新义务
- **当** 目录项被创建或变更时
- **系统应当** 记录该部门的更新义务及其触发事件（BR-02）
- 追溯：CAP-01、BR-02、ADR-0002

### FR-004 — 目录时效告警
- **当** 目录时效复核运行时
- **系统应当** 标记未履行更新义务的目录项，**并且应当** 不在缺少该告警信号的情况下将目录呈现为最新状态（BR-02）
- 追溯：CAP-01、BR-02、ADR-0002

### FR-005 — 拒绝须记录不予共享依据
- **当** 有条件共享请求被拒绝时
- **系统应当** 记录不予共享依据，**并且应当** 不记录无依据的拒绝（BR-03）
- 追溯：CAP-01、CAP-02、BR-03、ADR-0003

### FR-006 — 不予共享目录项须具备不予共享依据
- **当** 资源被归类为不予共享时
- **系统应当** 要求存在已记录的法律、法规或中共中央/国务院政策依据，**并且应当** 不允许在没有该依据的情况下发布（BR-03）
- 追溯：CAP-01、BR-03、ADR-0003

## CAP-05 分类分级与脱敏

### FR-007 — 分级驱动规则
- **当** 资源被指定分类分级时
- **系统应当** 根据政策派生该分级的脱敏规则和访问规则，并按类别分别声明（BR-04）
- 追溯：CAP-05、BR-04、ADR-0004

### FR-008 — 规则派生不针对单个数据集
- **当** 新数据集接入时
- **系统应当** 自动继承其分级对应的控制措施，**并且应当** 不要求人工授予数据集专用规则（BR-04）
- 追溯：CAP-05、BR-04、ADR-0004

### FR-009 — 分级变更后重新派生
- **当** 分级发生变更时
- **系统应当** 重新派生脱敏规则和访问规则，**并且应当** 不修补单个数据集规则（BR-04）
- 追溯：CAP-05、BR-04、ADR-0004

### FR-010 — 交换时应用脱敏
- **当** 数据向使用部门交付时
- **系统应当** 在交付前应用分级驱动的脱敏，**并且应当** 不依赖使用部门执行脱敏（BR-04）
- 追溯：CAP-05、CAP-04、BR-04、ADR-0004

### FR-011 — 强制执行可测试
- **当** 依据分级评估访问权限时
- **系统应当** 生成可依据政策进行测试的访问判定结果，从而能够检测未落实强制执行的分级（BR-04）
- 追溯：CAP-05、CAP-07、BR-04、ADR-0004

## CAP-02 授权与共享授权生命周期

### FR-012 — 共享授权记录使用用途、范围和期限
- **当** 审批创建共享授权时
- **系统应当** 记录使用部门、资源、**使用用途**、范围和期限，**并且应当** 不创建没有使用用途的共享授权（BR-05）
- 追溯：CAP-02、BR-05、ADR-0005

### FR-013 — 使用用途可核查
- **当** 记录共享授权的使用用途时
- **系统应当** 将其记录为可进行符合性评估的结构化属性，**并且应当** 不接受无法核查的自由文本（BR-05）
- 追溯：CAP-02、CAP-10、BR-05、ADR-0005

### FR-014 — 无条件共享无需协商
- **当** 请求针对无条件共享资源时
- **系统应当** 无需针对各使用部门逐一协商即完成共享授权，但仍须记录此次共享，**并且应当** 不以有条件工作流作为其前置闸门（BR-06）
- 追溯：CAP-02、BR-06

### FR-015 — 可撤销的共享授权
- **当** 创建共享授权时
- **系统应当** 使其可撤销，**并且应当** 不创建不可撤销的共享授权（BR-07）
- 追溯：CAP-02、BR-07、ADR-0005

### FR-016 — 撤销授权的提前量
- **当** 共享授权被撤销时
- **系统应当** 实际移除使用部门的访问权限并记录完成情况，**并且应当** 不把记录撤销行为本身视为撤销授权（BR-07）
- 追溯：CAP-02、BR-07、ADR-0005

### FR-017 — 无共享授权不得传输
- **当** 通过任何通道尝试任何传输时
- **系统应当** 要求存在当前有效且用途匹配的共享授权，**并且应当** 不在没有该授权的情况下执行传输（BR-08）
- 追溯：CAP-02、CAP-04、BR-08、ADR-0005

### FR-018 — 血缘闭环可追溯
- **当** 发生共享时
- **系统应当** 记录共享授权、审批、使用部门和交付物，**并且应当** 不允许无法追溯至其审批的共享（BR-08）
- 追溯：CAP-02、CAP-06、BR-08、ADR-0005

## CAP-04 交换通道

### FR-019 — 声明交换通道
- **当** 交换数据时
- **系统应当** 使用已声明的交换通道——库表（表到表）、文件或接口——**并且应当** 不允许使用已声明通道集合之外的通道（BR-09）
- 追溯：CAP-04、BR-09

## CAP-01 / CAP-10 治理

### FR-020 — 陈旧目录项路由
- **当** 检测到陈旧目录项时
- **系统应当** 将其连同负责人路由至提供部门，**并且应当** 不在没有负责人的情况下报告目录陈旧状态（BR-10）
- 追溯：CAP-01、BR-10

### FR-021 — 开放数据集描述
- **当** 开放数据集发布时
- **系统应当** 使用 W3C DCAT 元数据描述该数据集——数据集、分发物、发布者、主题（BR-11）
- 追溯：CAP-08、BR-11

### FR-022 — 每个分发物均有描述
- **当** 开放数据集包含分发物时
- **系统应当** 为每个分发物发布各自的 DCAT 分发物记录，**并且应当** 不发布未描述的形式（BR-11）
- 追溯：CAP-08、BR-11

### FR-023 — 双向一致性核对
- **当** 一致性核对运行时
- **系统应当** 将提供部门持有的内容与已交付的内容进行比较，并向提供部门报告差异（BR-12）
- 追溯：CAP-10、BR-12

### FR-024 — 使用用途符合性报告
- **当** 治理复核运行时
- **系统应当** 报告使用情况相对于使用用途的符合性，从而将第十四条的符合性作为可审计的问题，而不是假设（BR-05、BR-08）
- 追溯：CAP-10、CAP-02、BR-05、BR-08

### FR-025 — 封闭的共享类型词表
- **当** 目录项被创建或其共享类型发生变更时
- **系统应当** 仅接受三种既定类型——无条件、有条件、不予共享——**并且应当** 不允许第四种值或适用管理文件之外的值（BR-13）
- 追溯：CAP-01、BR-13、ADR-0006

### FR-026 — 单独记录开放依据
- **当** 数据集被提议进行开放数据发布时
- **系统应当** 记录与共享授权相区分的开放依据，**并且应当** 不将“可共享”视为推定的开放依据（BR-14）
- 追溯：CAP-08、BR-14
