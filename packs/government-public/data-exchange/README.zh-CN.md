## 本方案包涵盖的内容

政务数字服务的数据底座：可共享数据资源目录、访问这些资源的授权/审批工作流、
在部门之间传输数据的交换通道（数据库表、文件、API），以及围绕这些内容的
血缘/质量/治理。它是**数据共享底座**，不同于面向公民的服务门户
（一网通办 / 一站式服务），后者是该底座的使用方。核心难题是
**经授权、可追溯的共享**——未记录授权，数据不得流转；每次共享均可归因并接受审计。

## 涵盖范围

- 数据目录：资源登记/挂接、元数据、目录编制
  （目录编制）、提供部门/使用部门角色、目录发布
- 授权与审批：数据访问申请、审批工作流、授权生命周期、
  撤销授权、协议记录
- 交换通道：表到表（库表）、文件及基于 API 的（接口）
  共享；调度、批处理、增量交换
- 血缘与质量：从来源到使用部门的血缘、质量规则、监控、
  一致性核对
- 开放数据门户：公共数据集发布、采用 DCAT 建模的元数据、
  发现
- 安全与分类分级：数据分类分级（分级分类）、脱敏、访问控制、
  审计日志
- 治理：资源所有权、目录变更管理、使用统计

## 明确不涵盖的范围

- 面向公民的服务门户 / 一网通办（同系列一站式服务方案包；
  本方案包向其提供共享数据）
- 拥有源数据的部门业务系统（提供部门）
- 基于共享数据构建的大数据分析/BI（同系列 data-ai 方案包）
- 物理网络/云基础设施（政务云是托管底座）

## 开放问题

1. 核心中的交换通道构成：库表/文件/接口是否均为一等类型，还是
   以一种为主、其余作为适配器？
2. 与国家/省级交换层级的关系：单租户平台还是联邦节点？
3. 开放数据门户属于本方案包，还是单独的同级方案包？
4. 脱敏深度：集中式规则引擎还是按通道分别实施策略？

## 已确定的 ADR（不要重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | **目录项**是根对象，授权**仅**引用它——绝不引用源系统 |
| **0002** | 目录时效是**合规时钟**，平台依据已记录的更新义务呈现陈旧状态 |
| **0003** | 拒绝必须带有**依据**，且“不予共享”分类必须具备**法律依据**——这是必填字段，而非惯例 |
| **0004** | 分级按类别**派生**规则；以数据集为范围的覆盖规则是非法的 |
| **0005** | 使用用途是授权的一项**结构性**属性，因为无法针对一句话报告符合性 |
| **0006** | 共享类型词汇表**限定为三种**，且**开放数据是独立制度**，拥有自己的开放依据 |

## L3 阻断项

1. **通道组成**——表到表、文件和接口是否均为一等类型，还是以一种为主
   （开放问题 #1）尚未决定；这会影响数据模型和一致性核对设计。
2. **分级驱动规则映射**——“分级驱动规则”这一要求已确定；实际规则集
   需在条款层面确认 GB/T 43697-2024。
3. **结构化用途的表达能力**——FR-013 要求使用用途可校验；能够涵盖
   实际在用用途的结构尚未设计完成。
4. **七项零容忍不变量的验收标准**——NFR-001、
   NFR-002、NFR-003、NFR-004、NFR-005、NFR-008 以及“不予共享”
   依据检查需要可使构建失败的判据，而不是仅供报告的阈值。

### 明确未解决事项（已记录，勿遗忘）

- **联邦式节点还是集中式节点**——本方案包按单个市级或省级节点建模，
  并允许可选的联邦机制；核心是否采用联邦架构是明确的开放问题
  （`README.md` #2），本方案包不预设答案。
- **开放数据作为核心还是同级方案包**——本方案包同时对两者建模，
  但不假定开放数据义务是共享义务的子集；该门户是否属于本方案包的
  核心是明确的开放问题（#3）。
- **区域性实施规则**——国发〔2016〕51号是国家层面的法规依据；
  省级和市级规则可能增加本方案包未建模的义务。
- **GB/T 21063 条款映射**——目前仅按标准编号引用；条款级映射是
  `source-checked` 的前提条件。
