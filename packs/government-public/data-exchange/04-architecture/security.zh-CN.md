# 04 · 安全

> ⚠️ ASSUMPTION — 安全态势属于本方案包的设计范围。`02-requirements/compliance.md`
> 中列明的制度文件仅作为指称列出；未引用具体条款。

## 1. 血缘闭环就是控制面，且必须闭合

血缘闭环——授权 → 审批 → 共享 → 血缘——并非一项报告属性。它就是控制面：正是它使每一次传输都可归因于某个人作出的决定。

使闭环闭合的有两项条件，而第二项通常缺失：

| | |
|---|---|
| **没有有效且用途匹配的授权，不得传输** | 正向路径；一项虽存在但与用途不匹配的授权，不能作为本次传输的授权 |
| **每次共享都能回溯到相应审批** | 反向路径；一项共享若能追溯到授权却不能追溯到审批，就只闭合了一半，而半闭环正是无法归因的传输得以出现的原因 |

> 这种失效很明确：一条止于授权的共享追溯记录只能告诉你*某项事项已获授权*，却无法告诉你*由谁授权、依据为何*。这正是可审计闭环与看似合法的闭环之间的区别。

## 2. 脱敏是平台属性，而非使用部门的义务

由分类分级派生的脱敏由平台在交付前执行（BR-04、FR-010）。使用部门收到的是脱敏数据，而不是原始数据加上一份策略。

原因与同级方案包中的情况相同，而且可以度量：在使用部门的工具中执行的分类分级，只对该使用部门有效。一个分析笔记本、一名数据科学家和一个导出文件均属于使用部门。

> NFR-005 统计的是使用部门的**路径**，而不是工具配置，因为失效的是路径，而不是设置项。

## 3. 使用用途必须结构化，否则无法核验

第十四条要求使用部门只能在所声明的使用用途范围内使用数据。其工程实现上的后果是结构性的，而非文档性的：使用用途是一项可评估的结构化授权属性（FR-013，约束 6）。

> 自由文本形式的使用用途只满足要求的形式，却丝毫不满足其实质——“使用部门是否始终在该用途范围内？”不是能够针对一个句子回答的问题。NFR-008 衡量结构化使用用途的占比，因为正是该字段将义务转化为能力。

## 4. 撤销授权的衡量标准是它移除了什么

授权可以撤销，而撤销授权的价值在于访问权限实际被移除前的提前量（BR-07、FR-016、NFR-003）。

明确的目标是移除访问权限，而不是记录撤销这一行为。若授权已被记录为撤销，而使用部门仍能读取，则这只是名义上的撤销；两者之间的差距正是控制措施真正发挥作用的所在。

> NFR-003 的目标值刻意设定得很短，因为该要求所衡量的失效并非行政延迟——而是授权已撤销后，使用部门仍可读取的时间窗口。

## 5. 不予共享是一项控制，而非拒绝

不予共享决定记录其不予共享依据（BR-03、FR-005），而一项 **不予共享** 分类要求记录法律、法规或中共中央/国务院政策依据（FR-006，约束 2）。

工程实现上的后果是一个 **字段**：目录项必须能够存储并展示该不予共享依据。缺少来源与依据字段的共享类型下拉框无法满足这一要求，而仅记录类型的实现只完成了该要求中最容易实现的部分。

## 6. 开放数据是另一套规则体系，混同二者属于控制失效

开放数据发布受不同于部门间共享的规则约束：DCAT 元数据模型、同意依据和脱敏门槛均不相同。

本方案包的立场是：开放依据与数据能否共享是**不同问题**，二者不得混同——因为在部门间不予共享的数据集有时可以向公众发布，而可共享的数据集有时又不可发布。将其中一者视为另一者的子集，会在两个方向上都得出错误结论。

## 7. 审计证据

| 成果物 | 存放位置 | 可回答的问题 |
|---|---|---|
| **共享追溯记录** | 血缘存储 | “谁授权了这次传输，授权依据是什么，适用哪一项共享授权？” |
| **带结构化使用用途的授权** | 授权存储 | “该使用部门是否获准用于此用途，且该授权是否仍然有效？” |
| **撤销授权记录 + 完成记录** | 授权存储 | “访问权限是否确实已移除，耗时多久？” |
| **分类等级 + 派生规则** | 分类分级存储 | “该数据集是依据分类等级实施控制，还是依据人工授予的例外实施控制？” |
| **含依据的不予共享决定** | 目录存储 | “为何不予共享，作出该不予共享决定是否获准？” |
| **使用用途符合性报告** | 治理存储 | “使用部门是否始终处于所声明的使用用途范围内？” |

> 上述每一项均可从平台自身的记录中得出答案。使用用途符合性报告是最常缺失的一项，因为这要求使用用途从一开始就已结构化——因此，NFR-008 的测量先于 NFR-013。
