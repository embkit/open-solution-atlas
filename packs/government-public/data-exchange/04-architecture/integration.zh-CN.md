# 04 · 集成

> 与平台相邻系统之间的集成约定。ID 保持稳定；每个流程都可追溯至需求和规则。
>
> ⚠️ ASSUMPTION — 接口选型和协议属于方案包的设计范围。W3C DCAT 是开放数据元数据词汇表（起草期间已验证可访问）；未声明任何 DCAT profile。

## I. 集成点

| ID | 相邻系统 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **提供部门系统** | 双向 | 资源提取，以及对提供部门所持有数据进行一致性核对 |
| **I-02** | **使用部门系统** | 双向 | 接收请求并交付数据 |
| **I-03** | **身份 / 部门目录** | 入站 | 操作人员身份及其所属部门 |
| **I-04** | **跨平台接口**（市级、省级、国家级） | 双向 | 联邦共享 |
| **I-05** | **开放数据门户** | 出站 | 已发布的数据集和分发物 |
| **I-06** | **面向服务入口的身份提供方** | 出站 | 一网通办是**使用部门**，而不是核心组件 |
| **I-07** | **安全 / 等保管理平台** | 出站 | 遥测数据和报告 |

## F. 内部流程

### F-01 — 登记与分类分级
1. 提供部门登记一项资源；系统创建一个目录项，将提供部门、资源、分类分级、共享类型和使用部门关联起来。
2. 将资源归为不予共享时，必须具备已记录的不予共享依据。
3. 更新义务得到记录，并针对该义务提出目录时效失效问题。

### F-02 — 请求与审批
1. 使用部门以**结构化**的使用用途、范围和期限提出请求。
2. 无条件共享资源无需与各使用部门逐一协商，即可授予共享授权——但仍须记录。
3. 有条件共享资源进入审批流程；拒绝时记录其依据。
4. 审批创建共享授权。

### F-03 — 交换与闭环
1. 交换选择**已声明的交换通道**。
2. 交付前，由**平台**执行分类分级驱动的脱敏。
3. 传输记录关联交换通道、载荷、使用部门和共享授权。
4. 共享追溯链将传输 → 共享授权 → 审批 → 请求关联起来，并闭环至目录项。

### F-04 — 撤销授权
1. 共享授权被撤销或到期。
2. 在平台端以及该授权允许的每个交换通道上移除访问权限。
3. 记录撤销授权及其**完成**时间。

### F-05 — 治理
1. 针对更新义务提出目录时效失效问题，并路由至提供部门的责任人。
2. 一致性核对比较提供部门持有的数据与交付的数据。
3. 依据共享授权报告使用用途符合性。

### F-06 — 发布开放数据
1. 选择一个数据集并确立开放依据——这与该数据集能否在部门间共享是两个不同的问题。
2. 生成 DCAT 元数据：数据集、分发物、发布者、主题。
3. 门户接收该元数据。

## 故障模式约定

| 集成 | 必须处理的故障模式 |
|---|---|
| **I-01 提供部门** | 部分提取即为交换失败，须记录缺失内容；绝不能以静默方式执行部分更新——由提供部门负责的真实数据不得被静默更改 |
| **I-02 使用部门** | 使用部门端点不可用时，传输状态为*未知*，并可在同一共享授权下重试；不得重试共享授权，也不得自动延长共享授权 |
| **I-03 身份** | 无法解析部门身份时，请求**不予路由**，而不是路由至默认使用部门 |
| **I-04 跨平台** | 不可达的联邦节点记录为*未知*；绝不对远程目录状态作本地推定 |
| **I-05 开放数据门户** | 发布失败时，数据集保持未发布状态；绝不能以未描述的形式发布（BR-11） |
| **I-07 安全平台** | 遥测不可用只会降低可观测性，不会影响共享授权记录和血缘记录——这些记录存放在平台自身的存储中 |

> 其模式是：集成不可用时，外部路径能力降级，并记录为*未知*——绝不作推定，也绝不采用默认值。身份是唯一采用故障关闭（fail-closed）方式的情形，因为把请求路由给猜测的使用部门，等同于作出了一项无人实际给予的授权。

## 使用部门约定（使用部门必须接受的内容）

| 方面 | 使用部门集成所声明的内容 |
|---|---|
| **使用用途** | 记录在共享授权上，采用结构化且可核查的形式——而不是自由文本备注 |
| **范围和期限** | 设有明确边界，且自动强制执行到期处理（NFR-009） |
| **脱敏** | 由平台在交付前执行；使用部门收到的是已脱敏数据，而非原始数据和脱敏策略 |
| **撤销授权** | 访问权限的移除是实际执行且可度量的（NFR-003）；使用部门在权限移除后仍继续读取，属于使用部门侧的缺陷，平台必须检测到这种情况 |
| **无第三方** | 使用部门不得直接或以改变后的形式转交数据——这属于使用约束，因此是共享授权的属性 |

> 期望接收原始数据并在本地脱敏的使用部门，在集成层面等同于把控制措施放在了错误的层级。BR-04 将脱敏置于平台侧，使每个使用部门都继承这一控制；需要原始数据的使用部门，要么已明确获得原始数据授权，要么就不是该数据集的使用部门。
