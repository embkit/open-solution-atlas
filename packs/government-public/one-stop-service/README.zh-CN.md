## 本方案包涵盖内容

数字政府的综合服务平台和审批骨干：公民和企业通过一个网站/应用办理事项（“一件事”），无需前往各部门。该平台统一整合办事指南、在线申请、跨部门数据共享与核验、审批流程、电子证照/电子印章、行政收费缴付、进度跟踪以及“好差评”满意度反馈，同时满足等级保护和政务云部署要求。

## 范围内

- 统一服务目录：事项管理、指南要素（受理条件/材料/流程/时限）、区域/部门归属、事项版本管理
- 个人与企业空间：统一身份认证（对接政务实名）、我的申请、我的证照、消息中心
- 申请：智能表单、支持 OCR/电子证照免提交的材料上传、通过数据共享实现数据预填、“一件事一次办”编排包
- 审批骨干：部门任务路由、受理 → 审查 → 决定 → 出件、SLA 计时器、限时办结、一次性告知规则
- 跨部门核验：数据共享请求/响应网关、接口目录、同意/授权记录、调用审计
- 电子成果：电子证照签发/核验、电子印章、证照核验二维码
- 支付与物流：行政收费支付网关、文件邮寄
- 监管与反馈：好差评、投诉处理、监管仪表板、全业务审计（电子监察）
- 部署：政务云区域、网络分区、等保三级（MLPS）

## 明确不在范围内

- 部门内部专业系统（业务审批专网系统）——它们作为审批节点接入，不在此重建
- 政务 OA/内部办公（同系列工作流方案包模式）
- 公共数据开放门户（同系列 data-exchange 方案包候选项）

## 待决问题

1. 跨区域/跨层级（省–市–区–街道）路由模型的细化程度。
2. 接口共享网关与 data-exchange 平台的边界。
3. 将电子证照库视为外部平台依赖项，并采用标准集成契约。

## 已确定的 ADR（不得重新讨论）

| ADR | 决策 |
|---|---|
| **0001** | 一个事项具有**两种法定类型**之一，类型决定最终产出物——只有行政权力事项会产出决定书 |
| **0002** | 办事指南是**已发布契约**；变更须标注日期和责任归属，并记录申请提交时所依据的版本 |
| **0003** | 身份通过**国家级服务集成**；自行重新实现会形成需要额外对账的第二套身份，并带来另一重违规风险 |
| **0004** | 渠道是**共享核心之上的变体**；身份方面最容易失效 |
| **0005** | 防重复提交规则是**按字段**执行的；该控制项的失败模式，是系统表现得过于乐于代劳 |
| **0006** | 生命周期采用**法定术语**；办结时限从**受理**开始计时，且一次性告知 ≠ 补正 |
| **0007** | 印章和证照来自**国家级服务**；有效性在**签署时**记录，第 27 条将支持业务系统规定为本平台的义务 |
| **0008** | 电子归档是模型的一项**正确性要求**——必须经核验确认完整且可检索，而非作为附件存在 |

## 阻断 L3 的事项

1. **渠道适配器接口作为契约**——五个已声明方面目前仅存在于文字描述中；L3 需要接口本身。
2. **法定步骤状态机与办结时限语义**——术语、办结时限起点以及一次性告知和补正两种告知均已定义；L3 要求逐项列举，并说明暂停/恢复及阈值行为。
3. **十一项零容忍不变量的验收标准**——其中大多数属于字段级或渠道级，需要会导致构建失败的标准，而不是汇总式标准。
4. **允许采用的替代方案目录**——FR-013 要求为每个可共享获取字段定义回退方案；允许采用的替代方案集合尚未设计。
5. **印章状态查询依赖项**——平台会调用状态服务；对该服务的调用契约属于 L3 工作。

### 明确未解决的事项（已记录，未遗忘）

- **办结时限的起点**——受理被提出为设计立场，而非引自法规；若部署仍从提交时起统计，其指标会变差（NFR-010 用于发现旧算法仍在沿用）。
- **超时自动批准**——仅在明确政策允许时方可采用，绝不能作为默认设置；本文未决定特定制度下是否允许这样做。
- **统一电子印章技术标准**——《电子印章管理办法》要求符合国家标准，但未列明标准编号；本方案包也未指定编号。
- **保留期值**——BR-12 要求按类别给出保留期；本文未规定任何具体期限。
- **国家法规之外的行业规则**——省级和市级实施规则可能增加本方案包未建模的义务。
- **跨境目的地传输**——在 `data-exchange` CTL-04 中记录为方案包新增标识；本文未对照法规对其进行验证。
