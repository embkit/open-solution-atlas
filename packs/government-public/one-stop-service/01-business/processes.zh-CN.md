# 01-business / 流程

> 面向一站式政务服务平台的流程定义。每项流程均说明其触发条件、步骤以及约束这些步骤的规则。规则见 `business-rules.md`（BR-xx），本文仅引用，不予重述。
>
> ⚠️ ASSUMPTION — 流程拆分属于方案包设计。国令第716号提供法定生命周期术语，但不提供这些流程。

## P-01 — 发布事项

| | |
|---|---|
| **触发条件** | 创建或修订事项 |
| **结果** | 一个已发布的**事项**——目录根 |

1. 创建事项并确定其类别：行政权力事项或公共服务事项（BR-01）。
2. 明确办事指南的三个必备要素：受理条件、办事材料、办理流程（BR-02）。
3. 发布；办事指南**就是**面向公众的契约（BR-02）。

> BR-02：第六条使这三个要素成为强制要求，并要求办事指南予以公布。申请人有权依据已公布的内容行事，因此，默默变更的办事指南属于违法，而不只是前后不一致。

## P-02 — 查找与身份认证

| | |
|---|---|
| **触发条件** | 申请人通过任一渠道进入平台 |
| **结果** | 通过统一身份认证、且身份仅认证一次的申请人 |

1. 检索事项目录并阅读已发布的办事指南。
2. 通过**国家统一身份认证**服务完成认证——仅认证一次，且平台不另行持有相互竞争的公民身份信息（BR-03）。
3. 记录渠道；渠道是一种变体，绝不形成流程分叉（BR-04）。

> BR-03：第五条所称“一次认证、全网通办”意味着应当集成国家服务。重新实现公民身份体系会形成一套需要对账的第二身份，也会形成一套可能被突破的第二身份。

## P-03 — 数据预填与核验

| | |
|---|---|
| **触发条件** | 表单呈现时 |
| **结果** | 共享获取可以提供相应内容时，不再要求填写相关字段 |

1. 将每个字段分类为**可共享获取**或不可共享获取（BR-05）。
2. 对可共享获取的字段，使用共享数据进行数据预填和核验。
3. 可共享获取的字段不得设为**必填**输入项（BR-05）。
4. 查询失败时**降级为允许采用的替代方式**，绝不得悄然改为再次要求申请人提供（BR-05）。

> BR-05 即第七条，是本方案包的核心约束。要求提供材料很容易；证明材料已经可以获取却很难。默认要求申请人提供的平台看起来更友好，但不合规。

## P-04 — 提交

| | |
|---|---|
| **触发条件** | 申请人确认时 |
| **结果** | 一个纳入跟踪的办件 |

1. 收集表单、办事材料和同意声明。
2. 创建办件并将其录入状态机（BR-06）。
3. 启动首个法定步骤。

## P-05 — 受理或一次性告知

| | |
|---|---|
| **触发条件** | 对已提交的办件进行受理审查 |
| **结果** | **受理**，或者一次列明所有缺失内容的**一次性告知** |

1. 材料齐全的，予以受理——受理即启动办结时限计时和法定义务。
2. 材料不完整的，作出一次性告知：一次性提供完整清单（BR-07）。
3. 受理后如需补正材料，即为补正——这是不同于一次性告知的另一步骤（BR-07）。

> BR-07：之所以区分这两个术语，是因为它们属于不同步骤；混同二者，正是平台最终陷入分项驳回的原因。

## P-06 — 审查与决定

| | |
|---|---|
| **触发条件** | 已受理的办件 |
| **结果** | 在限时办结内作出的**决定** |

1. 进行审查，包括任何跨部门数据调用，且每次调用均须**取得同意并进行审计**（BR-08）。
2. 作出决定：同意、拒绝，或该事项规定的其他处置（BR-06）。
3. 办结时限从受理时开始计时，而非从提交时开始计时（BR-09）。

> BR-08：每次跨部门调用都需要取得同意并进行审计。没有任何已记录依据的调用既是合规缺陷，也能证明平台在过度收集数据。

## P-07 — 出件、签章与费用结清

| | |
|---|---|
| **触发条件** | 作出决定 |
| **结果** | 结果已出件、在适用情况下已加盖印章、费用已结清 |

1. 出件——向申请人出具决定结果。
2. 通过**国家统一电子印章系统**加盖电子印章（BR-10）。
3. 结果属于证照时，通过**国家电子证照共享服务系统**生成电子证照（BR-10）。
4. 事项涉及行政收费的，办理行政收费结算。

> BR-10：这些都是外部平台依赖项，应依据其已发布的标准进行集成。自行重新实现印章或身份体系既不合规，也会带来安全责任。

## P-08 — 好差评与归档

| | |
|---|---|
| **触发条件** | 已办结的办件 |
| **结果** | 已收集反馈；电子文件已归档 |

1. 好差评——收集申请人的评价。
2. 以**电子形式**归档电子文件（BR-11）。
3. 按类别适用保留期（BR-12）。

> BR-11：第十二条规定了电子归档义务。平台的归档对象是数据模型，而非各部门的归档系统。

## 规则覆盖情况

| 规则 | 流程 |
|---|---|
| BR-01 两种法定事项类别 | P-01 |
| BR-02 办事指南是公开契约 | P-01 |
| BR-03 通过国家服务进行身份认证 | P-02 |
| BR-04 各渠道是变体 | P-02、P-04 |
| BR-05 防止重复提交 | P-03 |
| BR-06 法定生命周期术语 | P-04、P-06 |
| BR-07 一次性告知 ≠ 补正 | P-05 |
| BR-08 跨部门调用须取得同意并进行审计 | P-06 |
| BR-09 办结时限从受理开始计时 | P-06 |
| BR-10 通过国家服务加盖印章和生成证照 | P-07 |
| BR-11 电子归档 | P-08 |
| BR-12 按类别适用保留期 | P-08 |
