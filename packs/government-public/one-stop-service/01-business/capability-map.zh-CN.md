## 1. L1 能力

| # | 能力 | 必须回答的问题 | 说明 / L1 定位 |
|---|---|---|---|
| **CAP-01** | **政务服务事项目录** | 可申请什么，以及适用哪些条件 | **根对象**，驱动表单、办事材料、路由和时限（`AGENTS.md`）；两种法定类型（行政权力/公共服务，第四条） |
| **CAP-02** | **已发布办事指南与受理条件** | 向申请人告知什么，以及实际执行什么 | 包含受理条件/办事材料/办理流程的办事指南对外**发布**，因而具有约束力（第六条） |
| **CAP-03** | **表单、办事材料与防重复提交** | 申请人必须提供什么，以及不得要求其提供什么 | 第七条是本能力的硬性约束；办事材料清单必须*推导得出*，而非手工维护 |
| **CAP-04** | **统一身份认证集成** | 谁在申请 | 集成国家统一服务；**不另建**本地公民身份体系（第五条，`AGENTS.md`） |
| **CAP-05** | **共享数据核验** | 如何在不要求申请人提供的情况下确认其信息 | 每次调用均须**取得同意并进行审计**（`AGENTS.md`）；使用 `data-exchange` 方案包 |
| **CAP-06** | **审批生命周期** | 办件如何从提交流转至决定 | 法定术语：受理/审查/决定/出件、一次性告知、补正、限时办结 |
| **CAP-07** | **电子印章与电子证照** | 如何对出件结果进行认证，以及如何签发电子证照 | **仅集成，绝不重新实现**；GB/T 369xx 接口 |
| **CAP-08** | **收费与支付** | 行政收费如何结算 | 仅适用于设有收费项目的政务服务事项 |
| **CAP-09** | **通知与进度** | 申请人当前处于什么阶段，以及需要做什么 | 进度、补正通知、出件、到期/政策提醒 |
| **CAP-10** | **归档、监管与反馈** | 事后能够证明什么，以及服务是否得到改善 | 电子归档是一项**法定义务**（第十二条）；监管数据流；好差评 |

## 2. 边界（各能力*不*负责的事项）

| 能力 | 明确**不**属于其职责范围的事项 |
|---|---|
| 01 目录 | 作出决定——那属于 06，由主管部门负责 |
| 02 办事指南 | 掌握权威政策——办事指南只是*重述*该政策；该政策归主管部门所有 |
| 03 表单 | 执行核验——那属于 05 |
| 04 身份 | 决定申请人具备何种资格——那属于 01/06 |
| 05 共享数据 | **持有**源数据——那属于 `data-exchange` 方案包 |
| 06 审批 | 起草办事指南——与流程不符的办事指南属于缺陷，需共同修复 |
| 07 印章与证照 | **签发印章或定义证照格式**——那属于国家服务（第九条/第十条，`AGENTS.md`） |
| 08 支付 | 决定收费是否合法——这取决于主管部门的法律依据 |
| 09 通知 | 作出决定——它负责告知，不负责决定 |
| 10 归档 | 决定保留期——那属于档案主管机关（第十二条）；平台负责执行 |
| 10 监管 | 裁定投诉——它负责呈现和分流 |

> 实践中最常被突破的边界是 **05 与 03**：共享数据查询失败时，团队往往会采取“干脆要求申请人提供”的做法。这会把暂时性的集成故障转化为违反第七条的情形。该边界必须通过明确规定的降级路径来强制执行，而不能依赖团队自律。

## 4. 整个平台的范围外事项

- **数据本身**——人口记录、证照记录等归 `data-exchange` 方案包及相应主管部门所有。
- **全国统一服务**——统一身份认证（第五条）、电子印章（第九条）和电子证照共享（第十条）均为集成依赖。
- **部门办件系统**——是集成目标，而非替代对象（国发〔2022〕5号）。
- **支付业务本身**——平台结算行政收费；它不是金融机构。
- **任何政务服务事项的法律实质问题**——平台负责路由和记录；它不裁定法律所要求的内容。
