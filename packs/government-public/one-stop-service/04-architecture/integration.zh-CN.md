# 04 · 集成

> 本节规定与外部服务和渠道的集成约定。各 ID 保持稳定；每项流程均可追溯至需求和规则。
>
> ⚠️ ASSUMPTION — 接口选择和协议属于方案包设计。TM Forum 和电子证照 GB/T 369xx 接口均按已发布标准使用；不声明任何 API 版本。

## I. 集成点

| ID | 合作方 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **国家统一身份认证服务** | 入站 | 一次认证、全网通办——唯一的身份认证路径 |
| **I-02** | **政务数据共享交换平台**（`data-exchange`） | 入站 | 第七条要求平台停止向申请人索要、改由共享方式获取的数据 |
| **I-03** | **国家统一电子印章系统** | 出站 | 加盖印章，以及供平台使用的**状态查询服务** |
| **I-04** | **国家电子证照共享服务系统** | 双向 | 通过已发布接口实现电子证照生成和互信互认 |
| **I-05** | **部门后台系统** | 入站 | 审批决定和状态 |
| **I-06** | **支付/国库** | 出站 | 行政收费结算 |
| **I-07** | **档案管理系统** | 出站 | 电子文件和记录 |
| **I-08** | **通知网关** | 出站 | 进度通知、补正通知和出件通知 |
| **I-09** | **好差评反馈渠道** | 入站 | 好差评和回应 |
| **I-10** | **机器翻译/无障碍服务** | 出站 | 为渠道提供辅助呈现 |

## F. 内部流程

### F-01 — 发布事项
1. 事项创建时即确定其法定类别。
2. 办事指南须声明受理条件、办事材料、办理流程——三者均须列明。
3. 办事指南发布后纳入版本管理；变更须注明日期并明确责任归属。

### F-02 — 身份认证与数据预填
1. 申请人通过国家统一身份认证服务进行一次身份认证。
2. 每个表单字段均须对照其共享分类予以确定。
3. 可共享获取的字段须进行数据预填或核验，绝不得要求申请人提供。
4. 查询失败时，须采用预先定义的允许替代方案。

### F-03 — 提交、受理、决定
1. 办件创建后，办结时限逻辑已就绪，但**尚未开始计时**。
2. 受理启动办结时限计时和法定义务。
3. 申请材料不完整时，须一次性、完整地作出一次性告知。
4. 审查使用跨部门调用，每次调用均须取得同意并进行审计。
5. 决定须连同作出该决定的权限和依据一并记录。

### F-04 — 出件、用印、结算、归档
1. 出件向申请人交付结果。
2. 通过国家统一电子印章系统加盖印章，并在签署时记录印章有效性；需要核验有效性时，应查询状态查询服务。
3. 适用时，通过国家电子证照共享服务系统生成电子证照。
4. 事项涉及收费的，应结算费用。
5. 电子文件应归档，并核验其完整性及可检索性。

### F-05 — 好差评
1. 记录申请人的好差评。
2. 如有回复，应记录该回复。

## 故障模式约定

| 集成 | 必须采用的故障模式处理 |
|---|---|
| **I-01 身份** | 身份上下文不可用时，意味着**无会话**，而不是访客会话。访客路径正是平台获取其本不应持有的公民身份的方式 |
| **I-02 共享平台** | 查询失败时，应采用**预先定义的允许替代方案**（FR-013）——绝不能转为再次索要，也绝不能悄然留下空字段。预填字段为空，等同于提出了申请人看不见的索要要求 |
| **I-03 印章系统** | 印章申请失败应**阻断**出件，而不是生成未加盖印章却标为“已出件”的文件。未经用印即出件所得文件，其法律状态只是一种呈现结果 |
| **I-04 证照服务** | 电子证照生成失败应阻断出件；本地自定义格式不得作为回退方案（FR-026） |
| **I-05 后台** | 后台系统不可用时，该步骤应保持为*未知*，绝不能自动批准。仅在明确政策允许时，方可在超时后自动批准；绝不能将其作为默认行为 |
| **I-07 归档** | 归档失败时，文件仍应按类别保留并予以**记录**，不得在无记录的情况下丢弃（FR-028） |
| **I-08 通知** | 通知失败仅使通知能力降级，绝不使法定步骤降级。补正义务不受送达失败影响 |

> 这一模式是：集成不可用时，应使外部路径降级，并将其记录为*未知*——
> 绝不作假设，绝不采用默认值。身份、印章和证照是采用故障关闭
> （fail-closed）的三种情形，因为每项服务若被重新实现，都会产生第二个
> 需要保障安全并进行对账的对象。

## 渠道约定（渠道必须声明的内容）

| 方面 | 渠道须声明的内容 |
|---|---|
| **输入** | 申请到达方式（Web 会话、小程序、POS 设备、辅助办理） |
| **支付路径** | 是否有可用的托管字段？采用哪条 POS 或市场平台路径？ |
| **身份处理** | 使用国家统一身份认证服务，只认证一次——独立进行身份认证的渠道不属于变体 |
| **办理来源** | 其连接哪些部门和后台系统 |
| **展示** | 公开哪些渠道变体属性 |

> 无法声明全部五项的适配器不是变体，而是分叉，BR-04 将予以拒绝。
> 身份方面失败最为严重：在本地进行身份认证的渠道会取得公民身份，
> 而这正是 `AGENTS.md` 所禁止的。
