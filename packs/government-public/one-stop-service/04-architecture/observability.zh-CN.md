## 绝不让步的十一项不变量

之所以是十一项，是因为该平台依托三项国家服务和两项法定约束，而上述每一种失败要么会因单个字段而违反某项规则，要么会把法律规定的行为描述成并非该行为的事物。

`obtainable_field_demanded`、`field_without_classification`、
`lookup_failure_reasked`、`exemption_without_reason`、`call_without_consent_basis`、
`seal_minted_locally`、`seal_validity_recorded_as_now`、`archive_unverified`、
`clock_started_at_submission`、`state_not_statutory_vocabulary` 和
`channel_identity_local` 必须保持为零。

其中三项具有一种值得点明的共同形态，因为这正是本方案包风险的形态：这些失败每次只发生在一个字段、一个渠道或一份文档上，而每一个具体实例看起来都像是有帮助、正确或无害。

> 如果仪表板将这些信号呈现得与其他信号无异，就会训练团队拿这些不变量来换取其他指标。之所以将这十一项单独标记，是因为在本领域，聚合数据永远无法揭示单个实例的违规。

## 平台必须能够回答的问题

| 问题 | 回答依据 |
|---|---|
| “这个字段是否本来就不应被索取？” | 字段分类，以及存在豁免时的豁免记录 |
| “我们是否再次索取了本可通过数据预填获得的信息？” | 查询结果记录 |
| “哪个机关提供了这些数据，作何用途？” | 跨部门调用审计 |
| “该文档当时是否已正确盖章，还是印章目前是否仍然有效？” | 签署时印章申请的有效性 |
| “该申请是否按时受理？” | 法定步骤和办结时限事件 |
| “电子文件是否完整且可检索？” | 电子档案验证 |
| “申请人有权依据什么内容？” | 提交时记录的办事指南版本 |

> 所有问题均可依据平台自身记录作答。前两个问题最常通过检查表单来回答，而违规恰恰就存在于表单之中。

## 追踪与关联

- 一条**申请**追踪链路涵盖：提交（连同所依据的办事指南版本）→ 身份核验 → 字段分类与查询 → 受理 → 审查及其相关调用 → 决定 → 印章及其有效性 → 出件 → 档案验证。每个步骤均标明相应的法定术语，因此，被错误描述的行为清晰可见。
- 一条**渠道**追踪链路涵盖：声明 → 身份处理 → 收到申请，因此，在本地进行身份认证的渠道属于审计发现，而非配置项。
- 一条**治理**追踪链路涵盖：针对被索取字段、无依据调用和未验证档案的审计发现，并将其路由至归口部门。

## 告警策略

- 一旦任何不变量被违反，即进行**呼叫**。
- 对于未标明责任归属的办事指南变更、办结时限超期以及重复通知率高于目标的情况，创建**工单**。
- 每周对三个趋势进行**审查**，因为其*变化方向*比其数值更重要：被索取字段中可共享获取字段所占比例上升，意味着该规则正在字段层面逐渐失效，而这也是该规则唯一可能发生失效的层面；补正率上升意味着受理正在接受办事指南所述并不完整的申请，这属于办事指南准确性问题，而非申请人的问题；并且
> 按事项类型统计，办结时限超期数量上升意味着某个具体步骤已成为瓶颈，
  这正是办结时限机制意在产出的可执行发现。
