# 04 · 安全

> ⚠️ ASSUMPTION — 安全态势由方案包设计确定。`02-requirements/compliance.md` 中所列法规仅为名称性引用；未引用具体条款。

## 1. 第七条是一项控制措施，而系统的自然倾向与之相悖

防止重复提交的规则不是一项便利性规则。它是重塑本平台的约束条件；之所以需要安全章节，是因为系统的自然倾向**违反了该规则**：

- 要求提交某份材料很容易；
- 证明该材料已经可以获取却很难；
- 默认要求申请人提供材料的平台看起来更友好，却不合规。

因此，这是一项结构性控制，而非程序性控制：

| 属性 | 之所以属于结构性控制的原因 |
|---|---|
| 逐字段分类 | 按整张表单分类会漏掉那个绝不应要求提供的具体字段 |
| 可共享获取的字段不得要求提供 | 页面渲染时仍然要求提供，本身即构成违规，而不只是配置不当 |
| 查询失败时明确规定允许采用的替代方案 | 回退方案本身就是全部控制措施；再次要求提供就意味着控制失效 |
| 记录豁免情况 | 未记录在案的豁免，会使规则从一项属性逐步退化为一种偏好 |

> 这种失效模式并非缺陷——而是平台表现得太乐于助人，并且每个字段都给了它发生这种失效的机会。NFR-001 至 NFR-003 的存在，是因为规则是逐字段失效的，而不是按整个平台失效。

## 2. 身份认证依托国家统一身份认证服务，重新实现只会形成责任风险

统一身份认证只做集成，绝不重新实现（BR-03、FR-006）。其后果源于同一推理：

- 自行重新实现公民身份认证，就等于增加了**第二套需要对账的身份信息**，而这种对账悄无声息；
- 它也等于增加了**第二套可能被攻破的身份信息**，而这一攻击面无人评估；
- 在本地进行身份认证的渠道已经新增了这样一套身份信息，因此渠道契约中与身份相关的方面失败最为严重。

> 身份上下文不可用意味着**不建立会话**，而不是建立访客会话。访客路径正是平台取得其本不应持有的公民身份信息的方式。

## 3. 电子印章的有效性是签署时记录的事实，而不是呈现结果

电子印章通过国家统一电子印章系统加盖（BR-10、FR-025），方案包要求记录**签署时的有效性**，而不是当前状态查询结果（约束 10、CTL-04）。

这一区别切实存在且影响重大：

| | |
|---|---|
| **签署时有效，此后失效** | 该文档已正确用印；后续失效不会向前追溯 |
| **签署时无效** | 该文档从未正确用印，无论印章当前状态是否良好 |

仅记录“印章当前是否有效”的平台无法区分这两种情况，而且给出的往往是更有利的那一种答案。

《电子印章管理办法》还要求提供**状态查询服务**，而平台应**调用**该服务，而非自行实现一套（`integration.md`）。第 27 条还规定，业务系统支持合规印章是平台自身架构必须履行的义务，而不只是进行集成的理由——BR-14 记录的正是这一点。

## 4. 跨部门调用须取得同意并接受审计，无依据的调用即构成审计发现

每次跨部门调用都要针对具体目的核验同意，并记录来源机关、相关字段和调用目的（BR-08、FR-020、FR-021）。

> 无法确定用途的调用应作为过度收集问题上报（FR-022）。这与字段级规则遵循同样的逻辑：把一切可能有用之物都调用一遍的自然倾向恰恰会违反规则，而控制措施在于形成记录，而不在于意图。

## 5. 办结时限从受理开始计时，这是与安全相关的真实性要求

办结时限从**受理**开始计时，而不是从提交开始（BR-09、FR-023）。

这是方案包的设计立场，而非引自某项法规；之所以放在本章，是因为如果不加说明，这种歧义会按对平台有利的方向解释。若从提交时间计量，而义务从受理时间起算，那么所有上报的绩效数字都会更好看，未履行的义务也会显得已经得到履行，而事实并非如此。

## 6. 归档是正确性要求，而非下游流程

电子文件以电子方式归档，并且归档结果须经验证为**完整且可检索**（BR-11、FR-028、FR-029）。

> 挂接到文档管理系统并不等于归档。第 12 条将平台的应用数据模型确定为归档对象，因此归档完整性是对该模型的正确性要求，而不是事后才执行的归档流程。

## 7. 审计证据

| 证据材料 | 存放位置 | 回答的问题 |
|---|---|---|
| **字段分类 + 豁免记录** | 数据共享存储 | “这个字段本来是否就不应被要求提供；如果不应，为什么会被要求提供？” |
| **调用审计记录** | 跨部门存储 | “哪个机关基于何种同意、出于何种目的提供了哪些信息？” |
| **含 validAtTs 的用印记录** | 印章存储 | “该文档是否已正确用印，还是仅仅因为印章当前状态良好？” |
| **法定步骤 + 办结时限事件** | 应用存储 | “该申请何时被受理，是否已超过其声明的时限？” |
| **所依据的办事指南版本** | 应用存储 | “申请人提交时有权依据的内容是什么？” |
| **归档验证** | 归档存储 | “电子文件是否完整且可检索？” |

> 上述每项问题均可通过平台自身的记录作答。实践中，字段分类记录和调用审计记录最常出现不完整的情况；正是这两项记录，使平台关于遵守第七条以及取得同意的主张能够接受核查，而不是仅凭平台自述。
