# 00-context / 利益相关方

## 1. 组织

| 组织 | 责任 | 系统关系 |
|---|---|---|
| **政务服务管理机构 / 政务服务中心** | 拥有平台、事项目录和服务标准 | 运营并治理平台 |
| **部门 / 政务部门** | 办理事项、发布办事指南、作出决定 | 上游提供方；各自负责本部门的事项和决定 |
| **机关内部审批** | 执行受理/审查/决定 | 通过平台代表该部门办理 |
| **国家 / 省级平台统筹机构** | 统筹一体化平台、标准及跨区域集成 | 对部门实施上层统筹管理 |
| **公安 / 市场监管 / 税务 / 人社** | 持有平台用于核验的共享数据 | 通过 `data-exchange` 方案包接入的数据来源 |
| **身份与认证机构**（统一身份认证） | 提供全国统一身份认证服务 | **外部平台依赖**——集成使用，绝不重新实现 |
| **电子印章管理机构**（国家统一电子印章系统） | 从国家统一电子印章系统签发印章 | **外部平台依赖**（`AGENTS.md`） |
| **电子证照共享服务运营方**（电子证照共享服务系统） | 运营证照目录、共享和互信互认服务 | **外部平台依赖**，GB/T 369xx 接口 |
| **档案主管部门**（档案部门） | 接收电子档案并制定归档要求 | 下游接收方（第十二条） |
| **支付 / 财政部门** | 收取行政性收费 | 集成参与方 |
| **监督 / 监管** | 对流程实施事前、事中和事后监管 | 使用流程数据 |
| **个人信息保护职能**（个人信息保护） | 合法依据、最小化、同意和删除 | 约束每一次数据调用 |
| **公众 / 媒体 / 研究人员** | 监督已发布的办事指南和办理结果 | 门户的只读使用者 |
| **存量系统承建方** | 运维需要集成的部门系统 | 集成合作方（国发〔2022〕5号） |

| 出件归档人员 | 出件归档人员 | 办理出件，加盖印章，归档电子文件 |
| 事项管理员 | 事项管理员 | 创建并维护事项，发布办事指南 |

| 好差评处理人 | 好差评处理人 | 接收并回应好差评和投诉 |
| 监督人员 | 监督人员 | 查阅流程和结果数据，用于事前事中事后监管 |

## 3. 作为行为主体的外部 / 上下游系统

- **全国一体化在线政务服务平台**——本平台依据第四条和国发〔2022〕5号与之集成的系统。
- **统一身份认证服务**（全国统一身份认证）——一次认证、全网通办（第五条）。
- **国家统一电子印章系统**——第九条。
- **电子证照共享服务系统**——第十条。
- **政务数据共享交换平台**——`data-exchange` 同级方案包；是第七条要求平台不再向申请人索要的全部信息的数据来源。
- **部门业务系统**——事项实际办理所在的系统。
- **档案管理系统**——第十二条。
- **财务 / 财政系统**——收费收取。
- **监管平台**——监管信息使用者。
- **工作人员身份认证**——供机关内部审批使用的政府内部身份标识。
- **OFD / 版式文档服务**——电子证照（第十条）和电子文件所引用的标准版式文档格式。

## 4. 行为主体目标（主要）

- **申请人**：只提交一次，准确掌握办理进度，不被转送至其他部门，也不会被要求提供政府已经持有的文件。
- **受理人员**：首次提交即做到完整，使一次性告知成为例外而非常态。
- **决定人员**：查看包括共享数据核验结果在内的完整档案，在限时办结期限内作出决定，无需重新查阅纸质文件。
- **事项管理员**：确保办事指南内容**属实**，因为其一经发布即成为办事依据。
- **部门负责人**：从头到尾办成“一件事”，同时始终明确哪项决定在法律上属于本部门。
- **平台运维**：集成存量部门系统，不重新实现国家服务。
- **个人信息处理者**：每次跨部门调用都须取得同意并可审计，且任何信息都不重复收集。
- **监督人员**：证明决定按时作出、处于权限范围内，并依据经核验数据作出。

> ⚠️ ASSUMPTION: 本方案包将**一次认证、全网通办**视为身份模型——申请人依托国家统一身份认证服务完成一次认证，平台不维护独立的公民身份。这一做法遵循第五条；“平台账户”与“国家身份”之间的边界属于 L2 集成问题，此处未作规定。
