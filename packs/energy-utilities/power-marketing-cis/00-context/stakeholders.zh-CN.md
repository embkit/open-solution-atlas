# 00-context / 干系人

## 1. 组织

| 组织 | 职责 | 与系统的关系 |
|---|---|---|
| **营销 / 客户服务部门** | 拥有 CIS 与客户生命周期 | 运营该平台 |
| **计量与采集** | 电表资产、采集、读数准确性 | 位于账单的上游 |
| **电价管理** | 解释并应用受监管电价 | 治理电价引擎的输入 |
| **电费核算** | 开票、调整、收入 | 消费读数与电价结果 |
| **95598 客服中心** | 热线接入、案件处理、派工 | 客户接触面中量最大的一个 |
| **现场运维** | 电表安装、抄表、停复电执行 | 执行工单 |
| **配网运营** | 网络状态、停电、复电 | 经由接口位于上游 |
| **收费渠道** | 收款、对账 | 位于计费的下游 |
| **政府与监管** | 电价核准、服务标准、投诉处理 | 外部权威 |
| **法律 / 合规** | 停电规则、客户权利 | 对护栏有权威 |
| **信息安全** | 客户数据、计量数据、等保合规 | 约束每一项能力 |
| **收入审计** | 正确计费与调整的证据 | 审批轨迹的只读消费方 |
| **大客户** | 合同、结算、特殊安排 | 一类流程不同的客户 |

## 3. 作为参与者的外部 / 上下游系统

- **配电自动化 / SCADA / OMS** —— **只**经由接口触达（`AGENTS.md`）。
- **AMI / 智能电表网络** —— 自动采集。
- **支付渠道** —— 银行、第三方、零售代办。
- **政府服务平台** —— 电力公司报送或发布的地方。
- **停电通知渠道** —— 短信、应用、门户。
- **资金 / 财务** —— 收入与结算。
- **监管报送系统** —— 法定报送义务。
- **短信 / 通知网关** —— 通知，包括停电前的通知。
- **税务 / 电子发票服务** —— 司法辖区要求时。

## 4. 参与者目标（主要）

- **客户**：一张我能看懂、与我的电表对得上、任何估算都清楚标注，而且绝不
  出现我本应被豁免的停电的账单。
- **计量**：读数被准确采集，异常被暴露，估算绝不被静默代入。
- **电价管理员**：一个规则版本在它的日期生效，作用于它该作用的每一张账单，
  也不作用于它不该作用的账单。
- **计费**：一个按时关闭的周期，异常由规则而非操作员判断来解决。
- **95598**：客户的真实处境可见——电表、读数历史、停电、缴费——无需转接。
- **调整审批人**：一次既够快因而会被使用、又够完整因而经得起辩护的审批。
- **现场操作员**：一条携带其护栏的指令，使规则禁止的停电无法被执行。
- **审计员**：「这张账单为什么是这个金额？」从记录中一次查询作答。

> ⚠️ ASSUMPTION: 本方案包假设电价引擎是一个**独立的、受治理的**组件，而不是
> 计费引擎内部的业务逻辑。这是「受监管的数学」的结构性后果，是一个设计立场，
> 而不是引用。
