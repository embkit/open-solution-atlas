# 04 · 集成

> 与外部系统的集成契约，以及接口接缝。ID 稳定；每条流都追溯到需求与规则。
>
> ⚠️ ASSUMPTION — 接口选型与协议属于方案包设计。只采用既有词汇；不主张任何
> API 版本。

## I. 集成点

| ID | 伙伴 | 方向 | 用途 |
|---|---|---|---|
| **I-01** | **配电 / OMS** | 双向 | 资源订单履行与状态反馈——**那条接缝** |
| **I-02** | **AMI / 计量网络** | 入 | 自动读数接入 |
| **I-03** | **现场作业管理** | 双向 | 计量服务与停复电的派工与完成 |
| **I-04** | **支付渠道** | 入 | 收款实绩 |
| **I-05** | **资金 / 财务** | 出 | 收入与结算 |
| **I-06** | **停电通知** | 双向 | 停电事件与客户通知 |
| **I-07** | **监管报送** | 出 | 法定报送 |

## F. 内部流程

### F-01 — 建档与分配
1. 当事方把客户、账户、服务点与电表解析为彼此独立的对象（BR-01）。
2. 按客户分类分配电价。

### F-02 — 抄表
1. 计量通过 AMR 或现场抄表采集。
2. 校验带着理由提出异常（BR-04）。
3. 在读数取不到的地方，估抄**按规则**应用并被标注（BR-05）。
4. 采集方式与每个读数一同记录。

### F-03 — 计价与出账
1. 解析带生效日的规则版本（BR-08）。
2. 跨越生效日的周期按求值拆分，而不是由操作员决定。
3. 发出一个费用事件，它随即不可变（BR-09）。
4. 周期关闭时，费用汇总成一张携带所使用**规则版本**的发票（BR-11）。

### F-04 — 服务
1. 从账户、电表、读数历史、缴费与停电上下文解析出客户的真实处境，据此创建
   案件（BR-06）。
2. 一张故障工单与服务实例关联。
3. 现场作业**经由接口**派发；没有客服动作直接改变网络状态（BR-07）。

### F-05 — 停复电
1. 提出该行为。
2. 流程把资格类别、通知期与受限时段**作为被强制的状态求值**（BR-15）。
3. 任一未通过的护栏阻断该行为。
4. 这次求值、其输入与其结果被记录为完整的决策记录。

### F-06 — 对账
1. 从仅追加的存储中读取费用事件。
2. 对账**双向**运行：对照订单（BR-12），以及对照库存用量（BR-12）。
3. 泄露发现——有量无客户、有开通无费用——被提出并按账龄管理。

## 失败模式契约

| 集成 | 必须具备的失败模式 |
|---|---|
| **I-01 配电/OMS** | OSS 不可用绝不能拖垮商业订单路径；状态是*未知*，并按未知记录。绝不假定已开通 |
| **I-02 计量** | 错过的采集窗口产生一个**异常**，绝不是一次静默代入。估算只按规则产生并带标注（BR-05） |
| **I-04 支付** | 渠道超时是*未知*，由资金侧查询解决——绝不是重试到第二笔贷记上 |
| **I-06 停电** | 停电事件丰富客服上下文；馈送不可用时降级的是上下文，绝不是案件 |
| **I-03 现场作业** | 派工失败是*未知*，不是一次已完成的停电。护栏求值不受影响 |

> 这个模式是：外部不可用时降级外部路径，并记录为*未知*——绝不被假定，绝不被
> 默认化。这里没有失败关闭的例外，因为要紧的行为（停电、更正）由平台自身的
> 护栏与审批流程把关，而不是由某一个外部信号把关。

## 接口契约（必须声明什么）

| 方面 | 由接口声明 |
|---|---|
| **载荷形态** | 资源订单请求与状态反馈，采用既有词汇 |
| **状态词汇** | 开通状态及其允许的迁移 |
| **时序** | 同步确认与异步状态，按操作分别声明 |
| **归属** | 哪一侧拥有资源调度、预留与释放 |
| **失败语义** | *未知*长什么样，以及它如何被解决 |

> 一个无法声明全部五项的接口不是接口，而是一种耦合；它终究会把控制义务
> 迁移进商业系统。
