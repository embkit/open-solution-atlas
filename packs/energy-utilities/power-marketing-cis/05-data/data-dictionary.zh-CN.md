# 05 · 数据字典

> 仅核心实体。字段语义具有规范效力；类型是示意性的。
>
> ⚠️ ASSUMPTION — 字段级设计属于方案包设计。某个字段若因某份文件而存在，
> 该文件在 `02-requirements/compliance.md` 中作为名称标注被列出，不引用条款。

## READING / ESTIMATE

| 字段 | 语义 |
|---|---|
| `collection_method` | NOT NULL（约束 4）。`ami` 表示自动采集，`field` 表示人工抄表。本方案包要求它的理由是：这是判断一个读数来自测量而非占位符的最廉价信号 |
| `READING_EXCEPTION.kind` | `missing`（从未采集）、`out_of_range`、`history_inconsistent`。每一种都有既定的解决路径（BR-04） |
| `ESTIMATE.rule_ref` | NOT NULL。是哪一条已声明规则产生了这个估算。没有规则的估算就是一次静默代入（BR-05） |
| `ESTIMATE.estimate_flag` | NOT NULL，始终为 TRUE。**那个结构性字段**——没有任何代码路径能把一个估算当作实测呈现而不破坏约束 8。正是它让账单在两个方向上都保持可证伪 |
| `reconciled_at` / `actual_value` | 当真实读数到达、估算被纠正时置位。复核是一个既定流程，而不是例行杂务——一个未被复核的估算是一个无人负责的悬而未决的财务问题 |

## TARIFF_RULE_VERSION

| 字段 | 语义 |
|---|---|
| `effective_from` / `effective_to` | 该版本的日期区间。NOT NULL，且当前版本时 `effective_to` 为 null |
| `effective_date` | 跨越周期使用的**拆分边界**。覆盖该日期的周期被划分，每段按当时生效的版本计算（约束 6、FR-009、NFR-006） |
| `status` | `draft`（尚未生效）、`published`（生效中）、`superseded`（为重新生成而保留）、`retired`（保留但从不适用） |
| `published_by` | 该版本背后的权威。一个规则版本是受治理的制品，而不是一次代码变更（ADR-0001） |

## CHARGE_EVENT

| 字段 | 语义 |
|---|---|
| `rule_version_ref` | NOT NULL（约束 3）。产生该金额的版本——**可复现性锚点**。没有它，发票重新生成不可能，而一次规则变更会静默地重述历史 |
| `order_ref` | NOT NULL。可归因到供电点，进而解析到一个客户账户——因此该费用可归因于所供应的内容（BR-12，订单侧） |
| `meter_id` | NOT NULL。产生该用量的供电点，因此用量可归因于某个客户（BR-12，库存侧）。**两侧都是必需的**：只有一侧就有一个方向没被检查 |
| 不可变性 | 仅追加；没有 UPDATE 或 DELETE 授权（约束 2、BR-09）。更正是一个新的**经批准的**事件，原件保留（BR-10） |

## INVOICE

| 字段 | 语义 |
|---|---|
| `rule_versions_used[]` | NOT NULL（约束 5、BR-11）。每笔费用计算所依据的规则版本——**不是**当前生效的版本。重新生成使用它们，这正是让一张历史账单在费率变更之后仍可复现的关键 |
| 重新生成 | `f(费用事件, 每个事件的规则版本, 调整事件)`——确定性的（NFR-004） |

## GUARDRAIL_EVALUATION

| 字段 | 语义 |
|---|---|
| `inputs[]` | 被求值的事实：账户、通知记录、受限时段日历、客户的资格类别 |
| `failed_guardrails[]` | 为空则允许该行为；非空则阻断。一次被阻断的停电连同其未通过的护栏是一个发现，而不是一次事故 |
| `evaluated_ts` | 在该行为被记录**之前**持久化（约束 9）。一个无法产出持久化求值记录的停电根本无法被记录 |

> ⚠️ ASSUMPTION — 这里每一个字段语义都是方案包设计。文件与字段的关联按本
> 仓库的范围决策，记录的是某份文件迫使软件*做什么*，而不是它说了什么。
