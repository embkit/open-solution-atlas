# 04 · 集成

> L3 数据流规范。协议/报文名称在 [`../SOURCES.md`](../SOURCES.md) 中引用；
> 频率、载荷形态与重试策略是方案包默认值 `(A)`——由部署画像替换。

## ERP ↔ TMS

| 流 | 方向 | 内容 | 说明 |
|---|---|---|---|
| 需求 | ERP → TMS | 销售/采购订单、Incoterms® 规则、时间窗 | FR-001；数量永不超出（BR-01） |
| 状态 | TMS → ERP | 运输段交付/异常摘要 | 驱动下游的应收/计费 |
| 成本入账 | TMS → ERP | 已批准的结算成本（FR-016） | 只在 AUTO_APPROVED 匹配之后 |

## WMS ↔ TMS

| 流 | 方向 | 内容 | 说明 |
|---|---|---|---|
| 出库/入库需求 | WMS → TMS | 已备货物、月台时间窗 | FR-001 |
| 经备货核验的交接 | WMS → TMS | 已核验的数量/批次 vs. 计划 | BR-10；差异阻断干净收尾 |
| 分配回执 | TMS → WMS | 供月台规划使用的承运商/车辆/ETA | FR-010 |

## 承运商 ↔ TMS

| 通道 | 用途 | 标准 |
|---|---|---|
| UN/EDIFACT | 指令 (IFTMIN/IFTMBF)、状态 (IFTSTA/IFCSUM) | UNECE 贸易便利化报文 |
| ANSI X12 | 状态 214、响应 990 | 北美交易伙伴 |
| REST/Webhook | 招标、状态、POD | 按部署的承运商画像 `(A)` |

## 面向伙伴/客户的发布

- **GS1 EPCIS 2.0 / CBV 2.0** 经捕获接口发布（2.0 起支持 JSON/JSON-LD +
  REST）；业务步骤/处置取自 CBV 词汇（FR-021、CTL-04）。
- 运输单/运输段 ID 在 ERP/WMS/TMS 之间保持可追溯（FR-020、ADR-0001）。

## 身份

- 用户的 SSO（OIDC/SAML）；承运商/伙伴 API 使用服务主体；最小权限角色
  （NFR-012）。跨方案包引用：`iam-platform`。

## 数据流细节（L3）

> 频率是 `(A)` 默认值；每条流都是至少一次投递，且消费方按所述键幂等。所有
> 时间戳为 ISO-8601 UTC，并做来源/接入双记录（BR-11）。

### F-01 需求接入（ERP/WMS → TMS）

| 方面 | 规范 |
|---|---|
| 传输 | HTTPS JSON 拉取或推送；ERP 也可向 TMS 接入 API 入队（C-01） |
| 载荷要点 | 需求来源键、授权数量、时间窗、Incoterms® 规则、危险品标记；不含行项定价（ADR-0001） |
| 频率 | 订单事件近实时 `(A)`；可回退到夜间对账文件 `(A)` |
| 幂等性 | 需求来源键（`system + sourceId`） |
| 失败 | 返回 `422` 并指明问题字段；源系统在修复后重试；不持久化任何部分行 |

### F-02 承运商招标与回执（TMS ↔ 承运商）

| 方面 | 规范 |
|---|---|
| 传输 | REST 伙伴界面（C-11）或承运商 EDI 画像（C-24） |
| 载荷要点 | 招标轮次、运输段事实（时间窗、重量/体积、危险品类别摘要）、报价引用；回执：ACCEPTED/REJECTED/TIMEOUT |
| 频率 | 派车时发出；提醒节奏 `(A)`；截止时间在服务端强制 |
| 幂等性 | `(legId, round)` |
| 失败 | 截止后的迟到/重复回执 → 记录为迟到事件，不追溯接单（SM-T2） |

### F-03 里程碑接入（车载终端/承运商/EDIFACT/X12 → TMS）

| 方面 | 规范 |
|---|---|
| 传输 | Webhook/流（车载终端）、IFTSTA/IFCSUM（EDIFACT）、214（X12）、REST（C-13/C-24） |
| 载荷要点 | 位置和/或状态；发布时映射到 CBV 2.0 业务步骤/处置（FR-021） |
| 频率 | 位置 `≤ 5 分钟/车` `(A)`；状态在变更时 |
| 幂等性 | `eventId`（来源提供或由报文身份派生） |
| 失败 | 接受乱序并在容差 `(A)` 内按 `source_ts` 投影；畸形报文被隔离并保留原始消息（AC-022） |

### F-04 WMS 交接（TMS ↔ WMS）

| 方面 | 规范 |
|---|---|
| 传输 | HTTPS JSON 事件（C-26），mTLS 服务身份 |
| 载荷要点 | 交接核验（计划 vs. 已核验的数量/批次、月台、时间戳）；分配回执（承运商/车辆/ETA） |
| 频率 | 月台事件时；分配变更时回执 `(A)` |
| 幂等性 | `(shipmentId, handoffEventSeq)` |
| 失败 | 差异开启带类型的异常（BR-10、SM-T4）；绝不静默对账 |

### F-05 发票与结算（承运商 → TMS → ERP）

| 方面 | 规范 |
|---|---|
| 传输 | REST（C-18）或 PDF/EDI 接入适配器；通过发件箱的 `settlement.approved` 入账 ERP |
| 载荷要点 | 按运输段的发票明细行；匹配结果差额；已批准的成本入账（不向 ERP 传递费率内部细节） |
| 频率 | 到达时；按周期批量入账 `(A)` |
| 幂等性 | 承运商发票号 |
| 失败 | 幻影发票（无已执行运输段）→ 开启争议；ERP 入账失败从发件箱重试且不重复 |

### F-06 EPCIS 发布（TMS → 伙伴）

| 方面 | 规范 |
|---|---|
| 传输 | EPCIS 2.0 捕获接口（按 2.0 绑定的 JSON-LD + REST） |
| 载荷要点 | 带 CBV 2.0 词汇的运输里程碑；PII 最小化（CTL-06） |
| 频率 | 已发布里程碑时（发车/到达/交付/异常）`(A)` |
| 幂等性 | EPCIS `eventID` |
| 失败 | 按可观测性章节告警发件箱延迟；绝不丢弃，只是延迟 |

### F-07 法规版本导入（管理员 → TMS）

| 方面 | 规范 |
|---|---|
| 传输 | 受审计的内部 API（C-23），受完整性保护的制品 |
| 载荷要点 | 版本表 + 制度 + 有效期 + 校验和 |
| 频率 | 每个发布周期（ADR 两年；IMDG 修正案周期；IATA 每年） |
| 幂等性 | 版本键 + 校验和 |
| 失败 | 校验和不匹配 → SM-T5 Rejected；在生效版本缺口阻断危险品派车（NFR-010） |
