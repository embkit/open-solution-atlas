# 02 · 功能需求

EARS 记法：`当 <触发条件> 系统应当 <响应>`。
ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）和一条业务规则（`BR-xx`）。
验收标准（AC-*）在 L3 定义。

## CAP-01 运输订单管理

### FR-001 — 需求接入
- **当** 需求从 ERP（销售/采购订单）或 WMS（出库/入库任务）到达，并带有
  Incoterms® 2020 规则与交付时间窗
- **系统应当** 创建运输订单行，其数量由授权需求推导而来且永不超出
  （BR-01、BR-12），并对超出量予以拒绝并给出问题来源引用。
- 追溯：CAP-01.1, BR-01, BR-12

### FR-002 — 集拼
- **当** 运输订单行共享兼容的航线、时间窗与操作约束（含危险品兼容，BR-08）
- **系统应当** 提议集拼为一票运输，并记录对该提议的接受/拒绝及操作者身份。
- 追溯：CAP-01.2, BR-08

### FR-003 — 多段运输
- **当** 一票运输跨越承运商或运输方式
- **系统应当** 为每一段建模其各自的承运商、计划、招标、里程碑与结算，并以
  共享的运输单身份相互关联。
- 追溯：CAP-01.3, BR-02

## CAP-02 承运商与费率管理

### FR-004 — 承运商主数据与资质
- **当** 承运商数据被维护
- **系统应当** 存储带生效日期的资质属性（服务等级、航线、保险、在适用情形下的
  危险品授权），并拒绝把无资质的承运商分配给相匹配的托运。
- 追溯：CAP-02.1, BR-07

### FR-005 — 费率合同
- **当** 费率合同或即时报价被维护
- **系统应当** 以带生效日期的方式对其做版本管理，标注具名组成部分
  （干线运费、燃油附加费基准、附加费），并在声明的截止点解析出适用版本
  （BR-04）。
- 追溯：CAP-02.2, CAP-02.3, BR-04

## CAP-03 装载规划

### FR-006 — 装载构建
- **当** 一票运输被规划到某辆车上
- **系统应当** 对照车辆运力（含配置的余量）计算总重与总体积，并拒绝超运力的
  计划（BR-09）。
- 追溯：CAP-03.1, CAP-03.2, BR-09

### FR-007 — 车辆与资源选择
- **当** 请求选择车辆
- **系统应当** 按运力、危险品授权、航线资格与可用性过滤，并列出被排除的候选
  及原因。
- 追溯：CAP-03.3, BR-07

## CAP-04 路径与派车

### FR-008 — 路径规划
- **当** 请求路径规划
- **系统应当** 经由可插拔的求解器边界产出遵守时间窗的停靠顺序（ADR-0002），
  在未配置求解器时回退到基于规则的排序。
- 追溯：CAP-04.1, ADR-0002

### FR-009 — 招标与接单
- **当** 一个派车计划被招标
- **系统应当** 按承运商分别记录 ACCEPTED / REJECTED / TIMEOUT 结果，在接单时
  冻结费率快照（BR-04），并要求先接单才能派车（BR-03）。
- 追溯：CAP-04.2, BR-03, BR-04

### FR-010 — 分配
- **当** 承运商接单
- **系统应当** 绑定车辆/司机（自有车队）或分包商引用，并把分配传递到仓库交接
  视图。
- 追溯：CAP-04.3, BR-10

## CAP-05 在途可视化

### FR-011 — 里程碑采集
- **当** 位置/状态数据从车载终端、承运商 EDI/API 或手工录入到达
- **系统应当** 追加带来源与接入时间戳的里程碑事件（BR-11），在已发布的部分
  使用 EPCIS 兼容词汇（FR-021）。
- 追溯：CAP-05.1, BR-11

### FR-012 — ETA 与异常管理
- **当** 新的里程碑使预计到达时间的变化超过配置的阈值 `(A)`
- **系统应当** 重算 ETA、开启一个带类型的异常（延误、损坏、拒收、短少），并
  通知升级名单；计划不被改写（BR-02）。
- 追溯：CAP-05.2, BR-02

### FR-013 — 送达证明
- **当** 发生交付
- **系统应当** 采集 POD（签名、照片、e-POD 引用），且只有在此之后才把该段
  运输转为 DELIVERED（BR-06），拒绝仅有状态的完成。
- 追溯：CAP-05.3, BR-06

## CAP-06 运费结算

### FR-014 — 成本计算
- **当** 一段运输完成
- **系统应当** 依据冻结的费率快照（BR-04）与实际服务（距离、重量、停靠点、
  附加费）计算预期运费成本。
- 追溯：CAP-06.1, BR-04

### FR-015 — 发票审计与三向匹配
- **当** 一张承运商发票到达
- **系统应当** 对其执行三向匹配（订单/招标 ↔ 执行事实 ↔ 发票，BR-05），
  在容差内自动通过，并开启一个列出每一个不匹配字段及其证据的争议流程。
- 追溯：CAP-06.2, BR-05

### FR-016 — 结算与争议
- **当** 某承运商某周期的已通过发票累积到一定数量
- **系统应当** 产出一个结算批次，并把争议结果保留为仅追加事件，供承运商记分
  卡消费。
- 追溯：CAP-06.3, BR-11

## CAP-07 危险品合规

### FR-017 — 危险品分类元数据
- **当** 某一托运行被申报为危险品
- **系统应当** 存储 UN 编号、正式运输名称、类别/项别、包装类别与数量，并针对
  已加载的法规数据表版本（视情况适用 ADR / IMDG / IATA DGR / JT/T 617）
  进行校验。
- 追溯：CAP-07.1, BR-07

### FR-018 — 隔离与装载校验
- **当** 危险品行被集拼或装载（BR-08）
- **系统应当** 依据法规数据校验隔离与积载约束，并拒绝不相容的组合，同时引用
  被违反的约束。
- 追溯：CAP-07.2, BR-08

### FR-019 — 危险品单证支持
- **当** 一票危险品运输被派车
- **系统应当** 输出适用法规版本所要求的托运/运输单证字段，并随该版本做版本
  管理——复制必需的*数据字段*，绝不把法规文本当作逻辑。
- 追溯：CAP-07.3, ADR-0003

## CAP-08 集成

### FR-020 — ERP/WMS 交接
- **当** 订单接入或交接事件发生
- **系统应当** 通过声明的接口与 ERP、WMS 交换它们，并让运输单/运输订单 ID
  在三个系统之间保持可追溯。
- 追溯：CAP-08.1, BR-10

### FR-021 — EPCIS 事件发布
- **当** 运输里程碑（发车、到达、交付、异常）发生
- **系统应当** 通过捕获接口，以 GS1 EPCIS 2.0 / CBV 2.0 词汇（业务步骤与
  处置）发布它们。
- 追溯：CAP-08.3

### FR-022 — 承运商 EDI/API
- **当** 配置了承运商连接
- **系统应当** 按承运商画像支持 UN/EDIFACT（IFTMIN/IFTSTA）、ANSI X12
  （214/990）或 REST，并提供报文级审计。
- 追溯：CAP-08.2
