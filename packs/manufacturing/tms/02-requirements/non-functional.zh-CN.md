# 02 · 非功能需求

> ⚠️ ASSUMPTION (A) — **本文件中的每一个数值目标都是工程预算，而不是测量
> 结果。** 没有任何一个追溯到公开基准或法规；它们在此声明，是为了让它们
> 可以被辩论，并在 L3/L4 被实测值替换。全部列于
> [`../SOURCES.md` §4](../SOURCES.md)。

| ID | 类别 | 目标 |
|---|---|---|
| NFR-001 | 可视化延迟 | 接入的位置/里程碑事件在运输单视图上反映 `≤ 60 秒 p95` `(A)` |
| NFR-002 | ETA 重算 | 相关里程碑之后，ETA 刷新 `≤ 30 秒 p95` `(A)` |
| NFR-003 | 招标送达 | 出站招标（EDI/API/Webhook）送达 `≤ 60 秒 p95` `(A)`；承运商回执异步处理 |
| NFR-004 | 事件持久性 | 不丢失任何已接收的里程碑事件（先持久写入再回执）；仅追加，更正以补偿事件表达（BR-11） |
| NFR-005 | 结算吞吐 | 标准运输段的发票三向匹配 `≤ 3 秒 p95` `(A)`；每月 `≤ 100k` 段的批次 `≤ 1 小时` `(A)` |
| NFR-006 | 规模档位 | `≤ 5 万`活跃运输单/天，`≤ 200 万`里程碑事件/天，`≤ 1 千`承运商连接 `(A)` |
| NFR-007 | 审计留存 | 执行事件、POD、发票、争议留存 `≥ 5 年` `(A)`（对齐当地诉讼时效；受监管变体更久） |
| NFR-008 | 互操作性 | EPCIS 发布符合 EPCIS/CBV 2.0；EDI 遵循 UN/EDIFACT 与 X12 名称；面向伙伴的数据不使用专有事件词汇 |
| NFR-009 | 可用性 | 订单/派车/结算核心服务月度 `≥ 99.9 %` `(A)` |
| NFR-010 | 危险品数据新鲜度 | 已加载的法规数据版本必须与运输日期在生效的版本一致；所需版本未加载时系统拒绝派车 |
| NFR-011 | 时间完整性 | 所有事件时间戳经 NTP 同步，偏差 `≤ 1 秒` `(A)`；来源与接入时间戳都存储（BR-11） |
| NFR-012 | 安全 | 带 SSO 的最小权限 RBAC；对派车/派车覆盖/结算动作的审计日志；个人数据（司机位置）留存最小化（GDPR） |
| NFR-013 | 可观测性 | 里程碑接入延迟、招标超时率、异常积压、匹配争议率、结算批次进度以指标形式暴露，并在配置阈值上告警 `(A)` |

> 上文每一个 `(A)` 标记都是一个等待被实测值或合同推导值替换的方案包策略
> 数字；预期由部署方覆盖它们。
