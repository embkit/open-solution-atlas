# 08-quality · 测试策略

层级、覆盖目标、测试数据，以及证明 NFR-001..NFR-013 与 CTL-01..CTL-08 的
性能/故障方案。AC 引用见 [`acceptance-criteria.md`](./acceptance-criteria.md)。

## 层级与覆盖目标

| 层级 | 它证明什么 | 特征 | 闸门 |
|---|---|---|---|
| 单元 | 领域不变量：BR-01 数量推导、BR-04 快照冻结、BR-05 容差结论、BR-06 POD 闸控、BR-09 运力+余量、BR-12 Incoterms 透传 | 纯函数，无 I/O | 领域 + 费率引擎 + 危险品校验器的行覆盖率 ≥ 90 % |
| 契约 | C-01..C-26 的 OpenAPI 3.1 一致性；RFC 9457 错误形态；幂等请求头；C-20 的职责分离 | 按模式校验的请求/响应 | 每个有文档的端点，含伙伴界面 |
| 集成 | 需求→运输单→招标→里程碑→POD→发票→结算旅程；EDI 适配器回路；WMS 交接；ERP 成本入账 | 临时存储 + 事件日志 + 假承运商/车载终端 | 顺路径 + 每种故障注入（F-01..F-08） |
| **状态机** | SM-T1..SM-T5 的迁移，包括非法迁移被拒；没有 POD 就无法到达 DELIVERED；轮次历史不可变 | 基于模型 | 覆盖全部 SM 迁移 |
| **仅追加 / 不可变** | 对里程碑/快照/匹配行的篡改尝试被拒；补偿事件绝不修改事实；重放确定性 | 日志重放 + 反向测试 | 事实被成功修改的次数为零，否则红灯（BR-11、AC-N04） |
| 并发 | 重复的招标回执（同一轮）只解析一次；重复的发票接入（同一发票号）只产生一次匹配运行；按运输段并行的里程碑接入保持有序 | 并行测试架 | 不产生双快照、不产生双匹配（NFR-008） |
| 性质 | 随机事件序列下的不变量：projection(plan) 等于最后一次计划修订；KPI 对照最初被接单的计划评估；结算合计 == Σ 快照作用行 | 基于性质，带种子 | 每晚 10,000 个随机序列 |
| 危险品合规 | 校验器对已加载版本语料：有效、无效 UN/PSN 配对、隔离冲突、版本缺失时拒绝、被篡改的版本导入 | 表驱动 | AC-017..020、AC-N05 |
| 端到端 | 经调度/结算工作台模拟器走 P-01..P-06 旅程 | 浏览器自动化 | 完整 AC 清单 |
| 性能 | 在 200 万事件/天形态数据上的 AC-N01..N03 负载与批次画像 | 负载发生器 | 跟踪回归；突破 NFR 即红灯 |
| 安全 | RBAC + 职责分离矩阵、伙伴渠道认证的反向测试、PII 最小化探针、依赖 CVE 扫描 | SAST + 载荷语料 | 任一职责分离绕过或 PII 泄露 = 红灯（CTL-06） |
| 控制 | 为一张争议发票做审计重建（快照→匹配→结果）；版本审计轨迹；EPCIS 发布完整性 | 日志重放 + 反向测试 | 每次运行都生成 CTL-01..CTL-08 的证据 |

## 测试数据

- **主语料：** 200 家承运商及其资质矩阵（航线、服务等级、危险品授权）、500 辆
  车辆（重量/体积/危险品变体）、带生效日期的费率合同（含燃油基准与附加费）。
- **里程碑语料：** 各承运商渠道的位置/状态流（车载终端桩、EDIFACT IFTSTA、
  X12 214、REST），含乱序、重复 `event_id`、时钟有偏差的代理。
- **发票语料：** 精确匹配、容差内 `(A)`、超容差、重复发票号、幻影发票（无已
  执行运输段）、收款方变更尝试。
- **危险品语料：** 各制度下的有效申报（ADR/JT 617/IMDG/IATA）、无效 UN/PSN
  配对、隔离冲突配对、版本缺失日期、被篡改的版本文件。
- 不含任何真实客户/承运商/司机数据；依赖时间的测试使用可控时钟（招标截止
  时间、版本在生效窗口）。

## 环境与晋级

```
PR        → lint + 单元 + 契约 + SM + 性质（快）
合并       → 集成 + 并发 + 危险品语料 + 预发上的安全/职责分离
发布      → 同一套件 + 性能画像 + 结算对账演练
每晚      → 10,000 个性质序列 + 投影与事实的对账作业
```

## 性能与故障方案

- **AC-N01/N02：** 针对 200 万事件/天形态数据集的 100 并发里程碑接入测试架；
  断言投影延迟与 ETA 的 p95 预算。
- **AC-N03：** 10 万运输段结算批次计时；单张发票匹配 p95。
- **故障注入：** 在接入中途杀掉事件存储（先持久写入再回执，AC-N04）；在报文
  中途丢掉承运商 EDI 会话然后重投（幂等性）；让求解器服务出故障（回退到
  基于规则，FR-008）；喂入被篡改的法规版本（AC-N05）；重放伙伴事件。
- **浸泡：** 24 小时峰值里程碑负载，观察发件箱延迟、死信队列增长与不变量违规。
