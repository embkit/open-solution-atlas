# 08-quality · 验收标准

每条 AC 都是一条映射到需求 ID 的可证伪测试陈述——也就是本方案包的**完成
定义**。「Given/When」条件都是具体的。NFR 的 AC（`AC-N*`）以
[`../02-requirements/non-functional.md`](../02-requirements/non-functional.md) 中的
`(A)` 预算为闸门；突破它们是红灯构建，但*这些数字本身*仍是等待被实测值替换的
方案包策略。

## 订单、集拼、规划

- **AC-001**（FR-001）：给定 100 件的授权需求，101 件的接入 → `422` 并
  指明来源引用，不持久化任何内容；100 件的接入能原样往返且 Incoterms® 规则
  保持完整。（BR-01、BR-12）
- **AC-002**（FR-002）：给定两条航线/时间窗兼容的订单行，其中一行被标记为
  危险品不兼容并存在隔离冲突，集拼只提议兼容的那一对；操作者的拒绝被连同
  身份记录。（BR-08）
- **AC-003**（FR-003）：一票多段运输的各段各自携带独立的承运商/招标/里程碑/
  结算；运输段级别的事实绝不出现在兄弟段的时间线上。
- **AC-004**（FR-006）：给定一辆 1000 kg / 6 m³ 且余量 5 % 的车辆，955 kg 的
  装载计划被接受；960 kg（低于 5 % 余量）→ `422`；拒绝信息同时引用重量与
  余量参数。（BR-09）
- **AC-005**（FR-007）：为危险品运输段选择车辆时，排除每一辆缺少匹配危险品
  授权的车辆，并逐个列出被排除的候选及未通过的资质。（BR-07）
- **AC-006**（FR-008）：未配置求解器时，路径规划返回遵守时间窗的基于规则的
  顺序；配置一个返回固定顺序的求解器桩时，同样的契约输入产出该桩的顺序——
  内核改动仅限配置。（ADR-0002）

## 招标与派车

- **AC-007**（FR-009）：招标的 ACCEPTED 回执冻结一个 RateSnapshot，其组成
  部分等于接单时的合同版本；此后修改合同不改变任何快照，且招标未 ACCEPTED
  时派车被阻断。（BR-03、BR-04）
- **AC-008**（FR-009）：截止前无回应的招标在轮次历史中呈现为 TIMEOUT；重新
  招标创建第 n+1 轮而不改写第 n 轮。（SM-T2、BR-11）
- **AC-009**（FR-010）：接单时，分配在一个投影周期内传播到包含承运商、车辆与
  ETA 的 WMS 交接视图。（BR-10）

## 可视化、异常、POD

- **AC-010**（FR-011）：从车载终端桩接入的里程碑出现在运输段时间线上，且
  `source_ts` 与 `ingestion_ts` 相互独立；重放同一 `event_id` 是空操作（不
  产生重复事实）。（BR-11）
- **AC-011**（FR-012）：给定 ETA 为 T 的已接单计划，越过阈值的延误里程碑
  开启一个带类型的异常并重算 ETA——计划修订及其原始 ETA 仍可读；准时率
  KPI 仍对照最初被接单的计划评估。（BR-02、ADR-0005）
- **AC-012**（FR-013）：`POST .../pod` 把运输段转为 DELIVERED 并发出
  `leg.delivered`；仅有「已交付」状态里程碑而**没有** POD 的情形下运输段仍
  在途并开启异常。（BR-06）
- **AC-013**（FR-013/FR-021）：POD 触发的交付恰好发布一个 EPCIS 2.0 事件，其
  业务步骤/处置取自 CBV 2.0 词汇，且发布载荷中除约定标识符外不含司机 PII。
  （CTL-04、CTL-06）

## 结算

- **AC-014**（FR-014）：为已完成运输段计算的成本等于冻结快照的干线运费 +
  燃油基准 + 附加费作用于实际值的结果；在合同版本变更后重跑同一计算返回同
  一个数字。（ADR-0004）
- **AC-015**（FR-015）：与执行在容差内（`≤ 3 % 或 ≤ ¥50` `(A)`）匹配的发票
  → AUTO_APPROVED；超出的 → DISPUTED，并列出每一个不匹配字段与证据引用；
  DISPUTED 不存在任何付款路径。（BR-05）
- **AC-016**（FR-016）：一个结算批次只包含某承运商/周期的 AUTO_APPROVED 或
  Adjusted 发票；调度员角色的会话调用批次契约 → `403`（职责分离）。
  （NFR-012、SM-T3）

## 危险品

- **AC-017**（FR-017）：UN 编号/PSN/类别配对在已加载的在生效版本中不存在的
  申报 → `fail` 并引用被违反的表行；有效申报返回 `pass` 以及所用的
  `edition_ref`。（BR-07）
- **AC-018**（FR-017/NFR-010）：在生效版本未加载（只存在一个被取代的版本）
  时，派车校验 → `409`；危险品运输段的派车被拒绝。（ADR-0003、SM-T5）
- **AC-019**（FR-018）：按已加载版本存在隔离冲突的两个危险品行被装载时遭
  拒绝并引用该约束；同样的配对配合合规的隔离方案则通过。（BR-08）
- **AC-020**（FR-019）：输出的运输单证恰好包含该版本要求的法规*字段*，绝不
  把法规散文渲染成系统文案。

## 集成

- **AC-021**（FR-020）：一个运输单/运输段 ID 在 TMS、它的 WMS 交接事件以及
  它的 ERP 成本入账中解析一致——一个跨三个系统的可追溯身份。（ADR-0001）
- **AC-022**（FR-022）：来自承运商桩的 IFTSTA 形态 EDI 报文映射为里程碑事件
  并保留报文级审计；畸形报文被隔离，适配器日志引用原始消息，绝不部分应用。

## NFR / 性能闸门（预算 `(A)`）

- **AC-N01**（NFR-001）：在 200 万事件/天形态的数据集上，100 个并发里程碑
  提交维持 p95 ≤ 60 秒的端到端投影延迟预算；断言实测 p95。
- **AC-N02**（NFR-002）：在同样负载下，相关里程碑之后的 ETA 重算 p95 ≤ 30 秒。
- **AC-N03**（NFR-005）：10 万运输段的月度结算批次在参考画像下 ≤ 1 小时完成；
  单张发票匹配 p95 ≤ 3 秒。
- **AC-N04**（NFR-004/007）：在接入中途杀掉事件存储；不丢失任何已确认的
  里程碑（先持久写入再回执），且重放是确定性的并保持仅追加的完整性。
- **AC-N05**（NFR-010）：版本守卫：导入被篡改的版本文件会失败完整性检查
  （SM-T5 Rejected），且永不会成为派车有效的版本。
- **AC-N06**（NFR-011/CTL-06）：在代理时钟有偏差的情况下双时间戳排序；司机
  位置留存作业删除超上限的行，且该删除有审计日志。
