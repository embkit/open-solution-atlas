# 09-delivery · 里程碑

按依赖排序的构建计划。每个里程碑都可演示，且只有通过其验证闸门才退出。任务
ID（`T-xx`）见 [`task-map.md`](./task-map.md)；AC ID 见
[`../08-quality/acceptance-criteria.md`](../08-quality/acceptance-criteria.md)。

| 里程碑 | 范围 | 退出闸门 |
|---|---|---|
| **M0 — 事件主干与身份** | 仅追加事实存储（里程碑、招标轮次、匹配结果）、投影、双时间戳、关联 ID、IAM/职责分离角色 | AC-N04、AC-N06；projection == fold(facts) 对账干净 |
| **M1 — 需求与主数据** | 运输订单接入 (BR-01/BR-12)、承运商/资质/车辆主数据、带生效日期的费率合同 | AC-001、AC-005；超量接入被拒 |
| **M2 — 规划** | 带危险品兼容的集拼、多段运输、装载构建 (BR-09)、带求解器契约与兜底的路径、车辆选择 | AC-002..AC-004、AC-006 |
| **M3 — 招标与派车** | 招标轮次、伙伴回执界面、快照冻结 (BR-04)、分配 + WMS 回执 | AC-007..AC-009 |
| **M4 — 可视化与 POD** | 里程碑接入（车载终端/EDI/REST 桩）、ETA/异常工作台、POD 闸控 (BR-06)、EPCIS 2.0 发件箱 | AC-010..AC-013 |
| **M5 — 结算** | 依据快照的成本、发票接入、三方匹配 (BR-05)、争议闭环、带职责分离的批次 | AC-014..AC-016 |
| **M6 — 危险品合规** | 法规版本导入/完整性 (SM-T5)、申报校验、隔离检查、单证字段输出 | AC-017..AC-020、AC-N05 |
| **M7 — 集成与加固** | EDI 适配器（IFTMIN/IFTSTA、214/990）、WMS/ERP 交接、性能与故障方案、安全复核 | AC-021、AC-022、AC-N01..N03 |

## 排序说明

- M6 依赖 M2（规划会调用隔离检查），但一旦版本存储（M0 主干）存在，就可以与
  M3–M5 并行构建。
- M5 依赖 M3（快照）与 M4（执行事实）；在两者都可演示之前它不能开始——没有
  它们的结算什么都测不出来。
- 性能闸门（AC-N01..N03）只有在 M4/M5 的量级下才有意义；它们在 M7 用成形
  数据集运行。
