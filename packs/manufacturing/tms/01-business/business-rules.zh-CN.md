# 01 · 业务规则

> 规则的 ID 是稳定的。理由中提及标准的规则会追溯到该标准
> （例如 BR-07 → ADR 2025 / JT/T 617 / IMDG / IATA DGR 数据表）。所有数值
> 参数（BR-05 容差、BR-09 运力余量等）都是**方案包策略**——见
> [`../SOURCES.md` §4](../SOURCES.md)。

| ID | 规则 | 理由 |
|---|---|---|
| BR-01 | 运输订单数量由授权需求推导而来，且永不超出（ERP 订单 / WMS 出库）；TMS 绝不凭空创造需求 | 单一商业权威（ADR-0001） |
| BR-02 | 计划与实际是两个独立状态；实际里程碑是仅追加事件，计划修订创建新的计划版本——历史绝不被改写 | 对账完整性（ADR-0005） |
| BR-03 | 一段运输只有在承运商接单后才能派车；自动接单（自有车队）是一项显式配置，而不是默认行为 | 承诺清晰 |
| BR-04 | 接单冻结用于结算的费率快照（合同版本、附加费、燃油基准），即使合同此后发生变化 | 发票可审计（ADR-0004） |
| BR-05 | 运费发票执行三向匹配（订单/招标 ↔ 执行事实 ↔ 发票）；超出容差 `(A) ≤ 3 % 或 ≤ ¥50 `(A)` 的不匹配进入争议流程，绝不静默付款 | 付款信任 |
| BR-06 | 一段运输只有在采集到送达证明事实（签名/照片/e-POD 引用）后才达到 DELIVERED；未被确认的到货是异常，不是完成 | 交付真相 |
| BR-07 | 装载危险品的货运行在派车前针对所引用的法规数据表（UN 编号/PSN/类别/包装类别/限制）进行校验；非法或无法归类的行会硬阻断该段运输 | ADR 2025 / IMDG 2024 / IATA DGR 67 / JT/T 617 ——只做校验，绝不重新实现法律（ADR-0003） |
| BR-08 | 集拼与装载构建必须遵守法规数据中的危险品隔离与积载约束；不相容的行绝不共用同一车辆 | 安全优先于利用率 |
| BR-09 | 装载重量 ≤ 车辆总重额定值，装载体积 ≤ 车辆容积，并带可配置的余量 `(A) ≥ 5 %`；超运力的计划被拒绝，而不是仅告警 | 物理与法定限制 |
| BR-10 | 仓库交接：货物在发车前经备货核验；计划数量与交接数量之间的差异被记录为事件，并阻断干净收尾 | WMS↔TMS 边界（兄弟方案包） |
| BR-11 | 所有执行事件都带来源与接入时间戳，且仅可追加；更正以引用原事件的补偿事件表达 | 数据完整性 |
| BR-12 | 订单上的 Incoterms® 2020 规则决定谁与谁订立并支付运输合同；TMS 消费该术语，绝不重新推导成本/风险分配 | ICC 规则是合同性的，不是系统逻辑 |

> BR-05 的容差、BR-09 的余量与 BR-03 的自动接单行为都是**方案包策略**的
> 例子——由部署方配置；本方案包不主张任何外部权威。
