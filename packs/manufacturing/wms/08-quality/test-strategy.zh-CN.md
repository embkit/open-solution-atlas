# 08-quality · 测试策略

层级、覆盖目标、测试数据，以及用于证明 NFR-001..NFR-014 和 CTL-01..CTL-07 的性能/故障测试方案。

## 层级与覆盖目标

| 层级 | 验证内容 | 特征 | 闸门 |
|---|---|---|---|
| 单元 | 领域不变量：BR-01 桶身份标识、BR-02 非负性、BR-05 预留生命周期、BR-06 批次流向、BR-09/10 盘点规则、GS1/AI 解析、策略排序（BR-03/04/07） | 纯逻辑，无 I/O | 领域 + 策略 + GS1 解析器的行覆盖率 ≥ 90 % |
| 契约 | C-01..C-31 的 OpenAPI 一致性；RFC 9457 错误结构；按货主范围筛选；幂等标头 | 经模式校验的请求/响应 | 所有有文档说明的端点，包括设备 Webhook |
| 集成 | 入站/单据 → 任务 → 库存变更 → 发件箱事件；仓储控制系统（WCS）任务循环；ERP 收货/发货过账；跨服务的行级安全（RLS） | 临时存储 + 事件日志 + 模拟 WCS | 正常路径 + 每项故障注入（F-01..F-10） |
| **并发/超卖** | 不得重复进行硬预留；软→硬预留原子化；预留与拣货之间发生崩溃 | 针对单个库存键的并行测试框架（NFR-002/008，AC-019） | **必须实现零超卖，否则为红灯** |
| 状态机 | SM-1..SM-6 转换，包括拒绝非法转换；任务完成操作具备幂等性（task+step+HU） | 基于模型 | 覆盖所有 SM 转换 |
| 属性 | 随机事件序列中的不变量：fold(log)==projection；Σbucket==on_hand；预留唯一性；补偿事件绝不修改事实 | 基于属性，使用随机种子 | 每夜执行 10,000 个随机序列（NFR-008/009） |
| E2E | 通过 RF/工作台模拟器在预发布环境中执行 P-01..P-08 端到端流程 | 浏览器/终端自动化 | 完整 AC 清单，包括 E-01..E-07 |
| 性能 | AC-N01..N04 负载与峰值测试配置 | 负载生成器 | 跟踪回归；违反 NFR 时告警 |
| 安全 | RBAC/行级安全（RLS）矩阵、职责分离（SoD）负向测试、IT/OT 允许列表、依赖项 CVE 扫描、标签伪造尝试 | SAST + 载荷语料集 | 任何跨货主越界或无界通道均为红灯 |
| 控制 | 审计重建、篡改可检测性、调整审批轨迹、追溯导出完整性 | 日志重放 + 负向测试 | 每次运行均生成 CTL-01..CTL-07 证据 |

## 测试数据

- **主语料库：**合成的 50k SKU 主数据，包含包装层级（EA/inner/case/pallet）、控制标志矩阵（批次/序列号/有效期/QC）、ABC 类别、危险品/温度属性；3 个仓库，其中 1 个为单一货主仓库，另 1 个为包含 ≥ 3 个货主的第三方物流仓库。
- **GS1 语料库（CTL-02）：**有效的 GTIN-8/12/13/14、校验位正确的 SSCC-18；AI 组合（10 批次、21 序列号、17 有效期、30/37 数量、重量）；负向样本：错误校验位、截断、重复 SSCC、非法 AI 顺序、处于打印机设备群最小/最大模块尺寸的标签（NFR-014）。
- **先到期先出/先进先出（FEFO/FIFO）语料库（BR-06）：**有效期重叠的批次、有效期相同时采用 FIFO 的决胜规则、位于有效期封锁窗口内的批次、采用后进先出（LIFO）/指定批次的 SKU。
- **并发语料库：**针对同一个 (SKU, lot, bin, owner) 键执行 N 个任务与 M 个单元的测试，其中 M < N（AC-019）；重复确认重放；预留后崩溃。
- **盘点语料库：**容差内、恰处于边界、超出容差、重新盘点、持续差异，以及自行审批尝试（BR-10/CTL-04）。
- 任何时候都绝不使用真实客户、供应商或货主数据；所有标识符均为合成数据。依赖时间的测试使用可控时钟，以覆盖有效期窗口和预留到期情况。

## 环境与晋级

```
PR        → lint + unit + contract + SM + property (fast)
merge     → integration + concurrency + RLS/security + E2E on staging
release   → same suite + performance profiles + DR drill (monthly minimum)
nightly   → 10,000 property sequences + reconciliation fold-vs-projection job
```

## 性能与故障测试方案

- **NFR-001 / AC-N01：**200 个并发用户的 RF 扫描测试工具（30 分钟）；断言 p95/p99。针对参考实现和 500M 事件数据集运行（NFR-003）。
- **NFR-002 / AC-N02：**10k 行波次分配计时，以及断言零超卖的并发预留测试工具。
- **NFR-004 / AC-N04：**持续 60/s 的变更负载，以及 10 分钟内突发至 120/s 的变更负载。
- **故障注入：**终止事务存储（RTO/RPO，NFR-006）；任务中途断开 RF 网络后重连（NFR-007/010）；对设备网关注入故障（FR-026 回退、单次变更）；重放设备事件；损坏事件行或尝试修改事件行（篡改可检测性，CTL-05）。
- **浸泡测试：**持续 24 h 的 RF 峰值负载，监控不变量违规和 DLQ 增长。

## 人工检查（明确标记）

- 在实际配置的打印机设备群上对 GS1 标签进行回扫（NFR-014）。
- 冷链/受监管叠加层**不属于核心范围**，仅使用各自的 `variants/` 进行测试——绝不作为核心方案包的通过/失败判定依据。
