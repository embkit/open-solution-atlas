# 09-delivery · 规模、工作量与风险

## 参考构建概况

- 仓储管理系统（WMS）是一个采用事件溯源的多服务系统，具有严格的正确性核心（单一库存写入方、原子预留）和广泛的仓库现场交互范围。相对比重集中于 M0（事件日志/Inventory）、M4（分配并发）和 M8（性能/HA/安全），而非 CRUD。
- 工作量以**相对档位**表示，而非日历工期估算：下文各里程碑的 T 恤规格用于表示各工作流之间的规划比例，而非用于排期。

| 里程碑 | 相对规模 | 构建工作量占比 | 主要成本驱动因素 |
|---|---|---|---|
| M0 基础 | XL | ~20 % | 事件日志、折叠、原子预留、行级安全（RLS） |
| M1 主数据与 GS1 | M | ~10 % | 通用、低风险 CRUD + 解析器 |
| M2 入库 | L | ~13 % | HU/SSCC、容差规则、上架策略 |
| M3 仓内作业 | L | ~12 % | 状态不变量、先到期先出/先进先出（FEFO/FIFO）、移库 |
| M4 出库与波次 | XL | ~18 % | 分配并发、防超卖 |
| M5 打包/发运/退货 | L | ~10 % | 发运闸门、装车/发运清单、GI 事件发布 |
| M6 盘点 | M | ~7 % | 差异/职责分离（SoD）、对账 |
| M7 自动化与追溯 | L | ~7 % | 网关边界、故障回退、追溯 |
| M8 加固 | L | ~13 % | 性能、高可用/灾难恢复（HA/DR）、安全测试套件 |

> ⚠️ ASSUMPTION: 上述相对档位和工作量占比是依据任务映射得出的示意性规划比例，而非实测数据；其用途是比较各工作流，而非安排日历工期。

- 多个编程智能体并行处理本方案包时，受跟踪任务的实现工作量会得到压缩；**不可压缩**的工作包括评审闸门、并发验证、RLS/SoD 安全验证和 DR 演练执行。

## 团队形态选项

| 形态 | 说明 |
|---|---|
| 单一工程师 | 仅 M0–M3 可行；M4/M8 的正确性评审实际上需要第二方参与 |
| 小型团队（2–4） | 建议的最低配置：一人负责 Inventory/事件核心（M0），其余成员分别负责入库/仓内作业与出库；一名评审人员负责并发与安全方面的 AC |
| 多智能体构建 | 首先完成 T-01..T-04（所有工作都依赖事件日志 + 预留原语）；并行推进 M1、M6、M7-adapter；**串行执行**所有涉及 Inventory 写入路径的任务 |

## 主要风险与缓解措施

| 风险 | 可能性 | 影响 | 缓解措施 |
|---|---|---|---|
| 并发场景下的超卖（本方案包的核心承诺） | 中 | 高 | T-03/T-04 原子比较并交换；将专用并发测试框架作为发布闸门（AC-019、AC-N02） |
| 事件日志/投影不一致 | 低 | 高 | 持续进行事件折叠结果与投影的对账；触发 sev-1 呼叫（T-02、AC-N09） |
| 策略引擎逐渐演变为按货主分叉的代码分支 | 中 | 高 | 执行 ADR-0004 的约束；仅进行配置变更；拒绝对某个货主作特殊处理的 PR |
| 设备网关将核心与厂商耦合 | 中 | 高 | 仅采用基于任务的边界（ADR-0003）；厂商适配器位于 `variants/` |
| 行级安全（RLS）/货主隔离回归 | 低 | 高 | 每次构建时执行自动化跨货主探测（T-05/T-37） |
| 规模化场景下未达到性能 SLO（NFR-001..004） | 中 | 中 | 针对 500M 事件数据集而非测试夹具进行性能剖析（T-34） |
| RF 离线处理导致重复过账 | 中 | 高 | 幂等确认键 + 重连时进行对账（T-36、AC-N07） |
| 范围扩张至估值/计划（ERP 的职责） | 中 | 高 | README 中的 ADR-0001 范围外清单；拒绝在契约中加入估值字段 |
| 受监管/保税/冷链功能被固化进核心 | 中 | 中 | 叠加层位于 `variants/`；核心仅编码控制义务 |

## 候选变体（非核心）

README 中声明的变体（manufacturing-linked、retail-ecom-3pl、cold-chain、xinchuang-cn）**不在核心范围内**，并各自单独估算规模；不得重新审议核心 ADR（ADR-0001..0004）。
