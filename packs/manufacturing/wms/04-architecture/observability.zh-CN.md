# 04-architecture / 可观测性

指标、日志、链路追踪、业务 KPI、告警和 SLO。链路追踪参见 NFR-013。

## 1. 三个遥测层面

1. **技术**：服务延迟/错误、队列深度、数据库/事件日志延迟、网关健康状况、RF/设备连接状态。
2. **运营（业务）**：按类型统计的未结任务/任务老化时长、波次与截单时间对比、月台状态、拣货/打包/发运吞吐量、短拣率、盘点差异。
3. **完整性（控制）**：超卖失败/预留冲突、负库存尝试、阻断货位上架尝试、被拒绝的扫描、未处理/DLQ 设备消息、调整量。

## 2. 关键指标与信号

| 领域 | 指标 |
|---|---|
| 入库 | 收到的预先发货通知数量、月台到库存耗时、收货异常率、上架任务老化时长 |
| 出库 | 波次释放→拣货→打包→发运延迟、行/小时、订单满足率、按时与截单时间对比、短拣率、重新分配次数 |
| 库存 | 准确率（BR-15）、未结调整、过期/冻结数量、零库存货位拣货尝试 |
| 任务 | 未结/进行中/异常任务数、任务交错比率、各执行主体生产率 |
| 自动化 | 任务接受延迟、故障率、回退至人工处理次数、设备事件延迟 |
| 平台 | p95/p99 扫描延迟（NFR-001）、分配时长（NFR-002）、变更操作 TPS、错误率 |
| 完整性 | 预留冲突拒绝次数、负库存尝试、不变量违规（可容忍告警数 = 0）、DLQ 深度 |

## 3. 日志与追踪

- 结构化日志使用关联 ID，覆盖订单 → 波次 → 任务 → 库存事件；跨服务及设备网关进行分布式追踪。
- 所有数量变更均已记录为业务事件（领域日志）；技术日志绝不能成为*唯一*的审计来源（CTL-05）。
- 日志包含仓库/货主维度；货主门户用户即使在仪表板中也只能查看其所属货主的数据（RLS）。

## 4. SLO 与告警（初始）

| SLO | 目标 | 告警阈值 |
|---|---|---|
| 扫描确认延迟 | p95 ≤ 800 ms（NFR-001） | p95 > 1 s for 5 min |
| 核心可用性 | ≥ 99.9%/mo（NFR-005） | 任何 sev-1 中断 |
| 事件发布延迟 | ≤ 30 s，outbox→bus | 延迟 > 2 min |
| 设备事件处理 | 无超过 5 min 的未处理事件 | DLQ 深度 > 0 / 延迟 |
| 分配 | ≤ 30 s/10k 行（NFR-002） | > 60 s |
| 截单风险 | 预计会错过承运商截单时间的波次 | 预测错过数 > 0 |
| 完整性不变量 | 0 次违规 | **发生任何违规时立即呼叫** |

## 5. 仪表板 / 角色

- **现场主管**：实时任务看板、异常队列、波次倒计时。
- **经理**：吞吐量、劳动生产率、空间使用情况、准确率趋势。
- **库存控制员**：盘点排程、差异、冻结/到期情况。
- **自动化工程师**：仓储控制系统/仓储执行系统健康状况、故障/回退情况。
- **货主（第三方物流）**：按本货主范围提供自助库存/吞吐量查询。

## 6. 合成/控制监控

- 持续验证 fold(event log) == stock projection（对账作业）；任何偏差均为 sev-1 完整性告警（验证 ADR-0002）。
- 定期断言一组模拟尝试（预留超出可用量、从冻结批次拣货）均被拒绝——控制级健康检查（CTL-03）。
