# ADR-0003 — 通过基于任务的设备网关集成自动化；WMS 永不控制机器

- 状态：已接受
- 日期：2026-10-08
- 标签：wcs, wes, ot, integration, safety, security

## 背景

自动化具有异构性：自动化立体库（AS-RS）、输送机/分拣机、自动导引车/自主移动机器人（AGV/AMR）、电子标签拣货各自采用不同的协议和运动级 API。将 WMS 业务逻辑与厂商专有机制耦合会：(a) 将产品锁定于特定厂商，(b) 允许业务系统驱动控制回路，从而模糊安全责任边界，以及 (c) 违反 IT/OT 分隔要求（IEC 62443）。

## 备选方案

1. WMS 直接调用厂商运动/IO API。
2. 在核心服务内部为每个厂商设置点对点适配器。
3. 采用单一基于任务的设备网关：WMS 发出业务任务并接收生命周期事件；所有运动和控制均由 WCS/WES 负责。

## 决策

采用方案 3。WMS 发布业务任务（移动托盘/容器标签（LP）A→B，将周转箱送至工位；源/目的地/优先级/装卸/物流单元（HU）——不涉及运动或 IO）。设备网关将其转换为各厂商的格式，并报告 accepted/arrived/picked/placed/faulted 状态及扫描结果。仅当 WMS 验证完成事件并采用与人工任务**相同**的变更路径时，库存才会发生变化（BR-14/FR-025）。设备网关是唯一通过 IT↔OT 连接通道暴露的 IT 组件（CTL-07/NFR-012）。人工回退复用相同的任务状态机（FR-026）。

## 后果

- 厂商中立的核心；新增自动化 = 增加网关适配器，而非更改核心。
- 安全边界清晰：WMS 不能直接驱动设备。
- 需要稳健的任务状态对账以及故障/回退语义；自动化中断时降级为人工处理，而非造成数据损坏。
- 网关的延迟/吞吐量对运营至关重要（NFR-013）。
