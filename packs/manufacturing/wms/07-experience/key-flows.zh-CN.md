# 07-experience · 关键流程

实施过程中必须遵守仓库现场的交互契约。这不是视觉设计；它规定了每个屏幕呈现哪些信息、按何种顺序呈现，以及哪些决策由服务端强制执行。每个流程均标明对应的流程编号（P-xx）及需求。

每个现场屏幕均遵循三条横向规则：

- **服务端权威控制点（BR-08）：** 扫描不匹配将阻断该步骤；终端不得“继续执行”。UI 便利功能绝不取代服务端检查（AGENTS.md 强制规则）。
- **离线容错（NFR-007）：** 确认操作在本地排队，并在重连时以幂等方式进行对账；屏幕必须显示明确的同步状态。
- **可归责性（CTL-01）：** 每次确认都记录操作员**和**设备；会话与二者绑定。

## E-01 收货工位（P-01, SM-1）

**目的：** 用最少键入将到货转为可用/待检库存，并完整记录所有差异。

- 信息顺序：预先发货通知（ASN）抬头（供应商 · PO · 月台）→ 行项目列表（预期数量与实点数量）→ 装卸/物流单元树（托盘→纸箱→EA）→ 处置提示。[FR-006, FR-007]
- 计数模式：**盲计**（隐藏账面数量）或**预期计数**；该模式是仓库设置，而非按用户切换的开关。[FR-007, BR-09]
- 构建装卸/物流单元（HU）时可打印系列货运包装箱代码（SSCC）标签；仅对控制标志要求提示批次、序列号和有效期的最小存货单位（SKU）显示这些提示。[FR-008, FR-002]
- 在 `±tol%`（BR-11）范围内的超收、短收或损坏可接受并记录；超出容差时，该行进入 `discrepancy-hold`，并通知 PO 负责人——屏幕须显示实际采用的确切阈值。
- 需要质检的 SKU 会被路由至 `qc-pending` 并分配待检库位；终端无法将其置为可用状态。[FR-009, CTL-03]
- 退出状态：进入 `putaway` 并生成上架任务。[FR-010]
- **失败界面：** SSCC 格式错误/重复 → 行内拒绝（`422`, CTL-02）；未知批次 → 异常库位，由主管处理（E-06）。

## E-02 拣货 — RF 终端（P-04, SM-3）

**目的：** 提供无歧义、经扫描验证且往返时间有界的单步拣货。

- 屏幕为单任务、单步骤：按 **来源库位 → 物品/托盘/容器标签（LP） → 数量** 的顺序；当前步骤确认前不显示下一条指令。[FR-020, BR-08b]
- 往返时延预算：提交 → 接受/下一条指令，p95 ≤ 800 ms，p99 ≤ 1.5 s（NFR-001）；UI 不得在热路径上添加阻断式动画。
- 预留完整性对用户不可见，但绝对有效：如果该库位/批次已被并行任务硬预留，则确认会被拒绝（`409`），任务将重新路由——绝不让拣货员自行解决竞态。[FR-019]
- 拣货数量不足必须选择原因代码，并立即提供从替代库位/批次重新分配或对订单作欠交处理的选项。[FR-020, BR-07]
- 拣货位库存低于补货最低量时，会产生补货任务，但不会阻断当前拣货员。[FR-013]
- **失败界面：** 网络中断 → 确认操作进入队列，并显示 `Offline — will sync` 状态标签；重连后，幂等确认键可防止重复过账（NFR-007/NFR-010）。

## E-03 复核与发运（P-05, SM-5）

**目的：** 防止错误或内容不完整的订单离开月台。

- 打包员扫描已拣选的托盘/容器标签；屏幕列出所需物品/数量/批次/序列号。对于受控货物，每个必需要素都必须扫描；不匹配将阻断操作。[FR-021, BR-08c]
- **发运闸门（BR-12）** 以明确检查清单呈现，而非笼统错误：必需批次/序列号已扫描、包装增值服务（VAS）已完成、重量已采集（如要求）、承运商标签和装车/发运清单已就绪、无阻断性异常。每个未满足项均按名称列出。[FR-021, FR-022]
- 装箱计算会推荐使用某个纸箱，并显示已采集的实际重量/体积。
- 装载：装载员扫描纸箱并将其装入拖车/装载批次；装车/发运清单与扫描所得集合进行比较（BR-08d）；装入错误装载批次的纸箱会被拒绝。[FR-022]
- 发运确认会扣减库存，并生成发货过账和出库 ASN；UI 应说明 ERP 过账为异步操作（ADR-0001）。
- **失败界面：** 缺少强制序列号 → 仅对受控货物阻断发运；非受控 SKU 可在记录原因后进行异常确认。

## E-04 主管 — 波次看板与截止倒计时（P-04）

**目的：** 确保已释放波次在承运商截止时间前完成；快速处理异常，同时不触及库存内部机制。

- 列：订单池 → 计划波次 → 已释放 → 拣货中 → 已打包 → 已装载/已发运；每个波次显示预计完成时间与 `cutoff_at` 的对比，以及**截止风险**标志。[FR-018, observability §2]
- 释放操作会在提交前说明后果：订单、订单行、预计拣货任务、将触发的补货，以及任何分配短缺。[FR-018]
- 分配在释放时以原子方式执行；预留冲突会导致整个释放失败，并列明被阻断的订单行——绝不产生半释放的波次。[FR-018, FR-019]
- 任务改派和任务交错（拣货 + 上架动线）通过一次操作完成；显示策略版本，使主管能够看出是*哪些规则*生成了任务。[FR-004, ADR-0004]

## E-05 循环盘点（P-06, SM-6）

**目的：** 通过盲计和职责分离式审批恢复准确性。

- 盘点期间，盘点员**看不到账面数量**；正在盘点的库位会被标记，并从上架候选中排除。[FR-024, BR-09]
- 在容差范围内 → 自动调整，盘点员仅看到“已记录”；不显示任何账面/差异数值。超出容差 → 立即提供复盘。
- 若差异持续存在 → 发起调整申请；审批人界面显示调整前/后数值、原因代码和盘点历史，且**申请人不能审批**（控件已禁用，实施职责分离（SoD））。[FR-024, BR-10, CTL-04]

## E-06 异常工作台（P-01/P-04/P-08, FR-028）

**目的：** 将所有卡住的工作单元集中到一个队列，并显示负责人和存续时长。

- 行：类型（短缺 · 逾期任务 · 被阻断库位 · 无候选库位 · 设备故障 · 损坏/DLQ 消息）、负责人、仓库、时长、建议处理方案，以及指向原始单据/任务的深层链接。[FR-028, integration §3]
- 建议处理方案仅供参考；覆盖操作（强制上架、允许负库存、取消波次）需要较高权限角色，并须记录原因。[security §3]
- 自动化故障会进入此工作台，并提供一键**回退到人工处理**，复用同一任务状态机——不会产生重复变更。[FR-026, ADR-0003]
- 空状态需列出当前生效的自动化项，例如：“没有未处理的异常——设备事件和预留正在自动监控。”

## E-07 货主门户（3PL）（FR-003, BR-13）

**目的：** 提供按货主隔离的自助可视性和处理凭证。

- 每个视图（库存、订单、入库、吞吐量、追溯）均通过行级安全（RLS）按会话所属货主过滤；不提供货主切换器。[FR-003, CTL-06]
- 按 SKU/批次/库位/状态提供实时现有量，并提供批次/序列号追溯和符合 EPCIS 规范的导出，以供召回使用。[FR-027]
- 可查看调整和冻结事件及其原因/审批人（只读）；门户绝不在列表、仪表板或导出中暴露其他货主的数据——这是经过验证的，而非假设。[CTL-01, CTL-06]

## E-08 必须设计的状态

| 情形 | 必需的用户可见行为 |
|---|---|
| RF 网络中断 | `Offline — N confirmations queued` 状态标签；排队的确认在重连后完成对账，不会重复过账（NFR-007） |
| 确认时预留丢失 | 任务自动重新路由；拣货员会看到新的指令，绝不会陷入死路（FR-019） |
| 波次分配部分失败 | 整个波次被拒绝；列明被阻断的订单行；不会留下半预留库存（FR-018） |
| 设备/自动化故障 | 任务移至异常工作台，并可一键回退到人工处理（FR-026） |
| 库位被阻断/正在盘点 | 不作为上架候选库位提供；如果被扫描，则拒绝并说明原因（BR-03/BR-09） |
| 盘点结果超出容差 | 提供复盘；申请人不能自行审批调整（BR-10/CTL-04） |
| 库存为零的货主 | 显示该货主的空状态；不显示跨货主内容，也不泄露错误（BR-13） |
