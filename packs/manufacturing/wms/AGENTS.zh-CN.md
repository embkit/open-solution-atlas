## 实施硬性规则

- **实物与财务 (ADR-0001)**：仓储管理系统（WMS）绝不计算库存价值；
  GR/GI/调整以事件形式传递至 ERP；绝不为匹配账簿数值而覆盖实物库存——应将差异转入盘点/调整工作流。
  核心库存实体或契约中不得包含货币字段。
- **仅追加库存 (ADR-0002)**：每次数量变更均为不可变的
  StockEvent，其中包含单据/任务/操作员/设备；更正应采用补偿
  事件。事实数据不得执行 UPDATE/DELETE。当前库存 = fold(events)。仅
  Inventory 服务 (C-25) 可写入库存。
- **禁止超卖**：硬预留由原子条件变更授予
  (BR-05, FR-019, C-23)；绝不为同一单元预留两次。
- **分桶不变量 (BR-01/BR-02)**：on_hand 分解和非负约束在 Inventory
  服务中通过事务机制强制执行——该服务是*唯一*的库存写入方。
- **设备边界 (ADR-0003)**：向仓储控制系统/仓储执行系统（WCS/WES）发出业务任务 (C-28)；
  绝不处理 PLC 运动/IO；设备消息仅驱动任务状态，库存变更
  必须通过与人工任务相同的经验证路径 (BR-14)。
- **策略即数据 (ADR-0004)**：上架/分配参数是带生效日期的
  配置；引擎提出方案，Inventory 负责验证硬约束。不得为各货主分叉代码。
- **扫描控制点 (BR-08)** 和 **先到期先出/先进先出 (FEFO/FIFO) (BR-06)** 必须在
  服务端强制执行，而不是依赖 UI 约定 (07-experience)。
- **职责分离 (SoD) (CTL-04)**：盘点员绝不能批准自己提出的超容差
  调整；调整前值/后值 + 原因 + 审批人均为必填项。
- **货主隔离 (BR-13/CTL-06)**：各处均采用按货主划分的行级安全 (RLS)；分配
  绝不跨货主。
- **IT/OT 边界 (CTL-07/NFR-012)**：仅设备网关可跨越至
  OT；必须基于允许列表、完成身份验证并以任务为依据。
- 受监管能力（电子签名/记录审查、保税账簿、
  温度偏离证据）位于 `variants/` 中——不得将其
  纳入核心。
- 任何与环境特定的内容 → `> ⚠️ ASSUMPTION:`；供应商选型仅放在
  `variants/` 中。

## L3 一致性要求（不可协商）

- ID 不可变：实现 FR/NFR/CTL/ADR/BR/SM/P/C/AC/T 引用时必须使用
  相同编号。
- **每项 AC 和每项任务 T 都必须追溯到一个或多个 FR/NFR/CTL/ADR/BR
  ID。**无法追溯的产物不算完成。
- `09-delivery/task-map.md` 中的每个 `T-xx` **与一张任务卡 1:1 映射**，并
  带有验证钩子；不得跳过该钩子。
- 验收标准章节是完成定义；`AC-Nxx` 是
  NFR/控制闸门。
