# 02 · 功能需求

EARS 记法：`当 <触发条件> 系统应当 <响应>`。
ID 永久稳定；每条都追溯到一项能力（`CAP-xx`）和一条业务规则（`BR-xx`）。
验收标准（AC-*）在 L3 定义。

## CAP-01 制造模型

### FR-001 — 主数据与生效日
- **当** 主数据（工厂、产线、工作中心、设备、物料、BOM、工艺路线、检验
  计划、人员、班次）发生变更
- **系统应当** 把该变更存为一个带生效日的新版本，并让已下达的工单绑定在它们
  下达时的那个版本上
- **并且应当** 拒绝删除任何被历史引用的版本。
- 追溯：CAP-01、BR-13

## CAP-02 计划承接

### FR-002 — 生产订单接入
- **当** 一张生产订单从 ERP 到达（创建/变更/取消）
- **系统应当** 在授权数量内按工艺路线拆分订单数量，创建或对账相应的工单
  （BR-01）
- **并且应当** 只把取消传播给尚未下达的工单。
- 追溯：CAP-02.1、BP-01

### FR-003 — 派工与有限队列
- **当** 工单准备好被排程
- **系统应当** 按可配置规则（优先级、到期日、换型分组）把它们派到产线/工作
  中心
- **并且应当** 允许在每个工作中心的有限队列内手工重排。
- 追溯：CAP-02.2、ADR-0004

### FR-004 — 下达闸门
- **当** 一名调度员下达一张工单
- **系统应当** 核验已备物料、工艺路线有效性与无质量冻结，并在拒绝下达时列出
  每一条未通过的条件。
- 追溯：CAP-02.3、BR-02

## CAP-03 执行与采集

### FR-005 — 工位操作
- **当** 一名操作员在工位终端上动作（开始/暂停/恢复/完成，录入良品/报废/返工
  数量）
- **系统应当** 按该工序的就绪状态校验（BR-02），并为每个动作记录一个不可变的
  执行事件。
- 追溯：CAP-03.1、BR-07

### FR-006 — 事件与参数采集
- **当** 工艺参数、计数或检验结果在工位上产生（人工或经设备集成）
- **系统应当** 把它们持久化为事件，绑定到工序、单元/批次、设备与操作员，并带
  来源与接入时间戳。
- 追溯：CAP-03.2、BR-10

### FR-007 — Andon 与升级
- **当** 一个异常由操作员或设备信号提出
- **系统应当** 开启一个 andon 事件，按角色与已耗时间通知升级矩阵，并记录
  确认/解决事件。
- 追溯：CAP-03.3、BP-04

### FR-008 — 操作员身份与技能
- **当** 一名操作员在工位登录
- **系统应当** 把其后的所有事件归属到该身份，并在该操作员缺少工序所需技能
  时告警（变体：阻断）。
- 追溯：CAP-01.3/03.1、CTL-04

## CAP-04 物料与谱系

### FR-009 — 备料与核验
- **当** 物料被备到一张工单上
- **系统应当** 要求对照已下达的 BOM 版本对物料与批次做扫码核验，并以具体理由
  拒绝不匹配。
- 追溯：CAP-04.1、BR-13

### FR-010 — 消耗记录
- **当** 物料在某道工序被消耗
- **系统应当** 针对具体批次记录消耗（实际扫码模式；按物料显式配置的反冲变
  体），并拒绝超出备料库存的消耗（BR-04）。
- 追溯：CAP-04.2

### FR-011 — 谱系遍历
- **当** 针对一个序列化单元或批次发起谱系查询
- **系统应当** 在留存窗口内跨全部工序返回反向关联（消耗的部件/批次）与正向关联
  （产出的单元）（NFR-005）。
- 追溯：CAP-04.3、BR-06

### FR-012 — 在制品跟踪
- **当** 单元/批次拆分在工序之间移动
- **系统应当** 从事件存储推导出当前在制品状态、数量与位置，并按工序汇总良率。
- 追溯：CAP-04.4、BR-03

## CAP-05 质量执行

### FR-013 — 检验闸门
- **当** 一道带计划检验的工序完成
- **系统应当** 在下一道工序解锁前要求一条已记录的检验结果，并把不合格结果
  路由到不合格品处理（FR-015）
- 阻断性闸门不可绕过（BR-05）。
- 追溯：CAP-05.1

### FR-014 — SPC 基线
- **当** 在某个受监控特性上采集到变量型数据
- **系统应当** 计算控制图统计量，并按配置规则对失控模式告警；深度 SPC 分析
  属于变体关注点。
- 追溯：CAP-05.2（变体深度）

### FR-015 — 不合格品与隔离
- **当** 提出一次不合格
- **系统应当** 隔离受影响的单元/批次（阻断放行与发运集成），带审批地记录处置
  （返工/报废/让步接收），并发出补偿事件以更新谱系状态。
- 追溯：CAP-05.3、BR-07

### FR-016 — eDHR/eBR（变体）
- **当** 受监管变体被启用
- **系统应当** 从事件汇编批次/器械历史记录，在配置的步骤要求电子签名
  （BR-11），并提供按例外审核的工具。
- 追溯：CAP-05.4；变体 `regulated-edhr`

## CAP-06 设备与效率

### FR-017 — 设备状态与停机
- **当** 设备状态变化（自动信号或人工录入）
- **系统应当** 记录带原因码的状态与停机事件，并在班次关闭前对未编码的停机
  自动编码（BR-08）。
- 追溯：CAP-06.1

### FR-018 — OEE 计算
- **系统应当** 严格按 BR-09，在工序、工作中心、产线与工厂各层级、按班次/日，
  仅从已校验的事件中计算 OEE。
- 追溯：CAP-06.2

### FR-019 — 工装计数（变体）
- **当** 工装/模具被使用
- **系统应当** 维护使用计数，并在达到维护阈值时告警。
- 追溯：CAP-06.3（变体）

## CAP-07 可视化与报告

### FR-020 — 产线看板与仪表盘
- **系统应当** 在 NFR-001 的延迟预算内，把实时在制品、andon 状态、目标与班次
  OEE 渲染到产线看板上。
- 追溯：CAP-07.1

### FR-021 — 可追溯性档案导出
- **当** 有人请求一份档案（审计、投诉、监管）
- **系统应当** 按 BR-06 生成一份完整且可导出的记录，包含检验结果与不合格品
  状态，并附一份完整性清单。
- 追溯：CAP-07.3、CTL-01/02
