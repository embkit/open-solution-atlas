- 通过模式（`法》第X条）定位仓库中的每一处**条文级**引用。共 **4 处**，均为当前内容编写工作中新增；此前没有此类引用。

**本轮检查的客观局限：**官方标准平台
（`openstd.samr.gov.cn`）对**搜索** URL 返回 HTTP 200，无论该标准号是否存在。此处的 200 只能证明可访问性，**不能证明存在性**。因此，标准的存在性始终通过显示标准名称和状态的搜索结果确认，绝不单独依赖 URL 探测。之所以记录这一区别，是因为这正是此前导致 `packs/data-ai/lakehouse-platform` 中出现捏造 ISO 引用的陷阱。

### 2.2 ❌ 缺口已闭合 — 《电子印章管理办法》确实存在

| | |
|---|---|
| 文件 | 《电子印章管理办法》 |
| 引文 | **国办发〔2025〕33号**，国务院办公厅 |
| 日期 | 签署于 2025-09-27，公布于 2025-10-09 |
| 状态 | **第三十八条：自公布之日起施行** |
| 官方文本 | <https://www.gov.cn/zhengce/content/202510/content_7043696.htm>（已获取全文） |

`workflow-bpm` 和 `one-stop-service` 此前都记录过这样一个开放问题：*“关于建立全国统一电子印章体系的要求未指定技术标准，因此本方案包也未指定任何标准。”* 这个问题**此前已可部分回答**，现已得到解答。关键支撑条款如下：

- **第五条** — 合规的电子印章与实体印章具有同等法律效力；加盖电子印章的电子文件与加盖实体印章的纸质文件具有同等效力。
- **第十六条** — 印章的电子签名证书必须有效，且由依法设立的电子认证机构签发；**印章有效期不得超过其证书的有效期**；数据格式、生成过程和**应用接口**必须符合国家标准。
- **第十七条** — 印章制作/备案机构**必须提供印章状态查询服务**。这是平台在设计时必须满足的一项具体集成要求。
- **第二十一条** — 原则是**“谁所有、谁控制，谁签章、谁负责”**。
- **第二十二条** — 用印过程信息必须**记录并留存**，从而使印章操作可追溯、可归责。
- **第二十三条** — 验证不仅应检查真实性/完整性/不可否认性，还应检查**印章在签署时是否有效**——这与验证印章当前是否有效是不同的检查。
- **第二十七条** — 行政机关和公共服务机构的业务系统**应支持合规电子印章**。这是一项*强制性要求*，也使 `one-stop-service` 的依赖关系论证不再仅建立在此前已有的依据之上。

## 3. 本次审计**未**涵盖的范围

明确说明如下，以免对本文件的范围作过度解读：

- 国际文件（GDPR、HIPAA、CCPA、EU AI Act、ISO/IEC、NIST、PCI DSS，以及技术标准）。未重新验证。
- 国家层面的临床适配规则和本地实施规则。

- 某项标准的**内容**是否与方案包对它的描述相符，而不是该标准是否存在、是否现行。

## 4. 持续性指导

1. **在未确认相关法律是否已经修订并重新编号之前，绝不引用中国法律条文编号。**《网络安全法》在方案包起草后的九个月内就证明了这一点。
2. **若条文提供的信息有限，应优先引用文书的标识信息（名称 + 文号 + 版本），而非其条文编号**；若条文能提供大量信息，则应核查编号。
3. **返回 200 的 URL 并不构成验证。** 标准搜索平台对不存在的标准号也会返回 200；同样，反爬虫 403/412 响应 (iso.org, nhc.gov.cn) 既不能证明标准存在，也不能证明其不存在。应通过明确*列明*标准及其状态的来源验证标准是否存在。
4. 将未获取的来源记录为未获取。仓库中的三个来源正是出于这一原因而有意不予引用。

## 5. 复现本次审计

提取过程可重复运行：

```powershell
# 各清单中不同的 regulatory id
Get-ChildItem -Recurse -Filter manifest.yaml | ForEach-Object {
  $in = $false
  Get-Content $_.FullName -Encoding UTF8 | ForEach-Object {
    if ($_ -match '^regulatory:') { $in = $true; return }
    if ($in -and $_ -match '^\S') { $in = $false }
    if ($in -and $_ -match 'id:\s*(\S+)') { $matches[1] }
  }
} | Sort-Object -Unique

# 仓库中的每处条文级引用
Get-ChildItem -Recurse -Include *.md -File |
  Where-Object { $_.FullName -notmatch '\\\.git\\|_site' } |
  Select-String -Pattern '法》第[一二三四五六七八九十百零]+条' -Encoding UTF8
```

第二条命令目前返回 **4 处命中**，分别位于
`workflow-bpm/00-context/regulatory-landscape.md` 和
`data-exchange/00-context/industry-brief.md`。这是需要关注的数量：
未经现行状态核查，该数量不应增长。
