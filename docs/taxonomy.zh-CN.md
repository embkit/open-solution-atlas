# 解决方案分类体系 v1

分类体系是方案库的货架地图。它有意采用**先按行业领域、再按能力**的方式组织——因为在受监管行业中，合规环境和业务语义会塑造整个解决方案。

每个方案包都恰好映射到一个 `domain` 和一个 `subdomain`。服务于所有行业的跨领域系统归入 `horizontal`。

图例：🟣 规划中 · 🟡 进行中（L1） · 🔵 L2 · 🟢 L3 智能体就绪 · ⚫ L4 已验证

> 这里的成熟度是指**完整性**，而非可信性。每个方案包还会在其清单文件中声明来源性质（`provenance`）和验证状态（`verification`）；当前所有方案包均为 `llm-drafted` / `unverified`。参见
> [方案包标准 §8](pack-standard.v1.md#8-provenance--verification)。

## finance — 金融（暂缓征集：银行类系统）

> **征集说明（2026-10）：**银行业专属子领域——银行核心系统、银行风险、银行监管报告、银行支付/清算——目前暂不征集，原因是为避免维护者产生利益冲突。该领域仍保留给明确的非银行系统：保险核心系统、通用第三方金融科技工具、开源金融基础设施模式。涉及受监管金融领域的方案包需要额外审查，并且仅可引用公开来源。

| 子领域 | 示例方案包 |
|---|---|
| 保险 | 保单管理、理赔、评级/再保险 |
| 通用金融科技基础设施 | 非银行支付抽象、开源账本模式、个人金融工具 |
| 财富管理（非银行分销） | 不由存款机构运营的基金/财富分销平台 |

## 对分类体系的贡献

分类体系通过拉取请求演进。新增子领域需要：（1）提供证据，证明至少有两个彼此不同的真实世界系统适合该领域；（2）用一段话界定其与相邻子领域之间的边界；（3）至少有一个引用该子领域的方案包提案。
